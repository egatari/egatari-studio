# Editor app (no install)

English | [日本語](editor.ja.md)

A web page that opens a deck folder directly and does what the [dev server](dev-server.md) does: preview, edit the source and the narration on the slide, and leave comments for Claude. It also opens a [portable file](reference.md#portable-file---portable) (one HTML file that carries its source, following the [portable deck format](https://github.com/egatari/egatari-spec)) without any folder, edits it in memory and saves it again. There is nothing to install and no terminal to use.

- **Browsers:** Google Chrome or Microsoft Edge on a computer (Windows, macOS, Linux, ChromeOS). Folders use the File System Access API (`showDirectoryPicker`), which Safari and Firefox do not have; on other browsers the first screen says so. A portable file can be opened and edited in any current browser; without the file pickers, saving downloads the file.
- **Network:** none, apart from loading the editor itself. The deck folder or file is read and written in the browser and is never uploaded. Only if you use browser TTS (in the [Audio panel](#narration-audio-audio-panel)), a separate TTS window of the editor's site downloads the model; the editor page itself still connects nowhere.

## Getting the editor

| Form | How | Notes |
|---|---|---|
| Hosted | <https://editor.egatari.org/> | Published from `main` by `.github/workflows/pages.yml`. Loads only the font files a deck needs. The old address `…/editor/` redirects there |
| One file | `npm run build:app`, then double-click `dist/editor.html` | About 10 MB: all font files are inside. Works from `file://` in Chrome and Edge; you can copy the file to anyone |
| Your own server | `npm run build:app`, then serve `dist/` as static files | Any static host (https, or `http://localhost`), at the root or under a path |

`npm run build:app` (`node tools/build-app.mjs [--out dist] [--no-single]`) needs `npm ci` first (it uses esbuild, a pinned dev dependency).

## Using it

1. **Open a deck.** Drop the deck folder (the folder with `deck.html`; if there is no `deck.html`, the first `.html` file at the top of the folder) onto the page, or press 「フォルダを開く」 / "Open folder". The browser asks once whether the page may edit that folder.
   - **New deck** makes `deck.html` and `narration.md` from the same template as `npm run new` (title, language, theme). Choose an empty folder to use it as is; if the folder is not empty, a new folder named after the title is made inside it.
   - **Recent folders** are listed on the first screen (the browser keeps the folder handles in IndexedDB; the contents are not stored). When you reopen one, the browser asks for permission again.
2. **Edit.** The keys are the same as the dev server (and the toolbar has buttons for them):

   | Key | Action |
   |---|---|
   | `e` | edit mode; **double-click** an outlined element to open its source (HTML, with math as `\( … \)`), ⌘/Ctrl+Enter to save |
   | `n` | narration drawer for the step on screen (speaker, add / delete / reorder turns) |
   | Alt+click (Mac: ⌥ Option+click) | leave a comment for Claude about that element (`comments.json`); the point you clicked is kept as a pin |
   | `c` | list of open comments, numbered; while it is open, the pins of the step on screen are marked on the slide. Click one to go to its slide and step (its pin flashes), “Resolve” to mark it done |

   The edit-mode bar, the source box, the narration drawer, the note box and the note list sit in one side panel on the right (the preview shrinks beside it), under an orange bar **編集中 — アプリ** / **Editing — app**. They are part of the editor page, not of the deck; **anything inside the slide area can be drawn by the deck, so trust only controls in the editor's own panels.** While the source or note box is open, the preview does not take clicks. The preview only points at what you double-clicked or Alt+clicked, and the editor reads the source, shows it and writes it when you press Save (or ⌘/Ctrl+Enter). The keys work with the focus on the preview or on the editor.

   As with the dev server, a save is refused if the file changed since the preview was built (the source hash or the narration revision does not match); reload and try again.
3. **Work with Claude Code.** Keep the editor open while Claude Code (or any editor) changes the folder. The editor looks at the files about every 1.5 s; when one changes it rebuilds and reloads the preview on the same slide and step. What you are typing in an editor card or the narration drawer stays while the preview reloads (it is in the editor page); if the same element or step changed meanwhile, the save is refused. If the build fails, the error is shown over the preview until the file is fixed.
4. **Present and share.** Use the toolbar (it fits one row from 1280 px wide; below that it wraps). **Open ▾** has Open folder… and Open file…; **Export ▾** groups the exports and printing:
   - **Quick check:** a subset of `npm run check` that runs in the preview (overflow, font size, title / conclusion length, missing narration, palette contrast). Click a result to go to the slide. It is a hint, not the full check: there are no component determinism, timeline, morph or accessibility checks, and the numbers can differ slightly from the command-line check because the window differs.
   - **Export ▾ → Export HTML:** builds the deck without the editing hooks and saves it as one HTML file (asks where to save). Double-click the file to present it anywhere.
   - **Export ▾ → Print / PDF:** the browser's print dialog for the deck (one page per slide with the final state of each, as with `tools/pdf.mjs`; choose “Save as PDF” and turn on “Background graphics”).
   - **Presenter view** (or `p` in the deck): a window with the current slide, the next step, the narration as speaker notes, a timer and the drawing tools. It controls the preview in the editor window.
   - **Fullscreen:** the preview fills the screen (for the projector).

## Narration audio (Audio panel)

**Audio** in the toolbar opens a card in the same trusted side panel, for the step on screen (it follows the slides; while recording or generating it stays on its step and says so if the slides moved). It works the same for a folder and for an opened portable file.

- **Current audio.** Plays the step's audio from `audio/manifest.json` (read from the folder or file in the editor page, never from the preview), with its kind (**recorded**, **TTS**, **imported**), length and source (for TTS: engine, model, voices, seed). A **stale** badge means the narration changed after the audio was made, or it is unknown which narration it was made from (format spec §5.4: its `inputHash` is `null` or differs from the current narration; for a manifest written by an older `tts/synth.py` without `inputHash`, the TTS cache record `audio/seg_<digest>.json` is compared instead). The Warnings list, the quick check and `npm run check` list stale steps too. The step's script is shown for reading aloud.
- **Record.** **● Record** asks the browser for the microphone (once per site) and records with `MediaRecorder` while a level meter and the elapsed time are shown; **■ Stop** ends it. Recording again keeps the earlier takes. Echo cancellation, noise suppression and automatic gain are off. A take is at most 600 s.
- **Import a file…** takes a WAV, MP3, M4A, Ogg, WebM or FLAC file (up to 64 MiB; the size is checked before reading).
- **Regenerate with TTS** makes the step with browser TTS: Irodori-TTS 500M-v3 for a Japanese deck (with the reading dictionary `tts/yomi.yaml`, applied with the same rules as `tts/yomi.py`; the voices of `voice.json`, `bob` and `alice` by default; seed 42, 40 steps), Kokoro-82M v1.0 otherwise (`bob` → `am_michael`, `alice` → `af_heart`, or a Kokoro voice name in `voice.json`). Each part between `{cue}` / `{mark}` boundaries is synthesized and post-processed on its own and the parts are joined like `tts/synth.py` does (350 ms between turns), so the take has cue times (`sync: "auto"`). The first time, the editor says what it downloads (about 1.26 GB for Irodori fp16, 2.44 GB on GPUs without fp16 shaders, about 330 MB for Kokoro; later runs read the browser cache) and opens a small window of the editor's site (`lab/tts-helper.html`) that loads the model and does the synthesis on this computer's GPU. That window receives only the text to read (after the reading dictionary) and the voice name, and returns audio. WebGPU is required (a recent Chrome or Edge on a computer); without it the button is off and the panel says to record instead or to use `tts/synth.py`. Not available in the single-file editor (`file://`). Other reference voices need `tts/synth.py`.
- **Post-processing** is the same as `tts/core.py`, in the browser (`kit/core/audio-core.mjs`): mono, 44.1 kHz, leading and trailing silence trimmed (−45 dB over a 20 ms window, 50 ms kept), loudness set to −20 LUFS (EBU R128 integrated loudness, one linear gain; where ffmpeg's loudnorm would switch to dynamic processing because the true peak would pass −1.5 dBTP, the gain stops at −1.5 dBTP instead). `tools/test-audio-core.mjs` compares lengths and loudness with `tts/core.py` on the same input.
- **Use this take** encodes the take as MP3 (LAME, 64 kbps CBR, mono, 44.1 kHz) and writes `audio/<rec|tts|imp>_<hash>.mp3` and the step's record in `audio/manifest.json` (the previous manifest goes to `.cache/edits/`; earlier audio files stay, like `tts/synth.py` leaves old wav files). The record says where the take came from: `kind` (`recorded`, `tts` or `imported`), `inputHash` (the narration the take was made from, at the time it was made), and for TTS a `recipe` (`engine`, `model`, `voice`, `seed`, `dictionary` = SHA-256 of the reading dictionary, `processing` = `trim-45-loud-20-v1`). Recorded and imported takes have no cue times (`sync: "none"`, cues empty): cue-driven motion and marks then advance by time. The step's length follows the new audio (`dur` in the manifest; the runtime computes the timeline from it); a `dur` override in `timeline.json` still wins, and the panel warns about it. Unused takes stay in memory until you use one or open another deck. `tts/synth.py` keeps recorded and imported takes (`--replace-recorded` replaces them).
- **Portable files:** using a take changes the in-memory folder; **Save** then writes it without rebuilding (tier A: only the step's audio record, its runtime audio entry and the archived audio change).

## Portable files (no folder)

A portable file is what `npm run build -- <deck.html> --portable` (or “Export portable file” in the editor) writes. It plays like any built deck, and it carries the deck's source and audio, so the editor can work on it without the original folder.

- **Open.** Press **Open file…** (on the first screen, or **Open ▾** in the toolbar), or drop the file onto the first screen. The editor reads the file as bytes and extracts it in a Web Worker with an HTML parser that runs no scripts; the file itself is never loaded as a page, so nothing in it runs during import. Every hash, size limit and path rule of the format is checked first, exactly as `npm run portable -- unpack` does. The HTML is parsed with budgets counted while parsing (elements, attributes, nesting depth), and the source files it carries may hold at most 500 000 tags, so a file of millions of tiny elements is refused before a full tree is built; a read that takes longer than 30 s stops the worker and refuses the file. The build and the code check of an opened deck (folder or portable file) also run in a worker, within the build limits (see [reference](reference.md#build-limits)); a build that takes longer than 60 s stops that worker and fails (`build-timeout`), and the page stays responsive meanwhile. The build reads from the folder only the files it references (at most 8 at a time, each up to its listed size; a file that grew since the listing is refused); a reply from a stopped worker is dropped. Every file is read with its size checked from `File.size` before reading and from the bytes read (`app/bounded-read.js`); `deck.html`, `narration.md` and `comments.json` have fixed limits (32 MiB, 16 MiB, 4 MiB) and a larger one is refused without being read. The source then lives in memory (an in-memory folder); the preview, the editing tools and the quick check work on it as on a folder. Outside changes are not watched (there is no folder).
- **Save.** **Save** writes the same file again when the browser gave a writable handle (Open file… or drag and drop in Chrome / Edge; the browser may ask for permission the first time). Otherwise it asks where to save, or downloads the file when there is no save dialog (Safari, Firefox). The document id (`docId`) stays, and Save never sets or changes `derivedFrom`. The menu next to Save (**Save ▾**) has:
  - **Save as new lesson…**: asks where to save and writes the lesson under a new `docId`, with the original recorded as `derivedFrom` (its `docId` and source hash). Copyright, attribution and creators are kept. The open document becomes the new lesson (later saves keep the new id).
  - **Save a copy…**: asks where to save and writes the same lesson (same `docId`) to another file.

  A dot (●) before the file name means there are unsaved changes; leaving the page or opening another file asks first. In every save the license, copyright, attribution and creators, members of the index the editor does not know (at every level: metadata, audio records, archived blobs, components and themes, extensions) and extension data are kept, and untouched audio is copied byte for byte. The editor may add the settings file (the lesson id and metadata at the root of the source) to a file that lacks it; that changes the source hash, which the save updates anyway.
- **Saving without rebuilding.** When only narration (the text of turns, marks and cues), audio or the timing overrides in `timeline.json` changed, Save does not rebuild the slides. It rewrites only the parts of the file that the [format](https://github.com/egatari/egatari-spec) lists for such an edit (§7.2, tier A): the changed entries of the runtime narration, mark, timing and audio data; the changed steps of the text layer that is readable without script; the source hash and the archive index with its hash; the archived files (new content added, content that nothing refers to any more removed); and, only when the new text uses characters the embedded fonts lack, a new font supplement (a style element with just the font files that cover those characters, from the editor's own font files; the fonts already in the file are not touched). Every other byte of the file stays exactly as it was, including runtime code written by another tool or another version. The status bar says “saved without rebuilding”. Removing all of a step's narration also removes that step's audio; the save notice says there are warnings, and the Warnings list names the step. Timing overrides are copied entry by entry; the runtime computes each step's length from them with the same formula as before.
- **Saving with a rebuild.** When you edited a slide (or anything else outside the list above changed, or the file's compiled lesson and its source disagree), Save rebuilds the whole file from the edited source with the editor's bundled kit, components and themes, so it plays exactly like the preview. Before saving it warns: **“The slides are rebuilt with the current version of this editor. Slides you did not edit may look different.”**, says why it cannot save without rebuilding, and saves only after **Rebuild and save** (Cancel keeps the changes unsaved). Known gap: the editor does not yet compare the slides before and after a rebuild; check the preview after saving.
- **Stale audio.** Editing a step's narration does not touch its audio: the bytes and the kind stay, the step is listed as stale in the warnings, and in the saved file its audio record still carries the hash of the narration it was made from, so every reader sees it as stale. Re-record it or regenerate it in the [Audio panel](#narration-audio-audio-panel).
- **Export ▾ → Export folder…** writes the source, the audio and `audio/manifest.json` to an empty folder you choose (the same files as `npm run portable -- unpack`); a folder that is not empty is refused. The folder then opens, builds and packs like any deck folder.
- **Export ▾ → Export portable file** (for an open folder) writes the folder as a portable file. The first time, a lesson id is written to the folder's settings file so that later exports keep it.
- **Not saved into the file:** comments for Claude and the backups in `.cache/edits/` stay in memory only (comments are review notes; the format leaves them out).

### Rights prompt

Each time a file is opened for editing, before the first change (the first save from edit mode or the narration drawer, or pressing Edit / Narration), the editor shows the lesson's title, creators, copyright, license and attribution as written in the file (they are claims; nothing verifies them). If the license does not permit derivatives (a Creative Commons `-ND` license, or “All rights reserved”), or there is a copyright notice but no license, it warns that modifying or sharing a modified copy may infringe the rights holder's copyright, and editing starts only after you tick the confirmation. Cancel leaves the file unchanged. Saving never removes the copyright, attribution or creators.

### Files the editor refuses or opens read-only

- **Refused, with the reason:** a file that is not a portable file or is play-only, a broken hash or a missing part, a path that is not allowed (e.g. `../`), a duplicate member in the index, a document id that disagrees with the settings file, and a newer source contract.
- **Newer major version, or a required feature the editor does not implement:** not opened for editing and never re-exported. The dialog offers **Export folder…** to extract the source when the index and the archived data check out with the rules of the version the editor knows; otherwise extraction is refused too. (Such a file may still play in a browser.)
- **Narration, audio and timing only:** a different runtime contract, or registry components or themes whose hash differs from the editor's (or that the editor does not have). The editor cannot rebuild such a file faithfully, so a notice says only narration, audio and timing can be edited: Edit (slide text) is refused, the narration drawer works, and Save rewrites only those parts without rebuilding. A change that needs a rebuild cannot be saved.
- **Read-only:** a file the editor cannot build, and a file of the previous kind whose compiled lesson and source also disagree. The deck is shown, Save is refused, and Export folder… works.
- **Its own code:** whether a deck has code of its own is decided from the built document — the source after every include and preprocessing step, covering every file the build reads as text whatever its extension (an image file included with `/*INCLUDE:…*/` counts), and the same bytes the preview then shows (a `<script>` without `src` whose content is empty or only whitespace is not code; one with only a comment is); the folder is not read a second time to check. Before anything from such a deck (or a file with the “extended” profile) runs, the editor says so and asks; the preview starts only after **Start the preview** (Cancel leaves the file closed). The preview is emptied before the question, so neither the previous deck nor anything of the new one is shown or runs behind it. While it is open, a notice stays at the top: the code runs only inside the preview, without network access, and cannot change the file. The same question comes for a folder with components (`components/…`, any `.js` file) or scripts in `deck.html`, once per opened folder (also when such code appears later).

## Files it writes

Exactly the same as the dev server ([dev-server.md#files-it-rewrites](dev-server.md#files-it-rewrites)), all inside the chosen folder:

- `deck.html`: only the contents of the element you edited
- `narration.md`: only the lines of the step you edited (comments and other lines stay)
- `comments.json`: comments for Claude, `[{id, created, key, range, pin, quote, comment, status}]` (`pin` is the clicked point `{x, y}` in slide coordinates, 1280×720; see the [dev server](dev-server.md#files-it-rewrites). To look at what the comments point at, run `npm run comment-shots -- <deck folder>` on the folder: it renders each open comment's step with its pin into `.cache/comment-shots/`)
- `audio/<rec|tts|imp>_<hash>.mp3` and `audio/manifest.json`: with **Use this take** in the Audio panel (only the step's record changes; the previous manifest is backed up)
- `.cache/edits/`: the previous `deck.html` / `narration.md` / `audio/manifest.json` before each change (the newest 30; cleanup deletes only files named like these backups, `<time>-<name>`, and leaves anything else in the folder)
- with “New deck”: `deck.html` and `narration.md`; with “Export HTML” and “Export portable file”: the file you chose (and, the first time, the lesson id in the settings file of the folder)
- with an opened portable file: nothing until you save (edits are in memory); then only the file you chose, or the files in the empty folder of “Export folder…” (saving without rebuilding rewrites only the parts listed above)

## Limits

- **Chrome / Edge only.** Mobile browsers cannot open folders either.
- **Command line only:** TTS with your own reference voices or the server engines (`tts/synth.py`), video and bundles (`tts/`, `render/`), the full check (`npm run check`), `tools/pdf.mjs`. The preview does not play the folder's audio (`audio/`): autoplay uses the default timing, as without audio; the Audio panel plays each step's audio in the editor page.
- **Audio panel in the editor app only.** The dev server has no Audio panel (open the folder in the editor app, or use `tts/synth.py`). Browser TTS needs WebGPU and the hosted or served editor.
- **Bigger exports.** The command-line build can subset the Japanese font with fonttools (`node tools/get-fonts.mjs`); the browser cannot, so the editor embeds the matching font files whole (as the command line does without the TTF files). `examples/minimal` is about 2.0 MB from the editor and 0.7 MB from `npm run build` with subsetting. The deck looks the same.
- **No Mincho in the single file.** The hosted editor includes BIZ UDPMincho (loaded only for decks that use it, such as theme `kokugo`); the single file `dist/editor.html` does not, to stay small. There a Mincho deck builds with a warning and shows the viewer's own Mincho font.
- **Bundled parts.** Components (`components/`), themes (`themes/`) and the runtime (`kit/`) of the repository are the ones bundled when the editor was built. Components and themes inside the deck folder (`components/<name>/index.js`, `themes/<name>/`) are read from the folder as usual.
- **Not read:** names starting with `.`, and the `out/`, `audio/`, `video/`, `bundle/` and `node_modules/` folders (up to 3000 files, 10 levels deep). `audio/` is read only to export a portable file.
- **Rebuilds are not compared yet.** A save that rebuilds (after a slide edit) builds the whole file again with the bundled kit, so a file made by an older or newer build changes outside the edited parts, and fonts are embedded whole. The editor does not yet show which slides changed besides the edited ones.
- **Font supplements err on the side of more.** For a file whose subset fonts declare no `unicode-range` (made on the command line by an earlier version), the editor knows only that the characters of the original narration are covered, so it may add font files for characters the subset already had (the file grows a little; it never lacks a glyph).
- **Network in the deck is blocked.** External images and scripts (`https://…`) do not load in the editor's preview; the build warns about them anyway.

## How it works and security

- **One build for both.** `kit/core/build-core.mjs` is the build (annotation, includes, KaTeX, components, narration, marks, timing, themes, assets, fonts) with no Node dependency; it reads files only through an interface it is given. `kit/build.mjs` passes Node's file system (plus fonttools subsetting and ffmpeg); the editor passes the chosen folder and the bundled kit, components, themes, KaTeX and fonts. With font subsetting off, both produce byte-identical HTML (`tools/test-app.mjs` checks this for `examples/minimal` and `examples/tmlr2026-calibration`). The narration parser and the narration rewriting (`kit/core/narration-core.mjs`) and the new-deck template (`kit/templates/new-deck.mjs`) are shared the same way.
- **One editing UI for both, outside the deck.** `server/editor-ui.js` (the source card, the narration drawer, the comment box and list) runs in the editor page here and in the dev server's frame page. It sends the same requests (`/__dev/source`, `/__dev/edit`, `/__dev/narration`, `/__dev/comment`, …): the dev server answers them over HTTP, the editor answers them in the page against the folder (`app/devapi.js`). Inside the deck there is only `server/hints.js`, which sends hints (see below).
- **The deck runs in a sandbox and cannot write.** The preview is an `<iframe sandbox="allow-scripts allow-modals">` without `allow-same-origin`, so the deck has an opaque origin: it cannot reach the editor page, its storage or the folder handles. `allow-modals` is there for printing. On top of the page's Content-Security-Policy (which allows loading only the editor itself and no frame navigation, `frame-src 'none'`), the preview document gets its own policy in force before any byte of the deck is parsed: the editor builds the document as a trusted prefix (doctype, `<html><head>`, `<meta charset>`, the policy `<meta>` and a small trusted shim) followed by the built deck unchanged, and never searches the deck's markup for a place to put the policy. The policy is `connect-src 'none'`, images, fonts, styles and media only from `data:` / `blob:` (the build embeds them), no workers, frames, forms or `<base>` (`'unsafe-eval'` stays because components build formulas with `new Function`, e.g. `m-sweep f="…"`). The presenter view is a window the editor opens, with the deck again in a sandboxed iframe under the same policy; the editor relays its messages.
- **Hints, not requests.** The preview has no way to ask for a write. It sends only hints: “edit the element with this `data-src` range and hash” (double-click in edit mode), “a note at this element” (Alt+click; the slide and step key, a short quote of the element, the text near the point and the point in slide coordinates), the keys `e` / `n` / `c` / Esc, and its position (`deck-pos`). A hint carries no text to write. The editor checks the source window and the shape of each hint, ignores an edit hint outside edit mode, reads the current source itself, checks that the range is an editable element of the current build and that the hash matches, and shows its own card; it writes only when you press Save or ⌘/Ctrl+Enter in that card or drawer. The rights prompt and read-only mode apply to these writes as before. The editor sends the preview only what it needs to show: edit mode on/off, the element to highlight, “go to this step”, print and quick check. The point of a note is checked as in the dev server (numbers only, clamped to the 1280×720 slide, other fields dropped; `app/devapi.js` checks it again with `kit/core/comment-core.mjs`); a forged point only moves the marker, and the markers over the preview are drawn by the editor page from the preview's own size.
- **The editor touches only the folder or file you chose**, and only after the browser's permission prompt.
- **A save stays with the deck it started on.** After every wait (rebuild, a question, the permission prompt, the save picker, creating and writing the file) the editor checks that the same deck is still open, and carries that check into the write itself: if another deck was opened meanwhile, the file is not replaced (the write is aborted) and nothing else is written. A new lesson id is written to the deck's settings, and the deck marked saved, only after the file has been written. An edit made while a save is in progress keeps the unsaved mark, because the saved file does not contain it.
- **While you edit in a trusted field** (a source or note box is open, or you are typing in the narration drawer or it has unsaved changes), the preview is `inert`; hints from the deck then neither open, close nor switch panels, and the narration step you are editing does not change.
- **Folders and links.** In-memory and OPFS folders cannot contain symbolic links. In a folder you pick, Chromium does not show links to the editor at all (they are not listed, cannot be opened by name and cannot be written; `tools/test-security.mjs` checks this), so the build cannot read a file outside the folder through one. The File System Access API gives the editor no way to tell links apart itself, so this relies on the browser.
- **Microphone and TTS only in the editor page.** Recording (`getUserMedia`, `MediaRecorder`), importing, post-processing and MP3 encoding run in the editor page; the preview cannot start them, and no audio is taken from the preview. Hints from the deck do not switch the Audio panel's step while it records, and the preview is `inert` meanwhile. The page's policy still allows no network: browser TTS runs in a separate window of the same site (`lab/tts-helper.html`, which, like the lab page, loads pinned libraries from jsDelivr and the model from Hugging Face) that is sent only the text to read and the voice name; the editor accepts audio only from that window, checks its sample rate and length, and processes it like a recording. Audio read from the folder is size-limited (manifest 16 MiB, each audio file 64 MiB).
- **Opening a portable file runs nothing from it.** The file is read as bytes and parsed in a Web Worker (bundled into the editor; the page's policy allows workers only from `blob:`) with the same parsing rules as a browser with scripting enabled (nothing is executed); the editor never navigates to it or inserts it into a page. Only the deck rebuilt from its source runs, in the same sandboxed preview as a folder.

## Publishing on GitHub Pages

`.github/workflows/pages.yml` builds `dist/` with `node tools/build-app.mjs --out _site` and deploys it to GitHub Pages: the editor at the root (`/`), the single file at `/editor.html`, the lab page at `/lab/irodori.html`, and at `/editor/` a page that redirects to `/` keeping the query and `#` (the editor used to live there). All paths are relative, so the same files work at the custom domain <https://editor.egatari.org/> (set in Settings → Pages → Custom domain, covering the whole site) and at <https://egatari.github.io/egatari-studio/> (which redirects to the custom domain). Only `main` deploys; running the workflow on another branch builds and uploads the artifact without deploying it. It does nothing until Pages is set up:

1. Settings → Pages → Build and deployment → Source: **GitHub Actions**.
2. Settings → Secrets and variables → Actions → Variables: add `EDITOR_PAGES` = `true` (without it, pushes skip the deploy, so the workflow does not fail before Pages is enabled).

## Language

The editor follows your browser language (Japanese or English). Switch with the **English / 日本語** button at the top right, or open `…/?lang=en` or `?lang=ja`. The choice is remembered; switching while a deck is open reopens the same folder (an opened portable file is closed; unsaved changes are asked about first). The editing tools (edit mode, the source card, the narration drawer, comments) follow the editor's language. (In the dev server they follow the deck's language, `<html lang>`.)
