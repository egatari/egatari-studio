# 編集アプリ（インストール不要）

[English](editor.md) | 日本語

作業フォルダを直接開き、[開発サーバー](dev-server.ja.md)と同じこと（プレビュー、スライドの上での原稿・口述原稿の編集、AI へのメモ）をするウェブページ。[1 ファイル（`.ega.html`）](reference.ja.md#1-ファイル--portable)（原稿も中に持つ 1 つの HTML。[持ち運べるデッキの形式](https://github.com/egatari/egatari-spec)に従う）も、フォルダなしで開き、メモリの上で直して保存し直せる。インストールもターミナルも要らない。最初の画面は 1 ファイルを先に置く（「1 ファイルを開く…」「新しいデッキ」「AI の出力を貼り付ける」。作業フォルダは「作業フォルダを開く…」）。

| 形 | 中身 | ここで |
|---|---|---|
| 作業フォルダ | `deck.html`・`narration.md`・`audio/` … の入ったフォルダ。コマンド・AI のコーディング道具（Claude Code・Codex・Gemini CLI など）・ほかのエディタが読み書きする | 「作業フォルダを開く…」（Chrome / Edge）で直す |
| 1 ファイル（`.ega.html`） | 原稿と音声を中に持つ 1 つの HTML（`--portable`）。ブラウザで開けば再生 | 「1 ファイルを開く…」で直す（どのブラウザでも） |
| 再生専用（`--play-only`） | 原稿を持たない 1 ファイル | 直せない（元の 1 ファイルか作業フォルダを開く） |
| 組み立てた HTML（`out/deck.html`） | 発表用の出力（「組み立てた HTML を書き出す」もこれ） | 直せない（作業フォルダを開く） |

- **ブラウザ：** パソコンの Google Chrome か Microsoft Edge（Windows・macOS・Linux・ChromeOS）。フォルダは File System Access API（`showDirectoryPicker`）を使うので、Safari と Firefox では開けない（最初の画面にそう出て、そこで新しく作る道として「AI の出力を貼り付ける」を示す。「新しいデッキ」はフォルダが要る）。1 ファイルは今のどのブラウザでも開いて直せる（ファイルを選ぶ画面がなければ、保存はダウンロードになり、保存のたびにダウンロードに新しいファイルができる。最初の画面と保存の知らせにそう出る：次はいちばん新しいものを開く）
- **通信：** アプリ自身の読み込みのほかは無い。作業フォルダやファイルはブラウザの中で読み書きし、どこにも送らない。ブラウザの TTS（[音声の板](#口述原稿の音声音声の板)）を使うときだけ、編集アプリのサイトの別の TTS の窓がモデルを取る（編集アプリのページそのものは、そのときもどこにも繋がらない）

## アプリの入手

| 形 | 開き方 | 備考 |
|---|---|---|
| 配信 | <https://studio.egatari.org/> | `main` から `.github/workflows/pages.yml` で公開する。字はデッキが使う分だけ読む。前の場所 `…/editor/` からはここへ移る |
| 1 ファイル版（`editor.html`） | `npm run build:app` のあと `dist/editor.html` をダブルクリック | 約 10 MB（字を全部入れてある）。Chrome・Edge なら `file://` で動く。このファイルを人に渡してもよい |
| 自分のサーバー | `npm run build:app` のあと `dist/` を静的に配る | どこでもよい（https か `http://localhost`）。サイトの根でも、下のパスでもよい |

`npm run build:app`（`node tools/build-app.mjs [--out dist] [--no-single]`）は先に `npm ci` が要る（版を固定した開発用の依存 esbuild を使う）。

## 使い方

1. **デッキを開く。** 1 ファイルは「1 ファイルを開く…」（[下](#1-ファイルフォルダなし)）。作業フォルダ（`deck.html` の入ったフォルダ。`deck.html` がなければフォルダの最上位の最初の `.html`）は画面に落とすか、「作業フォルダを開く…」を押す。そのフォルダを編集してよいか、ブラウザが 1 回たずねる
   - **新しいデッキ**：`npm run new` と同じ雛形から `deck.html` と `narration.md` を作る（タイトル・言語・テーマ）。空のフォルダを選べばそこに、空でなければ中にタイトルの名前のフォルダを作る
   - **最近開いたもの**：作業フォルダと 1 ファイルが最初の画面に並ぶ（ブラウザがハンドルを IndexedDB に残す。中身は残さない）。開き直すとき、ブラウザがもう一度許可を求める（1 ファイルは読む許可だけ。書く許可は「保存」のときに求める）。1 ファイルが並ぶのは、ブラウザがファイルのハンドルをくれたとき（Chrome / Edge の「1 ファイルを開く…」かドラッグ＆ドロップ）だけで、Safari・Firefox では並ばない
   - **見本の教材**（配信版だけ）：このリポジトリの見本を 1 ファイルにしたもの（`examples/minimal`・`pitch-fictional`・`kokugo-kanbun`・`tmlr2026-calibration`。音声なし）が最初の画面に並ぶ。「開く」は同じサイトからファイル（`examples/<名前>.ega.html`）を読み、選んだファイルとまったく同じように開く（取り込みの確かめも同じ。`tmlr2026-calibration` は独自の部品があるので動かす前に確かめ、最初の編集の前に権利の確認を出す）。1 ファイル版（`file://` の `editor.html`）には出ない
2. **直す。** キーは開発サーバーと同じ（道具の列にもボタンがある）

   | キー | すること |
   |---|---|
   | `e` | 編集モード。枠の出た要素を**ダブルクリック**すると原稿（HTML と `\( … \)` の式）が開く。⌘/Ctrl+Enter で保存 |
   | `n` | 表示中の段階の口述原稿の引き出し（話者、発言の追加・削除・並べ替え） |
   | Alt+クリック（Mac は ⌥ option+クリック） | その要素について AI へのメモを残す（`comments.json`）。押した点もピンとして残る |
   | `c` | 未対応の指示の一覧（番号付き）。開いている間、画面の段階のピンがスライドの上に出る。クリックでそのスライドと段階へ（ピンが光る）、「解決」で対応済み |

   編集モードの帯・原稿の欄・口述原稿の引き出し・コメントの欄と一覧は、どれも右の 1 つの板（プレビューはその横に縮む）にあり、板の上には橙の帯 **編集中 — アプリ** が付く。どれもデッキではなく編集アプリのページの一部。**スライドの場所に見えるものはデッキが描けるもの。信じてよいのはエディタ自身の板の道具だけ。** 原稿の欄・コメントの欄を開いている間、プレビューはクリックを受けない。プレビューはダブルクリックや Alt+クリックの場所を知らせるだけで、原稿を読み・見せ・「保存」（か ⌘/Ctrl+Enter）を押したときに書くのは編集アプリ。キーはプレビューの上でも編集アプリの上でも効く

   開発サーバーと同じく、プレビューを組んだ後にファイルが変わっていれば（原稿の hash・口述原稿の版が合わなければ）保存しない。読み込み直してからもう一度

   **Esc** で、開いている窓を上のものから 1 つずつ閉じる：書いている途中の原稿の欄・コメントの欄、次に音声の板・[録音モード](#録音モードキーボードだけで録る)・口述原稿の引き出し・コメントの一覧・横の板（品質チェック・警告・添付・使い方）のうち後に開いたもの。**Shift+Esc** で全部を閉じる。口述原稿の引き出しに保存していない入力があれば先に聞く。確かめの窓と一覧は、これまでどおり Esc で閉じる

   **保存の場所。** 下の帯の左端に、今どこに保存されているかをいつも出す（札の説明に詳しく）。作業フォルダは「作業フォルダ「…」に保存済み」：各欄の「保存」と録音・取り込み・TTS がその場でフォルダに書くので「保存」のボタンはなく、配るときは **書き出す ▾ →「配るための Egatari ファイル（編集可・.ega.html）を書き出す」**。1 ファイルは「「…」に保存済み」（「保存」で上書き）、ブラウザが上書きできないときは「「…」を開いています（保存はダウンロードに）」（「保存」のたびに新しいファイルがダウンロードされる）、メモリの上にだけ変更があるときは **保存していない変更があります**（タブを閉じると録音も含めて消える）、メモリの上にだけあるデッキ（チャットの AI の出力を貼り付けた・デッキの原稿だけを開いた）は **まだファイルに保存していません**
3. **AI のコーディング道具と一緒に。** AI のコーディング道具（やほかのエディタ）がフォルダを変える間も開いたままでよい。約 1.5 秒ごとにファイルを見て、変わったら組み直し、同じスライド・段階のままプレビューを読み込み直す。原稿の欄や口述原稿の引き出しで入力中のものは、プレビューを読み込み直しても残る（編集アプリのページにある）。その間に同じ要素や段階が変わっていれば、保存は断る。組み立てに失敗したら、直るまでプレビューの上にエラーを出す
4. **発表する・渡す。** 道具の列から（幅 1280 px 以上なら 1 行に収まり、それより狭いと折り返す）。「開く ▾」に「1 ファイルを開く…」と「作業フォルダを開く…」、「書き出す ▾」に書き出しと印刷がまとまっている
   - **品質チェック**：ブラウザ版の品質チェック。`npm run check` の一部をプレビューの中で行う（はみ出し・文字の大きさ・タイトルと結論の字数・口述原稿の抜け・パレットのコントラスト）。体裁の部分（はみ出しと縦組みの限り・箱で切れる字やスライドの外に出る字・図の中の字の大きさ・タイトルと結論の字数）はコマンド版と同じコード（`kit/core/layout-scan.mjs`）。結果をクリックでそのスライドへ。目安であって全部の品質チェックではない：部品の再現性・タイムライン・モーフ・読み上げは見ない。画面の大きさが違うので、数値がコマンド版の品質チェックとわずかに違うことがある
   - **書き出す ▾ →「組み立てた HTML を書き出す」**：編集の仕掛けを除いて組み、組み立てた HTML（再生だけ。原稿は入らない）として保存する（保存先をたずねる。最初に出す名前は教材の題名。下を参照）。ダブルクリックでどこでも発表できる
   - **書き出す ▾ →「配るための Egatari ファイル（編集可・.ega.html）を書き出す」**（作業フォルダ）：原稿と音声を中に持つ 1 ファイルにして、人に渡せる形で書き出す。作業フォルダはそのまま
   - **書き出す ▾ →「参加者に配る Egatari ファイル（再生のみ・.play.ega.html）を書き出す」**：原稿を持たない 1 ファイル（形式の §3.7。`--play-only` と同じ）。どのブラウザでも再生でき、編集はできない。1 ファイルを開いているときは保存したものから作る（保存していない変更があれば、先に「保存」）。作業フォルダはそのフォルダから
   - **書き出す ▾ →「ライブ（質問・投票）を付けて配る…」**：ライブ（授業中の質問と投票。形式の拡張 `live`、下書き）を付けた Egatari ファイル（再生のみ）。ホストのページでコピーした設定（ライブ ID・参加コード・ライブの時間）を貼り、参加者からの質問を受け付けるかとステップごとの投票を決め（投票は「4 枚目『XML の壁』・ステップ 1」のような表示名で出し、ステップの鍵は吹き出しに）、ホストのページに渡す投票の設定（表示名入り）をコピーして書き出す。まだ足りないものは **書き出す前に直すこと** に画面の言葉で出る。編集アプリ自身はどこにもつながらない。教材に残すのは参加コードのない設定だけ。[ライブ](distributing.ja.md#ライブ授業中の質問と投票下書き)を参照
   - **書き出す ▾ →「印刷 / PDF」**：デッキをブラウザの印刷にかける（`tools/pdf.mjs` と同じく、各スライドの最終状態を 1 ページずつ。「PDF に保存」を選ぶ。章の扉を含め、スライドの背景は「背景のグラフィック」を入れなくても画面と同じ色で刷られる）
   - **発表者ビュー**（デッキの `p` でも）：今の画面・次の段階・口述原稿（カンペ）・経過時間・描く道具の窓。編集アプリの窓のプレビューを操作する。音声を鳴らすのもそのプレビューで、発表者ビューで自動再生を始めても（<kbd>a</kbd> かそのボタン）、口述原稿の音声は編集アプリの窓で 1 回だけ鳴る
   - **全画面**：プレビューを画面いっぱいにする（投影用）

## スライド一覧（足す・複製・削除・並べ替え）

プレビューの左の端の **スライド一覧** のつまみで、そこに一覧を開きます（✕ で閉じます）。スライドを順に、そのスライドの最後のステップの縮図と見出しで並べます。縮図はデッキ自身が、一覧の後ろの sandbox の枠に描きます（プレビューと同じ決まり。クリックを受けず、読み上げソフトにも出しません）。一覧・ボタン・確かめの窓は編集アプリのページのものです。開いていたかどうかはこのブラウザが覚えます。

- **選ぶ**：スライドを押すか、一覧で ↑ ↓ Home End。プレビューもそのスライドへ動きます。プレビューを動かすと、選択も付いてきます
- **＋ 追加 ▾**：選んだスライドの後ろに、雛形から新しいスライドを入れます。**見出しと本文**・**2 列**・**図**（点線の枠と図の説明）・**章の扉**（`sec`）・**引用**（`box` と `cite` の行）。id（`s-xxxxxx`。文書の中で使っていないもの）はエディタが付け、口述原稿に `## 見出し {#id}` の節を、前のスライドの節の後ろに、ステップごとの仮の 1 行と一緒に足します。仮の行は印 `✎` で始まり、雛形の字も決まっている（どちらも `kit/core/template-text.mjs` に 1 か所で書く）ので、直し忘れが見つかります。品質チェック（ここと `npm run check`）は警告にし（`narrPlaceholder`・`templateText`）、TTS の前（音声の板・Colab の `tts-job.json`・`tts/synth.py`）と Egatari ファイルを書き出す前（編集可・再生専用・ライブ。`--portable`・`--play-only`）に、エディタかコマンドが先に一覧を出します。続けることもできます（**このまま作る**・**このまま書き出す**）。直さないと、TTS が仮の文を読み上げ、字幕と読める層にも入ります
- **複製**：選んだスライドの写しを、新しい id ですぐ後ろに入れます。口述原稿は写し、音声は写しません。写しのステップは、録るか作るまで一覧に **音声が要るステップ N** と出ます
- **削除**（一覧で Delete キーでも）：先に確かめます。窓はスライドの名前と、一緒に消えるもの（口述原稿の節、`audio/manifest.json` の音声の記録とそのファイル（ほかのステップが使っているファイルは残す）、録ってまだ使っていない音声）を出します。音声が古いときの決まり（形式 §5.4）と同じく、黙って作り直したり消したりはしません
- **並べ替え**：一覧の中でドラッグするか、**↑** / **↓** を押すか、一覧で Alt+↑ / Alt+↓。id は変わらず、口述原稿の節も同じ順に並べ替え、音声は鍵で付いたままです
- **元に戻す**（一覧の上）：直前のスライドの操作を取り消します。原稿・口述原稿・音声の記録と消した音声のファイルを、エディタが覚えている前の中身で書き戻し、使っていない録音も音声の板に戻します。次のスライドの操作まで、1 ファイルを保存するまで、別のデッキを開くまで使えます。その間に 3 つのファイルのどれかが変わっていれば（編集・外の道具）戻しません。どの操作でも、書き換える前のファイルは `.cache/edits/` に控えます

操作のたびに、`deck.html`・`narration.md`・`audio/manifest.json`（変わったものだけ）を書き、組み直し、そのスライドを見せて品質チェックを出します。読み上げソフトには何をしたかを知らせます（live region）。1 ファイルでは変更はメモリの上にあり、次の **保存** でファイルを組み直します（段 B）。組み直さない保存ではスライドの並びを変えられないためです（形式 §7.2。エディタの段 A の保存は `source-changed` で断り、組み直してよいかを聞きます）。口述原稿だけを直せる 1 ファイル（実行系か部品庫の版が違う）と読むだけの 1 ファイルでは使えません。スライドの鍵が重なっているデッキは、先に直す必要があります（理由を出します）。id のないスライドの鍵はそのままで、足したスライドと写したスライドには必ず id を付けます

## 口述原稿の音声（音声の板）

道具の列の **音声** は、同じ信頼する横の板に、画面に出ている段階の欄を開く（スライドに付いていく。音声を作って書いている間はその段階のままで、スライドが動いたらそう知らせる）。フォルダでも、開いた 1 ファイルでも同じに使える。

- **今の音声。** `audio/manifest.json` にある段階の音声を再生する（フォルダやファイルから編集アプリのページで読む。プレビューからは受け取らない）。種類（**録音**・**TTS**・**取り込み**）、長さ、出どころ（TTS ならエンジン・モデル・声・シード）も出す。**古い** の印は、音声を作った後に口述原稿が変わったか、どの口述原稿から作ったか分からないこと（format spec §5.4：`inputHash` が `null` か今の口述原稿と違う。`inputHash` のない前の `tts/synth.py` の manifest では、TTS の控え `audio/seg_<digest>.json` で比べる）。古い段階は、警告の一覧・品質チェック・`npm run check` にも出る。読み上げるための段階の原稿も出す：欄は原稿の長さに合わせて伸び（板の半分ほどまで）、右下の角で大きさを変えられる。掛け合いのデッキでは各ターンに Expert か Novice の印を付ける。**↶ 前に戻す** で、最後に作った音声の前にその段階が持っていた音声に戻す（下を参照）。
- **録音。** **● 録音 (r)** は、板の段階で[録音モード](#録音モードキーボードだけで録る)を開く（録り方は 1 つ）。1 段だけなら **Space** で録り、話して、もう一度 **Space**、そして **Esc**：板に戻り、その段階の新しい音声を見せる（板は録音モードの裏で開いたまま）。録音モードは原稿を大きく出してその横にメーターを置き、録った音声はすぐにその段階の音声にする。ここの **↶ 前に戻す** でその段階の前の音声へ順に戻れる（音声のファイルは消さない）。
- **ファイルから取り込む…** は WAV・MP3・M4A・Ogg・WebM・FLAC を読む（64 MiB まで。大きさは読む前に確かめる）。録音と同じく、すぐに使う。
- **声。** 話す役ごとに 1 つ（1 人の語りなら 1 つ、掛け合いなら Expert と Novice）の欄で選ぶ：日本語のデッキは `bob` と `alice`、英語のデッキは Kokoro の声（米・英の 8 つ。残りは **ほかの声** に畳む）。**▶ 見本** で事前に作った短い見本を鳴らす（`lab/voices/samples/`。モデルは読み込まない）。作業フォルダでは選んだ声を `voice.json` に書く。1 ファイルではこの画面を開いている間だけ覚え（`voice.json` を変えると保存が組み直しになるため）、作った音声の記録には使った声の名前が残る。`voice.json` の声がブラウザの TTS に入っていないときは、日本語も英語も同じに扱う：板がそう知らせ、TTS はその役の既定の声（`bob`・`alice`、または `am_michael`・`af_heart`）で作る。TTS の窓は知らない名前を断る（黙って別の声にしない）。
- **TTS で作り直す** は、ブラウザの TTS で段階を作る：日本語のデッキは Irodori-TTS 500M-v3（読み辞書 `tts/yomi.yaml` を `tts/yomi.py` と同じ規則で通す。声は `voice.json` のもの、既定は `bob` と `alice`。シード 0、ステップ 40。手元の mlx のサーバーもシード 0 だが、ブラウザは別の乱数の作り方で雑音を作るので、手元で作った音と波形は同じにならない）、ほかの言語は Kokoro-82M v1.0（`bob` → `am_michael`、`alice` → `af_heart`。`voice.json` に Kokoro の声の名前を書いてもよい）。`{cue}`・`{mark}` の区切りごとに合成して後処理し、`tts/synth.py` と同じくつなぐ（ターンの間は 350 ms）ので、区切りの時刻を持つ（`sync: "auto"`）。初めてのときは何を取得するかを見せて確かめ（Irodori の fp16 で約 1.26 GB、fp16 のシェーダーのない GPU では 2.44 GB、Kokoro で約 330 MB。2 回目からはブラウザのキャッシュから読む）、編集アプリのサイトの小さな窓（`lab/tts-helper.html`）を開く。その窓がモデルを読み込み、この PC の GPU で合成する。窓に渡すのは読む文（読み辞書の後）と声の名前だけで、返ってくるのは音だけ。WebGPU が要る（パソコンの新しい Chrome か Edge）。ないときはボタンが押せず、板はまず録音を勧める。1 ファイル版（`file://`）では使えない（板がそう知らせ、録音を勧める）。ほかの参照音声は `tts/synth.py` で。エンジンはスライドではなく口述原稿の言語で決める：`voice.json` の `"lang"`、次に口述原稿の文（日本語のデッキでも発言がほとんど英語なら英語）、最後に `<html lang>`。出す声と読み辞書も同じ言語に従う。
- **後処理** は `tts/core.py` と同じことをブラウザでする（`kit/core/audio-core.mjs`）：モノラル、44.1 kHz、前後の無音を削る（20 ms の窓で −45 dB、50 ms 残す）、音量を −20 LUFS に（EBU R128 の積分ラウドネス、一律のゲイン。トゥルーピークが −1.5 dBTP を超えるので ffmpeg の loudnorm なら動的な処理に切り替えるところでは、ゲインを −1.5 dBTP で止める）。この違いがあるので、後処理の名前は別の `trim-45-loud-20-cap-v1` にする。`tools/test-audio-core.mjs` が同じ入力で `tts/core.py` と長さと音量を比べる。
- **文の前処理**（`kit/core/tts-normalize.mjs`、規則 `join-num-counter@1`）は、各区切りをエンジンに渡す直前に、ブラウザでも Colab のノートブック（`colab/egatari_tts.py`。同じ規則で、共有の例で突き合わせる）でもかける：算用数字（0-9・全角の０-９。1.5 のような小数も）と、その直後の日本語の文字（ひらがな・カタカナ・漢字）の間の空白（ASCII・全角）を取る。「1 歩」は「1歩」になり、「いちぽ」と読まれない。「3 分」「10 本」「2 つ」も詰める一方、「x 2 y」「Chapter 3 is」や数字の前の空白（「第 3 章」）はそのまま。助数詞の読みの表は持たない。これは「何を言うか」ではなく「どう合成するか」なので、`ttsParts` と `inputHash` は変えず、取り直しの recipe に `"textNormalize": "join-num-counter@1"` を書く（format spec §5.4）。この項目のない音声（これまでに作ったすべて）は**古くならず**、そのまま鳴り、音声の板も一覧にしない：読みがおかしいと聞こえた段階は **TTS で作り直す** で作り直す。
- **音声を書く**（録音・取り込み・TTS の直後）ときは、取り直しを MP3（LAME、64 kbps の CBR、モノラル、44.1 kHz）にして、`audio/<rec|tts|imp>_<hash>.mp3` と `audio/manifest.json` の段階の記録を書く。MP3 のエンコーダは編集アプリのコードに入れない：編集アプリのサイトの `vendor/lame-wasm/` にある手を加えない `lame-wasm` のファイルで（LAME は LGPL。NOTICE を参照）、取り直しを MP3 にするときだけ読み込む。1 ファイル版は MP3 のエンコーダを持たず、WAV（16 bit。ファイルは大きい）で保存する。配信版でもエンコーダを読み込めなければ WAV。MP3 は 1105 標本（符号化の遅れ 576 と復号の遅れ 529、0.025057 秒）遅れて始まるので、それを `startOffset` に書き、実行系はその時刻から鳴らす（`dur` と区切りの時刻がずれない）（前の manifest は `.cache/edits/` に控え、前の音声のファイルは残す。`tts/synth.py` が古い wav を残すのと同じ）。記録には出どころを書く：`kind`（`recorded`・`tts`・`imported`）、`inputHash`（その取り直しを作ったときの口述原稿）、TTS なら `recipe`（`engine`・`model`・`voice`・`seed`・`dictionary` = 読み辞書の SHA-256）、どの種類にも `processing`（`trim-45-loud-20-cap-v1`）、MP3 なら `startOffset`。機器の名前・元のファイル名など録った状況の記録は書かない。録音と取り込みには区切りの時刻がない（`sync: "none"`、cues は空）ので、区切りに合わせた動きと注目の演出は時間で進む。段階の長さは新しい音声に合わせて決まる（manifest の `dur`。実行系がそこからタイムラインを計算する）。`timeline.json` の `dur` の上書きがあればそちらが勝ち、板がそれを知らせる。書けなかった取り直し（読むだけのファイル・権利の確認を断った）は **まだ使っていない音声** に「この音声を使う」と一緒に残り、使うか別のデッキを開くまでメモリの上にある。「前に戻す」のための前の記録もメモリの上だけに置く（段階ごとに 20 まで。別のデッキを開くまで）。`tts/synth.py` は録音と取り込みを残す（`--replace-recorded` で替える）。
- **1 ファイル：** 新しい音声でメモリの上のフォルダが変わり、**保存** で組み直さずに書く（段 A：その段階の音声の記録・実行系の音声の項目・中の音声だけが変わる）。
- **AI 合成音声。** どこかの段階の音声を TTS で作った（`kind: "tts"`）ときは、再生器の操作の帯に小さな札「AI 音声」（説明は「音声は AI で合成したものです」）、キーの一覧（<kbd>?</kbd>）に同じ文、その段階の発表者ビューに 1 行が出る。スライドの上や字幕には出さない。取り込んだ音声（`kind: "imported"`）は、キーの一覧と発表者ビューに「音声の作り方は記録されていません」と出し、録音には印を付けない。1 ファイル・再生専用の派生を含むどの出力も、種類を `deck-audio` の `kind` に入れる（format spec §5.2・§7.3）。

### Colab で音声を作る（WebGPU がないとき）

<!-- colab-verified --> **確認済み：2026-10-21、Irodori、Colab の T4 GPU（作者の環境で 1 回）。Kokoro と CPU はまだ**

WebGPU のない PC（学校の PC・Safari・iPad）のために、音声の板に **Colab で音声を作る** の群がある（ブラウザに WebGPU がなければ最初から開く）。無料の Colab（自分の Google アカウント）で同じ声の音声を作り、区切り（cue）の時刻つきで取り込む。ブラウザの TTS のほうは変わらない。

1. **① 必要な段階を書き出す（tts-job.json）。** 範囲（既定は音声のない段階と古い段階。すべての段階も選べる）を選ぶ。先に 1 度確かめる：**Colab では原稿の文が Google の環境で処理される**（モデルは Hugging Face から取る）。ダウンロードする `tts-job.json` には、読み上げる文（読み辞書を通した後で、`{cue}` / `{mark}` で区切ったもの）・声の名前・各段階の `inputHash`・`docId`・目標の recipe だけが入る。
2. **Colab を開く** で公式のノートブック [`colab/egatari-tts.ipynb`](../colab/egatari-tts.ipynb) を開く（リンクは版のタグに固定）。上のセルから順に実行し、聞かれたら `tts-job.json` をアップロードして、返ってくる zip をダウンロードする。日本語は Irodori-TTS 500M-v3（ONNX、版を固定）、ほかの言語は Kokoro-82M。T4 の GPU があると速く、なければ CPU（遅い）。Node の常駐ワーカー（`colab/irodori_node.mjs`）を 1 度だけ起動し、6 つの ONNX セッションとトークナイザは 1 度だけ読み込んで、区切りごとに合成する（区切りごとに seed と steps が同じなので、各区切りの音は決まる）。モデルは `local_dir` で実ファイルとして落とし（Hugging Face のキャッシュの symlink は onnxruntime-node が断る）、clone・インストール・Node が失敗したときは、その出力の最後の 30 行を出して止まる。エディタと同じ後処理（`trim-45-loud-20-cap-v1`）を区切りごとにかけ、ターンの間に 0.35 秒の無音を入れ、cue の時刻は実際の音から測る。核は [`colab/egatari_tts.py`](../colab/egatari_tts.py) で、モデルなしでローカルの dry-run ができる（`uv run --no-project --with numpy --with scipy python colab/egatari_tts.py tts-job.json out.zip --dry-run`）。ノートブックは `tools/make-colab-notebook.mjs` が作る（`npm run gen`）。
   **自分の参照音声（省略可・日本語の Irodori のみ）。** ノートブックの省略可のセルで `UPLOAD` にチェックを入れて 3〜30 秒の WAV か MP3（話す人は 1 人）を選ぶか、`DRIVE_PATH` に Drive のパスを書く。ノートブックは、読めること・3〜30 秒であること・無音でないことを確かめ、同梱の参照音声と同じ 48 kHz のモノラルに直して、ジョブのすべての話者の Irodori の参照音声にする。だめなファイルは理由つきのメッセージで止まる。セルに触れなければ、これまでの声をこれまでどおり使う。出力の形式と `inputHash` は変わらず、Kokoro は使わない。**使ってよい声（自分の声、または本人の許可のある声）だけ**にすること。ファイルは自分の Colab のランタイムの中にあり、ほかへは送られない（ランタイムが片づけられると消える）。

3. **② できた zip を取り込む…** で zip（`records.json` と `audio/*.wav`）を読む。エディタは各段階の `inputHash` を**今の**口述原稿から計算し直して照合する（ノートブックの値は信用しない）。合う段階は、ほかの音声と同じように書く（MP3・`kind: "tts"`・`sync: "auto"` と測った `cues`・`recipe`・`inputHash`・`startOffset`。仕様 §5.3 の引き取りの規則）。作業フォルダはその場で、1 ファイルはメモリの上に書いて「保存」（段 A）。書き出した後に原稿が変わった段階は **印付き** に出し、自動では使わない：**古い印のまま使う** は古い `inputHash` で書き（「古い」と出る）、**捨てる** は捨てる。今の原稿にない段階・記録が不備なもの（パス・cue の数が合わない）・音声がないものは、理由を出してスキップする。別の教材のための zip（`docId` が違う）は拒否する。読み辞書や後処理の版が違うときは知らせるだけ。

zip はダウンロード物なので信頼しない。バイトとして読み、割り当てる前に上限を課す（zip 512 MiB・音声 1 つ 64 MiB・`records.json` 4 MiB・段階は 400 まで。zip64・暗号化・知らない圧縮は断り、CRC-32 を確かめる）。読むのは `records.json` と `audio/<名前>.wav` だけ（名前を確かめる）。音声は本物の WAV として復号でき、長さが記録と合うこと。zip の中身を HTML やコードとして扱うことはない（仕様 §11）。

`tts-job.json` と `records.json`（`egatari: "tts-job"` / `"tts-records"`、`v: 1`）はエディタとノートブックの間のこの製品の取り決めで、形式の仕様の物ではない。`records.json` の各段階の記録は仕様 §5.2 の音声の記録の形（`file`・`dur`・`cues`・`kind`・`sync`・`inputHash`・`recipe`）。試験は `tools/test-colab.mjs`（zip の読み取り・job・取り込みの計画・敵対の zip・ノートブック、`uv` があれば Python の核の dry-run）と `tools/test-colab-app.mjs`（`tools/colab-fixture.mjs` で作った zip での編集アプリの往復。フォルダと 1 ファイル）。

## 録音モード（キーボードだけで録る）

<kbd>r</kbd>（編集アプリのページでもデッキの上でも）か、音声の板の「● 録音 (r)」で、口述原稿を全部キーボードだけで録るための広い画面を開きます。段階の口述原稿を**大きく**出し（掛け合いは Expert / Novice の札。長い原稿は中でスクロール）、プレビューは横の細い舞台の縮図になって録音の位置に付いてくるので、図を見ながら読めます。音声の板と同じく信頼する編集の画面の中にあり、マイク・録音・後処理・書き込みはプレビューでは一切行いません（デッキからの知らせで開けるのはこの画面だけで、録音は始まりません）。開いている間、プレビューは inert です。画面に出ている段階（音声の板からなら板の段階）から始まり、口述原稿のある段階を順に録ります。録り方はこれだけです：音声の板の「● 録音 (r)」はこの画面を開き、板は裏で開いたままなので、**Esc** で新しい音声の出た板に戻ります。

| キー | 動作 |
|---|---|
| **Space** | 録音の開始／停止。止めると後処理（音声の板と同じ：前後の無音を削る・−20 LUFS・モノラル 44.1 kHz）をして、**すぐその段階の音声**にします（kind `recorded`。これまでどおり「前に戻す」で戻せます）。段階は替わりません。開いた直後（と段階を移った直後）は、その段階を読み終えるまで Space のボタンが **準備中…** になります。その間に押した Space は覚えておき、準備ができしだい録り始めます（2 回押しても 1 回） |
| **Enter** | 録音中なら止めて採用し、次の段階へ。録った後（または音声のある段階）なら次の段階へ。次の段階は**待機**：自動では録り始めません（再生中の部屋の音を録らないため）。音声のない段階では、進まずにそう知らせます |
| **Backspace** | 取り直し。録音中は今のテイクを捨てます（何も書きません）。録った後は、そのテイクを「前に戻す」で外して前の音声に戻し、次の Space を待ちます。戻せるのは、このモードで録った音声だけです |
| **←** / **→** | 前・次の段階（録音中なら先に止めて採用） |
| **C** | 録音中に、口述原稿の `{cue}`・`{mark}` の区切りごとに押します（区切りは ①②… のチップで出て、次の区切りは太い枠、押したものは ✓）。押した時刻が cue になります（`sync: "manual"`。時刻は押した生の時刻から、前の無音を削った分を引いたもの）。押した数が区切りの数と違えば cue は書かず（`sync: "none"`。警告を出し、図は時間で進みます）、間違った同期は作りません |
| **Esc** | 閉じる（録音中は今のテイクを捨てます。**Shift+Esc** は開いている窓を全部）。フォーカスは元の場所に戻ります |

1 段は **Space → 話す → Enter** です。取り直したテイクは前のテイクの cue を使いません（仕様 §5.3）：`sync: "none"`・cue なしから始まり、C で埋めます。口述原稿を直して音声が古くなった段階には「古い」の知らせ、区切りがあって cue が未設定の段階には「図は時間で進みます」の知らせが出ます。掛け合いは段階ごとに 1 本のテイクです（1 人が両方の役を読むか、2 人が交互に）。入力の大きさのメーターと経過時間（1 つのテイクは 600 秒で止まり、そこまでを使う）、テイクの長さと音量の調整、音が割れていそうなときの警告が出ます。止めるキーの後に小さな尾（0.15 秒）を残して、語尾が切れないようにします。マイクは画面を閉じるまで開いたままで（許可は 1 回、録り始めの遅れなし）、閉じると手放します。書き込みが断られたとき（読むだけのファイル・権利の確認を断った）は、そのテイクは音声の板の「まだ使っていない音声」に残ります。

読み上げソフトには、この画面は modal の dialog です。live region が段階（n / N・題・音声の有無・区切りの数）・「録音中」・押した区切り・テイクの結果を知らせ、alert の領域が問題を知らせます。どのキーにもボタン（キーの aria-keyshortcuts つき）があり、`prefers-reduced-motion` ではメーターを 1 秒に数回だけ更新します。この画面の間、<kbd>e</kbd>・<kbd>n</kbd>・<kbd>r</kbd> は何もせず、ツールバーは inert です。

## 添付（下書き・試行）

下書き・試行（形式の §3.8 の案）：役割ごとに入れてよい形式と中身の確かめは[参照](reference.ja.md#1-ファイル--portable)のとおり。

道具の帯の **添付**（説明に「下書き・試行」）は、作業フォルダか開いた 1 ファイルの `attachments/` の下のファイルを並べる（形式の §3.8：読み手のための元の原稿・PDF・コード・データ・補足。[参照](reference.ja.md#1-ファイル--portable)）。**ファイルを足す…** で写し入れる（役割は形式から推す：`.pdf` → pdf、`.tex`・`.bib`・`.docx`・`.md` → source、`.py`・`.ipynb`・環境の定義 → code、`.csv`・`.tsv`・`.json`・`.xlsx` → data、画像と `.txt` → supplement）、ファイルごとに題を尋ねる（要る。1 行で 120 字まで。ファイル名から埋めてあり、直せる）。形式が許さないファイルは、理由と規則（§3.8）を言って断る：名前から分かるもの（実行できるファイル・`.js`・`.bat`・`.ps1` など OS がスクリプトとして開く拡張子・HTML・SVG・ZIP・マクロを入れられる Office と古い形式の Office・音声と動画・どの役割も受けない形式）は題を尋ねる前に、中身から分かるもの（JavaScript のある PDF・文書の中へ移るほかの開いたときの動作や `GoTo`・`URI` のほかの動作のある PDF・パスワードの要る暗号化した PDF・マクロや外への参照のある Office・名前を替えた実行ファイル・2 つの形式を重ねたファイル・音声と動画）は読んだ後・書く前に。表計算のソフトが数式として読みうる値は知らせて足す。行ごとに役割（なし：入れるが読み手の一覧に出ない。ファイルの形式を受けない役割は断る）・題（要る：ないものは入れるが一覧に出ない。消せない）・説明（任意。1〜2 文で 300 字まで。ダウンロードの一覧の題の下に出る）・**名前を替える…**（新しい名前も足すときと同じく確かめる）・**消す**。役割・題・説明は `egatari.json`（`attachments`。ほかの項目は残し、`.cache/edits/` に控え）に書く。`attachments/` の外・`..`・予約名・重なる名前は断り、上限（1 つ 10 MiB・合わせて 20 MiB・100 個）を超えるファイルは読む前に断る。フォルダから消すときは `.cache/edits/` に控えを残す。エディタは添付を開かず、プレビューにも渡さない。1 ファイルでは **保存** まではメモリの上で、保存は段 A：変わるのは索引の添付の項目・その塊・原稿の hash だけ。1 ファイルの最初の変更の前には、ほかの編集と同じく権利の確認が出る。**授業の部屋の結果を取り込む…** は、ライブからダウンロードした結果を役割 `data` の添付にし、要約を出す（[ライブ](distributing.ja.md#ライブ授業中の質問と投票下書き)の「授業の後」）。

## 1 ファイル（フォルダなし）

1 ファイルは、`npm run build -- <deck.html> --portable`（または編集アプリの「配るための Egatari ファイル（編集可・.ega.html）を書き出す」）が書くもの（作業フォルダの最上位に、題名から作った名前で書き、パスを表示する）。組んだデッキと同じように再生でき、デッキの原稿と音声を中に持つので、元のフォルダがなくても編集アプリで直せる。学ぶ人への配り方（Google ドライブ・メール・LMS）は [distributing.ja.md](distributing.ja.md)。

- **開く。** 「1 ファイルを開く…」（最初の画面か、道具の列の「開く ▾」）を押すか、ファイルを最初の画面に落とす。編集アプリはファイルをバイト列として読み、スクリプトを動かさない HTML の解析器で、Web Worker の中で取り出す。ファイルそのものをページとして読み込むことはないので、取り出しの間に中のものは何も動かない。形式のハッシュ・大きさの上限・パスの規則を先にすべて確かめる（`npm run portable -- unpack` と同じ）。HTML は上限（要素・属性・入れ子の深さ）を解析の途中で数えながら解析し、中の原稿のファイルに書かれたタグも 500000 までにするので、小さな要素を何百万も並べたファイルは、全部の木を作る前に断る。読むのに 30 秒より長くかかれば Worker を止めて断る。開いたデッキ（フォルダ・1 ファイル）の組み立てとコードの確かめも Worker の中で、組み立ての上限（[reference](reference.ja.md#組み立ての上限)）の内で行い、60 秒より長くかかればその Worker を止めて失敗にする（`build-timeout`）。その間もページは固まらない。フォルダから読むのは組み立てが参照したファイルだけ（同時に 8 つまで、1 つは一覧の大きさまで。一覧の後で大きくなったファイルは断る）で、止めた Worker からの答えは捨てる。どのファイルも、読む前に `File.size` で、読んだ後に読んだバイトで大きさを確かめ（`app/bounded-read.js`）、`deck.html`・`narration.md`・`comments.json` には決まった上限（32 MiB・16 MiB・4 MiB）があり、超えるものは読まずに断る。原稿はメモリの上（メモリの上のフォルダ）に置き、プレビュー・編集の道具・品質チェックはフォルダのときと同じように動く。フォルダがないので、外での変更は見張らない
- **保存。** 「保存」は、ブラウザが書き込めるハンドルをくれたとき（Chrome / Edge の「1 ファイルを開く…」かドラッグ＆ドロップ。初めは許可をたずねることがある）は同じファイルに書き直す。そうでなければ保存先をたずね、保存の画面がなければ（Safari・Firefox）ダウンロードする。文書の識別子（`docId`）は変えず、`derivedFrom` を付けることも変えることもない。「保存」の横の一覧（保存 ▾）には次の 2 つがある
  - **「新しい教材として保存…」**：保存先をたずね、新しい `docId` の教材として書く。元の教材を `derivedFrom`（元の `docId` と原稿の hash）に記録し、著作権・クレジット・作り手はそのまま残す。開いている文書は新しい教材になる（この後の保存も新しい識別子のまま）
  - **「別のファイルに保存…」**：保存先をたずね、同じ教材（同じ `docId`）を別のファイルに書く

  ファイル名の前の ● は保存していない変更の印。ページを離れるときや別のファイルを開くときは先にたずねる。どの保存でも、ライセンス・著作権・クレジット・作り手、編集アプリの知らない索引の項目（どの深さでも：metadata・音声の記録・塊・部品とテーマ・拡張の中）と拡張のデータは残し、触れていない音声はバイトのまま写す。設定のファイル（原稿の根にある教材の識別子と metadata）がないファイルには、編集アプリが足すことがある。それで原稿の hash は変わるが、保存はもともとそれを書き直す
- **組み直さずに保存する。** 口述原稿（発言の文・注目の演出・区切り）、音声、`timeline.json` の秒数の上書きだけが変わったときは、「保存」はスライドを組み直さない。[形式](https://github.com/egatari/egatari-spec)がそういう編集に挙げる所（§7.2 の段 A）だけを書き換える：実行系の口述原稿・注目の演出・秒数・音声のデータのうち変わった段階の項目、スクリプトなしで読める文字の層のうち変わった段階、原稿の hash と索引とその hash、中に入れたファイル（新しい中身を足し、どこからも参照されなくなった中身を除く）、そして新しい文に、埋め込んだ字にない字があるときだけ、字の補い（その字を含む字の分割ファイルだけを、編集アプリが持つ字から入れた新しい style 要素。前からある字のデータには触れない）。ファイルのほかのバイトは、ほかの道具や別の版が書いた実行系も含めて、1 バイトも変えない。状態の欄に「組み直さずに」と出る。段階の口述原稿をすべて消すと、その段階の音声も消える。保存の知らせに警告があることが出て、「警告」の一覧にその段階が出る。秒数の上書きは項目ごとに写し、各段階の長さは実行系がそれまでと同じ式で計算する
- **組み直して保存する。** スライドを直したとき（または上の所の外が変わった、ファイルの組んだ教材と原稿が食い違うとき）は、直した原稿から編集アプリに同梱の kit・部品・テーマでファイル全体を組み直すので、プレビューとまったく同じに再生する。保存の前に **「スライドはこのエディタの今のバージョンで組み直されます。編集していないスライドも、見え方が変わることがあります。」** と知らせ、組み直さずに保存できない理由も見せ、「組み直して保存」を押してから保存する（取消なら変更は保存しないまま）。まだできないこと：組み直しの前と後のスライドを比べること。保存した後にプレビューで確かめる
- **古い音声。** 段階の口述原稿を直しても、その音声には触れない（バイトも種類もそのまま）。その段階は警告に「音声が古い」と出て、保存したファイルでも音声の記録は作ったときの口述原稿の hash のままなので、どの読み手にも古いと分かる。[音声の板](#口述原稿の音声音声の板)で録り直すか、作り直す
- **書き出す ▾ →「作業フォルダに書き出す…」** は、選んだ空のフォルダに原稿・音声・`audio/manifest.json` を書く（`npm run portable -- unpack` と同じファイル）。空でないフォルダは断る。書き出したフォルダは、ふつうの作業フォルダとして開け、組め、まとめられる
- **書き出す ▾ →「配るための Egatari ファイル（編集可・.ega.html）を書き出す」**（フォルダを開いているとき）は、フォルダを 1 ファイルにする。最初に出すファイルの名前は教材の題名（設定のファイルの `metadata.title`、なければデッキの `<title>`）で、どの OS でも使える形にする（`\ / : * ? " < > |` と制御文字を除き、頭の点と終わりの点・空白を除き、`CON` などの予約の名前を避け、80 字・255 バイトまで）。題名がなければデッキのファイルの名前。初回は教材の識別子をフォルダの設定のファイルに書き、次からの書き出しでも同じものを使う
- **作業フォルダから書き出した写し**（`exportedFrom`、形式の §3.1）。作業フォルダの「Egatari ファイル（編集可）を書き出す」（コマンドの `--portable` も）は、そのファイルにフォルダの写しという印を、書き出したときのフォルダの原稿の hash と一緒に付ける（時刻・パス・名前は入れない）。そういうファイルを開くと「フォルダから書き出した写しです。ここで直した分は、フォルダには入りません。フォルダに戻すには『作業フォルダに書き出す』を使ってください。」と知らせ、**作業フォルダに書き出す…** のボタン（書き出す ▾ →「作業フォルダに書き出す…」と同じ）を出す。編集は断らない。「保存」と「別のファイルに保存…」は印を変えないので、写しの原稿の hash が印と違ってくると「書き出したあと、この写しで直した所があります。」を足す。「新しい教材として保存」は印を外す（新しい `docId` の教材は写しではないので、開き直しても知らせは出ない）。フォルダなしで編集アプリから始めた教材（貼り付けたもの・`deck.html` だけから開いたもの）には印が付かない。展開したフォルダは印を持たず、原本になる。次の書き出しが新しい印を書く。写しとフォルダの両方が手元にあれば、`npm run portable -- compare <ファイル> <フォルダ>` が書き出しの後にどちらを直したかを言う（[参照](reference.ja.md#1-ファイル--portable)）。
- **ファイルに入らないもの：** AI へのメモ（コメント）と `.cache/edits/` の控えはメモリの上にだけ残る（コメントは見直しの覚え書きなので、形式が外す）

### 権利の確認

ファイルを編集のために開くたびに、最初の変更の前に（編集モードや口述原稿の引き出しで最初に保存するとき、または「編集」「口述原稿」を押したとき）、ファイルに書かれた題名・作り手・著作権・ライセンス・クレジットの表示を見せる（どれも申告で、確かめたものではない）。改変を認めないライセンス（Creative Commons の `-ND`、All rights reserved）か、ライセンスがなく著作権の表示だけのときは、改変や改変したものの配布が権利者の著作権を侵すおそれがあると知らせ、確認のチェックを入れるまで編集を始めない。取消ならファイルは変わらない。保存で著作権・クレジット・作り手を消すことはない。

### 原稿の deck.html・組んだ発表の HTML を開いたとき

- **デッキの原稿**（作業フォルダの `deck.html`。GitHub から落としたものなど。`<section class="slide">` があり、組み立ての実行系や形式のブロックがない）は断らない。口述原稿・音声・そのデッキだけの部品は同じフォルダに別のファイルとしてあることを説明し、「作業フォルダを開く…」（フォルダを選ぶ画面。選んだフォルダをふつうに開く）・「このファイルだけを開く」・「取消」を出す。「このファイルだけ」は `deck.html` だけのメモリの上のデッキを新しく作る：口述原稿と音声はない。部品庫の部品とテーマは使え、参照しているのにないファイル（そのデッキだけの部品・`{{JSON:…}}` のデータ・取り込み・図）は組み立ての知らせ（1 つにつき 1 回）になり、空のまま組む（メモリの上のデッキはすべてこうする。フォルダは今までどおり、ないファイルがあれば組み立てが失敗する）。ほかの開いたファイルと同じに扱う：デッキにコードがあれば先に確かめ、新しい `docId` で、権利の確認は出さず（権利が書かれていない）、`deck.html` だけを開いていてまだ保存していないことを知らせる。「保存」は保存先をたずねる：「1 ファイル（`.ega.html`）に保存…」か「作業フォルダに書き出す…」（空のフォルダ）
- **組んだ発表の HTML**（`out/deck.html` など。組み立ての実行系と `deck-meta` はあるが原稿がない）は専用の言葉で断る：発表用に組んだもので、作業フォルダ（「作業フォルダを開く…」を出す）か 1 ファイルを開くように言う
- **1 ファイルの再生専用版**（`.play.ega.html`）はそう名指しして断る：そのままブラウザで再生でき、編集するには元の 1 ファイルか作業フォルダを開く。ほかの HTML は「1 ファイルではない」と言う

### 断るファイル・読むだけで開くファイル

- **理由を見せて断る：** 1 ファイルでないもの・再生専用のもの（上を参照）、ハッシュが合わないもの・一部が欠けたもの、許されないパス（`../` など）、索引の同じ名前の項目、設定のファイルと食い違う文書の識別子、新しい原稿の書き方の版
- **新しい major の版、編集アプリが実装していない必須の機能：** 編集のためには開かず、書き出し（作り直し）もしない。索引と中のデータが、編集アプリの知っている版の規則で確かめられれば、原稿を取り出す「作業フォルダに書き出す…」を申し出る。確かめられなければ取り出しも断る（そういうファイルもブラウザで再生はできる）
- **口述原稿・音声・秒数だけ：** 実行系の約束の版が違うもの、部品庫・テーマ庫の部品の hash が編集アプリのものと違う（または編集アプリにない）もの。編集アプリではそのとおりに組み直せないので、口述原稿・音声・秒数だけを編集できると上に知らせる。「編集」（スライドの文字）は断り、口述原稿の引き出しは使え、「保存」は組み直さずにその所だけを書き換える。組み直しの要る変更は保存できない
- **読むだけ：** 編集アプリで組み立てられないもの、ひとつ前の種類で、しかも組んだ教材と原稿が食い違うもの。デッキは表示し、保存は断り、「作業フォルダに書き出す…」はできる
- **独自のコード：** デッキが自前のコードを持つかは、組んだ文書から決める（取り込み・前処理の後の原稿全体。組み立てがテキストとして読むファイルは拡張子によらずすべて含み（`/*INCLUDE:…*/` で取り込んだ画像のファイルも）、そのあとプレビューに出すのと同じバイト）。`src` がなく中身が空か空白だけの `<script>` はコードに数えない（コメントだけのものは数える）。調べるためにフォルダをもう一度読むことはしない。そういうデッキ（と「extended」のファイル）は、その中のものが動く前に知らせてたずね、「プレビューを始める」を押してからプレビューを始める（取消ならファイルは開かない）。たずねる前にプレビューを空にするので、前のデッキも新しいデッキも、たずねる窓の後ろに出ることも動くこともない。開いている間は上に知らせを出す：コードはプレビューの中だけで、外へ繋がらずに動き、ファイルを書き換えられない。部品（`components/…`、どれかの `.js`）や `deck.html` のスクリプトを持つフォルダも、開くたびに 1 回同じことをたずねる（あとからそういうコードが現れたときも）

## チャットの AI で下書きする（貼り付けと修正依頼）

初めの下書きは、コーディング道具なしで、チャットの AI（claude.ai・Gemini・ChatGPT など）にも書かせられる。AI への指示は、**共通の本体** [authoring-with-llms.ja.md](authoring-with-llms.ja.md)（[English](authoring-with-llms.md)。規格・出力の形と、どの教材でも使える部品 `m-menu`・`m-flow`・`m-bars`）と、教材の種類ごとの**系列の指示** [llm-parts/](llm-parts/)：`academic`（`m-sweep`・`m-curves`・`m-seq`・`m-collect`）、`business`（`m-kpi`・`m-quad`・`m-market` と `m-flow` のお金の流れ）、`kokugo`（`m-kanbun`・`m-kobun`・`m-gendai`・縦書きのスライド）、`info`（`m-codetree`）。部品はどれもちょうど 1 か所に属す（README の `series:` の行）。`node tools/make-llm-guide.mjs` が約束事・部品の README・`tools/llm-guide/` から作り、古くなるか、共通の本体と系列 1 つで 40 KB を超えると `npm test` が失敗する。`node kit/llm-pack.mjs --series academic,info --lang ja` はエディタがコピーするのと同じ文章を出す（`--list` で系列と大きさ。KB は UTF-8 のバイト数 / 1024 で、貼り付けの窓と同じ数。英語と日本語の列、`--lang` を付ければその言語だけ。`--help` で使い方）。

- **AI の出力を貼り付ける。** 最初の画面か、**開く ▾ → AI の出力を貼り付ける…**。窓にはまずチャットに貼る指示がある：教材に要る系列に印を付け（それぞれ加わる大きさ付き。デッキを開いていれば、その部品とテーマから推した系列、なければ `academic` に印）、**AI への指示をコピー** を押す（共通の本体の「AI への指示」から後ろと、印を付けた系列の指示、最後に記入欄の付いた頼み方。押すと「コピーしました。チャットに貼り付けてください」と出る）。チャットに貼り付けたら、最後の「頼みたいこと」の記入欄を埋めて送る（新しく作るか、そのチャットでの議論の内容で作るかの 2 通り。書かない項目は消してよく、AI がほどよく決める）。次に AI の**返事の全体**を（チャットのコピーのボタンで）貼り付けて **取り込む** を押す。エディタは 2 つのコードの囲み `deck.html` と `narration.md` を取り出す（```` ```html ````・```` ```markdown ````・```` ```html title="deck.html" ```` のような名前や、囲みの前の行のファイル名も分かる。Windows の改行、囲みの前・間・後の文章、余分な囲みはかまわない。同じファイルの囲みが 2 つなら最後のものを使う）。閉じていない囲みは返事が途中で切れたということなので、窓にそう書き、何も開かず、**AI に送り直しを頼む文をコピー**を出す（足りない `narration.md` の囲みだけ、または教材の全体を短くして送り直してもらう）。切れたのが `narration.md` だけなら、その囲みだけの返事を、届いていた `deck.html` と合わせて開く。囲みのない返事も断る。囲みの印なしで画面からコピーした返事は、`<!DOCTYPE html>` から `</html>` までをデッキ、その後ろを口述原稿として取り出し、そのことを知らせる
- **id。** AI にはスライドの id を書かないように頼んでいる。エディタは、id のないスライドに新しい id を付け、口述原稿の見出しを `## 見出し {#id}` に書き換える（`npm run ids` と同じ本体の `kit/core/slide-ids.mjs`）。見出しが同じスライドが 2 枚以上あれば、口述原稿のその見出しの節を順に対応させる
- **開いたファイルと同じに扱う。** 原稿は組み立ての Worker で 1 ファイルにし、開いたファイルとまったく同じに開く：コードの確かめは中身から決めるので、`<script>`（ほか動くもの）の入った返事は先に **プレビューを始める** を聞き、取消なら何も開かない。新しいデッキは新しい `docId` で、まだ保存していない（●）。**保存** で保存先を聞く。自分の下書きなので権利の確認は出さない。開いたら品質チェックをかける
- **AI への修正依頼をコピー。** 品質チェックの板にある。修正依頼の文章をクリップボードにコピーして見せる：指摘（エラーと警告）、それが破った規格（規格には `R-title` のような名前があり、文章は同じ指示から取る）、デッキが使っている部品の説明（指示と同じ文章）、はみ出しと小さい字の量（「本文を 97 px（46 px の行でおよそ 3 行）減らす」「字を 23.2px から 24px 以上に上げる」）、口述原稿についての組み立ての知らせ、今の `deck.html` と `narration.md`。デッキが長い（合わせて 40000 字を超える）ときは、指摘のあるスライドとその口述原稿だけを載せ、そのスライドだけを返すよう頼む。同じチャットに貼り付け、**返事を貼り付ける…** を押すと、**今のデッキを置き換える** を選んだ貼り付けの窓が開く
- **今のデッキを置き換える。** 文書はそのまま：1 ファイルなら `docId`・設定・音声・部品を残して原稿だけを入れ替える（保存するまでは未保存）。フォルダなら `deck.html` と `narration.md` を、`.cache/edits/` に控えを残して書き、コードが現れたらコードの確かめをもう一度聞く。id 付きの `<section>` の一部だけの返事は、そのスライドと口述原稿の節だけを置き換える
- **品質チェックに足したもの：** スライドにない段階の口述原稿（エラー）、表紙など static のスライドの口述原稿、式やいくつもの記号を入れた読みの指定 `{x|y}`（警告。読みは 1 つの記号か用語に 1 つ）。コマンド版の品質チェックも同じ 3 つを見る

## 書き換えるファイル

開発サーバーとまったく同じ（[dev-server.ja.md](dev-server.ja.md) の「書き換えるファイル」）。どれも選んだフォルダの中

- `deck.html`：編集した要素の中身だけ
- `narration.md`：編集した段階の行だけ（注釈やほかの行はそのまま）
- `comments.json`：AI へのメモ `[{id, created, key, range, pin, quote, comment, status}]`（`pin` は押した点 `{x, y}` のスライドの座標、1280×720。[開発サーバー](dev-server.ja.md#書き換えるファイル)を参照。指示が何を指しているかを見るには、フォルダに `npm run comment-shots -- <作業フォルダ>` を動かす：未対応の指示ごとに、その段階をピン付きで `.cache/comment-shots/` に描く）
- `audio/<rec|tts|imp>_<hash>.mp3` と `audio/manifest.json`：音声の板の **この音声を使う** で（変わるのはその段階の記録だけ。前の manifest は控える）
- [スライド一覧](#スライド一覧足す複製削除並べ替え)で：`deck.html`（スライドをまるごと入れる・写す・消す・動かす）、`narration.md`（節をまるごと）、`audio/manifest.json` と、スライドを消したときはその音声の `audio/` のファイル（先に控える。元に戻すで書き戻す）
- `.cache/edits/`：書き換える前の `deck.html`・`narration.md`・`audio/manifest.json`（新しい 30 個。掃除で消すのは控えの名前の形（`<時刻>-<名前>`）のファイルだけで、フォルダのほかのものは残す）
- 「新しいデッキ」では `deck.html` と `narration.md`、「組み立てた HTML を書き出す」「配るための Egatari ファイル（編集可・.ega.html）を書き出す」では選んだファイル（と、初回はフォルダの設定のファイルの教材の識別子）
- 1 ファイルを開いたとき：保存するまで何も書かない（直したものはメモリの上）。保存では選んだファイルだけ（組み直さない保存では、上に挙げた所だけを書き換える）、「作業フォルダに書き出す…」では選んだ空のフォルダのファイルだけ

## できないこと

- **Chrome・Edge だけ。** スマートフォンのブラウザもフォルダを開けない
- **ブラウザの TTS のモデル。** モデルは編集アプリのサイトのブラウザのキャッシュに置かれる（Irodori-TTS は約 1.26 GB、Kokoro は約 330 MB）。「使い方」に、このサイトが使っている保存領域（`navigator.storage.estimate`）と入っているモデルが出て、「モデルを消す」で消せる（作った音声は消えない。次に使うときに取得し直す）。TTS の窓はモデルを読み込むとき、古い版のモデルのキャッシュを消し、ブラウザに保存領域を残すよう求める（`navigator.storage.persist`）。求めが通らなければ、ディスクの空きが足りないときにブラウザがモデルを消すことがあり、Safari は 1 週間ほど開かないと消す
- **コマンドで行うもの：** 自分の参照音声やサーバーのエンジンでの TTS（`tts/synth.py`）・動画（`tts/` `render/`）、品質チェックのコマンド版（`npm run check`）、`tools/pdf.mjs`。プレビューは `audio/manifest.json` の音声（フォルダでも 1 ファイルでも）を自動再生（`a`）で鳴らす：編集アプリが音声のファイルを読んでそのバイトをプレビューに渡し、プレビューは自分の文書の `blob:` の URL で鳴らす（砂場のプレビューはフォルダも編集アプリの `blob:` の URL も読めない）
- **音声の板は編集アプリだけ。** 開発サーバーには音声の板がない（フォルダを編集アプリで開くか、`tts/synth.py` を使う）。ブラウザの TTS には WebGPU と、配信版か配った編集アプリが要る
- **書き出しが大きい。** コマンドの build は fonttools で和文の字を絞り込める（`node tools/get-fonts.mjs`）が、ブラウザではできないので、使う字を含む分割ファイルをそのまま埋め込む（TTF がないときのコマンドと同じ）。`examples/minimal` は編集アプリで約 2.0 MB、絞り込んだ `npm run build` で 0.7 MB。見た目は同じ
- **1 ファイル版に明朝はない。** 配信版の編集アプリは BIZ UDP明朝を持つ（明朝を使うデッキ、たとえばテーマ `kokugo` のときだけ読む）が、1 ファイル版 `dist/editor.html` は小さく保つために持たない。そこでは明朝のデッキは知らせを出して組まれ、見る人の機械の明朝で出る
- **同梱のもの。** 部品庫の部品（`vendor/components/` のすべての版と `components.lock.json`）・テーマ（`themes/`）・実行系（`kit/`）は、アプリを組んだときのもの。教材は、記録したハッシュに合う版の部品がアプリにあれば、その版で組み直す。作業フォルダの中の部品とテーマ（`components/<名前>/index.js`、`themes/<名前>/`）は、いつもどおりフォルダから読む。どちらにもないテーマ（自分のテーマのフォルダにある機関のテーマなど。コマンドは `EGATARI_THEMES`・`~/.egatari/themes` で見つける）は `theme not found: "<名前>"` と警告して `default` で組み、プレビューの上の知らせに「テーマのフォルダを選ぶ…」を出す（警告の一覧にも）
- **自分のテーマのフォルダ。** 「テーマのフォルダを選ぶ…」か、「開く ▾」（とはじめの画面）の「テーマのフォルダ…」で、自分のテーマのフォルダ（たとえば `~/.egatari/themes`。macOS の選ぶ画面では ⌘⇧. で隠しフォルダが見える）を 1 回だけ選ぶ。その後はコマンドと同じ順と同じ根の決まりでテーマを探す：作業フォルダ → その `themes/` → このフォルダ → 同梱のテーマ。テーマのファイル・ロゴ・`extends` の親は、そのテーマの根（か同梱のテーマ）の外に出ない。フォルダは読むだけで開き、書き込まない。中身はデッキのファイルと同じく信頼しない（テーマの CSS は同じ消毒を通り、ロゴは data URI になる）。読むのは、組み立てが使うテーマのファイルだけ。ブラウザはフォルダのハンドルを IndexedDB に残し（中身は残さない）、次に要るときに読む許可をもう一度求める：知らせに「テーマのフォルダ「<名前>」を使う」を出す。「テーマのフォルダ…」で今のフォルダとそのテーマを見て、替える・忘れることができる。1 ファイルに書き出す・保存すると、使った自分のテーマは原稿の `themes/<名前>/` として入るので、ほかの所でも同じテーマで組み直せる（`npm run build -- --portable` で作った 1 ファイルは、もうそこに入れている）
- **読まないもの：** `.` で始まる名前と、`out/` `audio/` `video/` `bundle/` `node_modules/` のフォルダ（3000 ファイル・10 階層まで）。`audio/` は 1 ファイルに書き出すときだけ読む
- **組み直しはまだ比べない。** スライドを直した後の保存は、同梱の kit でファイル全体を組み直す（なので、古い・新しい build で作ったファイルは直した所の外も変わり、字は分割ファイルごと埋め込む）。直したスライドのほかにどのスライドが変わったかは、まだ見せない
- **字の補いは多めになることがある。** 絞り込んだ字に `unicode-range` のないファイル（前の版がコマンドで作ったもの）では、元の口述原稿の字があることしか分からないので、絞り込んだ字がもう持っている字の分割ファイルも足すことがある（ファイルが少し大きくなる。字が欠けることはない）
- **デッキの中からの通信は止まる。** 外部の画像やスクリプト（`https://…`）はプレビューに出ない（build はもともと警告する）

## 仕組みと安全

- **組み立ては 1 つ。** `kit/core/build-core.mjs` が組み立ての本体（注記・取り込み・KaTeX・部品・口述原稿・注目の演出・秒数・テーマ・ファイルの埋め込み・字）で、Node に依存せず、渡された口を通してだけファイルを読む。`kit/build.mjs` は Node のファイル（と fonttools の絞り込み・ffmpeg）を、編集アプリは選んだフォルダと同梱の kit・部品・テーマ・KaTeX・字を渡す。字の絞り込みを切れば、両方が 1 バイトも違わない HTML を出す（`tools/test-app.mjs` が `examples/minimal` と `examples/tmlr2026-calibration` で確かめる）。口述原稿の解析と書き換え（`kit/core/narration-core.mjs`）と新しいデッキの雛形（`kit/templates/new-deck.mjs`）も同じく共有する
- **編集の画面も 1 つで、デッキの外にある。** `server/editor-ui.js`（原稿の欄・口述原稿の引き出し・コメントの欄と一覧）は、ここでは編集アプリのページで、開発サーバーでは外枠のページで動く。どちらも同じ問い合わせ（`/__dev/source` `/__dev/edit` `/__dev/narration` `/__dev/comment` …）を送り、開発サーバーは HTTP で、編集アプリはページの中で開いたフォルダについて答える（`app/devapi.js`）。デッキの中にあるのは知らせを送る `server/hints.js` だけ（下）
- **デッキは砂場の中で動き、書き込めない。** プレビューは `allow-same-origin` を付けない `<iframe sandbox="allow-scripts allow-modals">` なので、デッキは origin を持たない。編集アプリの画面・保存領域・フォルダのハンドルに届かない。`allow-modals` は印刷のため。ページの Content-Security-Policy（アプリ自身の読み込みだけを許し、iframe の移動は許さない：`frame-src 'none'`）に重ねて、プレビューの文書には別の決まりを、デッキのどのバイトを解析するよりも前に効かせる。編集アプリはプレビューの文書を「信頼する先頭部分（doctype・`<html><head>`・`<meta charset>`・決まりの `<meta>`・小さな信頼する仲立ち）＋組んだデッキそのまま」として組み、デッキの文書の中を探して決まりを入れることはしない。決まりは `connect-src 'none'`、画像・字・スタイル・音声は `data:` / `blob:` だけ（組み立てが埋め込む）、Worker・iframe・フォーム・`<base>` は使えない（`'unsafe-eval'` は、取り下げた部品の版のためだけにプレビューの決まりに残す。次の項目）。発表者ビューは編集アプリが開く窓で、その中のデッキもまた同じ決まりの砂場の iframe。やり取りは編集アプリが中継する
- **編集アプリのページは eval を許さない。許していたのは取り下げた部品の版のため。** ページ自身の Content-Security-Policy に `'unsafe-eval'` はない（あるのは `'wasm-unsafe-eval'` だけで、MP3 エンコーダの WebAssembly のため。`eval` も `new Function` も許さない。配信版も 1 ファイル版 `editor.html` も。試験がページの CSP 違反を見張る）。部品庫 v1.0.0・1.0.1 の `m-sweep`・`m-curves` は式を `new Function` で動かすので、部品庫はその版を取り下げ（yank）、置き換えを v1.0.2 とした（[SECURITY.md](../SECURITY.md#components-yanked-by-the-registry)）。取り下げた版を記録した教材を開くと、編集アプリは知らせと **「1.0.2 で組み直す」** ボタンを出し、版を勝手に替えることはしない（仕様 §6。組み直すと部品の同一性の hash や見え方が変わることがあり、組み直した後の知らせに、どの hash が変わったかを書く）。そのときまでは教材は今のまま再生できるが、プレビューの枠（`allow-same-origin` のない sandbox。編集アプリのページ・保存領域・フォルダのハンドルに届かない origin）の中だけ。枠はこのページの決まりを受け継ぐので、編集アプリの中では取り下げた版の `m-sweep`・`m-curves` は式を計算できず、図の代わりの表示（`DECK.componentErrors`）になり、教材のほかの部分は動く。プレビューの決まり（`PREVIEW_CSP`）と開発サーバーのデッキの文書（編集アプリのページを周りに持たない、最上位の sandbox の文書）は `'unsafe-eval'` を残すので、そちらでは取り下げた版も動く
- **頼みではなく知らせ。** プレビューには書き込みを頼む口がない。送れるのは知らせだけ：「この `data-src` の範囲と hash の要素を直したい」（編集モードでダブルクリック）、「この要素にコメントしたい」（Alt+クリック。スライドと段階の鍵、要素の短い引用、点の近くの字、点のスライドの座標）、鍵の `e`・`n`・`c`・`r`・Esc（`r` は録音モードの画面を開くだけ）、今の位置（`deck-pos`）。知らせは書き込む本文を持たない。編集アプリは送り元の窓と知らせの形を確かめ、編集モードでないときの edit の知らせは無視し、今の原稿を自分で読み、範囲が今の組み立ての直せる要素で hash が合うことを確かめて、自分の欄を見せる。書くのは、その欄や引き出しで「保存」か ⌘/Ctrl+Enter を押したときだけ。権利の確認と読むだけのファイルは、これまでどおりこの書き込みにかかる。編集アプリからプレビューに送るのは、見せるのに要るものだけ（編集モードの入り切り・印を付ける要素・「その段階へ」・印刷・品質チェック）。指示の点は開発サーバーと同じく確かめる（数だけ、1280×720 のスライドの外は端に寄せ、ほかの項目は捨てる。`app/devapi.js` も `kit/core/comment-core.mjs` でもう一度確かめる）。偽の点で変わるのは印の位置だけで、プレビューの上の印は、編集アプリのページがプレビューの大きさから描く
- **触るのは選んだフォルダかファイルだけ**で、ブラウザの許可を得てから
- **保存は始めたときのデッキに結び付く。** 待つたび（組み直し・確かめの窓・権利の確認・保存先を選ぶ画面・ファイルを作る・書く）の後に、同じデッキが開いたままかを確かめ、その確かめを書き込みの中まで運ぶ：その間に別のデッキを開いたら、ファイルを入れ替えず（書き込みを取り消す）、ほかにも何も書かない。新しい教材の識別子をデッキの設定に書くのと「保存した」にするのは、ファイルを書いた後だけ。保存している間にした編集は、保存したファイルに入っていないので、未保存の印のまま
- **信頼する欄で編集している間**（原稿の欄・指示の欄を開いている、口述原稿の引き出しで入力している・未保存の変更がある）は、プレビューを `inert` にする。その間はデッキからの知らせで板の欄を開け閉め・切り替えせず、編集している口述原稿の段階も替えない
- **フォルダとリンク。** メモリの上・OPFS のフォルダはシンボリックリンクを持てない。選んだフォルダの中のリンクは、Chromium では編集アプリにまったく見えない（一覧に出ず、名前でも開けず、書けない。`tools/test-security.mjs` が確かめる）ので、組み立てがリンク越しにフォルダの外のファイルを読むことはない。File System Access API には編集アプリ自身がリンクを見分ける手段がないので、これはブラウザに頼っている
- **マイクと TTS は編集アプリのページだけで。** 録音（`getUserMedia`・`MediaRecorder`）・取り込み・後処理・MP3 にするのは編集アプリのページで、プレビューからは始められず、プレビューから音声を受け取ることもない。録音は録音モードだけで行い、開いている間プレビューは `inert`。音声の板が音声を作って書いている間は、デッキからの知らせで板の段階を替えない。ページの決まりはそのままで通信を許さない：ブラウザの TTS は同じサイトの別の窓（`lab/tts-helper.html`。試験ページと同じく、版を固定したライブラリを jsDelivr から、モデルを Hugging Face から取る）で動かし、窓に送るのは読む文と声の名前だけ。編集アプリはその窓からの音だけを受け、標本化周波数と長さを確かめ、録音と同じく後処理する。フォルダから読む音声には上限がある（manifest は 16 MiB、音声のファイルは 1 つ 64 MiB）
- **1 ファイルを開いても、その中のものは何も動かない。** ファイルはバイト列として読み、スクリプトを動かすブラウザと同じ解析の規則で（何も実行しない）Web Worker（編集アプリに同梱。ページの決まりは `blob:` の Worker だけを許す）の中で解析する。そのファイルへ移動したり、ページに入れたりはしない。動くのは原稿から組み直したデッキだけで、フォルダのときと同じ砂場のプレビューの中

## GitHub Pages で配る

`.github/workflows/pages.yml` が `node tools/build-app.mjs --out _site` で組み、GitHub Pages に置く（編集アプリは根 `/`、1 ファイル版は `/editor.html`、試験ページは `/lab/irodori.html`。前に編集アプリがあった `/editor/` は、問い合わせと `#` を残して `/` へ移すページ）。パスはどれも相対なので、同じファイルが独自ドメイン <https://studio.egatari.org/>（Settings → Pages → Custom domain で設定し、サイト全体に効く）でも <https://egatari.github.io/egatari-studio/>（独自ドメインへ移る）でも動く。置く（deploy）のはリリースのタグだけ：タグ `vX.Y.Z`（数 3 つ。`v0.5.0-rc.1` などの rc のタグは置かない）を push したときと、そのタグで workflow を走らせたとき（その版を置き直す）。`main` への push と pull request は組むだけで（リリースの前に組み立ての壊れに気づくため）、ブランチで走らせると組むだけの試し。リリースの手順は [RELEASING.ja.md](../RELEASING.ja.md)。Pages を設定するまでは何も置かない

1. Settings → Pages → Build and deployment → Source を **GitHub Actions** にする
2. Settings → Secrets and variables → Actions → Variables に `EDITOR_PAGES` = `true` を足す（なければ組むだけで、何も置かない）
3. Settings → Environments → `github-pages` → Deployment branches and tags にタグの決まり `v*.*.*` を足す（この environment はふだん `main` だけを許すので、足さないとタグからの deploy は断られる）
4. リリースのタグを push するか、タグを選んで workflow を走らせる（Actions → pages → Run workflow）

組み立ては見本も 1 ファイルにして `examples/<名前>.ega.html` に置き（`tools/examples-portable.mjs`。合わせて約 14 MB。`--no-examples` で入れない）、編集アプリの最初の画面に並べる。組むのは見本のフォルダの一時的な写しから（`examples/` には何も書かない）。`egatari.json` のない見本（雛形として写してよい `minimal` など）には名前から決めた `docId` を与えるので、組むたびに同じ文書になる

### リリースに添えるファイル

`npm run release:assets`（`tools/release-assets.mjs`）が同じ見本のファイルを `out/release/` に組み、`examples.json`（名前・題名・言語・枚数・大きさ・sha256）を添える。どこにも上げない。GitHub のリリースには人の手で添える（たとえば `gh release create v<版> out/release/*.ega.html`）

### 版ごとの URL（凍結した写し）

サイトは v0.4.1 からのすべてのリリースを残す。根は最新のリリース、`/vX.Y.Z/`（たとえば <https://studio.egatari.org/v0.4.2/>）はそのリリースを凍結した写しで、中の形は同じ（`/vX.Y.Z/editor.html`・`/vX.Y.Z/lab/…`・`/vX.Y.Z/examples/…`）。Pages は 1 回に 1 つの artifact を置くので、リリースの deploy が組み立てる（`node tools/site-versions.mjs assemble`）：いま組んだものを根と `/v<その版>/` に、公開済みの前の各リリースからは添えたファイル `editor-site-vX.Y.Z.tar.gz` を取り、リリースの説明の行 `editor-site-vX.Y.Z.tar.gz sha256: <16 進>`（と GitHub が記録するそのファイルの digest）と合うか確かめて `/vX.Y.Z/` に広げる。そのファイルのないリリース（v0.4.0 まで）は飛ばし、sha256 の行がない・合わないときは組み立てを失敗にする。このファイルは組んだ `dist/` を、何度作っても同じバイトになるようにまとめたもの（`node tools/site-versions.mjs asset vX.Y.Z` が、タグの git worktree で `npm ci` してから組む）で、リリースのときに添える（[RELEASING.ja.md](../RELEASING.ja.md)）。根の `versions.json` が版を並べる。`main` への push と pull request でも、同じ組み立てを試しとして走らせる。1 つの版が約 50 MB なので、GitHub Pages の上限 1 GB には約 18 版が入る。800 MB を超えると知らせ、1 GB を超えると失敗にする

- **知らせと一覧。** 写しは上に 1 行を出す：「Egatari Studio v0.4.2（そのリリースのまま凍結した写し）を使っています」・最新版（根。`?lang` は残す）へのリンク・ほかの版の一覧。✕ で隠せる。根は最初の画面の下に版の一覧を出す。この知らせより前に組んだ写し（v0.4.1・v0.4.2）には、組み立てが `index.html` と `editor.html` に根の `version-notice.js` を読み込ませる（決まりの `<meta>` の後に `<script>` を 1 つ。写しのほかの所は変えない）
- **ブラウザのデータは共有。** どの版も同じサイト（同じ origin）なので、ブラウザのデータを共有する：最近開いたもの（IndexedDB の `motion-slides-editor`。ファイルのハンドルと名前だけを持ち、どの版も同じ形で読むので、ある版で開いたファイルはどの版にも並ぶ）・画面の言葉（`localStorage`）・利用者のテーマのフォルダ・ブラウザの TTS のモデル（Cache Storage。モデルの版ごとの名前なので、同じモデルの版どうしは 1.26 GB の取得を共有する）。ほかのモデルの版のキャッシュを消すのは根だけで、写しは消さない（`lab/model-cache.mjs` の `inFrozenCopy`）。ただし写しの v0.4.1・v0.4.2 はこの決まりより前のものなので、後のリリースがモデルを替えると、その新しいモデルを消す。最近開いたものの保存の形を将来変えるときは、DB の名前を替えること（古い写しも開き続けるため）。service worker はない。ウェブアプリの manifest の scope は各写しのフォルダ

## 画面の言葉

ふだんはブラウザの言語（日本語か英語）に合わせる。右上の **English / 日本語** のボタンで切り替えるか、`…/?lang=en`・`?lang=ja` で開く。選んだ言葉は覚えておき、デッキを開いたまま切り替えても同じフォルダを開き直す（開いた 1 ファイルは閉じる。保存していない変更があれば先にたずねる）。編集の道具（編集モード・原稿の欄・口述原稿の引き出し・コメント）は編集アプリの言葉に合わせる（開発サーバーではデッキの言語 `<html lang>` に合わせる）。
