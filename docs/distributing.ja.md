# 参加者に教材を配る

[English](distributing.md) | 日本語

教材は 1 つの HTML ファイルで配る：[Egatari ファイル（`.ega.html`）](reference.ja.md#1-ファイル--portable)か、参加者にはふつうその再生専用の写し（`--play-only`。編集できるスライドと台本を持たず、再生するスライドと音声だけ）。**ダウンロードしてブラウザで開けば**、今のどのブラウザ（Chrome・Edge・Safari・Firefox）でもオフラインで再生できる。困りごとのほとんどは、ファイルを開かずにプレビューだけを見せる場所から起きる。

| 配り方 | 参加者に伝えること | 気をつけること |
|---|---|---|
| Google ドライブ（ドライブで共有する Google Classroom も） | 「ファイルをダウンロードしてから、ブラウザで開いてください」 | ドライブのプレビューは HTML を文字で見せるか何も見せず、教材は動かない。要る人に共有する（または「リンクを知っている全員」） |
| メール | 「添付を保存してから、ブラウザで開いてください」 | メールの大きさの上限（20〜25 MB のことが多い。音声が入ると大きくなる）。学校のメールの検査が `.html` の添付を止めたり外したりすることがある。そのときは `.zip` にするか、ドライブのリンクで送る |
| LMS（Moodle・Canvas・Classroom など） | 「ダウンロードしてから開いてください」 | ファイルの資料として載せ、選べるなら表示を「ダウンロード」にする。LMS のページの中で表示すると、スクリプトが止められて再生できないことがある |
| 自分のウェブの場所（学校のウェブサーバー・GitHub Pages など） | URL | そのまま開ける。スマートフォンやタブレットでも。静的なファイルを置ける所ならどこでもよく、サーバーでは何も動かない |

**Egatari ファイルが動く場所**（各社の文書で確認、2026-10-23。すべての機械では試していない）：

| 置き場所 | 動くか |
|---|---|
| PC のブラウザでダウンロードして開く | 動く |
| ウェブの置き場所（学校のウェブサーバー・GitHub Pages・Cloudflare Pages など） | 動く |
| Moodle（ファイルの資源、「開く」か「埋め込み」） | 動くはず（実際の Moodle では未確認）。学生の提出物は強制ダウンロードになることがある |
| Google ドライブ・Google Classroom のプレビュー | 動かない（プレビューは中身の文字を見せる） |
| SharePoint・OneDrive・Teams | 動かない（スクリプトの入った HTML はダウンロードになる） |
| iPhone・iPad の「ファイル」アプリ | 動かない（Quick Look は JavaScript を動かさない） |

**iPhone・iPad では** [Egatari Viewer](viewer.ja.md)（`viewer.egatari.org`、ホーム画面の名前は Ega Viewer）で開いてもらう：[iPhone・iPad で教材を開く（Egatari Viewer）](viewer-sharing.ja.md)。

- **参加者には再生専用の写しを渡す**（`--play-only`）。直せるファイルは手元に残す
- **公開の URL は、アドレスを知っている人なら誰でも見られる。** ウェブの置き場所にはサインインがない。授業の人だけに見せたいものは置かない

- **スマートフォン・タブレット：** ファイルのアプリの簡易表示（iPhone の「ファイル」App など）では動かないことがある。ブラウザで開くか、URL を渡す。すべての機械と経路はまだ確かめていない。動いた・動かなかった経路を教えてほしい（[感想を送る](https://github.com/egatari/egatari-studio/issues/new?template=feedback.yml)）
- **授業の前に確かめる：** 配るファイルを、自分のでない計算機で、参加者と同じやり方（ダウンロードしてから開く）で開き、音声付きで 1 枚再生してみる
- **直せるファイルは手元に：** 配るのは再生専用の写しにし、あとで直すための Egatari ファイルか作業フォルダは手元に残す（再生専用の写しは直せない）
- **WebGPU のない PC での音声：** WebGPU のない PC でも、エディタで AI 音声をクラウドで作れる（[AI 音声をクラウドで作る（Google Colab）](editor.ja.md#クラウドで作るgoogle-colab)）。<!-- colab-verified --> 確認済み：2026-10-23、CPU（講習で、Irodori）。2026-10-24、T4 で固定した版（cuda13 の組）：Irodori 23 ステップを 42 秒、Kokoro 59 ステップを 30 秒。2026-10-25、持ち主の手での計測（10 ステップ・話者 1 人。日本語 209 字・英語 518 字）：T4 の日本語（Irodori）は読み込み 34 秒・合成 19 秒、T4 の英語（Kokoro）は読み込み 4 秒・合成 4 秒、CPU の英語は読み込み 7 秒・合成 33 秒（1 ステップ約 3 秒で十分使える）、CPU の日本語は読み込み 1 分・1 ステップ約 60 秒（steps=40）。1 ステップだけの手での計測は steps=40 で 90 秒、steps=16 で 52.5 秒（この版より前の、fp16 の重みで参照音声を毎回符号化していたとき）<!-- /colab-verified -->。**プライバシー：** Colab では台本の文が Google の環境で処理されるので、共有してよい文だけに使う。書き出す `tts-job.json` には読み上げる文と声の名前だけが入り、教材のほかのものは入らない

## 教室で映す

- **順番：** 先に発表者ビューを開き（`p`）、それから聴き手の窓をプロジェクターの画面に移して全画面にする（`f`）。発表者ビューは手元の画面に残る
- **発表者ビューを閉じる：** 発表者ビューでは、Esc（描く道具を使っていないとき）・`p`・**発表者ビューを閉じる（p）** で閉じ、本体の窓にフォーカスを返す。全画面のときは、全画面をやめるだけ。本体の窓で `p` を押しても閉じる。発表者の窓にフォーカスがない間は、大きな「ここを押すと操作できます」の覆いが最初のクリックを受ける
- **発表者ビューから抜けられないとき：** 画面を覆ったままキーが効かないときは、Mac は cmd+Tab で本体の窓に戻って `p`（Windows は Alt+Tab。Windows ではまだ確かめていない）。キーの一覧（<kbd>?</kbd>）にも同じことを書いてある
- **黒い画面：** `b` で窓全体を真っ黒にする。隅に薄く「黒い画面中 — b か Esc で戻ります」が 2 秒出て、マウスを動かすとまた出る。`b`・Esc・クリック・矢印・Space・PageUp/PageDown・Home/End で黒い画面を終え、スライドは動かない。続けるにはもう一度キーを押す

## ライブ（授業中の質問と投票。下書き）

ライブは試用中（プレリリース）です。形式の拡張 `live` は草案なので、結果のファイルの形はまだ変わることがあります

Egatari ファイル（再生専用）に **ライブ**（[形式の拡張 `live`](https://github.com/egatari/egatari-spec/blob/main/extensions/live.md)。下書き）を付けられる。決めたライブの時間のあいだ、ファイルを開いた参加者が、アプリもアカウントもなしに、教材の中から質問を送り、投票に答えられる。教材の中でネットワークを使うのはここだけで、参加者が **参加する** を押した後だけ。

1. 編集アプリで **ファイル ▾ → エクスポート ▸ →「参加者用（再生専用）…」** を選び、**ライブ（質問・投票）を付ける** に印を付けて（同じ窓にライブの設定が出る）、**ライブ ID と参加コードをこの画面で作る** を押す（乱数から作る。編集アプリはこのときもどこにもつながらない）。ライブの時間（開始と終了）を決め、質問の入／切と投票を決める（表示名は 3. を参照）。すると窓に **1 本の文字列** が出る：**文字列をコピー** し、**ホストのページを開く** で開いたページに 1 回だけ貼り、確認を済ませて **このライブを作る** を押す。文字列にはライブ ID・参加コード・ライブの時間・質問・投票の設定がすべて入っているので、ホストのページでほかに入れるものはなく、編集アプリに何かを貼り戻す必要もない。ホストのページに一度だけ出るホスト用リンクをブックマークしてからエクスポートする（5.）。文字列にはエクスポートするファイルに入らない秘密の値も入っているので、ファイルを持っているだけの人はそのライブを作れず、ホストになれない。文字列は参加者に渡さない。**文字列をコピー** の隣の **設定の文字列を保存する** で、小さなテキストのファイル（`egatari-live-setup-<ライブ ID>.txt`）としてダウンロードできる。ホスト用リンクと同じように扱う。貼る前に編集アプリを閉じるかもしれないときは保存しておく：同じ文字列はもう出せず、配ったファイルは誰も作れないライブを指したままになる。文字列は教材にも `egatari.json` にも、どのエクスポートにも書かない。ライブを作ったあとでライブの時間を変えるときは、ライブ ID と参加コードを作り直して貼り直す。あいだに編集アプリを閉じた（参加コードは覚えていない）ときは、ホスト用リンクのページの **Egatari Studio に貼る設定** を前からの方法で貼れば、同じライブのままエクスポートできる

   **前からの方法**（同じ窓の **ホストのページで先にライブを作った場合** の中）も残る：下の 2.〜4.
2. ライブのサーバー（既定は `https://live.egatari.org`。サービスと通信の約束は [egatari/live](https://github.com/egatari/live)）のホストのページで **ライブを作る**。ライブの時間（開始と終了）を決める。一度だけ出るホスト用リンクをブックマークする（ライブを操作するためのコードが入っている。なくしたら作り直す）。**待機室を使う** にすると、ホストが許可した人だけが参加できる
3. 編集アプリで **ファイル ▾ → エクスポート ▸ →「参加者用（再生専用）…」** を選び、**ライブ（質問・投票）を付ける** に印を付ける。ホストのページでコピーした **Egatari Studio に貼る設定**（ライブ ID・参加コード・ライブの時間）を貼る。参加者からの質問を教材全体で受け付けるかを決め、ステップごとに投票（設問と 2〜6 の選択肢）を追加する（**今プレビューに出ているステップにする** で画面のステップを入れられる）。投票には、教材のどこかを言う表示名が付く（例「4 枚目『XML の壁』・ステップ 1」。スライドの番号、約 24 字で切ったスライドの見出し、ステップの番号。番号は 1 から）。表示名はステップの候補と投票の一覧に出て、ステップの鍵（例 `s-cjatth:0`）は吹き出しに残る。ステップを変えると表示名も変わる。表示名ができる前に残した投票は、設定を開いたときにスライドがまだあれば付き、なければ鍵から「s-cjatth · ステップ 1」の形で出る。まだ足りないものは **エクスポートする前に直すこと** に画面の言葉で出る
4. **投票の設定をコピー** し、ホストのページの **投票の設定** に貼る（ライブが同じ投票を知るため。知らない質問・投票や選択肢への投票はライブが断る）。JSON には表示名（`label`。表示のための字で、鍵は変わらない）が入るので、ホストのページと参加用のページはステップの鍵の代わりに「4 枚目『XML の壁』・ステップ 1」を出し、結果の JSON にも残る。表示名のないライブでは、投票をステップの鍵で出す（「s-cjatth · ステップ 1」。`*` は「教材全体」）
5. **ライブを付けてエクスポート…** で Egatari ファイル（再生専用）を書く。配り方はいつもと同じ（ダウンロードしてからブラウザで開く）

参加者の写しのふるまい：

- **ネットワークに出ない：** ライブがない・ライブの時間の外（両端に 2 分のゆとり）・ブラウザで直接開いていない（ファイルかウェブのアドレスから）ときは何もしない。編集アプリのプレビュー、ほかのページの中（LMS・埋め込み）、動画（`?mode=video`）、印刷、発表者ビューではつながない。編集アプリのプレビューでは、代わりにライブ ID を字で見せる。ほかのページの中や、つなげない形で見せているとき（チャットのアプリやファイルのアプリの表示、ほかの種類のアドレス）は、**ブラウザで参加する** を出す。ライブの参加用のページ（`https://<サーバー>/join#room=…&key=…`。参加コードは `#` の後ろだけ）を新しいタブで開くリンクで、押すまで何も読み込まない
- **ファイルからつながる端末：** パソコンのブラウザ（Chrome・Edge・Firefox・Safari）でダウンロードしたファイルを開けばつながる。Android では、ファイルのアプリからダウンロードしたファイルを Chrome で開いたとき（`content://` のアドレス）もつながる。参加者が自分で開いたファイルとして扱い、条件は同じ（枠の中でない・ライブの時間の中・写しの決まり・**参加する** を 1 回押す）。iPhone と iPad では、ダウンロードした HTML のファイルをブラウザで動かせない（ファイルのアプリはスクリプトなしで見せるだけ）ので、ホストのページの **参加用リンク** を使う。参加用リンクはどの端末でも使える。Slack などのチャットのアプリは、大きな写し（音声入り）をプレビューできないことがあるので、ダウンロードしてもらう
- **参加の前に 1 回押す：** 教材は右上の小さな **ライブ** の印だけで始まる。印を押すと板が開き、教材がつながる先を見せて **参加する** を出す。参加中は、板をたたんでいても印そのものがずっと見える印になる（緑の点と、読み上げ用の状態の字）。**退出する** は開いた板にある。押したことはそのタブのあいだだけ覚える（新しいタブではまた聞く）
- **送るのは：** 参加者が送ると決めた質問と投票、入れたときだけ名前、端末で作った乱数の番号（ブラウザの記憶に置く。使えなければメモリだけ）、つながりを保つ ping。見ている位置や時間は送らない。教材全体で受け付ける質問では、送るを押したときに画面にあるステップの鍵を、その質問に付ける
- **要るときだけ開く：** 板をたたんでいる間、スライドは窓いっぱいに出る。投票のあるステップでは板が自分で開き（読み上げで知らせ、フォーカスは動かさない）、そのステップを離れるとまたたたむ。**開いたままにする**（ピン）を押したときと、印から自分で開いたときはたたまない。教材全体の質問は、どのスライドでも印を押せば質問の欄が開く。**×** か Esc でたたむ
- **舞台の外：** 開いた板は右（縦長の画面では下）に出し、スライドは残りの場所に収める。板がスライドを隠すことはない（そのかわり、開いている間スライドは小さくなる）。スライド・字幕・印・動画のコマ・印刷は変わらない。投票はそのステップに来たときに出る。サーバーから来た字はすべて文字として出す
- **つなぎ直し：** ライブの時間の中でだけ、ライブのサーバーの表のとおりにつなぎ直す。通信が切れたときは間をあけて（1・2・4 … 30 秒、±20%）、ホストがライブを終えた（4423）ときはゆっくり（30 秒より後）、満員（4430）・送りすぎ（4429）の後は 60 秒より後、まだ早い（4425）ときは開始の時刻に。参加コードが変わった（4440）、ライブの時間が終わった・ライブがない（4410・4404）、参加コードが違う（4403）、同じ人がほかで参加した（4409）、ホストが参加を許可しなかった（4441。**もう一度試す** を出す）ときは、わけを見せて止まり、自分からはつなぎ直さない。待機室では、許可されるまで「待機室で待っています」と出す
- **大きさ：** 既定のサーバーのライブは、同時に 60 人まで、ライブの時間は 3 時間まで。編集アプリは 3 時間より長いライブの時間を断る
- **つなぐ先を絞る：** 写しには CSP（コンテンツ セキュリティ ポリシー）を入れ、`connect-src` はライブのサーバー（そのホストの `https://` と `wss://`）だけ。プレーヤーも、WebSocket の行き先が宣言した origin か確かめる。サーバーからは何も（スクリプト・スタイル・画像）読み込まない

教材そのものには参加コードのない設定だけを残す（`egatari.json` と Egatari ファイルの索引の `extensions.live`）。参加コードはエクスポートした写しにだけ入る。写しを持っていれば、ライブ中は誰でも参加できる。写しが広がったときは、ホストのページで **参加コードを変更** すると古い写しは参加できなくなる（わけを見せる）。コマンドでは `node kit/build.mjs <教材> --play-only --live room.json`（`room.json` はホストのページの「コピー」の設定。投票は `egatari.json` の `extensions.live`、なければ `room.json` から）。

**質問（下書き）：** 右下の小さな **?** から、どのスライドでも質問の欄を開ける。質問には、画面にあるステップ（欄にスライドとステップを出す）と、教材のこの版が結び付く。**囲む** でスライドの上をなぞって、聞きたいところを囲める（なくてもよい。Esc で終わり、ステップが変わると消える）。質問はホストだけが見る。名前を入れなければ名前なしで届く。**?** の横の **わからない** は、画面のステップに文なしの一押しを送る（もう一度押すと取り消す）。ホストにはステップごとの人数が届く。ホストはホストのページで似た質問をまとめ、短い返事を送れる。返事は質問した人にだけ届き、ホストが **参加者全員にも見せる** に印を付ければ全員に出る。返事は板の **ホストからの返事** に出る（ライブ中にファイルを開き直しても出る）。**参加者用（再生専用）…** のライブの設定に **わからない** の印がある（初めは入）。

**授業の前に通しで確かめる：** ライブの時間が今から始まるライブを作り、エクスポートし、2 台で写しを開いて参加し、質問と投票を送って、ホストのページに出ることを確かめる。配るときは、スマートフォンとタブレットのために参加用リンクも添える。ホストのページの **配るときの文** に、そのまま貼れる文がある。

**授業の後：結果を教材に残す（下書き）。** ライブが残っているうち（既定ではライブの時間が終わってから 24 時間）にホストのページで結果（JSON）をダウンロードし、**ファイル ▾ →「ファイルの情報…」** の添付の **ライブの結果を取り込む…** で取り込む。書く前にファイルを確かめる：ライブのサーバーの結果の形（[egatari/live](https://github.com/egatari/live) の Schema の写し）で、10 MiB までの UTF-8 の JSON で、添付の中身の検査（形式の §3.8）に通ること。ほかのものは理由を言って断る。結果のライブ ID がこの教材のライブの設定と違えば知らせるが、それでも取り込める（ライブを作り直したことがある）。役割 `data` の添付になり、名前は `attachments/live-<部屋>-<日付>.json`、題は「ライブの結果（<ライブ ID>、<日付>）」（ライブ ID と始まった日だけ。件数も参加者の字も入れない）、説明は参加者の質問と答えが入っていること。添付の一覧では「参加者の回答」の印と短い要約（質問の数と、投票ごとの数）を出す。中の字はすべて文字として出す。

結果には参加者が打った字（質問。名前を書いた人はその名前も）が入る。はじめて取り込むときに一度だけそう知らせる。結果は教材のファイルにだけ残り、どこにも送らない。Egatari ファイル（再生専用）には、ライブを付けても付けなくても **決して入らない**。結果が入る Egatari ファイル（.ega.html）をエクスポートするときは「Live の結果が入っています。人に渡すなら外してください」と知らせ、**結果を外してエクスポート** を選べる（作業フォルダの添付はそのまま）。コマンドでは `npm run portable -- attach <作業フォルダ> <results.json>`（英語の題は `--en`）で同じように足せる。`npm run portable -- pack <作業フォルダ>` と `node kit/build.mjs <deck> --portable` は同じ知らせを出し、`--without-live-results` で外す。
