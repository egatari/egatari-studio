# Security

## Trust model: a deck is code

Treat a deck folder like a source-code repository, not like a document. Build, check, render or serve only decks you trust.

- **Scripts run.** Inline `<script>` in `deck.html`, components (`components/<name>/index.js`, deck-local ones first) and component attribute expressions run in the browser that opens the built HTML, and in the headless Chrome used by `kit/check.mjs`, `tools/pdf.mjs`, `render/` and the tests (Playwright).
- **Build reads local files, inside the deck folder only.** `/*INCLUDE:…*/`, `{{JSON:…}}`, `{{FIG:…}}`, `narration.md`, `timeline.json`, `macros.tex`, `audio/manifest.json` and referenced assets (`<img src>`, `<link rel="stylesheet">`, CSS `url()`, …) are resolved relative to the deck folder (`INCLUDE` also searches `kit/`). Paths that leave the folder, through `../`, an absolute path or a symbolic link, are refused with a warning and nothing is read. Components (`components/<name>/index.js`) and theme files (`theme.json`, `tokens.css`, logos, and every theme reached through `extends`, at any depth) are checked by real path against their authorized root before they are read: the deck folder for deck-local ones, the repository's `components/` or `themes/` for registry ones. A deck-local theme can extend only themes in the deck folder or in `themes/`, so `extends` cannot leave through `../`, an absolute path or a link. A refused file is not read and the build warns (`refused: …`); a refused theme falls back to `themes/default`, a refused deck-local component is not replaced by the registry one. Links that stay inside the folder are followed for reads. What you name on the command line is trusted: the deck file itself, a `--theme`, an `-o` output path.
- **Build size is bounded.** Includes, embeds (`data:` URIs, stylesheets, scripts, `@import`) and formulas are counted while they are expanded, and the build stops with `build-too-large` as soon as a budget is exceeded (defaults: 10 000 includes and embeds, 64 Mi characters after preprocessing, 256 Mi after embedding, 500 000 tags before each parse, 20 000 formulas; `opts.limits` changes them). Every file the build reads — source, includes, embeds, theme files and logos through every `extends`, components, narration, audio, fonts, runtime — counts toward the same include count and one aggregate read budget (`readChars`, 256 Mi), charged from the file size before the file is read, so a 1 GiB logo, stylesheet, component or audio file is refused without being read; the logos and the whole output are size-checked before they are joined. The size is only an estimate: each read is also charged with the bytes actually read, and a file larger than its reported size is refused. Only regular files are read: on Node the build checks the path (`lstat`) and the opened descriptor (`fstat`), opens non-blocking and reads at most the allowed bytes from that descriptor, so a FIFO, device or socket in the deck folder is refused (`build-not-a-file`) instead of blocking the build. The portable export (`--portable`, `--play-only`, the editor's export) uses the same budget as its build for everything it reads itself (narration, copied sources, `voice.json`, `egatari.json`, audio before and after compression, segment metadata) and checks the archive chunks and the whole file, with every layer it inserts, before encoding and joining. In the editor app, the build and the classification of an opened deck run in a worker that is terminated after 60 s. The editor reads only the files a build actually references (never the rest of the folder), at most 8 at a time and within the same budget (checked from the folder listing before reading, from `File.size` again right before reading, and from the bytes read); messages are bound to the worker that sent them, so a reply from a stopped worker is dropped and never reaches its replacement, and reads still queued for a stopped worker are not started.
- **Build output is self-contained.** Local assets are embedded as data URIs. `http(s)` references are left as they are, and the build warns that the deck is then not fully offline.
- **The dev server is local-only.** `server/dev.mjs` listens on `127.0.0.1` only, accepts only `Host: 127.0.0.1:<port>` or `localhost:<port>` (against DNS rebinding), and writes (text edits, narration, comments) need JSON, a same-origin request (requests with `Origin: null` or a cross-site `Sec-Fetch-Site` are refused) and a per-run token. It writes only inside the deck folder (`deck.html`, `narration.md`, `comments.json`, `.cache/edits/`), through one helper (`kit/safe-fs.mjs`) that refuses when the file or any folder between the deck folder and it is a symbolic link (even one pointing inside, and dangling ones), checks that the real parent is inside the deck folder, and writes an exclusive temporary file in the same folder that is synced and renamed over the target. Backup cleanup deletes only regular files named like backups (`<time>-<name>`, the same rule as the editor app's cleanup), in a backup folder that is itself checked; other files in `.cache/edits/` are never deleted. It reads `narration.md`, `comments.json` and `deck.html` only if their real path is inside the deck folder, and watches the deck folder, `audio/`, `data/`, `figs/` and `components/` only if they are real folders inside it (a symbolic link is not watched, with a warning). The same helper is used by `npm run ids`, `npm run portable -- unpack` / `pack` and the build's `out/` and `egatari.json` writes. Not covered: the TTS and video tools (`tts/`, `render/`, tier 2) and `npm run new` write without these checks, and a race in which another local process swaps a folder for a link between the check and the write is not prevented (the threat is a link placed in a deck folder, not a concurrent process). Do not expose it to a network or put it behind a proxy.
- **TTS output.** `tts/synth.py` stops before writing `audio/`, `.cache/voices/` or the files in them through a symbolic link (since 0.2.2). It does not limit what it reads: `narration.md`, `voice.json` and a reference voice named by path in `voice.json` may be anywhere, by design.
- **While you edit, the deck cannot write.** In the dev server and in the editor app the deck (its inline scripts and components) runs in a sandboxed iframe with an opaque origin (`sandbox="allow-scripts allow-modals"`, no `allow-same-origin`) and a Content-Security-Policy with `connect-src 'none'` and every other resource limited to `data:` / `blob:` (the dev server also allows its own `/deck/audio/` for audio and frames only its exact preview endpoint `/preview`, which it serves only into its own frame page — with a capability issued with that page and `Sec-Fetch-Dest: iframe` — and never as a top-level document; every file it serves from the deck folder carries a CSP `sandbox` and is served as an inert download unless it is audio, video, an image or a font). The editor app puts that policy in a trusted prefix of the preview document, before any byte of the deck. The editing UI (`server/editor-ui.js`) runs outside the deck: in the dev server's frame page, which alone holds the per-run token, and in the editor app's own page, which alone holds the folder handles. The deck can only send hints (`server/hints.js`: which element or step to open, a note position, the keys `e` / `n` / `c` / Esc, its position); a hint carries no text to write. The editing UI reads the source itself, checks the range and hash against the current build, shows the text in its own card, and writes only when you press Save (or ⌘/Ctrl+Enter) there. The rights prompt and read-only modes of the editor app apply to those writes. `tools/hostile-deck.mjs` is a deck that tries to write in every way we know of; the dev-server and editor-app tests check that it changes nothing.
- **A deck's own code still runs in the preview.** It cannot write or reach the network, but it can show anything inside the preview. **Anything inside the slide area can be drawn by the deck; trust only controls in the editor's own panels.** All editing controls (edit-mode bar, source box, note box and list, narration drawer) are drawn outside the slide area, in a side panel under an orange marker bar (“Editing — app” / “Editing — dev server”); while you edit in a trusted field (source or note box open, typing in the narration drawer or unsaved narration), the preview is inert so it cannot catch your clicks, and hints from the deck do not switch the panels. A fake card drawn by the deck cannot save. Before the editor app runs a deck's own code, it says so and starts the preview (and the presenter view) only after you confirm. Whether a deck has code is decided from its content, never from the profile a portable file declares, and from the built document — the source after every include, including files of any extension, the same bytes that are then shown: scripts without a data type, `<meta http-equiv="refresh">`, event-handler attributes, `javascript:` URLs, `srcdoc`, embedded documents, included SVG or HTML with any of these, JavaScript files, and component formulas that are not plain arithmetic. A file declared “core” whose content has code is treated as having code, with a warning.
- **Opening a portable file allocates within limits.** Sizes are checked before allocation, the HTML is parsed with budgets for elements, attributes and nesting counted while parsing, and the editor app stops a read that takes longer than 30 s.
- **Registry names in portable files are identifiers.** `components[].name` and `themes[].name` of registry entries must match `^[a-z][a-z0-9-]{0,63}$` (format spec); the reader refuses others (`invalid-index`), and `npm run portable -- unpack` compares a registry component only through a contained regular-file read of `components/<name>/index.js` (a link out of `components/` counts as missing). A name such as `../../private` no longer reveals whether, or with which hash, a file outside the registry exists.
- **Classification parses as a browser with scripting on.** `<noscript>` (also `<noembed>`, `<noframes>`, `<iframe>` text) is raw text and ends at the first closing tag, so markup that a scripting-disabled parser would read as an attribute value cannot hide a script that runs. The build's boundary search, the portable reader and tier-A edits use the same mode.
- **Links in folders opened in the editor app.** The memory and OPFS workspaces cannot contain links. For a folder picked with the File System Access API, Chromium (tested with 155 on macOS) does not list links inside the folder, cannot open them by name and cannot write through them (`tools/test-security.mjs` checks this); the API offers no way for the app to detect links itself, so this relies on the browser.
- **Saves stay with their deck.** The editor app rechecks after every wait that the deck a save started on is still open, aborts the file write otherwise, and marks a deck saved only if no edit happened during the save.
- **TTS and video** (tier 2) send narration text to the TTS server in `IRODORI_URL` (default `http://localhost:8882`). Point it only at a server you run or trust.

`comments.json`, `.cache/`, `.env*` and `*.local.json` are gitignored so that review notes, edit history and local settings are not published by accident.

## Reporting a vulnerability

Please report security issues privately through GitHub's **Report a vulnerability** button (Security → Advisories) on <https://github.com/moiku/motion-academic-slides>, rather than in a public issue. Include the affected file or command, a minimal deck that reproduces it, and the impact. You should get a reply within two weeks. There is no bug bounty.
