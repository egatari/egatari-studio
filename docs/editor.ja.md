# 編集アプリ（インストール不要）

[English](editor.md) | 日本語

デッキのフォルダを直接開き、[開発サーバー](dev-server.ja.md)と同じこと（プレビュー、スライドの上での原稿・口述原稿の編集、Claude への指示）をするウェブページ。[持ち運べる 1 ファイル](reference.ja.md#持ち運べる-1-ファイル--portable)（原稿も中に持つ 1 つの HTML。[持ち運べるデッキの形式](https://github.com/egatari/egatari-spec)に従う）も、フォルダなしで開き、メモリの上で直して保存し直せる。インストールもターミナルも要らない。

- **ブラウザ：** パソコンの Google Chrome か Microsoft Edge（Windows・macOS・Linux・ChromeOS）。フォルダは File System Access API（`showDirectoryPicker`）を使うので、Safari と Firefox では開けない（最初の画面にそう出る）。持ち運べる 1 ファイルは今のどのブラウザでも開いて直せる（ファイルを選ぶ画面がなければ、保存はダウンロードになる）
- **通信：** アプリ自身の読み込みのほかは無い。デッキのフォルダやファイルはブラウザの中で読み書きし、どこにも送らない

## アプリの入手

| 形 | 開き方 | 備考 |
|---|---|---|
| 配信 | <https://moiku.github.io/motion-academic-slides/editor/> | `main` から `.github/workflows/pages.yml` で公開する。字はデッキが使う分だけ読む |
| 1 ファイル | `npm run build:app` のあと `dist/editor.html` をダブルクリック | 約 10 MB（字を全部入れてある）。Chrome・Edge なら `file://` で動く。このファイルを人に渡してもよい |
| 自分のサーバー | `npm run build:app` のあと `dist/editor/` を静的に配る | どこでもよい（https か `http://localhost`） |

`npm run build:app`（`node tools/build-app.mjs [--out dist] [--no-single]`）は先に `npm ci` が要る（版を固定した開発用の依存 esbuild を使う）。

## 使い方

1. **デッキを開く。** デッキのフォルダ（`deck.html` の入ったフォルダ。`deck.html` がなければフォルダの最上位の最初の `.html`）を画面に落とすか、「フォルダを開く」を押す。そのフォルダを編集してよいか、ブラウザが 1 回たずねる
   - **新しいデッキ**：`npm run new` と同じ雛形から `deck.html` と `narration.md` を作る（タイトル・言語・テーマ）。空のフォルダを選べばそこに、空でなければ中にタイトルの名前のフォルダを作る
   - **最近開いたフォルダ**：最初の画面に並ぶ（ブラウザがフォルダのハンドルを IndexedDB に残す。中身は残さない）。開き直すとき、ブラウザがもう一度許可を求める
2. **直す。** キーは開発サーバーと同じ（道具の列にもボタンがある）

   | キー | すること |
   |---|---|
   | `e` | 編集モード。枠の出た要素を**ダブルクリック**すると原稿（HTML と `\( … \)` の式）が開く。⌘/Ctrl+Enter で保存 |
   | `n` | 表示中の段階の口述原稿の引き出し（話者、発言の追加・削除・並べ替え） |
   | Alt+クリック（Mac は ⌥ option+クリック） | その要素について Claude への指示を残す（`comments.json`） |
   | `c` | 未対応の指示の一覧。クリックでそのスライドへ、「解決」で対応済み |

   原稿の欄・口述原稿の引き出し（右。プレビューはその横に縮む）・コメントの欄と一覧は、デッキではなく編集アプリのページの一部。プレビューはダブルクリックや Alt+クリックの場所を知らせるだけで、原稿を読み・見せ・「保存」（か ⌘/Ctrl+Enter）を押したときに書くのは編集アプリ。キーはプレビューの上でも編集アプリの上でも効く

   開発サーバーと同じく、プレビューを組んだ後にファイルが変わっていれば（原稿の hash・口述原稿の版が合わなければ）保存しない。読み込み直してからもう一度
3. **Claude Code と一緒に。** Claude Code（やほかのエディタ）がフォルダを変える間も開いたままでよい。約 1.5 秒ごとにファイルを見て、変わったら組み直し、同じスライド・段階のままプレビューを読み込み直す。原稿の欄や口述原稿の引き出しで入力中のものは、プレビューを読み込み直しても残る（編集アプリのページにある）。その間に同じ要素や段階が変わっていれば、保存は断る。組み立てに失敗したら、直るまでプレビューの上にエラーを出す
4. **発表する・渡す。** 道具の列から
   - **簡易チェック**：`npm run check` の一部をプレビューの中で行う（はみ出し・文字の大きさ・タイトルと結論の字数・口述原稿の抜け・パレットのコントラスト）。結果をクリックでそのスライドへ。目安であって全部の検査ではない：部品の再現性・タイムライン・モーフ・読み上げは見ない。画面の大きさが違うので、数値がコマンドの検査とわずかに違うことがある
   - **HTML を書き出す**：編集の仕掛けを除いて組み、1 つの HTML に保存する（保存先をたずねる）。ダブルクリックでどこでも発表できる
   - **印刷 / PDF**：デッキをブラウザの印刷にかける（`tools/pdf.mjs` と同じく、各スライドの最終状態を 1 ページずつ。「PDF に保存」を選び、「背景のグラフィック」を入れる）
   - **発表者ビュー**（デッキの `p` でも）：今の画面・次の段階・口述原稿（カンペ）・経過時間・描く道具の窓。編集アプリの窓のプレビューを操作する
   - **全画面**：プレビューを画面いっぱいにする（投影用）

## 持ち運べる 1 ファイル（フォルダなし）

持ち運べる 1 ファイルは、`npm run build -- <deck.html> --portable`（または編集アプリの「1 ファイル（持ち運べる形）を書き出す」）が書くもの。組んだデッキと同じように再生でき、デッキの原稿と音声を中に持つので、元のフォルダがなくても編集アプリで直せる。

- **開く。** 「ファイルを開く…」（最初の画面か道具の列）を押すか、ファイルを最初の画面に落とす。編集アプリはファイルをバイト列として読み、スクリプトを動かさない HTML の解析器で、Web Worker の中で取り出す。ファイルそのものをページとして読み込むことはないので、取り出しの間に中のものは何も動かない。形式のハッシュ・大きさの上限・パスの規則を先にすべて確かめる（`npm run portable -- unpack` と同じ）。原稿はメモリの上（メモリの上のフォルダ）に置き、プレビュー・編集の道具・簡易チェックはフォルダのときと同じように動く。フォルダがないので、外での変更は見張らない
- **保存。** 「保存」は、ブラウザが書き込めるハンドルをくれたとき（Chrome / Edge の「ファイルを開く…」かドラッグ＆ドロップ。初めは許可をたずねることがある）は同じファイルに書き直す。そうでなければ保存先をたずね、保存の画面がなければ（Safari・Firefox）ダウンロードする。「名前を付けて保存…」はいつも保存先をたずねる。保存するファイルは、直した原稿から編集アプリに同梱の kit・部品・テーマで組み直すので、プレビューとまったく同じに再生する。文書の識別子（`docId`）、ライセンス・著作権・クレジット・作り手、索引の知らない項目と拡張のデータは残し、音声はバイトのまま写す。ファイル名の前の ● は保存していない変更の印。ページを離れるときや別のファイルを開くときは先にたずねる
- **古い音声。** 段階の口述原稿を直しても、その音声には触れない。その段階は警告に「音声が古い」と出る（保存したファイルでも、音声の記録は前の口述原稿の hash のまま）。音声を作り直すには、フォルダに書き出してコマンドで TTS を
- **「フォルダに書き出す…」** は、選んだ空のフォルダに原稿・音声・`audio/manifest.json` を書く（`npm run portable -- unpack` と同じファイル）。空でないフォルダは断る。書き出したフォルダは、ふつうのデッキのフォルダとして開け、組め、まとめられる
- **「1 ファイル（持ち運べる形）を書き出す」**（フォルダを開いているとき）は、フォルダを持ち運べる 1 ファイルにする。初回は教材の識別子をフォルダの設定のファイルに書き、次からの書き出しでも同じものを使う
- **ファイルに入らないもの：** Claude への指示（コメント）と `.cache/edits/` の控えはメモリの上にだけ残る（コメントは見直しの覚え書きなので、形式が外す）

### 権利の確認

開いたファイルを最初に編集する前に（編集モードや口述原稿の引き出しで最初に保存するとき、または「編集」「口述原稿」を押したとき）、ファイルに書かれた題名・作り手・著作権・ライセンス・クレジットの表示を見せる（どれも申告で、確かめたものではない）。改変を認めないライセンス（Creative Commons の `-ND`、All rights reserved）か、ライセンスがなく著作権の表示だけのときは、改変や改変したものの配布が権利者の著作権を侵すおそれがあると知らせ、確認のチェックを入れるまで編集を始めない。取消ならファイルは変わらない。保存で著作権・クレジット・作り手を消すことはない。

### 断るファイル・読むだけで開くファイル

- **理由を見せて断る：** 持ち運べる 1 ファイルでないもの・再生専用のもの、ハッシュが合わないもの・一部が欠けたもの、許されないパス（`../` など）、索引の同じ名前の項目、設定のファイルと食い違う文書の識別子、実装していない必須の機能、新しい原稿の書き方の版
- **新しい major の版：** 編集のためには開かず、知っている版の規則で確かめたうえで原稿を取り出す「フォルダに書き出す…」を申し出る
- **読むだけ：** 実行系の約束の版が違うもの、部品庫・テーマ庫の部品の hash が編集アプリのものと違う（または編集アプリにない）もの。デッキは表示し、保存は断り、「フォルダに書き出す…」はできる
- **独自のコード：** 自前のスクリプトや部品を持つファイル（「extended」のもの）は、その中のものが動く前に知らせてたずね、「プレビューを始める」を押してからプレビューを始める（取消ならファイルは開かない）。開いている間は上に知らせを出す：コードはプレビューの中だけで、外へ繋がらずに動き、ファイルを書き換えられない。部品（`components/…`、どれかの `.js`）や `deck.html` のスクリプトを持つフォルダも、開くたびに 1 回同じことをたずねる（あとからそういうコードが現れたときも）

## 書き換えるファイル

開発サーバーとまったく同じ（[dev-server.ja.md](dev-server.ja.md) の「書き換えるファイル」）。どれも選んだフォルダの中

- `deck.html`：編集した要素の中身だけ
- `narration.md`：編集した段階の行だけ（注釈やほかの行はそのまま）
- `comments.json`：Claude への指示 `[{id, created, key, range, quote, comment, status}]`
- `.cache/edits/`：書き換える前の `deck.html`・`narration.md`（新しい 30 個）
- 「新しいデッキ」では `deck.html` と `narration.md`、「HTML を書き出す」「1 ファイル（持ち運べる形）を書き出す」では選んだファイル（と、初回はフォルダの設定のファイルの教材の識別子）
- 持ち運べる 1 ファイルを開いたとき：保存するまで何も書かない（直したものはメモリの上）。保存では選んだファイルだけ、「フォルダに書き出す…」では選んだ空のフォルダのファイルだけ

## できないこと

- **Chrome・Edge だけ。** スマートフォンのブラウザもフォルダを開けない
- **コマンドで行うもの：** 読み上げ音声（TTS）・動画・教材バンドル（`tts/` `render/`）、全部の検査（`npm run check`）、`tools/pdf.mjs`。フォルダの音声（`audio/`）は読まない：自動再生は音声がないときと同じ既定の秒数
- **書き出しが大きい。** コマンドの build は fonttools で和文の字を絞り込める（`node tools/get-fonts.mjs`）が、ブラウザではできないので、使う字を含む分割ファイルをそのまま埋め込む（TTF がないときのコマンドと同じ）。`examples/minimal` は編集アプリで約 2.0 MB、絞り込んだ `npm run build` で 0.7 MB。見た目は同じ
- **同梱のもの。** リポジトリの部品（`components/`）・テーマ（`themes/`）・実行系（`kit/`）は、アプリを組んだときのもの。デッキのフォルダの中の部品とテーマ（`components/<名前>/index.js`、`themes/<名前>/`）は、いつもどおりフォルダから読む
- **読まないもの：** `.` で始まる名前と、`out/` `audio/` `video/` `bundle/` `node_modules/` のフォルダ（3000 ファイル・10 階層まで）。`audio/` は持ち運べる 1 ファイルに書き出すときだけ読む
- **持ち運べる 1 ファイルは保存で組み直す。** 変えた口述原稿と音声だけをその場で差し替えることはまだせず、同梱の kit でファイル全体を組み直す（なので、古い・新しい build で作ったファイルは直した所の外も変わり、字は分割ファイルごと埋め込む）。前後で全スライドを比べることもまだしない
- **デッキの中からの通信は止まる。** 外部の画像やスクリプト（`https://…`）はプレビューに出ない（build はもともと警告する）

## 仕組みと安全

- **組み立ては 1 つ。** `kit/core/build-core.mjs` が組み立ての本体（注記・取り込み・KaTeX・部品・口述原稿・注目の演出・秒数・テーマ・ファイルの埋め込み・字）で、Node に依存せず、渡された口を通してだけファイルを読む。`kit/build.mjs` は Node のファイル（と fonttools の絞り込み・ffmpeg）を、編集アプリは選んだフォルダと同梱の kit・部品・テーマ・KaTeX・字を渡す。字の絞り込みを切れば、両方が 1 バイトも違わない HTML を出す（`tools/test-app.mjs` が `examples/minimal` と `examples/tmlr2026-calibration` で確かめる）。口述原稿の解析と書き換え（`kit/core/narration-core.mjs`）と新しいデッキの雛形（`kit/templates/new-deck.mjs`）も同じく共有する
- **編集の画面も 1 つで、デッキの外にある。** `server/editor-ui.js`（原稿の欄・口述原稿の引き出し・コメントの欄と一覧）は、ここでは編集アプリのページで、開発サーバーでは外枠のページで動く。どちらも同じ問い合わせ（`/__dev/source` `/__dev/edit` `/__dev/narration` `/__dev/comment` …）を送り、開発サーバーは HTTP で、編集アプリはページの中で開いたフォルダについて答える（`app/devapi.js`）。デッキの中にあるのは知らせを送る `server/hints.js` だけ（下）
- **デッキは砂場の中で動き、書き込めない。** プレビューは `allow-same-origin` を付けない `<iframe sandbox="allow-scripts allow-modals">` なので、デッキは origin を持たない。編集アプリの画面・保存領域・フォルダのハンドルに届かない。`allow-modals` は印刷のため。ページの Content-Security-Policy（アプリ自身の読み込みだけを許す）に重ねて、プレビューの文書には、どのスクリプトよりも前に別の決まりを入れる：`connect-src 'none'`、画像・字・スタイル・音声は `data:` / `blob:` だけ（組み立てが埋め込む）、Worker・フォーム・`<base>` は使えない（部品が `new Function` で式を作る（`m-sweep f="…"` など）ので `'unsafe-eval'` は残す）。発表者ビューは編集アプリが開く窓で、その中のデッキもまた同じ決まりの砂場の iframe。やり取りは編集アプリが中継する
- **頼みではなく知らせ。** プレビューには書き込みを頼む口がない。送れるのは知らせだけ：「この `data-src` の範囲と hash の要素を直したい」（編集モードでダブルクリック）、「この要素にコメントしたい」（Alt+クリック。スライドと段階の鍵と、要素の短い引用）、鍵の `e`・`n`・`c`・Esc、今の位置（`deck-pos`）。知らせは書き込む本文を持たない。編集アプリは送り元の窓と知らせの形を確かめ、編集モードでないときの edit の知らせは無視し、今の原稿を自分で読み、範囲が今の組み立ての直せる要素で hash が合うことを確かめて、自分の欄を見せる。書くのは、その欄や引き出しで「保存」か ⌘/Ctrl+Enter を押したときだけ。権利の確認と読むだけのファイルは、これまでどおりこの書き込みにかかる。編集アプリからプレビューに送るのは、見せるのに要るものだけ（編集モードの入り切り・印を付ける要素・「その段階へ」・印刷・簡易チェック）
- **触るのは選んだフォルダかファイルだけ**で、ブラウザの許可を得てから
- **持ち運べる 1 ファイルを開いても、その中のものは何も動かない。** ファイルはバイト列として読み、スクリプトを無効にして Web Worker（編集アプリに同梱。ページの決まりは `blob:` の Worker だけを許す）の中で解析する。そのファイルへ移動したり、ページに入れたりはしない。動くのは原稿から組み直したデッキだけで、フォルダのときと同じ砂場のプレビューの中

## GitHub Pages で配る

`.github/workflows/pages.yml` が `node tools/build-app.mjs --out _site` で組み、GitHub Pages に置く（編集アプリは `/editor/`、1 ファイル版は `/editor.html`）。Pages を設定するまでは何もしない

1. Settings → Pages → Build and deployment → Source を **GitHub Actions** にする
2. Settings → Secrets and variables → Actions → Variables に `EDITOR_PAGES` = `true` を足す（なければ push で置く手順を飛ばすので、Pages を有効にする前に失敗しない）
3. 1 回走らせる（Actions → pages → Run workflow）か、`main` に push する

## 確かめ方

`node tools/test-app.mjs [作業用のフォルダ] [--shots 画像のフォルダ]`（`npm test` に入っている）は、作業用のフォルダに編集アプリを組んで 127.0.0.1 で配り、ブラウザの OPFS（origin-private file system）にデッキのフォルダを作って `window.__APP_TEST_OPEN(handle)` で開く。同じ HTML になること・原稿の編集（その間にファイルが変わったときの 409 も）・口述原稿の引き出し（発言を足す・CRLF のまま・409）・指示・外での変更・組み立ての失敗・簡易チェック・書き出し・発表者ビュー・英語の画面・`file://` の 1 ファイル版と、コンソールのエラーが無いことを確かめる。書き込みを試みるデッキのフォルダ（`tools/hostile-deck.mjs`：古い書き込みの知らせと偽の本文の知らせを送り、合言葉を探し、編集アプリのページに触り、書き込みの口に `fetch`・XHR・beacon する部品とインラインのスクリプト）は、動く前にたずね、フォルダの中を何も変えず、編集アプリで「保存」を押したときだけ書かれることを確かめる。持ち運べる 1 ファイルは、`examples/minimal`（dry-run の音声つき）と `tools/portable-fixtures.mjs` の試験用の文書から作り、開く・権利の確認（改変を認めないライセンスの確認も）・文字と口述原稿の編集・OPFS のファイルのハンドルへの保存・開き直し（同じ `docId`、変えていない音声の hash が同じ、展開したフォルダがメモリの上のものと同じ）・「フォルダに書き出す…」と「1 ファイルを書き出す」（同じバイト）・独自のコードの知らせ・印のスクリプトが編集アプリのページでも読み取りの Worker でも動かないこと・断るファイル（パスの抜け出し・新しい major の版・索引の重複・知らない必須の機能）・読むだけのファイル・ダウンロードでの保存を確かめる。`node tools/test-workspace.mjs` は、メモリの上のフォルダと権利の規則をブラウザなしで確かめる。

## 画面の言葉

ふだんはブラウザの言語（日本語か英語）に合わせる。右上の **English / 日本語** のボタンで切り替えるか、`…/editor/?lang=en`・`?lang=ja` で開く。選んだ言葉は覚えておき、デッキを開いたまま切り替えても同じフォルダを開き直す（開いた持ち運べる 1 ファイルは閉じる。保存していない変更があれば先にたずねる）。編集の道具（編集モード・原稿の欄・口述原稿の引き出し・コメント）は編集アプリの言葉に合わせる（開発サーバーではデッキの言語 `<html lang>` に合わせる）。
