# Security

## Trust model: a deck is code

Treat a deck folder like a source-code repository, not like a document. Build, check, render or serve only decks you trust.

- **Scripts run.** Inline `<script>` in `deck.html`, components (`components/<name>/index.js`, deck-local ones first) and component attribute expressions run in the browser that opens the built HTML, and in the headless Chrome used by `kit/check.mjs`, `tools/pdf.mjs`, `render/` and the tests (Playwright).
- **Build reads local files, inside the deck folder only.** `/*INCLUDE:…*/`, `{{JSON:…}}`, `{{FIG:…}}`, `narration.md`, `timeline.json`, `macros.tex`, `audio/manifest.json` and referenced assets (`<img src>`, `<link rel="stylesheet">`, CSS `url()`, …) are resolved relative to the deck folder (`INCLUDE` also searches `kit/`). Paths that leave the folder, through `../`, an absolute path or a symbolic link, are refused with a warning and nothing is read. A deck's `<html data-theme>` may only name a theme in the deck folder or in `themes/` (a `--theme` given on the command line is trusted).
- **Build output is self-contained.** Local assets are embedded as data URIs. `http(s)` references are left as they are, and the build warns that the deck is then not fully offline.
- **The dev server is local-only.** `server/dev.mjs` listens on `127.0.0.1` only, accepts only `Host: 127.0.0.1:<port>` or `localhost:<port>` (against DNS rebinding), and writes (text edits, narration, comments) need JSON, a same-origin request (requests with `Origin: null` or a cross-site `Sec-Fetch-Site` are refused) and a per-run token. It writes only inside the deck folder (`deck.html`, `narration.md`, `comments.json`, `.cache/`). Do not expose it to a network or put it behind a proxy.
- **While you edit, the deck cannot write.** In the dev server and in the editor app the deck (its inline scripts and components) runs in a sandboxed iframe with an opaque origin (`sandbox="allow-scripts allow-modals"`, no `allow-same-origin`) and a Content-Security-Policy with `connect-src 'none'` and every other resource limited to `data:` / `blob:` (the dev server also allows its own `/deck/audio/` for audio and frames only its exact preview endpoint `/preview`; every file it serves from the deck folder carries a CSP `sandbox` and is served as an inert download unless it is audio, video, an image or a font). The editor app puts that policy in a trusted prefix of the preview document, before any byte of the deck. The editing UI (`server/editor-ui.js`) runs outside the deck: in the dev server's frame page, which alone holds the per-run token, and in the editor app's own page, which alone holds the folder handles. The deck can only send hints (`server/hints.js`: which element or step to open, a note position, the keys `e` / `n` / `c` / Esc, its position); a hint carries no text to write. The editing UI reads the source itself, checks the range and hash against the current build, shows the text in its own card, and writes only when you press Save (or ⌘/Ctrl+Enter) there. The rights prompt and read-only modes of the editor app apply to those writes. `tools/hostile-deck.mjs` is a deck that tries to write in every way we know of; the dev-server and editor-app tests check that it changes nothing.
- **A deck's own code still runs in the preview.** It cannot write or reach the network, but it can show anything inside the preview. **Anything inside the slide area can be drawn by the deck; trust only controls in the editor's own panels.** All editing controls (edit-mode bar, source box, note box and list, narration drawer) are drawn outside the slide area, in a side panel under an orange marker bar (“Editing — app” / “Editing — dev server”); while a source or note box is open, the preview is inert so it cannot catch your clicks. A fake card drawn by the deck cannot save. Before the editor app runs a deck's own code, it says so and starts the preview (and the presenter view) only after you confirm. Whether a deck has code is decided from its content, never from the profile a portable file declares: scripts without a data type, event-handler attributes, `javascript:` URLs, `srcdoc`, embedded documents, included SVG or HTML with any of these, JavaScript files, and component formulas that are not plain arithmetic. A file declared “core” whose content has code is treated as having code, with a warning.
- **TTS and video** (tier 2) send narration text to the TTS server in `IRODORI_URL` (default `http://localhost:8882`). Point it only at a server you run or trust.

`comments.json`, `.cache/`, `.env*` and `*.local.json` are gitignored so that review notes, edit history and local settings are not published by accident.

## Reporting a vulnerability

Please report security issues privately through GitHub's **Report a vulnerability** button (Security → Advisories) on <https://github.com/moiku/motion-academic-slides>, rather than in a public issue. Include the affected file or command, a minimal deck that reproduces it, and the impact. You should get a reply within two weeks. There is no bug bounty.
