# 編集アプリ（インストール不要）

[English](editor.md) | 日本語

作業フォルダを直接開き、[開発サーバー](dev-server.ja.md)と同じこと（プレビュー、スライドの上での原稿・台本の編集、コメント）をするウェブページ。[Egatari ファイル（`.ega.html`）](reference.ja.md#1-ファイル--portable)（原稿も中に持つ 1 つの HTML。[Egatari の形式](https://github.com/egatari/egatari-spec)に従う）も、フォルダなしで開き、メモリの上で直して保存し直せる。インストールもターミナルも要らない。最初の画面は Egatari ファイルを先に置く（「ファイルを開く（.ega.html）…」「新規作成…」。作業フォルダは「フォルダで作業する…」）。

| 形 | 中身 | ここで |
|---|---|---|
| 作業フォルダ | `deck.html`・`narration.md`・`audio/` … の入ったフォルダ。コマンド・AI のコーディング道具（Claude Code・Codex・Gemini CLI など）・ほかのエディタが読み書きする | 「フォルダで作業する…」（Chrome / Edge）で直す |
| Egatari ファイル（`.ega.html`） | 原稿と音声を中に持つ 1 つの HTML（`--portable`）。ブラウザで開けば再生 | 「開く…」で直す（どのブラウザでも） |
| 再生専用（`--play-only`） | 原稿を持たない Egatari ファイル | 直せない（元の Egatari ファイルか作業フォルダを開く） |
| 組み立てた HTML（`out/deck.html`） | コマンド（`node kit/build.mjs`）の発表用の出力（編集アプリからはエクスポートしない） | 直せない（作業フォルダを開く） |

- **ブラウザ：** パソコンの Google Chrome か Microsoft Edge（Windows・macOS・Linux・ChromeOS）。フォルダは File System Access API（`showDirectoryPicker`）を使うので、Safari と Firefox では開けない（最初の画面にそう出て、そこで新しく作る道として「新規作成… → チャットの AI に書いてもらう」を示す）。Egatari ファイルは今のどのブラウザでも開いて直せる（ファイルを選ぶ画面がなければ、保存はダウンロードになり、保存のたびにダウンロードに新しいファイルができる。最初の画面と保存の知らせにそう出る：次はいちばん新しいものを開く）
- **通信：** アプリ自身の読み込みのほかは無い。作業フォルダやファイルはブラウザの中で読み書きし、どこにも送らない。「AI 音声をこの PC で作る」（[音声の板](#台本の音声音声の板)）を使うときだけ、編集アプリのサイトの別の TTS の窓がモデルを取る（編集アプリのページそのものは、そのときもどこにも繋がらない）

## アプリの入手

| 形 | 開き方 | 備考 |
|---|---|---|
| 配信 | <https://studio.egatari.org/> | `main` から `.github/workflows/pages.yml` で公開する。字は教材が使う分だけ読む。前の場所 `…/editor/` からはここへ移る |
| オフライン版のエディタ（`editor.html`） | `npm run build:app` のあと `dist/editor.html` をダブルクリック | 約 10 MB（字を全部入れてある）。Chrome・Edge なら `file://` で動く。このファイルを人に渡してもよい |
| 自分のサーバー | `npm run build:app` のあと `dist/` を静的に配る | どこでもよい（https か `http://localhost`）。サイトの根でも、下のパスでもよい |

`npm run build:app`（`node tools/build-app.mjs [--out dist] [--no-single]`）は先に `npm ci` が要る（版を固定した開発用の依存 esbuild を使う）。

## 使い方

1. **教材を開く。** Egatari ファイルは最初の画面の「ファイルを開く（.ega.html）…」か **ファイル ▾ →「開く…」**（[下](#egatari-ファイルフォルダなし)）。作業フォルダ（`deck.html` の入ったフォルダ。`deck.html` がなければフォルダの最上位の最初の `.html`）は画面に落とすか、「フォルダで作業する…」（最初の画面か **ファイル ▾**）を押す。そのフォルダを編集してよいか、ブラウザが 1 回たずねる
   - **最初の画面**は上から：**新規作成…**（主のボタン。チャットの AI に教材を書いてもらう。[下](#チャットの-ai-で下書きする貼り付けと修正依頼)）、**ファイルを開く（.ega.html）…** と落とす場所、**最近のファイル**、**サンプル**、小さく **Claude Code・Cowork で作る（上級）**（行き先は `app/main.js` の `WITH_CLAUDE_URL` の 1 か所。説明のページは未定）、**フォルダで作業する…**。4 つのファイルの種類の表は使い方（**?**）にある。新しい作業フォルダはコマンドの `npm run new` で作る
   - **最近のファイル**：作業フォルダと Egatari ファイルが最初の画面に並ぶ（ブラウザがハンドルを IndexedDB に残す。中身は残さない）。開き直すとき、ブラウザがもう一度許可を求める（Egatari ファイルは読む許可だけ。書く許可は「保存」のときに求める）。Egatari ファイルが並ぶのは、ブラウザがファイルのハンドルをくれたとき（Chrome / Edge の「ファイルを開く（.ega.html）…」かドラッグ＆ドロップ）だけで、Safari・Firefox では並ばない
   - **サンプル**（配信版だけ）：このリポジトリのサンプルを Egatari ファイルにしたもの（`examples/minimal`・`pitch-fictional`・`kokugo-kanbun`・`tmlr2026-calibration`。音声なし）が最初の画面に並ぶ。「開く」は同じサイトからファイル（`examples/<名前>.ega.html`）を読み、選んだファイルとまったく同じように開く（取り込みの確かめも同じ。`tmlr2026-calibration` は独自のパーツがあるので動かす前に確かめ、最初の編集の前に編集の確認を出す）。オフライン版のエディタ（`file://` の `editor.html`）には出ない
2. **直す。** キーは開発サーバーと同じ（道具の列にもボタンがある。右の板の見出しになるまでは、仮の群 **編集 (e)**・**台本 (n)**・**コメント (c)**・**音声**）

   | キー | すること |
   |---|---|
   | `e` | 編集モード。枠の出た要素を**ダブルクリック**すると原稿（HTML と `\( … \)` の式）が開く。⌘/Ctrl+Enter で保存 |
   | `l` | 先のステップを薄く見せる（入／切。字幕と同じ選び）：全部のステップを見せ、まだ来ていないステップを薄くする（`--preview-opacity`、既定 0.45）。今のステップに印は付けない。`data-preview="none"` を付けた答えは隠したまま。`?mode=talk&preview=1` と同じ |
   | `n` | 表示中のステップの台本の引き出し（話者、発言の追加・削除・並べ替え） |
   | Alt+クリック（Mac は ⌥ option+クリック） | その要素について コメントを残す（`comments.json`）。押した点もピンとして残る |
   | `m`（編集モードの帯の「マーカー（m）」のボタン、編集中は「マーカー」（キーは m）になるスライドのツールバーのペンのボタンでも。`d` でも開く） | マーカー（編集モードの間だけ）：スライドに丸や矢印を描く。描き終えるとその印についてコメントの欄が横の板に開く。欄が開いている間は続けて描け（矢印と丸、いくつもの印。20 本まで）、どの線も同じコメントの印になる。「残す」で全部の印をコメントと一緒に残し（`strokes`）、「キャンセル」で全部捨てる |
   | `c` | 未対応のコメントの一覧（番号付き）。開いている間、画面のステップのピンがスライドの上に出る。クリックでそのスライドとステップへ（ピンが光る）、「解決」で対応済み |

   編集モードの帯・原稿の欄・台本の引き出し・コメントの欄と一覧は、どれも右の 1 つの板（プレビューはその横に縮む）にあり、板の上には橙の帯 **編集中 — アプリ** が付く。どれも教材ではなく編集アプリのページの一部。**スライドの場所に見えるものは教材が描けるもの。信じてよいのはエディタ自身の板の道具だけ。** 原稿の欄・コメントの欄を開いている間、プレビューはクリックを受けない。プレビューはダブルクリックや Alt+クリックの場所を知らせるだけで、原稿を読み・見せ・「保存」（か ⌘/Ctrl+Enter）を押したときに書くのは編集アプリ。キーはプレビューの上でも編集アプリの上でも効く

   **編集モードと発表の道具は同時に使わない。** 編集モードに入ると、レーザーポインター・ペン・消えるペンを切り（書いた線は見えたまま残り、その上には描けない）、自動再生と音声を止め、スライド一覧・黒い画面・キーの一覧（?）・全画面・打ちかけのページ番号を閉じる。授業と字幕はそのまま。編集している間は、ツールバーの道具のボタン（自動再生・レーザーポインター・消えるペン・色・消す・一覧・全画面）を隠し、そのキー（`x` `v` Shift+`d` Backspace `o` `a` `b` `f`）は効かない。ペンのボタンだけは同じ絵のまま **マーカー** という名前で残り、そのボタンとペンのキー `d` は、ペンの代わりにマーカーを入り切りする（上の表）。発表者ビューで道具を選んでも切れる。編集モードを出ても、どれも元には戻さない。入力欄（原稿の欄や教材の中の入力欄）で打ったキーは、いつも字として入り、道具やスライドの操作にはならない。今のモードは下の帯の右端に出し（**編集中**・**発表の道具：ペン**・**表示**）、読み上げソフトにも知らせる。スライドには重ねない

   開発サーバーと同じく、プレビューを組んだ後にファイルが変わっていれば（原稿の hash・台本の版が合わなければ）保存しない。読み込み直してからもう一度

   **Esc** で、開いている窓を上のものから 1 つずつ閉じる：書いている途中の原稿の欄・コメントの欄、次に音声の板・[録音モード](#録音モードキーボードだけで録る)・台本の引き出し・コメントの一覧・横の板（品質チェック・ファイルの情報・使い方）のうち後に開いたもの。**Shift+Esc** で全部を閉じる。台本の引き出しに保存していない入力があれば先に聞く。確かめの窓と一覧は、これまでどおり Esc で閉じる

   **保存の場所。** 下の帯の左端に、今どこに保存されているかをいつも出す（札の説明に詳しく）。作業フォルダは「作業フォルダ「…」に保存済み」：各欄の「保存」と録音・取り込み・TTS がその場でフォルダに書くので、**ファイル ▾ →「保存」** は押してもわけを言うだけ。Egatari ファイルにするには **ファイル ▾ →「名前を付けて保存…」**（編集可・`.ega.html`）。Egatari ファイルは「「…」に保存済み」（「保存」で上書き）、ブラウザが上書きできないときは「「…」を開いています（保存はダウンロードに）」（「保存」のたびに新しいファイルがダウンロードされる）、メモリの上にだけ変更があるときは **保存していない変更があります**（タブを閉じると録音も含めて消える）、メモリの上にだけある教材（チャットの AI の出力を貼り付けた・スライドのファイルだけを開いた）は **まだファイルに保存していません**
3. **AI のコーディング道具と一緒に。** AI のコーディング道具（やほかのエディタ）がフォルダを変える間も開いたままでよい。約 1.5 秒ごとにファイルを見て、変わったら組み直し、同じスライド・ステップのままプレビューを読み込み直す。原稿の欄や台本の引き出しで入力中のものは、プレビューを読み込み直しても残る（編集アプリのページにある）。その間に同じ要素やステップが変わっていれば、保存は断る。組み立てに失敗したら、直るまでプレビューの上にエラーを出す
4. **道具の列。** **ファイル ▾**・**スライド ▾**・**品質チェック**・**プレビュー ▾** の 4 つ（と仮の板の群、使い方の **?**）。幅 1280 px 以上なら 1 行に収まり、それより狭いと折り返す。一覧は ARIA のメニューボタンの形：ボタンの Enter・Space・↓ で開いて最初の項目へ、↑ で最後の項目へ。一覧の中は ↑↓ で移り（端で回る）、Home・End で端へ、字でその字で始まる項目へ、→ か Enter で **エクスポート ▸** を開き、← か Esc で閉じる。Esc で一覧を閉じてボタンに戻り、Tab や外を押しても閉じる。一覧や確かめの窓が開いている間は、キーをプレビューに送らない（`e`・`n`・`c` の切り替えにもならない）

   | 一覧 | 項目 |
   |---|---|
   | **ファイル ▾** | **新規作成…**・**開く…**・**保存**（Egatari ファイル。作業フォルダでは、編集するたびに保存されることを言う）・**名前を付けて保存…**（Egatari ファイル：別のファイルに。新しい教材としても保存できる。作業フォルダ：Egatari ファイル（編集可）に）・**エクスポート ▸**（**参加者用（再生専用）…**・**印刷・PDF**、Egatari ファイルでは **作業フォルダにエクスポート…** も）・**ファイルの情報…**・**フォルダで作業する…** |
   | **スライド ▾** | **スライドの挿入…**（テンプレートから・チャットの AI に書いてもらう）・**複製**・**削除**（スライド一覧で選んだスライド。一覧を閉じていればプレビューに出ているスライド）・**修正…**・**テーマを変更…** |
   | **品質チェック** | ブラウザ版の品質チェック。組み立てとプレビューの読み込みのたびに約 1 秒後に自分でかかり（組み立ての途中はかけない）、札にそのエラーと警告の数を出す（エラーがあればエラーの色）。組み立てと保存の警告は板の先頭に一覧で出る |
   | **プレビュー ▾** | 表示のモードを 1 つ選ぶ：**スライドショーで確かめる (f)**（全画面にもする）・**動画で確かめる**（プレビューをそのモードで読み込み直す）・**先のステップを薄く見せる (l)**（スライドショーの入／切）・**発表者ビューで確かめる (p)**・「発表するときは、保存した .ega.html をブラウザで開きます」の添え書き |

   **ファイル ▾** の後ろの ● は、Egatari ファイルに保存していない変更があること
   - **品質チェック**：ブラウザ版の品質チェック。`npm run check` の一部をプレビューの中で行う（はみ出し・文字の大きさ・タイトルと結論の字数・台本の抜け・パレットのコントラスト）。体裁の部分（はみ出しと縦組みの限り・箱で切れる字やスライドの外に出る字・図の中の字の大きさ・タイトルと結論の字数）はコマンド版と同じコード（`kit/core/layout-scan.mjs`）。結果をクリックでそのスライドへ。目安であって全部の品質チェックではない：パーツの再現性・タイムライン・モーフ・読み上げは見ない。画面の大きさが違うので、数値がコマンド版の品質チェックとわずかに違うことがある
   - 組み立てた HTML（`out/deck.html`）は、編集アプリからはエクスポートしない。コマンドの `node kit/build.mjs` で組む
   - **ファイル ▾ →「名前を付けて保存…」**（作業フォルダ）：原稿と音声を中に持つ Egatari ファイル（編集可・`.ega.html`）にして、人に渡せる形で保存する。作業フォルダはそのまま
   - **ファイル ▾ → エクスポート ▸ →「参加者用（再生専用）…」**：原稿を持たない Egatari ファイル（形式の §3.7。`--play-only` と同じ）。どのブラウザでも再生でき、編集はできない。Egatari ファイルを開いているときは保存したものから作る（保存していない変更があれば、先に「保存」）。作業フォルダはそのフォルダから。窓に **ライブ（質問・投票）を付ける** のチェックがある。ファイルの名前は教材の題名に `.play.ega.html`
   - 同じ窓の **ライブ（質問・投票）を付ける**：印を付けると同じ窓にライブの設定が出て、**エクスポート…** でライブ（授業中の質問と投票。形式の拡張 `live`、下書き）を付けた Egatari ファイル（再生専用）。ライブ ID と参加コードを窓で作って、ホストがホストのページに 1 回だけ貼る 1 本の文字列をコピーし（ホストのページでコピーした設定を貼る前からの方法も、たたんで残す）、参加者からの質問を受け付けるかとステップごとの投票を決め（投票は「4 枚目『XML の壁』・ステップ 1」のような表示名で出し、ステップの鍵は吹き出しに）、ホストのページに渡す投票の設定（表示名入り）をコピーしてエクスポートする。まだ足りないものは **エクスポートの前に直すこと** に画面の言葉で出て、直すまで **エクスポート…** は窓を閉じずに最初の 1 つを知らせる。ファイルの名前には、題名の側にライブの始まる日の印を付ける（例：`題名（ライブ 10-30）.play.ega.html`。英語の画面では `Title (live 10-30).play.ega.html`）。拡張子は変えない。授業の後の結果の取り込みは **ファイル ▾ →「ファイルの情報…」** の添付で。編集アプリ自身はどこにもつながらない。教材に残すのは参加コードのない設定だけ。[ライブ](distributing.ja.md#ライブ授業中の質問と投票下書き)を参照
   - **ファイル ▾ → エクスポート ▸ →「印刷・PDF」**：スライドをブラウザの印刷にかける（`tools/pdf.mjs` と同じく、各スライドの最終状態を 1 ページずつ。「PDF に保存」を選ぶ。章の扉を含め、スライドの背景は「背景のグラフィック」を入れなくても画面と同じ色で刷られる）
   - **プレビュー ▾ →「発表者ビューで確かめる」**（教材の `p` でも）：今の画面・次のステップ・台本（カンペ）・経過時間・描く道具の窓。編集アプリの窓のプレビューを操作する。音声を鳴らすのもそのプレビューで、発表者ビューで自動再生を始めても（<kbd>a</kbd> かそのボタン）、台本の音声は編集アプリの窓で 1 回だけ鳴る。プレビューでもう一度 `p` を押すと閉じる。発表者ビューでは、Esc（描く道具を使っていないとき）・`p`・**発表者ビューを閉じる（p）** で窓を閉じ、編集アプリの窓にフォーカスを返す。発表者の窓が全画面のときは、全画面をやめるだけ。窓にフォーカスがない間は、大きな「ここを押すと操作できます」の覆いが最初のクリックを受ける。プロジェクターで使う順番は、先に発表者ビューを開き、それから聴き手の窓（編集アプリの **スライドショーで確かめる**）をプロジェクターの画面で全画面にする
   - **発表者ビューから抜けられないとき**：画面を覆ったままキーが効かないときは、Mac は cmd+Tab で編集アプリの窓に戻って `p`（Windows は Alt+Tab。Windows ではまだ確かめていない）。キーの一覧（<kbd>?</kbd>）にも同じことを書いてある
   - **プレビュー ▾ →「スライドショーで確かめる」**（`f` でも）：プレビューを画面いっぱいにして、投影の見え方を確かめる。「動画で確かめる」で、もう 1 つの表示のモード（動画）の見え方を確かめる。「先のステップを薄く見せる」（`l` でも）は、スライドショーで先のステップを薄く見せる入／切（字幕と同じ選び）。ここはプレビューで、発表するときは保存した `.ega.html` をブラウザで開く
   - **キー**：道具の列・見出し・状態の行を押した後も、矢印・PageUp/PageDown・Home/End・`b`（黒い画面：プレビュー全体を真っ黒にする。隅に薄く「黒い画面中 — b か Esc で戻ります」が 2 秒出て、マウスを動かすとまた出る。もう一度 `b`・Esc・クリック・矢印・Space・PageUp/PageDown・Home/End で戻り、スライドは動かない）・`a`・`f` はスライドに届く（編集モードの間は `b`・`a`・`f` は効かない）。未保存の台本でプレビューが止まっている間にプレビューを押すかキーを押すと、そのわけを保存・元に戻すのボタンと一緒に出す
   - **発表者ビューの黒い画面**：本体が黒い画面している間、発表者ビューには「黒い画面中」と出て、そこで `b` を押しても本体を黒い画面・解除できる。黒い画面の間に発表者ビューで矢印・Space・PageUp/PageDown を押すと、黒い画面を終えるだけでスライドは動かない

## スライド一覧（足す・複製・削除・並べ替え）

プレビューの左の端の **スライド一覧** のつまみで、そこに一覧を開きます（✕ で閉じます）。スライドを順に、そのスライドの最後のステップのサムネイルと見出しで並べます。サムネイルは教材自身が、一覧の後ろの sandbox の枠に描きます（プレビューと同じ決まり。クリックを受けず、読み上げソフトにも出しません）。一覧・ボタン・確かめの窓は編集アプリのページのものです。開いていたかどうかはこのブラウザが覚えます。

- **選ぶ**：スライドを押すか、一覧で ↑ ↓ Home End。プレビューもそのスライドへ動きます。プレビューを動かすと、選択も付いてきます
- **スライドの挿入 ▾**：選んだスライドの後ろに、テンプレートからか、チャットの AI に書いてもらって（**チャットの AI に書いてもらう…**。下の「スライドの挿入…」）新しいスライドを入れます。テンプレートは**見出しと本文**・**2 列**・**図**（点線の枠と図の説明）・**章の扉**（`sec`）・**引用**（`box` と `cite` の行）。id（`s-xxxxxx`。文書の中で使っていないもの）はエディタが付け、台本に `## 見出し {#id}` の節を、前のスライドの節の後ろに、ステップごとの仮の 1 行と一緒に足します。仮の行は印 `✎` で始まり、テンプレートの字も決まっている（どちらも `kit/core/template-text.mjs` に 1 か所で書く）ので、直し忘れが見つかります。品質チェック（ここと `npm run check`）は警告にし（`narrPlaceholder`・`templateText`）、TTS の前（音声の板・Colab の `tts-job.json`・`tts/synth.py`）と Egatari ファイルをエクスポートする前（編集可・再生専用・ライブ。`--portable`・`--play-only`）に、エディタかコマンドが先に一覧を出します。続けることもできます（**このまま作る**・**このままエクスポート**）。直さないと、TTS が仮の文を読み上げ、字幕と読める層にも入ります
- **複製**：選んだスライドの写しを、新しい id ですぐ後ろに入れます。台本は写し、音声は写しません。写しのステップは、録るか作るまで一覧に **音声が要るステップ N** と出ます
- **削除**（一覧で Delete キーでも）：先に確かめます。窓はスライドの名前と、一緒に消えるもの（台本の節、`audio/manifest.json` の音声の記録とそのファイル（ほかのステップが使っているファイルは残す）、録ってまだ使っていない音声）を出します。音声の更新が必要なときの決まり（形式 §5.4）と同じく、黙って作り直したり消したりはしません
- **並べ替え**：一覧の中でドラッグするか、**↑** / **↓** を押すか、一覧で Alt+↑ / Alt+↓。id は変わらず、台本の節も同じ順に並べ替え、音声は鍵で付いたままです
- **元に戻す**（一覧の上）：直前のスライドの操作を取り消します。原稿・台本・音声の記録と消した音声のファイルを、エディタが覚えている前の中身で書き戻し、使っていない録音も音声の板に戻します。次のスライドの操作まで、Egatari ファイルを保存するまで、別の教材を開くまで使えます。その間に 3 つのファイルのどれかが変わっていれば（編集・外の道具）戻しません。どの操作でも、書き換える前のファイルは `.cache/edits/` に控えます

操作のたびに、`deck.html`・`narration.md`・`audio/manifest.json`（変わったものだけ）を書き、組み直し、そのスライドを見せて品質チェックを出します。読み上げソフトには何をしたかを知らせます（live region）。Egatari ファイルでは変更はメモリの上にあり、次の **保存** でファイルを組み直します（段 B）。組み直さない保存ではスライドの並びを変えられないためです（形式 §7.2。エディタの段 A の保存は `source-changed` で断り、組み直してよいかを聞きます）。台本だけを直せる Egatari ファイル（実行系かパーツライブラリの版が違う）と読むだけの Egatari ファイルでは使えません。スライドの鍵が重なっている教材は、先に直す必要があります（理由を出します）。id のないスライドの鍵はそのままで、足したスライドと写したスライドには必ず id を付けます

## 台本の音声（音声の板）

道具の列の **音声** は、同じ信頼する横の板に欄を開く。フォルダでも、開いた Egatari ファイルでも同じに使える。上から 3 つの区画（設計はプロジェクトの覚え書きの `handoff/audio-flow-2026-10-25.md`。backlog #82・#83・#85・#89）：

- **A. この教材の音声**（いつも上）：状態の 1 行と、ボタンは多くて 1 つ。1 行は、音声のあるステップの数（「まだ音声がありません（8 ステップ）」「8 ステップのうち 5 ステップに音声があります」「8 ステップすべてに音声があります」）、台本が変わって更新が必要なステップの数、声を変えた後も前の声のままの AI 音声のステップの数（`inputHash` は声を含まないので、AI 音声の記録の `recipe.voice` と今の声（Egatari ファイルの選択、なければ `voice.json`、なければ既定）を比べる。`recipe.voice` のない記録と dry-run の音声は数えない）。Egatari ファイルでは「保存するまでファイルには入っていません」を足す。ボタンは、音声のないステップがあれば **残りの音声を作る（n ステップ）**、古いステップか前の声のステップだけなら **音声を更新（n ステップ）**、Egatari ファイルで作るものがなければ **保存**、音声が 1 つもなければ出さない（B を開いておく）。ボタンは前に使ったやり方で続ける：クラウド（そのステップの台本を書き出す。C1）・この PC（そのステップを作る）・録音（その最初のステップで録音モードを開く）。やり方は `egatari.json` の `studio.audioMethod`（`cloud`・`local`・`rec`。`updateConfig` で書くので、ほかの項目はバイトのまま）に覚え、Egatari ファイルではこの画面の間だけ覚える。まだやり方がなければ、ボタンは B を開く。
- **B. 音声をどう付けますか**（初めは開き、全部のステップに音声がそろうとたたむ）：答えの上に **声**（1 つ、掛け合いなら **説明する人の声**・**質問する人の声**。新規作成の ② と同じ言葉）、答えは **AI 音声をクラウドで作る（Google Colab）**（既定）、**AI 音声をこの PC で作る**（このブラウザで作れるとき、つまり配信版か配った編集アプリで WebGPU があるときだけ出し、そのときは既定。初めてのときにモデルを取得すると添え、**この PC で作る（n ステップ）** を出す）、**自分の声で録音する**（**録音モードを開く (r)**。音声のない最初のステップから）。
- **C. このステップ**（画面に出ているステップ。スライドに付いていき、音声を作って書いている間はそのステップのままで、スライドが動いたらそう知らせる）：見出し「スライド 3「…」・ステップ 2」、今の音声（「AI 音声 · 5.2 秒」「録音 · 4.8 秒 · 更新が必要」「まだ音声がありません」）、ボタン **▶ 聞く**・**読み上げで聞く**・**● 録音 (r)**・**ファイルから取り込む…**・**↶ 前に戻す**・（この PC で作れるときだけ）**この PC で作り直す**、そのステップの台本（読むだけ。直すのは「台本」の板）。`{cue}`・`{mark}` があれば「動きに合わせる所が n 個あります（録音では C で置けます）」。

細かいこと：

- **今の音声。** `audio/manifest.json` にあるステップの音声を再生する（フォルダやファイルから編集アプリのページで読む。プレビューからは受け取らない）。**▶ 聞く** で鳴らし、種類（**録音**・**AI 音声**・**取り込み**）、長さ、出どころ（TTS ならエンジン・モデル・声・シード）も出す。**更新が必要** の印は、音声を作った後に台本が変わったか、どの台本から作ったか分からないこと（format spec §5.4：`inputHash` が `null` か今の台本と違う。`inputHash` のない前の `tts/synth.py` の manifest では、TTS の控え `audio/seg_<digest>.json` で比べる）。古いステップは、品質チェック（組み立ての警告）と `npm run check` にも出る。読み上げるためのステップの台本も出す：欄は台本の長さに合わせて伸び（板の半分ほどまで）、右下の角で大きさを変えられる。掛け合いの教材では各ターンに Expert か Novice の印を付ける（台本の書き方。声の欄は説明する人・質問する人）。**↶ 前に戻す** で、最後に作った音声の前にそのステップが持っていた音声に戻す（下を参照）。
- **録音。** **● 録音 (r)**（と B の **録音モードを開く (r)**。音声のない最初のステップで）は、板のステップで[録音モード](#録音モードキーボードだけで録る)を開く（録り方は 1 つ）。1 段だけなら **Space** で録り、話して、もう一度 **Space**、そして **Esc**：板に戻り、そのステップの新しい音声を見せる（板は録音モードの裏で開いたまま）。録音モードは台本を大きく出してその横にメーターを置き、録った音声はすぐにそのステップの音声にする。ここの **↶ 前に戻す** でそのステップの前の音声へ順に戻れる（音声のファイルは消さない）。
- **ファイルから取り込む…** は WAV・MP3・M4A・Ogg・WebM・FLAC を読む（64 MiB まで。大きさは読む前に確かめる）。録音と同じく、すぐに使う。
- **声。** 話す役ごとに 1 つ（1 人の語りなら 1 つ、掛け合いなら Expert と Novice）の欄で選ぶ：日本語の教材は `bob` と `alice`、英語の教材は Kokoro の声（米・英の 8 つ。残りは **ほかの声** に畳む）。**▶ 見本** で事前に作った短い見本を鳴らす（`lab/voices/samples/`。モデルは読み込まない）。作業フォルダでは選んだ声を `voice.json` に書く。Egatari ファイルではこの画面を開いている間だけ覚え（`voice.json` を変えると保存が組み直しになるため）、作った音声の記録には使った声の名前が残る。`voice.json` の声が、この PC で作る AI 音声にないときは、日本語も英語も同じに扱う：板がそう知らせ、TTS はその役の既定の声（`bob`・`alice`、または `am_michael`・`af_heart`）で作る。TTS の窓は知らない名前を断る（黙って別の声にしない）。
- **AI 音声をこの PC で作る**（B。音声の要るステップをまとめて）と **この PC で作り直す**（C。そのステップ）は、ブラウザの中で AI 音声を作る：日本語の教材は Irodori-TTS 500M-v3（読み辞書 `tts/yomi.yaml` を `tts/yomi.py` と同じ規則で通す。声は `voice.json` のもの、既定は `bob` と `alice`。シード 0、ステップ 40。手元の mlx のサーバーもシード 0 だが、ブラウザは別の乱数の作り方で雑音を作るので、手元で作った音と波形は同じにならない）、ほかの言語は Kokoro-82M v1.0（`bob` → `am_michael`、`alice` → `af_heart`。`voice.json` に Kokoro の声の名前を書いてもよい）。`{cue}`・`{mark}` で分けた部分ごとに合成して後処理し、`tts/synth.py` と同じくつなぐ（ターンの間は 350 ms）ので、タイミングの時刻を持つ（`sync: "auto"`）。初めてのときは何を取得するかを見せて確かめ（Irodori の fp16 で約 1.26 GB、fp16 のシェーダーのない GPU では 2.44 GB、Kokoro で約 330 MB。2 回目からはブラウザのキャッシュから読む）、編集アプリのサイトの小さな窓（`lab/tts-helper.html`）を開く。その窓がモデルを読み込み、この PC の GPU で合成する。窓に渡すのは読む文（読み辞書の後）と声の名前だけで、返ってくるのは音だけ。WebGPU が要り（パソコンの新しい Chrome か Edge）、オフライン版のエディタ（`file://`）では使えない。使えないときは「この PC」の答えもボタンも出さず、クラウドが既定になる（WebGPU の有無を前に出した言い方はしない）。ほかの参照音声は `tts/synth.py` で。エンジンはスライドではなく台本の言語で決める：`voice.json` の `"lang"`、次に台本の文（日本語の教材でも発言がほとんど英語なら英語）、最後に `<html lang>`。出す声と読み辞書も同じ言語に従う。
- **後処理** は `tts/core.py` と同じことをブラウザでする（`kit/core/audio-core.mjs`）：モノラル、44.1 kHz、前後の無音を削る（20 ms の窓で −45 dB、50 ms 残す）、音量を −20 LUFS に（EBU R128 の積分ラウドネス、一律のゲイン。トゥルーピークが −1.5 dBTP を超えるので ffmpeg の loudnorm なら動的な処理に切り替えるところでは、ゲインを −1.5 dBTP で止める）。この違いがあるので、後処理の名前は別の `trim-45-loud-20-cap-v1` にする。`tools/test-audio-core.mjs` が同じ入力で `tts/core.py` と長さと音量を比べる。
- **文の前処理**（`kit/core/tts-normalize.mjs`、規則 `join-num-counter@1`）は、各部分をエンジンに渡す直前に、ブラウザでも Colab のノートブック（`colab/egatari_tts.py`。同じ規則で、共有の例で突き合わせる）でもかける：算用数字（0-9・全角の０-９。1.5 のような小数も）と、その直後の日本語の文字（ひらがな・カタカナ・漢字）の間の空白（ASCII・全角）を取る。「1 歩」は「1歩」になり、「いちぽ」と読まれない。「3 分」「10 本」「2 つ」も詰める一方、「x 2 y」「Chapter 3 is」や数字の前の空白（「第 3 章」）はそのまま。助数詞の読みの表は持たない。これは「何を言うか」ではなく「どう合成するか」なので、`ttsParts` と `inputHash` は変えず、取り直しの recipe に `"textNormalize": "join-num-counter@1"` を書く（format spec §5.4）。この項目のない音声（これまでに作ったすべて）は**古くならず**、そのまま鳴り、音声の板も一覧にしない：読みがおかしいと聞こえたステップは **この PC で作り直す** かクラウドで作り直す。
- **音声を書く**（録音・取り込み・TTS の直後）ときは、取り直しを MP3（LAME、64 kbps の CBR、モノラル、44.1 kHz）にして、`audio/<rec|tts|imp>_<hash>.mp3` と `audio/manifest.json` のステップの記録を書く。MP3 のエンコーダは編集アプリのコードに入れない：編集アプリのサイトの `vendor/lame-wasm/` にある手を加えない `lame-wasm` のファイルで（LAME は LGPL。NOTICE を参照）、取り直しを MP3 にするときだけ読み込む。オフライン版のエディタは MP3 のエンコーダを持たず、WAV（16 bit。ファイルは大きい）で保存する。配信版でもエンコーダを読み込めなければ WAV。MP3 は 1105 標本（符号化の遅れ 576 と復号の遅れ 529、0.025057 秒）遅れて始まるので、それを `startOffset` に書き、実行系はその時刻から鳴らす（`dur` とタイミングの時刻がずれない）（前の manifest は `.cache/edits/` に控え、前の音声のファイルは残す。`tts/synth.py` が古い wav を残すのと同じ）。記録には出どころを書く：`kind`（`recorded`・`tts`・`imported`）、`inputHash`（その取り直しを作ったときの台本）、TTS なら `recipe`（`engine`・`model`・`voice`・`seed`・`dictionary` = 読み辞書の SHA-256）、どの種類にも `processing`（`trim-45-loud-20-cap-v1`）、MP3 なら `startOffset`。機器の名前・元のファイル名など録った状況の記録は書かない。録音と取り込みにはタイミングの時刻がない（`sync: "none"`、cues は空）ので、タイミングに合わせた動きと強調は時間で進む。ステップの長さは新しい音声に合わせて決まる（manifest の `dur`。実行系がそこからタイムラインを計算する）。`timeline.json` の `dur` の上書きがあればそちらが勝ち、板がそれを知らせる。書けなかった取り直し（読むだけのファイル・編集の確認を断った）は **まだ使っていない音声** に「この音声を使う」と一緒に残り、使うか別の教材を開くまでメモリの上にある。「前に戻す」のための前の記録もメモリの上だけに置く（ステップごとに 20 まで。別の教材を開くまで）。`tts/synth.py` は録音と取り込みを残す（`--replace-recorded` で替える）。
- **読み上げで聞く**（音声ファイルにはなりません）。 今のステップの台本を、この端末の読み上げの声で読む（format spec §5.6 のプレビュー）。読みの `{x|y}` は y を読み、`{cue}`・`{mark:…}` と `@x-` の行は読まない。日本語には AI 音声と同じ読み辞書（`tts/yomi.yaml`）と文の前処理（`join-num-counter@1`）を当てる（`kit/core/read-aloud.mjs`、プレーヤーと同じ）。**選んだ語を読み上げで聞く** は、台本の欄で選んだ語や文だけを読む（このステップの `{x|y}` の読みも当てる。読み方のボタン #101 の「試しに聞く」も同じ口 `readAloud(text, lang)`（`app/read-aloud.js`）を使う）。読んでいる間は「読み上げ中」と出て、「■ 止める」・別のステップへの移動・板を閉じると止まる。端末の中で動く声（`localService`）だけを使い、ネットワークの声は使わない。その言語の声が端末にないときは、そう知らせ、音声が要るなら AI 音声（クラウドの Google Colab か、この PC）で作るよう案内する。何も書かない：作業フォルダにも Egatari ファイルにも音声の記録にも残らず、音声ファイルにはならない。
- **Egatari ファイル：** 新しい音声でメモリの上のフォルダが変わり、**保存** で組み直さずに書く（段 A：そのステップの音声の記録・実行系の音声の項目・中の音声だけが変わる）。
- **AI 合成音声。** どこかのステップの音声を TTS で作った（`kind: "tts"`）ときは、プレーヤーのツールバーに小さな札「AI 音声」（説明は「音声は AI で合成したものです」）、キーの一覧（<kbd>?</kbd>）に同じ文、そのステップの発表者ビューに 1 行が出る。スライドの上や字幕には出さない。取り込んだ音声（`kind: "imported"`）は、キーの一覧と発表者ビューに「音声の作り方は記録されていません」と出し、録音には印を付けない。Egatari ファイル・再生専用の派生を含むどの出力も、種類を `deck-audio` の `kind` に入れる（format spec §5.2・§7.3）。

## 録音モード（キーボードだけで録る）

<kbd>r</kbd>（編集アプリのページでも教材の上でも）か、音声の板の「● 録音 (r)」で、台本を全部キーボードだけで録るための広い画面を開きます。ステップの台本を**大きく**出し（掛け合いは Expert / Novice の札。長い台本は中でスクロール）、プレビューは横の細い舞台のサムネイルになって録音の位置に付いてくるので、図を見ながら読めます。音声の板と同じく信頼する編集の画面の中にあり、マイク・録音・後処理・書き込みはプレビューでは一切行いません（教材からの知らせで開けるのはこの画面だけで、録音は始まりません）。開いている間、プレビューは inert です。画面に出ているステップ（音声の板からなら板のステップ）から始まり、台本のあるステップを順に録ります。録り方はこれだけです：音声の板の「● 録音 (r)」はこの画面を開き、板は裏で開いたままなので、**Esc** で新しい音声の出た板に戻ります。

| キー | 動作 |
|---|---|
| **Space** | 録音の開始／停止。止めると後処理（音声の板と同じ：前後の無音を削る・−20 LUFS・モノラル 44.1 kHz）をして、**すぐそのステップの音声**にします（kind `recorded`。これまでどおり「前に戻す」で戻せます）。ステップは替わりません。開いた直後（とステップを移った直後）は、そのステップを読み終えるまで Space のボタンが **準備中…** になります。その間に押した Space は覚えておき、準備ができしだい録り始めます（2 回押しても 1 回） |
| **Enter** | 録音中なら止めて採用し、次のステップへ。録った後（または音声のあるステップ）なら次のステップへ。次のステップは**待機**：自動では録り始めません（再生中の部屋の音を録らないため）。音声のないステップでは、進まずにそう知らせます |
| **Backspace** | 取り直し。録音中は今のテイクを捨てます（何も書きません）。録った後は、そのテイクを「前に戻す」で外して前の音声に戻し、次の Space を待ちます。戻せるのは、このモードで録った音声だけです |
| **←** / **→** | 前・次のステップ（録音中なら先に止めて採用） |
| **C** | 録音中に、台本の `{cue}`・`{mark}` のタイミングごとに押します（タイミングは ①②… のチップで出て、次のタイミングは太い枠、押したものは ✓）。押した時刻が cue になります（`sync: "manual"`。時刻は押した生の時刻から、前の無音を削った分を引いたもの）。押した数がタイミングの数と違えば cue は書かず（`sync: "none"`。警告を出し、図は時間で進みます）、間違った同期は作りません |
| **Esc** | 閉じる（録音中は今のテイクを捨てます。**Shift+Esc** は開いている窓を全部）。フォーカスは元の場所に戻ります |

1 段は **Space → 話す → Enter** です。取り直したテイクは前のテイクの cue を使いません（仕様 §5.3）：`sync: "none"`・cue なしから始まり、C で埋めます。台本を直して音声が古くなったステップには「古い」の知らせ、タイミングがあって cue が未設定のステップには「図は時間で進みます」の知らせが出ます。掛け合いはステップごとに 1 本のテイクです（1 人が両方の役を読むか、2 人が交互に）。入力の大きさのメーターと経過時間（1 つのテイクは 600 秒で止まり、そこまでを使う）、テイクの長さと音量の調整、音が割れていそうなときの警告が出ます。止めるキーの後に小さな尾（0.15 秒）を残して、語尾が切れないようにします。マイクは画面を閉じるまで開いたままで（許可は 1 回、録り始めの遅れなし）、閉じると手放します。書き込みが断られたとき（読むだけのファイル・編集の確認を断った）は、そのテイクは音声の板の「まだ使っていない音声」に残ります。

読み上げソフトには、この画面は modal の dialog です。live region がステップ（n / N・題・音声の有無・タイミングの数）・「録音中」・押したタイミング・テイクの結果を知らせ、alert の領域が問題を知らせます。どのキーにもボタン（キーの aria-keyshortcuts つき）があり、`prefers-reduced-motion` ではメーターを 1 秒に数回だけ更新します。この画面の間、<kbd>e</kbd>・<kbd>n</kbd>・<kbd>r</kbd> は何もせず、ツールバーは inert です。

**ファイル ▾ →「ファイルの情報…」** は、`egatari.json` の `metadata` の題名・ライセンス・作り手・著作権・クレジットの表示を出し（ここでは読むだけ。作業フォルダなら `egatari.json` を直す）、形式（「形式：Egatari 1.0（WD …）」。ファイルの `version` と、`vendor/egatari-spec/SOURCE.json` に仕様の写しの版があればその版）と作った Studio（「作った Studio：0.4.6」。`generator.version` から。作業フォルダは「この Studio：…」）、「再生は、ファイルに入ったプレーヤーで動きます。編集はいつも最新の Studio で行ってください」の添え書きを出し、その下に添付（見出しは「添付（下書き・試行）」）を出す。添付は、作業フォルダか開いた Egatari ファイルの `attachments/` の下のファイルを並べる（形式の §3.8：読み手のための元の原稿・PDF・コード・データ・補足。[参照](reference.ja.md#1-ファイル--portable)）。**ファイルを足す…** で写し入れる（役割は形式から推す：`.pdf` → pdf、`.tex`・`.bib`・`.docx`・`.md` → source、`.py`・`.ipynb`・環境の定義 → code、`.csv`・`.tsv`・`.json`・`.xlsx` → data、画像と `.txt` → supplement）、ファイルごとに題を尋ねる（要る。1 行で 120 字まで。ファイル名から埋めてあり、直せる）。形式が許さないファイルは、理由と規則（§3.8）を言って断る：名前から分かるもの（実行できるファイル・`.js`・`.bat`・`.ps1` など OS がスクリプトとして開く拡張子・HTML・SVG・ZIP・マクロを入れられる Office のファイルと、.doc・.xls・.ppt の古い Office のファイル・音声と動画・どの役割も受けない形式）は題を尋ねる前に、中身から分かるもの（JavaScript のある PDF・文書の中へ移るほかの開いたときの動作や `GoTo`・`URI` のほかの動作のある PDF・パスワードの要る暗号化した PDF・マクロや外への参照のある Office・名前を替えた実行ファイル・2 つの形式を重ねたファイル・音声と動画）は読んだ後・書く前に。表計算のソフトが数式として読みうる値は知らせて足す。行ごとに役割（なし：入れるが読み手の一覧に出ない。ファイルの形式を受けない役割は断る）・題（要る：ないものは入れるが一覧に出ない。消せない）・説明（任意。1〜2 文で 300 字まで。ダウンロードの一覧の題の下に出る）・**名前を替える…**（新しい名前も足すときと同じく確かめる）・**消す**。役割・題・説明は `egatari.json`（`attachments`。ほかの項目は残し、`.cache/edits/` に控え）に書く。`attachments/` の外・`..`・予約名・重なる名前は断り、上限（1 つ 10 MiB・合わせて 20 MiB・100 個）を超えるファイルは読む前に断る。フォルダから消すときは `.cache/edits/` に控えを残す。エディタは添付を開かず、プレビューにも渡さない。Egatari ファイルでは **保存** まではメモリの上で、保存は段 A：変わるのは索引の添付の項目・その塊・原稿の hash だけ。Egatari ファイルの最初の変更の前には、ほかの編集と同じく編集の確認が出る。**ライブの結果を取り込む…** は、ライブからダウンロードした結果を役割 `data` の添付にし、要約を出す（[ライブ](distributing.ja.md#ライブ授業中の質問と投票下書き)の「授業の後」）。

## Egatari ファイル（フォルダなし）

Egatari ファイルは、`npm run build -- <deck.html> --portable`（または編集アプリの **ファイル ▾ →「名前を付けて保存…」**）が書くもの（作業フォルダの最上位に、題名から作った名前で書き、パスを表示する）。組んだ教材と同じように再生でき、スライド・台本・音声を中に持つので、元のフォルダがなくても編集アプリで直せる。人への配り方（Google ドライブ・メール・LMS）は [distributing.ja.md](distributing.ja.md)。

- **開く。** 最初の画面の「ファイルを開く（.ega.html）…」か **ファイル ▾ →「開く…」** を押すか、ファイルを最初の画面に落とす。編集アプリはファイルをバイト列として読み、スクリプトを動かさない HTML の解析器で、Web Worker の中で取り出す。ファイルそのものをページとして読み込むことはないので、取り出しの間に中のものは何も動かない。形式のハッシュ・大きさの上限・パスの規則を先にすべて確かめる（`npm run portable -- unpack` と同じ）。HTML は上限（要素・属性・入れ子の深さ）を解析の途中で数えながら解析し、中の原稿のファイルに書かれたタグも 500000 までにするので、小さな要素を何百万も並べたファイルは、全部の木を作る前に断る。読むのに 30 秒より長くかかれば Worker を止めて断る。開いた教材（フォルダ・Egatari ファイル）の組み立てとコードの確かめも Worker の中で、組み立ての上限（[reference](reference.ja.md#組み立ての上限)）の内で行い、60 秒より長くかかればその Worker を止めて失敗にする（`build-timeout`）。その間もページは固まらない。フォルダから読むのは組み立てが参照したファイルだけ（同時に 8 つまで、1 つは一覧の大きさまで。一覧の後で大きくなったファイルは断る）で、止めた Worker からの答えは捨てる。どのファイルも、読む前に `File.size` で、読んだ後に読んだバイトで大きさを確かめ（`app/bounded-read.js`）、`deck.html`・`narration.md`・`comments.json` には決まった上限（32 MiB・16 MiB・4 MiB）があり、超えるものは読まずに断る。原稿はメモリの上（メモリの上のフォルダ）に置き、プレビュー・編集の道具・品質チェックはフォルダのときと同じように動く。フォルダがないので、外での変更は見張らない
- **保存。** 「保存」は、ブラウザが書き込めるハンドルをくれたとき（Chrome / Edge の「ファイルを開く（.ega.html）…」かドラッグ＆ドロップ。初めは許可をたずねることがある）は同じファイルに書き直す。そうでなければ保存先をたずね、保存の画面がなければ（Safari・Firefox）ダウンロードする。文書の識別子（`docId`）は変えず、`derivedFrom` を付けることも変えることもない。**ファイル ▾ →「名前を付けて保存…」** は、**新しいファイルとして保存する（元のファイルとは別のものになります）** かを聞く
  - 印を付けたとき：保存先をたずね、新しい `docId` の教材として書く。元の教材を `derivedFrom`（元の `docId` と原稿の hash）に記録し、著作権・クレジット・作り手はそのまま残す。開いている文書は新しい教材になる（この後の保存も新しい識別子のまま）
  - 付けないとき：保存先をたずね、同じ教材（同じ `docId`）を別のファイルに書く

  ファイル名の前の ● は保存していない変更の印。ページを離れるときや別のファイルを開くときは先にたずねる。どの保存でも、ライセンス・著作権・クレジット・作り手、編集アプリの知らない索引の項目（どの深さでも：metadata・音声の記録・塊・パーツとテーマ・拡張の中）と拡張のデータは残し、触れていない音声はバイトのまま写す。設定のファイル（原稿の根にある教材の識別子と metadata）がないファイルには、編集アプリが足すことがある。それで原稿の hash は変わるが、保存はもともとそれを書き直す
- **組み直さずに保存する。** 台本（発言の文・強調・タイミング）、音声、`timeline.json` の秒数の上書きだけが変わったときは、「保存」はスライドを組み直さない。[形式](https://github.com/egatari/egatari-spec)がそういう編集に挙げる所（§7.2 の段 A）だけを書き換える：実行系の台本・強調・秒数・音声のデータのうち変わったステップの項目、スクリプトなしで読める文字の層のうち変わったステップ、原稿の hash と索引とその hash、中に入れたファイル（新しい中身を足し、どこからも参照されなくなった中身を除く）、そして新しい文に、埋め込んだ字にない字があるときだけ、字の補い（その字を含む字の分割ファイルだけを、編集アプリが持つ字から入れた新しい style 要素。前からある字のデータには触れない）。ファイルのほかのバイトは、ほかの道具や別の版が書いた実行系も含めて、1 バイトも変えない。状態の欄に「組み直さずに」と出る。ステップの台本をすべて消すと、そのステップの音声も消える。保存の知らせに警告があることが出て、品質チェックの板にそのステップが出る。秒数の上書きは項目ごとに写し、各ステップの長さは実行系がそれまでと同じ式で計算する
- **組み直して保存する。** スライドを直したとき（または上の所の外が変わった、ファイルの組んだ教材と原稿が食い違うとき）は、直した原稿から編集アプリに同梱の kit・パーツ・テーマでファイル全体を組み直すので、プレビューとまったく同じに再生する。保存の前に **「スライドはこのエディタの今のバージョンで組み直されます。編集していないスライドも、見え方が変わることがあります。」** と知らせ、組み直さずに保存できない理由も見せ、「組み直して保存」を押してから保存する（キャンセルなら変更は保存しないまま）。ファイルがほかのプレーヤーを持っていたとき（索引のプレーヤーが Egatari Player でない）は、続けて **「プレーヤーが変わります」** の窓で、ファイルのプレーヤーと保存したファイルに入るプレーヤーを名前と版で見せる（「このファイルは Other Player 2.0.0 で再生します。保存すると、Egatari Player 1.0.0 で再生するファイルになります。…」）。「保存」で保存し、「キャンセル」なら変更は保存せず、ファイルもそのまま（形式の仕様 §4.1）。同じプレーヤーの新しい版になるだけなら聞かない。まだできないこと：組み直しの前と後のスライドを比べること。保存した後にプレビューで確かめる
- **更新が必要な音声。** ステップの台本を直しても、その音声には触れない（バイトも種類もそのまま）。そのステップは警告に「音声の更新が必要」と出て、保存したファイルでも音声の記録は作ったときの台本の hash のままなので、どの読み手にも古いと分かる。[音声の板](#台本の音声音声の板)で録り直すか、作り直す
- **ファイル ▾ → エクスポート ▸ →「作業フォルダにエクスポート…」** は、選んだ空のフォルダに原稿・音声・`audio/manifest.json` を書く（`npm run portable -- unpack` と同じファイル）。空でないフォルダは断る。エクスポートしたフォルダは、ふつうの作業フォルダとして開け、組め、まとめられる
- **ファイル ▾ →「名前を付けて保存…」**（フォルダを開いているとき）は、フォルダを Egatari ファイル（編集可・`.ega.html`）にする。最初に出すファイルの名前は教材の題名（設定のファイルの `metadata.title`、なければ教材の `<title>`）で、どの OS でも使える形にする（`\ / : * ? " < > |` と制御文字を除き、頭の点と終わりの点・空白を除き、`CON` などの予約の名前を避け、80 字・255 バイトまで）。題名がなければスライドのファイルの名前。初回は教材の識別子をフォルダの設定のファイルに書き、次からのエクスポートでも同じものを使う
- **作業フォルダからエクスポートした写し**（`exportedFrom`、形式の §3.1）。作業フォルダの「名前を付けて保存…」（コマンドの `--portable` も）は、そのファイルにフォルダの写しという印を、エクスポートしたときのフォルダの原稿の hash と一緒に付ける（時刻・パス・名前は入れない）。そういうファイルを開くと「フォルダからエクスポートした写しです。ここで直した分は、フォルダには入りません。フォルダに戻すには『作業フォルダにエクスポート』を使ってください。」と知らせ、**作業フォルダにエクスポート…** のボタン（ファイル ▾ → エクスポート ▸ →「作業フォルダにエクスポート…」と同じ）を出す。編集は断らない。「保存」と「名前を付けて保存…」は印を変えないので、写しの原稿の hash が印と違ってくると「エクスポートしたあと、この写しで直した所があります。」を足す。「新しいファイルとして保存する」に印を付けた保存は印を外す（新しい `docId` の教材は写しではないので、開き直しても知らせは出ない）。フォルダなしで編集アプリから始めた教材（貼り付けたもの・`deck.html` だけから開いたもの）には印が付かない。展開したフォルダは印を持たず、原本になる。次のエクスポートが新しい印を書く。写しとフォルダの両方が手元にあれば、`npm run portable -- compare <ファイル> <フォルダ>` がエクスポートの後にどちらを直したかを言う（[参照](reference.ja.md#1-ファイル--portable)）。
- **ファイルに入らないもの：** コメントと `.cache/edits/` の控えはメモリの上にだけ残る（コメントは見直しの覚え書きなので、形式が外す）

### 編集の確認（このファイルを編集しますか）

ファイルを編集のために開くたびに、最初の変更の前に（編集モードや台本の引き出しで最初に保存するとき、または「編集」「台本」を押したとき）、ファイルに書かれた題名・作り手・著作権・ライセンス・クレジットの表示を見せる（どれも申告で、確かめたものではない）。改変を認めないライセンス（Creative Commons の `-ND`、All rights reserved）か、ライセンスがなく著作権の表示だけのときは、改変や改変したものの配布が権利者の著作権を侵すおそれがあると知らせ、確認のチェックを入れるまで編集を始めない。キャンセルならファイルは変わらない。保存で著作権・クレジット・作り手を消すことはない。

### スライドのファイル（deck.html）・組んだ発表の HTML を開いたとき

- **スライドのファイル**（作業フォルダの `deck.html`。GitHub から落としたものなど。`<section class="slide">` があり、組み立ての実行系や形式のブロックがない）は断らない。台本・音声・その教材だけのパーツは同じフォルダに別のファイルとしてあることを説明し、「作業フォルダを開く…」（フォルダを選ぶ画面。選んだフォルダをふつうに開く）・「このファイルだけを開く」・「キャンセル」を出す。「このファイルだけ」は `deck.html` だけのメモリの上の教材を新しく作る：台本と音声はない。パーツライブラリのパーツとテーマは使え、参照しているのにないファイル（その教材だけのパーツ・`{{JSON:…}}` のデータ・取り込み・図）は組み立ての知らせ（1 つにつき 1 回）になり、中身なしで組む（メモリの上の教材はすべてこうする。フォルダは今までどおり、ないファイルがあれば組み立てが失敗する）。ほかの開いたファイルと同じに扱う：教材にコードがあれば先に確かめ、新しい `docId` で、編集の確認は出さず（権利が書かれていない）、`deck.html` だけを開いていてまだ保存していないことを知らせる。「保存」は保存先をたずねる：「Egatari ファイル（`.ega.html`）に保存…」か「作業フォルダにエクスポート…」（空のフォルダ）
- **組んだ発表の HTML**（`out/deck.html` など。組み立ての実行系と `deck-meta` はあるが原稿がない）は専用の言葉で断る：発表用に組んだもので、作業フォルダ（「作業フォルダを開く…」を出す）か Egatari ファイルを開くように言う
- **Egatari ファイルの再生専用版**（`.play.ega.html`）はそう名指しして断る：そのままブラウザで再生でき、編集するには元の Egatari ファイルか作業フォルダを開く。ほかの HTML は「Egatari ファイルではない」と言う

### 断るファイル・読むだけで開くファイル

- **理由を見せて断る：** Egatari ファイルでないもの・再生専用のもの（上を参照）、ハッシュが合わないもの・一部が欠けたもの、許されないパス（`../` など）、索引の同じ名前の項目、設定のファイルと食い違う文書の識別子、新しい原稿の書き方の版
- **新しい major の版、編集アプリが実装していない必須の機能：** 編集のためには開かず、エクスポート（作り直し）もしない。索引と中のデータが、編集アプリの知っている版の規則で確かめられれば、原稿を取り出す「作業フォルダにエクスポート…」を申し出る。確かめられなければ取り出しも断る（そういうファイルもブラウザで再生はできる）
- **台本・音声・秒数だけ：** パーツライブラリ・テーマ庫のパーツの hash が編集アプリのものと違う（または編集アプリにない）もの。編集アプリではそのとおりに組み直せないので、台本・音声・秒数だけを編集できると上に知らせる。「編集」（スライドの文字）は断り、台本の引き出しは使え、「保存」は組み直さずにその所だけを書き換える。組み直しの要る変更は保存できない
- **読むだけ：** 編集アプリで組み立てられないもの、ひとつ前の種類で、しかも組んだ教材と原稿が食い違うもの。教材は表示し、保存は断り、「作業フォルダにエクスポート…」はできる
- **独自のコード：** 教材が自前のコードを持つかは、組んだ文書から決める（取り込み・前処理の後の原稿全体。組み立てがテキストとして読むファイルは拡張子によらずすべて含み（`/*INCLUDE:…*/` で取り込んだ画像のファイルも）、そのあとプレビューに出すのと同じバイト）。`src` がなく中身が空か空白だけの `<script>` はコードに数えない（コメントだけのものは数える）。調べるためにフォルダをもう一度読むことはしない。そういう教材（と「extended」のファイル）は、その中のものが動く前に知らせてたずね、「プレビューを始める」を押してからプレビューを始める（キャンセルならファイルは開かない）。たずねる前にプレビューを空にするので、前の教材も新しい教材も、たずねる窓の後ろに出ることも動くこともない。開いている間は上に知らせを出す：コードはプレビューの中だけで、外へ繋がらずに動き、ファイルを書き換えられない。パーツ（`components/…`、どれかの `.js`）や `deck.html` のスクリプトを持つフォルダも、開くたびに 1 回同じことをたずねる（あとからそういうコードが現れたときも）

## チャットの AI で下書きする（貼り付けと修正依頼）

の答えをコピーし、横に **指示の大きさ：N KB** を出す。押すと「コピーしました（N KB）。チャットの AI のタブに貼り付けて送ってください。長いので、貼るとファイルの添付の形になることがありますが、そのまま送ってかまいません。AI が書き終えたら ⑤ へ」。① か ② の答えが欠けていれば、その問いを開いて言う
  5. **AI の出力を貼り付けます。** 「AI の出力には、灰色の枠（コードブロック）が 2 つあります…」。欄は 2 つ：**スライド（deck.html）** と **台本（narration.md）**。それぞれの下に状態（「まだ貼っていません」「✓ スライド 6 枚」「✓ 台本 6 節」、読めなければそのわけ）。出力の全体をどちらの欄に貼っても 2 つに分けて入れ（「出力の全体だったので、スライドと台本に分けました」）、違う欄に貼ったもの（台本の欄にスライドなど）は正しい欄へ移して知らせる。コードブロックの外の文や枠の行ごと貼ったときは、取り出したコードブロックだけを欄に残し、「出力からスライドのコードブロックを取り出しました」と知らせる（分けた・移したときも、欄には取り出したものが残る）。隠れた「待ち」の状態はなく、欄を消せば最初から。**作成** はスライドの欄が埋まれば押せ、台本の欄が空ならボタンのすぐ左に「台本なしで作成します（台本はあとで書けます）」と出す。**作成**・**挿入**・**置き換える** はいつも同じ場所にあり、押せない間はすぐ左に、欠けているもののうち最初の 1 つを出す（「① に答えてください」→「② のタイトルを書いてください」→「⑤ にスライドを貼り付けてください」。構成案を待つ間は「⑤ に構成案を貼り付けてください」、欄が読めなければ「⑤ の欄の下の知らせを見てください」。挿入は「③ にスライドを貼り付けてください」、修正は「③ にスライドか台本を貼り付けてください」）
- **長い教材は 2 回に分けて。** 長さが 9 枚から（分は 1 分 ≒ 1 枚）は、写す文の最後に「まず構成案だけを返してください」（R-outline）が付き、AI は ```` ```outline ```` のコードブロック 1 つ（全スライドの見出しと 1 行の要点の表）で返す。⑤ は **⑤ AI の構成案を貼り付けます** になり（構成案の欄と **次へ**。その間 **作成** は押せない）、受け取ると「構成案：24 枚 **変更**」にたたみ、「6 枚ずつ作ります」と一覧と **1〜6 枚目を頼む指示をコピー**（その範囲の `deck.html` の全体を、構成案と一緒に頼む）と 2 つの欄を出す。作成すると、構成案を `egatari.json` の `studio.outline`（`{v: 1, next, rows}`）に残す（`updateConfig` を通すので、ほかの項目はバイトのまま）。知らせに **構成案：残り N 枚（全 M 枚）** と **次の 6 枚を頼む** が出て、スライドの挿入のページで次の範囲（「構成案の 7〜12 枚目」。構成案と前のスライド付き）を頼み、入れた後に `next` を進める。壊れた構成案（コードブロックがない・閉じていない・表の行がない・見出しのない行・2 枚より少ない・60 枚より多い）は、わけを言って断る

  エディタは 2 つのコードブロック `deck.html` と `narration.md` を取り出す（```` ```html ````・```` ```markdown ````・```` ```html title="deck.html" ```` のような名前や、コードブロックの前の行のファイル名も分かる。Windows の改行、前・間・後の文章、余分なコードブロックはかまわない。同じファイルが 2 つなら最後のものを使う）。コードブロックの右上のコピーで写したものには ``` の行がないので、中身から決める（`<section class="slide"` があればスライド、`## 見出し` と `[0]` などの行があれば台本）。``` の行がなく両方が入ったものは分けられないので、写し方を添えて断る。どちらでもないものも断る。閉じていないコードブロックは出力が途中で切れたということなので、その欄にそう書き、**送り直しの指示をコピー** を出す（足りない台本だけ、または教材の全体を短くして送り直してもらう）。切れたのが台本だけなら、スライドは受け取り、送り直してもらった台本を台本の欄に貼る。コードブロックの印なしで画面からコピーした出力の全体は、`<!DOCTYPE html>` から `</html>` までをスライド、その後ろを台本として取り出し、そのことを知らせる
- **id。** AI にはスライドの id を書かないように頼んでいる。エディタは、id のないスライドに新しい id を付け、台本の見出しを `## 見出し {#id}` に書き換える（`npm run ids` と同じ本体の `kit/core/slide-ids.mjs`）。見出しが同じスライドが 2 枚以上あれば、台本のその見出しの節を順に対応させる
- **開いたファイルと同じに扱う。** 原稿は組み立ての Worker で Egatari ファイルにし、開いたファイルとまったく同じに開く：コードの確かめは中身から決めるので、`<script>`（ほか動くもの）の入った出力は先に **プレビューを始める** を聞き、キャンセルなら何も開かない。新しい教材は新しい `docId` で、まだ保存していない（●）。**保存** で保存先を聞く。開くときに、最後に指示を写したときの選び方を `egatari.json` の `studio.newDeck`（`{v: 1, plan, category, subcategory, subjects, purposesOff}`。`plan` は `free` か `paid`、plan のない前の記録は `free`。`updateConfig` を通す）に残す。シード値は書かない（format spec §8.4：パーツの見せ方は `variant="<名前>"` だけで選び、書かなければそのパーツの既定の見せ方。原稿にある `variant` はそのまま残す。前の原稿の `data-egatari-seed` は誰も読まない属性で、消さずにそのまま残る）。自分の下書きなので編集の確認は出さない。開いたら品質チェックをかける
- **スライドの挿入… → チャットの AI に書いてもらう**（backlog #93）。3 つの問い：**① どんなスライドを足しますか**（挿入する場所を出し、足す枚数（1〜10）と足したいこと）→ **② チャットの AI に指示を送ります**（専用の短い指示。`kit/core/llm-insert.mjs`：「スライド X の後ろに、続きのスライドを n 枚」、スライドの見出しの一覧、挿入する場所の前のスライドとその台本だけ。教材を作ったのとは別のチャットに送るときは **この教材を作ったのとは別のチャットに送る（指示の全体も付けます）** に印を付けると、前に指示が入る）→ **③ AI の出力を貼り付けます**（新規作成の ⑤ と同じ 2 つの欄。台本の欄が空なら「台本なしで挿入します」）→ **挿入**。出力のスライドを順にその場所へ入れ、スライド一覧と同じやり方（`newIdFor`）で新しい id を付け、台本の節（`## 見出し {#id}`）を同じ順で入れ（台本のないスライドには仮の行）、スライド一覧と同じ道で書き（`.cache/edits/` の控え・**元に戻す**・組み直し）、品質チェックをかける
- **修正…** **① どこを直してほしいですか**（直してほしいこと。なくてもよい）→ **② チャットの AI に修正依頼を送ります**（品質チェックの指摘（かけ直す）、① に書いたこと、開いているコメント（`comments.json`。解決したものは入れない。ピンやマーカーの画像は backlog #90）、今のスライドと台本。直すことがなければそう言う）→ **③ AI の出力を貼り付けます**（同じ 2 つの欄。「直したスライドだけが出力されたときは、そのスライドだけを置き換えます」）→ **置き換える**。片方の欄だけでも押せる（横に「台本は今のままにします」か「スライドは今のままにします」）
- **AI への修正依頼をコピー。** 品質チェックの板にある。修正依頼の文章をクリップボードにコピーして見せる：指摘（エラーと警告）、それが破った規格（規格には `R-title` のような名前があり、文章は同じ指示から取る）、教材が使っているパーツの説明（指示と同じ文章）、はみ出しと小さい字の量（「本文を 97 px（46 px の行でおよそ 3 行）減らす」「字を 23.2px から 24px 以上に上げる」）、台本についての組み立ての知らせ、今の `deck.html` と `narration.md`。教材が長い（合わせて 40000 字を超える）ときは、指摘のあるスライドとその台本だけを載せ、そのスライドだけを返すよう頼む。同じチャットに貼り付け、**AI の出力を貼り付ける…** を押すと、**修正…** の ③ が開く
- **置き換え（修正… の ③）。** 出力を今の教材に入れる（Egatari ファイル（再生専用）では使えない）。文書はそのまま：Egatari ファイルなら `docId`・設定・音声・パーツを残して原稿だけを入れ替える（保存するまでは未保存）。フォルダなら `deck.html` と `narration.md` を、`.cache/edits/` に控えを残して書き、コードが現れたらコードの確かめをもう一度聞く。id 付きの `<section>` の一部だけの出力は、そのスライドと台本の節だけを置き換える。台本の欄だけなら台本だけを（節がどれも id 付きなら、その節だけを）置き換える
- **品質チェックに足したもの：** スライドにないステップの台本（エラー）、表紙など static のスライドの台本、式やいくつもの記号を入れた読みの指定 `{x|y}`（警告。読みは 1 つの記号か用語に 1 つ）。コマンド版の品質チェックも同じ 3 つを見る

## 書き換えるファイル

開発サーバーとまったく同じ（[dev-server.ja.md](dev-server.ja.md) の「書き換えるファイル」）。どれも選んだフォルダの中

- `deck.html`：編集した要素の中身だけ
- `narration.md`：編集したステップの行だけ（注釈やほかの行はそのまま）
- `comments.json`：コメント `[{id, created, key, range, pin, quote, comment, status}]`（`pin` は押した点 `{x, y}` のスライドの座標、1280×720。マーカーは描いた印 `strokes` を足す（前のコメントは 1 本の `stroke` のこともある）：[約束事 §13](contract.ja.md#13-レビューのメモ手書きの印)。[開発サーバー](dev-server.ja.md#書き換えるファイル)を参照。コメントが何を指しているかを見るには、フォルダに `npm run comment-shots -- <作業フォルダ>` を動かす：未対応のコメントごとに、そのステップをピン付きで `.cache/comment-shots/` に描く）
- `audio/<rec|tts|imp>_<hash>.mp3` と `audio/manifest.json`：音声の板の **この音声を使う** で（変わるのはそのステップの記録だけ。前の manifest は控える）
- [スライド一覧](#スライド一覧足す複製削除並べ替え)で：`deck.html`（スライドをまるごと入れる・写す・消す・動かす）、`narration.md`（節をまるごと）、`audio/manifest.json` と、スライドを消したときはその音声の `audio/` のファイル（先に控える。元に戻すで書き戻す）
- `.cache/edits/`：書き換える前の `deck.html`・`narration.md`・`audio/manifest.json`（新しい 30 個。掃除で消すのは控えの名前の形（`<時刻>-<名前>`）のファイルだけで、フォルダのほかのものは残す）
- 作業フォルダの「名前を付けて保存…」と「参加者用（再生専用）…」では選んだファイル（と、初回はフォルダの設定のファイルの教材の識別子）
- Egatari ファイルを開いたとき：保存するまで何も書かない（直したものはメモリの上）。保存では選んだファイルだけ（組み直さない保存では、上に挙げた所だけを書き換える）、「作業フォルダにエクスポート…」では選んだ空のフォルダのファイルだけ

## できないこと

- **Chrome・Edge だけ。** スマートフォンのブラウザもフォルダを開けない
- **この PC で AI 音声を作るモデル。** モデルは編集アプリのサイトのブラウザのキャッシュに置かれる（Irodori-TTS は約 1.26 GB、Kokoro は約 330 MB）。「使い方」に、このサイトが使っている保存領域（`navigator.storage.estimate`）と入っているモデルが出て、「モデルを消す」で消せる（作った音声は消えない。次に使うときに取得し直す）。TTS の窓はモデルを読み込むとき、古い版のモデルのキャッシュを消し、ブラウザに保存領域を残すよう求める（`navigator.storage.persist`）。求めが通らなければ、ディスクの空きが足りないときにブラウザがモデルを消すことがあり、Safari は 1 週間ほど開かないと消す
- **コマンドで行うもの：** 自分の参照音声やサーバーのエンジンでの TTS（`tts/synth.py`）・動画（`tts/` `render/`）、品質チェックのコマンド版（`npm run check`）、`tools/pdf.mjs`。プレビューは `audio/manifest.json` の音声（フォルダでも Egatari ファイルでも）を自動再生（`a`）で鳴らす：編集アプリが音声のファイルを読んでそのバイトをプレビューに渡し、プレビューは自分の文書の `blob:` の URL で鳴らす（砂場のプレビューはフォルダも編集アプリの `blob:` の URL も読めない）
- **音声の板は編集アプリだけ。** 開発サーバーには音声の板がない（フォルダを編集アプリで開くか、`tts/synth.py` を使う）。AI 音声をこの PC で作るには、WebGPU と、配信版か配った編集アプリが要る
- **エクスポートが大きい。** コマンドの build は fonttools で和文の字を絞り込める（`node tools/get-fonts.mjs`）が、ブラウザではできないので、使う字を含む分割ファイルをそのまま埋め込む（TTF がないときのコマンドと同じ）。`examples/minimal` は編集アプリで約 2.0 MB、絞り込んだ `npm run build` で 0.7 MB。見た目は同じ
- **オフライン版のエディタに明朝はない。** 配信版の編集アプリは BIZ UDP明朝を持つ（明朝を使う教材、たとえばテーマ `kokugo` のときだけ読む）が、オフライン版のエディタ `dist/editor.html` は小さく保つために持たない。そこでは明朝の教材は知らせを出して組まれ、見る人の機械の明朝で出る
- **同梱のもの。** パーツライブラリのパーツ（`vendor/components/` のすべての版と `components.lock.json`）・テーマ（`themes/`）・実行系（`kit/`）は、アプリを組んだときのもの。教材は、記録したハッシュに合う版のパーツがアプリにあれば、その版で組み直す。テーマも同じく記録した版で組み直す（前の版は `vendor/themes/` と `themes.lock.json`）。その版が今の版でなければ、プレビューは記録した色のままで、上の知らせがそう言い、今の版で変わる色（前 → 今、色見本つき）を挙げて「テーマを更新」を出す。今の版で組み直すのはそのボタンを押したときだけ（`egatari.json` の `themes` と教材の記録を替える。保存すると新しい色で書く）。黙って色を変えない（[リファレンス](reference.ja.md)「テーマの版」）。作業フォルダの中のパーツとテーマ（`components/<名前>/index.js`、`themes/<名前>/`）は、いつもどおりフォルダから読む。どちらにもないテーマ（自分のテーマのフォルダにある機関のテーマなど。コマンドは `EGATARI_THEMES`・`~/.egatari/themes` で見つける）は `theme not found: "<名前>"` と警告して `default` で組み、プレビューの上の知らせに「テーマを読み込む…」を出す（警告の一覧にも）
- **テーマを読み込む。** 「テーマを読み込む…」（テーマの知らせ、新規作成の ③ のテーマの一覧の最後、はじめの画面の「自分のテーマ…」）で、小さな窓「テーマを読み込む」を開く：「テーマを ZIP ファイルか、テーマのフォルダから読み込みます。」と、「ZIP ファイルを選ぶ…」「フォルダを選ぶ…」（フォルダを選べるブラウザ（Chrome・Edge）だけ）「キャンセル」。ファイルやフォルダを選ぶ画面はそのボタンから開くので、iPad でも開ける。
- **自分のテーマのフォルダ。** 「フォルダを選ぶ…」で、自分のテーマのフォルダ（たとえば `~/.egatari/themes`。macOS の選ぶ画面では ⌘⇧. で隠しフォルダが見える）を 1 回だけ選ぶ。その後はコマンドと同じ順と同じ根の決まりでテーマを探す：作業フォルダ → その `themes/` → このフォルダ → 同梱のテーマ。テーマのファイル・ロゴ・`extends` の親は、そのテーマの根（か同梱のテーマ）の外に出ない。フォルダは読むだけで開き、書き込まない。中身は教材のファイルと同じく信頼しない（テーマの CSS は同じ消毒を通り、ロゴは data URI になる）。読むのは、組み立てが使うテーマのファイルだけ。ブラウザはフォルダのハンドルを IndexedDB に残し（中身は残さない）、次に要るときに読む許可をもう一度求める：知らせに「テーマのフォルダ「<名前>」を使う」を出す。「自分のテーマ…」で今のフォルダとそのテーマを見て、「このフォルダを忘れる」で忘れる。Egatari ファイルにエクスポート・保存すると、使った自分のテーマは原稿の `themes/<名前>/` として入るので、ほかの所でも同じテーマで組み直せる（`npm run build -- --portable` で作った Egatari ファイルは、もうそこに入れている）
- **ZIP ファイルのテーマ（自分のテーマ）。** フォルダを選べない Safari・Firefox・iPad も含め、どのブラウザでも「ZIP ファイルを選ぶ…」で `.zip` からテーマを読み込める。ZIP ファイルの中の深さ 5 までの、`tokens.css` のあるフォルダがそれぞれ 1 つのテーマで、名前はそのフォルダの名前（ZIP ファイルの最上位に `tokens.css` があればファイルの名前）。すべて読み込むので、同じ ZIP ファイルの中のテーマどうしの `extends` も解決する。読むのは `tokens.css`・`theme.json`・その `logos` に書いたテーマのフォルダの中のロゴ・最上位の `LICENSE*` だけ。ZIP ファイルは信頼しない：32 MB・3000 項目・テーマのファイルは合わせて 16 MB まで（tokens.css 4 MB、theme.json 64 KB、ロゴは 1 つ 4 MB）。`..`・絶対パス・シンボリックリンクの項目や、1 つの小文字の識別子（`^[a-z][a-z0-9-]{0,63}$`）でないテーマの名前があれば、ファイルごと読み込まず、その項目の名前と次にすることを知らせる。読み込んだテーマは中身ごとこのブラウザに保存し（IndexedDB。テーマの名前ごと）、テーマの一覧の「自分のテーマ」の見出しの下に出す。同じ名前のテーマがもうあれば置き換え、「同じ名前のテーマ「<名前>」があったので、今読み込んだものに置き換えました。」と知らせる。はじめの画面の「自分のテーマ…」は、保存したテーマを見せる名前ごとに並べ、それぞれに「削除」を付ける（確かめてから消す：「「<名前>」をこのブラウザから削除します。読み込んだ ZIP ファイルは残ります。」）。削除したテーマを使う教材は `default` で組み、知らせに「このブラウザに保存したテーマにありません（削除したか、まだ読み込んでいません）。「テーマを読み込む…」で ZIP ファイルかテーマのフォルダから読み込んでください」と出す。組み立ては保存したテーマをテーマのフォルダと同じ場所・同じ順・同じ決まりで読み、テーマのフォルダにも同じ名前のテーマがあれば、あとから選んだ・読み込んだほうを使う（そのようなフォルダを選ぶと「同じ名前のテーマ「<名前>」が、このブラウザにも保存してあります。フォルダのものを使います。」と知らせる）。テーマの ZIP ファイルの作り方：テーマのフォルダを圧縮する（Mac は Finder で右クリック →「圧縮」、Windows は右クリック →「送る」→「圧縮 (zip 形式) フォルダー」）か、GitHub のテーマのリポジトリで「Code」→「Download ZIP」
- **読まないもの：** `.` で始まる名前と、`out/` `audio/` `video/` `bundle/` `node_modules/` のフォルダ（3000 ファイル・10 階層まで）。`audio/` は Egatari ファイルに保存するときだけ読む
- **組み直しはまだ比べない。** スライドを直した後の保存は、同梱の kit でファイル全体を組み直す（なので、古い・新しい build で作ったファイルは直した所の外も変わり、字は分割ファイルごと埋め込む）。直したスライドのほかにどのスライドが変わったかは、まだ見せない
- **字の補いは多めになることがある。** 絞り込んだ字に `unicode-range` のないファイル（前の版がコマンドで作ったもの）では、元の台本の字があることしか分からないので、絞り込んだ字がもう持っている字の分割ファイルも足すことがある（ファイルが少し大きくなる。字が欠けることはない）
- **教材の中からの通信は止まる。** 外部の画像やスクリプト（`https://…`）はプレビューに出ない（build はもともと警告する）

## 仕組みと安全

- **組み立ては 1 つ。** `kit/core/build-core.mjs` が組み立ての本体（注記・取り込み・KaTeX・パーツ・台本・強調・秒数・テーマ・ファイルの埋め込み・字）で、Node に依存せず、渡された口を通してだけファイルを読む。`kit/build.mjs` は Node のファイル（と fonttools の絞り込み・ffmpeg）を、編集アプリは選んだフォルダと同梱の kit・パーツ・テーマ・KaTeX・字を渡す。字の絞り込みを切れば、両方が 1 バイトも違わない HTML を出す（`tools/test-app.mjs` が `examples/minimal` と `examples/tmlr2026-calibration` で確かめる）。台本の解析と書き換え（`kit/core/narration-core.mjs`）と新規作成のテンプレート（`kit/templates/new-deck.mjs`）も同じく共有する
- **編集の画面も 1 つで、教材の外にある。** `server/editor-ui.js`（原稿の欄・台本の引き出し・コメントの欄と一覧）は、ここでは編集アプリのページで、開発サーバーでは外枠のページで動く。どちらも同じ問い合わせ（`/__dev/source` `/__dev/edit` `/__dev/narration` `/__dev/comment` …）を送り、開発サーバーは HTTP で、編集アプリはページの中で開いたフォルダについて答える（`app/devapi.js`）。教材の中にあるのは知らせを送る `server/hints.js` だけ（下）
- **教材は砂場の中で動き、書き込めない。** プレビューは `allow-same-origin` を付けない `<iframe sandbox="allow-scripts allow-modals">` なので、教材は origin を持たない。編集アプリの画面・保存領域・フォルダのハンドルに届かない。`allow-modals` は印刷のため。ページの Content-Security-Policy（アプリ自身の読み込みだけを許し、iframe の移動は許さない：`frame-src 'none'`）に重ねて、プレビューの文書には別の決まりを、教材のどのバイトを解析するよりも前に効かせる。編集アプリはプレビューの文書を「信頼する先頭部分（doctype・`<html><head>`・`<meta charset>`・CSP の `<meta>`・小さな信頼する仲立ち）＋組んだ教材そのまま」として組み、教材の文書の中を探して決まりを入れることはしない。決まりは `connect-src 'none'`、画像・字・スタイル・音声は `data:` / `blob:` だけ（組み立てが埋め込む）、Worker・iframe・フォーム・`<base>` は使えない（`'unsafe-eval'` は、取り下げたパーツの版のためだけにプレビューの決まりに残す。次の項目）。発表者ビューは編集アプリが開く窓で、その中の教材もまた同じ決まりの砂場の iframe。やり取りは編集アプリが中継する
- **編集アプリのページは eval を許さない。許していたのは取り下げたパーツの版のため。** ページ自身の Content-Security-Policy に `'unsafe-eval'` はない（あるのは `'wasm-unsafe-eval'` だけで、MP3 エンコーダの WebAssembly のため。`eval` も `new Function` も許さない。配信版も オフライン版のエディタ `editor.html` も。試験がページの CSP 違反を見張る）。パーツライブラリ v1.0.0・1.0.1 の `m-sweep`・`m-curves` は式を `new Function` で動かすので、パーツライブラリはその版を取り下げ（yank）、置き換えを v1.0.2 とした（[SECURITY.md](../SECURITY.md#components-yanked-by-the-registry)）。取り下げた版を記録した教材を開くと、編集アプリは知らせと **「1.0.2 で組み直す」** ボタンを出し、版を勝手に替えることはしない（仕様 §6。組み直すとパーツの同一性の hash や見え方が変わることがあり、組み直した後の知らせに、どの hash が変わったかを書く）。そのときまでは教材は今のまま再生できるが、プレビューの枠（`allow-same-origin` のない sandbox。編集アプリのページ・保存領域・フォルダのハンドルに届かない origin）の中だけ。枠はこのページの決まりを受け継ぐので、編集アプリの中では取り下げた版の `m-sweep`・`m-curves` は式を計算できず、図の代わりの表示（`DECK.componentErrors`）になり、教材のほかの部分は動く。プレビューの決まり（`PREVIEW_CSP`）と開発サーバーの教材の文書（編集アプリのページを周りに持たない、最上位の sandbox の文書）は `'unsafe-eval'` を残すので、そちらでは取り下げた版も動く
- **頼みではなく知らせ。** プレビューには書き込みを頼む口がない。送れるのは知らせだけ：「この `data-src` の範囲と hash の要素を直したい」（編集モードでダブルクリック）、「この要素にコメントしたい」（Alt+クリック。スライドとステップの鍵、要素の短い引用、点の近くの字、点のスライドの座標）、鍵の `e`・`n`・`c`・`r`・Esc（`r` は録音モードの画面を開くだけ）、今の位置（`deck-pos`）。知らせは書き込む本文を持たない。編集アプリは送り元の窓と知らせの形を確かめ、編集モードでないときの edit の知らせは無視し、今の原稿を自分で読み、範囲が今の組み立ての直せる要素で hash が合うことを確かめて、自分の欄を見せる。書くのは、その欄や引き出しで「保存」か ⌘/Ctrl+Enter を押したときだけ。編集の確認と読むだけのファイルは、これまでどおりこの書き込みにかかる。編集アプリからプレビューに送るのは、見せるのに要るものだけ（編集モードの入り切り・印を付ける要素・「そのステップへ」・印刷・品質チェック）。コメントの点は開発サーバーと同じく確かめる（数だけ、1280×720 のスライドの外は端に寄せ、ほかの項目は捨てる。`app/devapi.js` も `kit/core/comment-core.mjs` でもう一度確かめる）。偽の点で変わるのは印の位置だけで、プレビューの上の印は、編集アプリのページがプレビューの大きさから描く
- **触るのは選んだフォルダかファイルだけ**で、ブラウザの許可を得てから
- **保存は始めたときの教材に結び付く。** 待つたび（組み直し・確かめの窓・編集の確認・保存先を選ぶ画面・ファイルを作る・書く）の後に、同じ教材が開いたままかを確かめ、その確かめを書き込みの中まで運ぶ：その間に別の教材を開いたら、ファイルを入れ替えず（書き込みを取り消す）、ほかにも何も書かない。新しい教材の識別子を教材の設定に書くのと「保存した」にするのは、ファイルを書いた後だけ。保存している間にした編集は、保存したファイルに入っていないので、未保存の印のまま
- **信頼する欄で編集している間**（原稿の欄・コメントの欄を開いている、台本の引き出しで入力している・未保存の変更がある）は、プレビューを `inert` にする。その間は教材からの知らせで板の欄を開け閉め・切り替えせず、編集している台本のステップも替えない
- **フォルダとリンク。** メモリの上・OPFS のフォルダはシンボリックリンクを持てない。選んだフォルダの中のリンクは、Chromium では編集アプリにまったく見えない（一覧に出ず、名前でも開けず、書けない。`tools/test-security.mjs` が確かめる）ので、組み立てがリンク越しにフォルダの外のファイルを読むことはない。File System Access API には編集アプリ自身がリンクを見分ける手段がないので、これはブラウザに頼っている
- **マイクと TTS は編集アプリのページだけで。** 録音（`getUserMedia`・`MediaRecorder`）・取り込み・後処理・MP3 にするのは編集アプリのページで、プレビューからは始められず、プレビューから音声を受け取ることもない。録音は録音モードだけで行い、開いている間プレビューは `inert`。音声の板が音声を作って書いている間は、教材からの知らせで板のステップを替えない。ページの決まりはそのままで通信を許さない：この PC で作る AI 音声は、同じサイトの別の窓（`lab/tts-helper.html`。試験ページと同じく、版を固定したライブラリを jsDelivr から、モデルを Hugging Face から取る）で動かし、窓に送るのは読む文と声の名前だけ。編集アプリはその窓からの音だけを受け、標本化周波数と長さを確かめ、録音と同じく後処理する。フォルダから読む音声には上限がある（manifest は 16 MiB、音声のファイルは 1 つ 64 MiB）
- **Egatari ファイルを開いても、その中のものは何も動かない。** ファイルはバイト列として読み、スクリプトを動かすブラウザと同じ解析の規則で（何も実行しない）Web Worker（編集アプリに同梱。ページの決まりは `blob:` の Worker だけを許す）の中で解析する。そのファイルへ移動したり、ページに入れたりはしない。動くのは原稿から組み直した教材だけで、フォルダのときと同じ砂場のプレビューの中

## GitHub Pages で配る

`.github/workflows/pages.yml` が `node tools/build-app.mjs --out _site` で組み、GitHub Pages に置く（編集アプリは根 `/`、オフライン版のエディタは `/editor.html`、試験ページは `/lab/irodori.html`。前に編集アプリがあった `/editor/` は、問い合わせと `#` を残して `/` へ移すページ）。パスはどれも相対なので、同じファイルが独自ドメイン <https://studio.egatari.org/>（Settings → Pages → Custom domain で設定し、サイト全体に効く）でも <https://egatari.github.io/egatari-studio/>（独自ドメインへ移る）でも動く。置く（deploy）のはリリースのタグだけ：タグ `vX.Y.Z`（数 3 つ。`v0.5.0-rc.1` などの rc のタグは置かない）を push したときと、そのタグで workflow を走らせたとき（その版を置き直す）。`main` への push と pull request は組むだけで（リリースの前に組み立ての壊れに気づくため）、ブランチで走らせると組むだけの試し。リリースの手順は [RELEASING.ja.md](../RELEASING.ja.md)。Pages を設定するまでは何も置かない

1. Settings → Pages → Build and deployment → Source を **GitHub Actions** にする
2. Settings → Secrets and variables → Actions → Variables に `EDITOR_PAGES` = `true` を足す（なければ組むだけで、何も置かない）
3. Settings → Environments → `github-pages` → Deployment branches and tags にタグの決まり `v*.*.*` を足す（この environment はふだん `main` だけを許すので、足さないとタグからの deploy は断られる）
4. リリースのタグを push するか、タグを選んで workflow を走らせる（Actions → pages → Run workflow）

組み立てはサンプルも Egatari ファイルにして `examples/<名前>.ega.html` に置き（`tools/examples-portable.mjs`。合わせて約 14 MB。`--no-examples` で入れない）、編集アプリの最初の画面に並べる。組むのはサンプルのフォルダの一時的な写しから（`examples/` には何も書かない）。`egatari.json` のないサンプル（テンプレートとして写してよい `minimal` など）には名前から決めた `docId` を与えるので、組むたびに同じ文書になる

### リリースに添えるファイル

`npm run release:assets`（`tools/release-assets.mjs`）が同じサンプルのファイルを `out/release/` に組み、`examples.json`（名前・題名・言語・枚数・大きさ・sha256）を添える。どこにも上げない。GitHub のリリースには人の手で添える（たとえば `gh release create v<版> out/release/*.ega.html`）

### 版ごとの URL（凍結した写し）

サイトは v0.4.1 からのすべてのリリースを残す。根は最新のリリース、`/vX.Y.Z/`（たとえば <https://studio.egatari.org/v0.4.2/>）はそのリリースを凍結した写しで、中の形は同じ（`/vX.Y.Z/editor.html`・`/vX.Y.Z/lab/…`・`/vX.Y.Z/examples/…`）。Pages は 1 回に 1 つの artifact を置くので、リリースの deploy が組み立てる（`node tools/site-versions.mjs assemble`）：いま組んだものを根と `/v<その版>/` に、公開済みの前の各リリースからは添えたファイル `editor-site-vX.Y.Z.tar.gz` を取り、リリースの説明の行 `editor-site-vX.Y.Z.tar.gz sha256: <16 進>`（と GitHub が記録するそのファイルの digest）と合うか確かめて `/vX.Y.Z/` に広げる。そのファイルのないリリース（v0.4.0 まで）は飛ばし、sha256 の行がない・合わないときは組み立てを失敗にする。このファイルは組んだ `dist/` を、何度作っても同じバイトになるようにまとめたもの（`node tools/site-versions.mjs asset vX.Y.Z` が、タグの git worktree で `npm ci` してから組む）で、リリースのときに添える（[RELEASING.ja.md](../RELEASING.ja.md)）。根の `versions.json` が版を並べる。`main` への push と pull request でも、同じ組み立てを試しとして走らせる。1 つの版が約 50 MB なので、GitHub Pages の上限 1 GB には約 18 版が入る。800 MB を超えると知らせ、1 GB を超えると失敗にする

- **知らせと一覧。** 写しは上に 1 行を出す：「Egatari Studio v0.4.2（そのリリースのまま凍結した写し）を使っています」・最新版（根。`?lang` は残す）へのリンク・ほかの版の一覧。✕ で隠せる。根は最初の画面の下に版の一覧を出す。この知らせより前に組んだ写し（v0.4.1・v0.4.2）には、組み立てが `index.html` と `editor.html` に根の `version-notice.js` を読み込ませる（決まりの `<meta>` の後に `<script>` を 1 つ。写しのほかの所は変えない）
- **ブラウザのデータは共有。** どの版も同じサイト（同じ origin）なので、ブラウザのデータを共有する：最近開いたもの（IndexedDB の `motion-slides-editor`。ファイルのハンドルと名前だけを持ち、どの版も同じ形で読むので、ある版で開いたファイルはどの版にも並ぶ）・画面の言葉（`localStorage`）・利用者のテーマのフォルダ・この PC で AI 音声を作るモデル（Cache Storage。モデルの版ごとの名前なので、同じモデルの版どうしは 1.26 GB の取得を共有する）。ほかのモデルの版のキャッシュを消すのは根だけで、写しは消さない（`lab/model-cache.mjs` の `inFrozenCopy`）。ただし写しの v0.4.1・v0.4.2 はこの決まりより前のものなので、後のリリースがモデルを替えると、その新しいモデルを消す。最近開いたものの保存の形を将来変えるときは、DB の名前を替えること（古い写しも開き続けるため）。service worker はない。ウェブアプリの manifest の scope は各写しのフォルダ
