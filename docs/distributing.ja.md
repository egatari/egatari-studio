# 参加者に Egatari ファイルを配布する

[English](distributing.md) | 日本語

Egatari ファイルは 1 つの HTML ファイルで配布する：[Egatari ファイル（`.ega.html`）](reference.ja.md#1-ファイル--portable)か、参加者にはふつうその再生専用のコピー（`--play-only`。編集できるスライドと台本を持たず、再生するスライドと音声だけ）。**ダウンロードしてブラウザで開けば**、今のどのブラウザ（Chrome・Edge・Safari・Firefox）でもオフラインで再生できる。困りごとのほとんどは、ファイルを開かずにプレビューだけを見せる場所から起きる。

| 配布の方法 | 参加者に伝えること | 気をつけること |
|---|---|---|
| Google ドライブ（ドライブで共有する Google Classroom も） | 「ファイルをダウンロードしてから、ブラウザで開いてください」 | ドライブのプレビューは HTML を文字で見せるか何も見せず、スライドは動かない。要る人に共有する（または「リンクを知っている全員」） |
| メール | 「添付を保存してから、ブラウザで開いてください」 | メールの大きさの上限（20〜25 MB のことが多い。音声が入ると大きくなる）。学校のメールのフィルターが `.html` の添付を止めたり削除したりすることがある。そのときは `.zip` にするか、ドライブのリンクで送信する |
| LMS（Moodle・Canvas・Classroom など） | 「ダウンロードしてから開いてください」 | ファイルの資料として載せ、選べるなら表示を「ダウンロード」にする。LMS のページの中で表示すると、スクリプトが止められて再生できないことがある |
| 進み具合を取る LMS（Moodle など SCORM 1.2 の LMS） | なし（LMS の活動を開くだけ） | SCORM パッケージをエクスポートし、SCORM の活動として追加する。始めた・完了した・どこまで進んだか・学習した時間が LMS に記録される。[LMS で進み具合を取る（SCORM）](#lms-で進み具合を取るscorm)を参照 |
| 自分のウェブの場所（学校のウェブサーバー・GitHub Pages など） | URL | そのまま開ける。スマートフォンやタブレットでも。静的なファイルを置ける所ならどこでもよく、サーバーでは何も動かない |

**Egatari ファイルが動く場所**（各社の文書で確認、2026-10-23。すべての端末では試していない）：

| 置き場所 | 動くか |
|---|---|
| PC のブラウザでダウンロードして開く | 動く |
| ウェブの置き場所（学校のウェブサーバー・GitHub Pages・Cloudflare Pages など） | 動く |
| Moodle（ファイルの資源、「開く」か「埋め込み」） | 動くはず（実際の Moodle では未確認）。学生の提出物は強制ダウンロードになることがある |
| Google ドライブ・Google Classroom のプレビュー | 動かない（プレビューは中身の文字を見せる） |
| SharePoint・OneDrive・Teams | 動かない（スクリプトの入った HTML はダウンロードになる） |
| iPhone・iPad の「ファイル」アプリ | 動かない（Quick Look は JavaScript を動かさない） |

**iPhone・iPad では** [Egatari Viewer](viewer.ja.md)（`viewer.egatari.org`、ホーム画面の名前は Ega Viewer）で開くよう案内する：[iPhone・iPad で Egatari ファイルを開く（Egatari Viewer）](viewer-sharing.ja.md)。

- **参加者には再生専用のコピーを配布する**（`--play-only`）。編集できるファイルは自分で保存しておく
- **公開の URL は、アドレスを知っている人なら誰でも見られる。** ウェブの置き場所にはサインインがない。授業の人だけに見せたいものは置かない

- **スマートフォン・タブレット：** ファイルのアプリの簡易表示（iPhone の「ファイル」App など）では動かないことがある。ブラウザで開くか、URL を送信する。すべての端末と経路はまだ確認していない。動いた・動かなかった経路を教えてほしい（[感想を送信する](https://github.com/egatari/egatari-studio/issues/new?template=feedback.yml)）
- **授業の前に確認する：** 配布するファイルを、自分のでない計算機で、参加者と同じやり方（ダウンロードしてから開く）で開き、音声付きで 1 枚再生して確認する
- **編集できるファイルは自分で保存しておく：** 配布するのは再生専用のコピーにし、あとで編集するための Egatari ファイルか作業フォルダは自分で保存しておく（再生専用のコピーは編集できない）
- **WebGPU のない PC での音声：** WebGPU のない PC でも、エディタで AI 音声をクラウドで作れる（[AI 音声をクラウドで作る（Google Colab）](editor.ja.md#クラウドで作るgoogle-colab)）。<!-- colab-verified --> 確認済み：2026-10-23、CPU（講習で、Irodori）。2026-10-24、T4 で固定したバージョン（cuda13 の組）：Irodori 23 ステップを 42 秒、Kokoro 59 ステップを 30 秒。2026-10-25、持ち主の手での計測（10 ステップ・話者 1 人。日本語 209 字・英語 518 字）：T4 の日本語（Irodori）は読み込み 34 秒・合成 19 秒、T4 の英語（Kokoro）は読み込み 4 秒・合成 4 秒、CPU の英語は読み込み 7 秒・合成 33 秒（1 ステップ約 3 秒で十分使える）、CPU の日本語は読み込み 1 分・1 ステップ約 60 秒（steps=40）。1 ステップだけの手での計測は steps=40 で 90 秒、steps=16 で 52.5 秒（このバージョンより前の、fp16 の重みで参照音声を毎回符号化していたとき）<!-- /colab-verified -->。**プライバシー：** Colab では台本の文が Google の環境で処理されるので、共有してよい文だけに使う。エクスポートする `tts-job.json` には読み上げる文と声の名前だけが含まれ、ファイルのほかのものは含まれない

## LMS で進み具合を取る（SCORM）

誰がファイルを開始し、誰が終えたかを LMS で見たいときは、ふつうのファイルでなく **SCORM 1.2 のパッケージ**で配布する。Moodle はプラグインなしで SCORM 1.2 の進み具合を記録でき、ほかの多くの LMS も受け付ける。

- **作り方：** エディタの **ファイル ▾ → エクスポート ▸ LMS 用（SCORM）…** で **ダウンロード**。コマンドでは `egatari build <作業フォルダ> --scorm`（または `node kit/build.mjs … --scorm`）が作業フォルダに `<タイトル>.scorm.zip` を書く。保存していない変更のある Egatari ファイルでは、参加者用（再生専用）と同じく、先に保存するよう求める
- **中身：** zip には、再生専用のコピーを `index.html` として（`--play-only` が書くファイルとバイトまで同じ。ダイアログの **確認問題** がファイルの設定と違えば、その `deck-meta` の `completion.checks` だけが違う）と、`imsmanifest.xml`（SCO が 1 つ。識別子は `egatari-<docId>`、題はファイルのタイトル）が含まれる。`index.html` を取り出せば、そのまま再生専用のファイルに戻る。同じファイルからはいつも同じ zip になる（並びと時刻を固定し、圧縮しない）
- **LMS に追加する：** Moodle では **活動またはリソースを追加する → SCORM パッケージ**、ILIAS では **SCORM/AICC ラーニングモジュール** で zip を選ぶ
- **ILIAS の「パーセント」：** 学習進捗の設定で、進捗に数える SCO（このファイル）を選んでいないと、まだ始めていない人も 100% と出る。SCO にチェックを入れると、完了で 100%、それまでは 0% になる（ILIAS の決まりで、ファイルの側では変えられない）
- **LMS に記録されるもの：** 中のプレーヤーが LMS の SCORM の API を見つけ、最初のクリックかキーで「未完了（incomplete）」、進むたびに位置と見たステップ（次に開くと続きから）、ファイルの完了の条件を満たすと「完了（completed）」、閉じると学習した時間を送信する。パーツの問い（「予想と答え」など）があれば点数も送信する：正解のある問いのうち正解した割合を 0〜100 で（`cmi.core.score.raw`。min は 0、max は 100）。合格・不合格はない
- **いつ完了になるか：** `egatari.json` の `metadata.completion` で決まる（エクスポートのダイアログに平たい言葉で表示される）。既定は、すべてのステップをスライドで再生するか本（本のないファイルは台本で読む）で読んだとき。`{"visitedFraction": 0.9}` でステップの 9 割に下げ、`{"reachedEnd": true}` は最後のステップだけ、`"played": true` を追加するとスライドで再生したステップだけを数える。ダイアログの **確認問題** で条件を足せる（`metadata.completion` の `"checks"`。作業フォルダでは選んだものを `egatari.json` に残す）：「すべて答えたら完了」（`"answered"`）か「すべて正解したら完了」（`"correct"`）で、どちらも少なくとも 1 回。問いは、ファイルの中のパーツが宣言したもの（たとえばパーツ集 2.3.0 の「予想と答え」1 つに 1 問）で、ファイルを開いたときに、まだ見ていないスライドの分も数える。問いを宣言しないパーツは問いを持たず、その答えは記録しない。まだ答えていない問いがあれば完了にならず、点数では正解していない問いに数える。一度完了になれば、未完了には戻らない
- **確認問題は試験ではない：** 理解の確認と完了の条件のためのもの。答えはファイルの中にあり、学習者の端末で判定するので、ソースから分かる。成績を付ける試験は LMS の小テストに任せる
- **限り：** SCORM 1.2 で進み具合を送信できるプレーヤーを含むファイルだけ（このバージョンの Egatari ファイルはどれも `deck-meta.tracking` に `scorm12` を持つ）。ステップが多すぎて再開のデータが SCORM 1.2 の 4096 字を超えうるファイル（およそ 8,000 ステップより多い）は断る。ILIAS では、始めた・完了した・続きから・学習した時間が記録されることを確認した（スマホからも）。閉じる間際の送信を受け取れない LMS（ILIAS、Safari 全般）では、続きの位置は最後に記録した所（最後にスライドを切り替えた所）になる

## 教室で映す

- **順番：** 先に発表者ビューを開き（`p`）、それから聴き手のウィンドウをプロジェクターの画面に移動して全画面にする（`f`）。発表者ビューは発表者の画面に残る
- **発表者ビューを閉じる：** 発表者ビューでは、Esc（描くツールを使っていないとき）・`p`・**発表者ビューを閉じる（p）** で閉じ、本体のウィンドウにフォーカスを返す。全画面のときは、全画面をやめるだけ。本体のウィンドウで `p` を押しても閉じる。発表者のウィンドウにフォーカスがない間は、大きな「ここを押すと操作できます」の覆いが最初のクリックを受ける
- **発表者ビューから抜けられないとき：** 画面を覆ったままキーが効かないときは、Mac は cmd+Tab で本体のウィンドウに戻って `p`（Windows は Alt+Tab。Windows ではまだ確認していない）。キーの一覧（<kbd>?</kbd>）にも同じことを書いてある
- **しおり：** `data-bookmark="結果の表"`（20 字までの名前。見せる中身の名前にする）を付けたスライドは、ツールバーと発表者ビューにその名前のボタンが出る。押すとそのスライドの最終状態に飛ぶ。使い道は 2 つ：本編の要所の最終状態へ飛んで戻る（質疑で結果の表を見せ直すときなど）、付録の扉（`data-bookmark="付録の扉"`）へ飛ぶ。`q` で次のしおりへ、**元の位置に戻る** か Backspace で戻る。ツールバーに入りきらないときは、しおりのボタンは 1 つの **しおり ▾** にまとまり、押すと名前の一覧が開く。Studio では **スライド ▾ → しおりを付ける…**
- **黒い画面：** `b` でウィンドウ全体を真っ黒にする。隅に薄く「黒い画面中 — b か Esc で戻ります」が 2 秒出て、マウスを動かすとまた出る。`b`・Esc・クリック・矢印・Space・PageUp/PageDown・Home/End で黒い画面を終え、スライドは動かない。続けるにはもう一度キーを押す

## ライブ（授業中の質問と投票。下書き）

ライブは試用中（プレリリース）です。形式の拡張 `live` は草案なので、結果のファイルの形はまだ変わることがあります

Egatari ファイル（再生専用）に **ライブ**（[形式の拡張 `live`](https://github.com/egatari/egatari-spec/blob/main/extensions/live.md)。下書き）を付けられる。決めたライブの時間のあいだ、ファイルを開いた参加者が、アプリもアカウントもなしに、ファイルの中から質問を送信し、投票に答えられる。ファイルの中でネットワークを使うのはここだけで、参加者が **参加する** を押した後だけ。

1. 編集アプリで **ファイル ▾ → エクスポート ▸ →「参加者用（再生専用）…」** を選び、**ライブ（質問・投票）を付ける** に印を付けて（同じダイアログにライブの設定が表示される）、**ライブ ID と参加コードをこの画面で作る** を押す（乱数から作る。編集アプリはこのときもどこにも接続しない）。ライブの時間（開始と終了）を決め、質問のオン／オフと投票を決める（表示名は 3. を参照）。するとダイアログに **1 本の文字列** が表示される：**文字列をコピー** し、**ホストのページを開く** で開いたページに 1 回だけ貼り、確認を済ませて **このライブを作る** を押す。文字列にはライブ ID・参加コード・ライブの時間・質問・投票の設定がすべて含まれているので、ホストのページでほかに入力するものはなく、編集アプリに何かを貼り戻す必要もない。ホストのページに一度だけ出るホスト用リンクをブックマークしてからエクスポートする（5.）。文字列にはエクスポートするファイルに含まれない秘密の値も含まれているので、ファイルを持っているだけの人はそのライブを作れず、ホストになれない。文字列は参加者に配布しない。**文字列をコピー** の隣の **設定の文字列を保存する** で、小さなテキストのファイル（`egatari-live-setup-<ライブ ID>.txt`）としてダウンロードできる。ホスト用リンクと同じように扱う。貼る前に編集アプリを閉じるかもしれないときは保存しておく：同じ文字列はもう出せず、配布したファイルは誰も作れないライブを指したままになる。文字列はファイル・`egatari.json`・どのエクスポートにも書かない。ライブを作ったあとでライブの時間を変えるときは、ライブ ID と参加コードを作り直して貼り直す。あいだに編集アプリを閉じた（参加コードは保存していない）ときは、ホスト用リンクのページの **Egatari Studio に貼る設定** を前からの方法で貼れば、同じライブのままエクスポートできる

   **前からの方法**（同じダイアログの **ホストのページで先にライブを作った場合** の中）も使える：下の 2.〜4.
2. ライブのサーバー（既定は `https://live.egatari.org`。サービスと通信の仕様は [egatari/live](https://github.com/egatari/live)）のホストのページで **ライブを作る**。ライブの時間（開始と終了）を決める。一度だけ出るホスト用リンクをブックマークする（ライブを操作するためのコードが入っている。なくしたら作り直す）。**待機室を使う** にすると、ホストが許可した人だけが参加できる
3. 編集アプリで **ファイル ▾ → エクスポート ▸ →「参加者用（再生専用）…」** を選び、**ライブ（質問・投票）を付ける** に印を付ける。ホストのページでコピーした **Egatari Studio に貼る設定**（ライブ ID・参加コード・ライブの時間）を貼る。参加者からの質問をファイル全体で受け付けるかを決め、ステップごとに投票（設問と 2〜6 の選択肢）を追加する（**今プレビューに表示しているステップにする** で表示中のステップを入力できる）。投票には、ファイルのどこかを示す表示名が付く（例「4 枚目『XML の壁』・ステップ 1」。スライドの番号、約 24 字で切ったスライドの見出し、ステップの番号。番号は 1 から）。表示名はステップの候補と投票の一覧に出て、スライドの id とステップ（例 `s-cjatth:0`）は吹き出しに表示される。ステップを変えると表示名も変わる。表示名ができる前に保存した投票は、設定を開いたときにスライドがまだあれば付き、なければ id から「s-cjatth · ステップ 1」の形で出る。まだ足りないものは **エクスポートする前に修正すること** に表示される
4. **投票の設定をコピー** し、ホストのページの **投票の設定** に貼る（ライブが同じ投票を知るため。知らない質問・投票や選択肢への投票はライブが断る）。JSON には表示名（`label`。表示のための字で、スライドの id とステップは変わらない）が含まれるので、ホストのページと参加用のページはスライドの id とステップの代わりに「4 枚目『XML の壁』・ステップ 1」を表示し、結果の JSON にも保存される。表示名のないライブでは、投票をスライドの id とステップで出す（「s-cjatth · ステップ 1」。`*` は「ファイル全体」）
5. **ライブを付けてエクスポート…** で Egatari ファイル（再生専用）を書く。配布の方法はいつもと同じ（ダウンロードしてからブラウザで開く）

参加者のコピーのふるまい：

- **ネットワークに出ない：** ライブがない・ライブの時間の外（両端に 2 分のゆとり）・ブラウザで直接開いていない（ファイルかウェブのアドレスから）ときは何もしない。編集アプリのプレビュー、ほかのページの中（LMS・埋め込み）、動画（`?mode=video`）、印刷、発表者ビューでは接続しない。編集アプリのプレビューでは、代わりにライブ ID を字で表示する。ほかのページの中や、接続できない形で見せているとき（チャットのアプリやファイルのアプリの表示、ほかの種類のアドレス）は、**ブラウザで参加する** を出す。ライブの参加用のページ（`https://<サーバー>/join#room=…&key=…`。参加コードは `#` の後ろだけ）を新しいタブで開くリンクで、押すまで何も読み込まない
- **ファイルから接続できる端末：** パソコンのブラウザ（Chrome・Edge・Firefox・Safari）でダウンロードしたファイルを開けば接続できる。Android では、ファイルのアプリからダウンロードしたファイルを Chrome で開いたとき（`content://` のアドレス）も接続できる。参加者が自分で開いたファイルとして扱い、条件は同じ（枠の中でない・ライブの時間の中・コピーの決まり・**参加する** を 1 回押す）。iPhone と iPad では、ダウンロードした HTML のファイルをブラウザで動かせない（ファイルのアプリはスクリプトなしで見せるだけ）ので、ホストのページの **参加用リンク** を使う。参加用リンクはどの端末でも使える。Slack などのチャットのアプリは、大きなコピー（音声入り）をプレビューできないことがあるので、ダウンロードするよう案内する
- **参加の前に 1 回押す：** ファイルは右上の小さな **ライブ** の印だけで始まる。印を押すとパネルが開き、ファイルの接続先を表示して **参加する** を出す。参加中は、パネルをたたんでいても印そのものがずっと見える印になる（緑の点と、読み上げ用の状態の字）。**退出する** は開いたパネルにある。押したことはそのタブのあいだだけ記憶する（新しいタブではまた確認する）
- **送信するのは：** 参加者が送信した質問と投票、入力したときだけ名前、端末で作った乱数の番号（ブラウザの記憶に置く。使えなければメモリだけ）、接続を保つ ping。表示中の位置や時間は送信しない。ファイル全体で受け付ける質問では、「送信」を押したときに表示中のスライドの id とステップを、その質問に付ける
- **要るときだけ開く：** パネルをたたんでいる間、スライドはウィンドウいっぱいに出る。投票のあるステップではパネルが自分で開き（読み上げで知らせ、フォーカスは動かさない）、そのステップを離れるとまたたたむ。**開いたままにする**（ピン）を押したときと、印から自分で開いたときはたたまない。ファイル全体の質問は、どのスライドでも印を押せば質問の欄が開く。**×** か Esc でたたむ
- **スライド（表示領域）の外：** 開いたパネルは右（縦長の画面では下）に出し、スライドは残りの場所に収める。パネルがスライドを隠すことはない（そのかわり、開いている間スライドは小さくなる）。スライド・字幕・印・動画のコマ・印刷は変わらない。投票はそのステップに来たときに出る。サーバーから来た字はすべて文字として出す
- **再接続：** ライブの時間の中でだけ、ライブのサーバーの表のとおりに再接続する。通信が切れたときは間をあけて（1・2・4 … 30 秒、±20%）、ホストがライブを終えた（4423）ときはゆっくり（30 秒より後）、満員（4430）・送信しすぎ（4429）の後は 60 秒より後、まだ早い（4425）ときは開始の時刻に。参加コードが変わった（4440）、ライブの時間が終わった・ライブがない（4410・4404）、参加コードが違う（4403）、同じ人がほかで参加した（4409）、ホストが参加を許可しなかった（4441。**もう一度試す** を出す）ときは、わけを見せて止まり、自分からは再接続しない。待機室では、許可されるまで「待機室で待っています」と出す
- **大きさ：** 既定のサーバーのライブは、同時に 60 人まで、ライブの時間は 3 時間まで。編集アプリは 3 時間より長いライブの時間を断る
- **接続先を絞る：** コピーには CSP（コンテンツ セキュリティ ポリシー）を含め、`connect-src` はライブのサーバー（そのホストの `https://` と `wss://`）だけ。プレーヤーも、WebSocket の行き先が宣言した origin か確認する。接続のアドレスにはライブ ID だけを含め、参加コードと参加する人の乱数の ID は、接続した後の最初のメッセージで送信する（プロキシやサーバーの記録に残らない）。サーバーからは何も（スクリプト・スタイル・画像）読み込まない

ファイルそのものには参加コードのない設定だけを保存する（`egatari.json` と Egatari ファイルの索引の `extensions.live`）。参加コードはエクスポートしたコピーにだけ含まれる。コピーを持っていれば、ライブ中は誰でも参加できる。コピーが広がったときは、ホストのページで **参加コードを変更** すると古いコピーは参加できなくなる（わけを見せる）。コマンドでは `node kit/build.mjs <作業フォルダ> --play-only --live room.json`（`room.json` はホストのページの「コピー」の設定。投票は `egatari.json` の `extensions.live`、なければ `room.json` から）。

**質問（下書き）：** 右下の小さな **?** から、どのスライドでも質問の欄を開ける。質問には、表示中のステップ（欄にスライドとステップを表示する）と、ファイルのこのバージョンが結び付く。**囲む** でスライドの上をなぞって、聞きたいところを囲める（なくてもよい。Esc で終わり、ステップが変わると消える）。質問はホストだけが見る。名前を入力しなければ名前なしで届く。**?** の横の **わからない** は、表示中のステップに文なしの一押しを送信する（もう一度押すと取り消す）。ホストにはステップごとの人数が届く。ホストはホストのページで似た質問をまとめ、短い回答を送信できる。回答は質問した人にだけ届き、ホストが **参加者全員にも見せる** に印を付ければ全員に出る。回答はパネルの **ホストからの回答** に出る（ライブ中にファイルを開き直しても出る）。**参加者用（再生専用）…** のライブの設定に **わからない** の印がある（初めはオン）。

**授業の前に通しで確認する：** ライブの時間が今から始まるライブを作り、エクスポートし、2 台でコピーを開いて参加し、質問と投票を送信して、ホストのページに表示されることを確認する。配布するときは、スマートフォンとタブレットのために参加用リンクも添える。ホストのページの **配布するときの文** に、そのまま貼れる文がある。

**授業の後：結果をファイルに保存する（下書き）。** ライブが残っているうち（既定ではライブの時間が終わってから 24 時間）にホストのページで結果（JSON）をダウンロードし、**ファイル ▾ →「ファイルの情報…」** の添付の **ライブの結果を取り込む…** で取り込む。書く前にファイルを確認する：ライブのサーバーの結果の形（[egatari/live](https://github.com/egatari/live) の Schema のコピー）で、10 MiB までの UTF-8 の JSON で、添付の中身のチェック（形式の §3.8）に通ること。ほかのものは理由を言って断る。結果のライブ ID がこのファイルのライブの設定と違えば知らせるが、それでも取り込める（ライブを作り直したことがある）。役割 `data` の添付になり、名前は `attachments/live-<部屋>-<日付>.json`、題は「ライブの結果（<ライブ ID>、<日付>）」（ライブ ID と始まった日だけ。件数も参加者の字も含めない）、説明は参加者の質問と答えが含まれていること。添付の一覧では「参加者の回答」の印と短い要約（質問の数と、投票ごとの数）を出す。中の字はすべて文字として出す。

結果には参加者が打った字（質問。名前を書いた人はその名前も）が含まれる。はじめて取り込むときに一度だけそう知らせる。結果はこのファイルにだけ保存され、どこにも送信しない。Egatari ファイル（再生専用）には、ライブの有無にかかわらず **決して含まれない**。結果を含む Egatari ファイル（.ega.html）をエクスポートするときは「Live の結果が入っています。配布するときは除いてください」と知らせ、**結果を除いてエクスポート** を選べる（作業フォルダの添付はそのままです）。コマンドでは `npm run portable -- attach <作業フォルダ> <results.json>`（英語の題は `--en`）で同じように追加できる。`npm run portable -- pack <作業フォルダ>` と `node kit/build.mjs <deck> --portable` は同じ通知を出し、`--without-live-results` で除く。
