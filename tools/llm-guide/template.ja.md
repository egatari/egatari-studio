# チャットの AI で Egatari の教材を書く

[English](authoring-with-llms.md) | 日本語

**使う人へ。**チャットの AI（claude.ai・Gemini・ChatGPT など）に、[Egatari](https://github.com/egatari/egatari-spec) の教材（Egatari はオープンなファイル形式、Egatari Studio はその編集アプリ）の初めの下書きを書かせるための指示のまとめです。段階ごとに出る HTML のスライドと、その口述原稿ができます。インストールも Claude Code も要りません。

1. 新しいチャットを開き、**「AI への指示」から最後までをすべて**貼り付け（またはこのファイルを添付し）、作りたいもの（題目・聞き手・長さ・言語・話者）を書きます。編集アプリでも写せます（**AI の出力を貼り付ける → AI への指示を写す**）
2. AI の**返事の全体**を（チャットの写すボタンで）写し、Egatari Studio の **開く ▾ → AI の出力を貼り付ける…** に貼り付けます。エディタが 2 つのファイルを取り出し、どのスライドにも変わらない id を付け、検査して開きます
3. 簡易チェックの知らせを直すか、簡易チェックの板の **AI への直しの依頼を写す** を押して同じチャットに貼り付け、返事をまた貼り付けます（「今のデッキを置き換える」を選ぶ）

# AI への指示

短い **Egatari の教材**を 1 つ書いてください。段階ごとに出る HTML のスライド（`deck.html`）と、その口述原稿（`narration.md`）です。どちらも自動で組まれ、検査されます。ここに書いていないものは使えません。教材は利用者が頼む言語で書きます（スライドと口述原稿は同じ言語）。決まりには **R-fit** のような名前があり、直しの依頼は破った決まりを名前で示します。

**始める前に（よくある失敗）：**

- **2 つの囲みはどちらも最後まで書いて閉じる。**返事が長くなりそうなら枚数を減らし（5〜7 枚で足りる）、囲みの途中で終わらない（R-output）
- **1280×720 のスライドの大きさ**（検査器が測る。R-fit）：本文の場所は 1184 × 443 px（565 px まで。`noconcl` なら 1184 × 558）。本文の字は 32 px で 1 行 46 px なので、入るのは**およそ 8 行**。はみ出す 46 px ごとに 1 行を削る。**図や部品の中も含め、字はすべて 24 px 以上**
- **グラフと図：**部品は大きさによらず字を 24〜28 px で描く（SVG を自分の画素で描く）ので、字ではなく部品の大きさを決める。軸のある図（`m-sweep`・`m-curves`・`m-seq`）は目盛りと名前に左 86 px、上下合わせて 80 px を使うので、高さ **300〜380 px**、幅 **560 px 以上**にする（`<div class="cols">` なら図の列を 55% 以上に）。380 px の部品の下に入るのは短い 1 行、2 行なら 330 px に
- **その場で書く `<svg>`：**字は「表示の幅 ÷ viewBox の幅」で縮むので、viewBox を表示する画素で書く（`<svg viewBox="0 0 560 320" width="560" height="320">`）。`font-size` は 24 以上。`width:100%` と違う viewBox の幅を組み合わせない（幅 600 の viewBox を 580 px で出すと 24 が 23.2 px になる）。合う部品があれば部品を使う

## 1. 出力の形

- **R-output** 返事は**ちょうど 2 つのコードの囲み**にし、この順で、名前を `deck.html` と `narration.md` にする（始まりの行は ```` ```deck.html ```` と ```` ```narration.md ````）。2 つの間には何も書かない（前後に 1 行の添え書きはよい）。1 つのファイルを何個かの囲みに分けない。ファイル・キャンバス・添付では出さず、2 つの囲みをチャットの返事の本文に書く。ほかのファイルを参照しない（画像・`{{FIG:…}}`・`{{JSON:…}}`・外の URL・`<link>` は使わない）。囲みの途中で終わらない（長くなりすぎるなら枚数を減らす）
- **R-noids** スライドの id を**書かない**。`<section class="slide">` に `id` を付けず、口述原稿の見出しにも `{#…}` を付けない。id は取り込みのときにエディタが付ける。すでに id のあるデッキを渡されたとき（直しの依頼）は、今ある `id="…"` と `{#…}` をそのまま残す

## 2. deck.html

### 2.1 骨組み

```html
<!DOCTYPE html>
<html lang="ja" data-theme="default">
<head>
<meta charset="utf-8">
<meta name="viewport" content="width=device-width, initial-scale=1">
<title>教材の題名</title>
</head>
<body>
<div id="stage">
  <section class="slide cover noconcl static"> … </section>
  <section class="slide"> … </section>
</div>
</body>
</html>
```

- `lang`：`ja`・`en` など（教材の言語）。`data-theme`：{{THEMES}} のどれか（ビジネス・ピッチは `business`、国語は `kokugo`、ほかは `default`）
- `<script>` は部品のデータ（§2.6）だけ。`<link>` は使わない。`<style>` は配置（大きさ・間隔）だけに使い、色は書かない

### 2.2 スライド

- 普通のスライド：`<h2>` の見出し、`<div class="body">…</div>`、`<div class="concl"><span>…</span></div>`（結論の行。短い 1 文）
- 表紙：`<section class="slide cover noconcl static">` に、あれば `<div class="venue">…</div>`、`<h1>題名</h1>`、あれば `<div class="au">…</div>`
- `<section>` の class：`noconcl`（結論の行なし）、`static`（段階なし）、`nostep`（箇条書きも初めから全部）、`layout-tate`（縦書きのスライド）、属性 `data-morph`（§2.5）
- `.body` の中：`<p class="sub">` 小見出し、`<div class="big">` 主要な式、`<p class="note">` 補足、`<div class="thm">` 定理の枠、`<div class="cols">` 横並び、普通の `<p>` `<ul>` `<ol>` `<table>`
- 字の強調（字に色を付ける唯一の方法）：`term`（用語・問い）、`emph`（結論・問題・目標）、`muted`（既知の結果・控えめ）、`b`（太字）
- **R-headings** スライドの見出し（表紙は `h1`、ほかは `h2`）は**すべて違う**ものにする（同じになるなら語を足す）。そのスライドの口述原稿の節は `## ` に続けて**見出しとまったく同じ文字列**で始める（`<br>` などのタグは除く）
- **R-colors** 色はテーマだけで：上の class と式のマクロ `\hlE` `\hlT` `\hlM`。16 進・`rgb()`・色の名前・`\color`・`\textcolor` は使わない。部品や SVG の中では：{{contract §3 "**色はテーマの CSS 変数だけ"}}

### 2.3 段階（出す順 = 話す順）

- **R-steps** 段階 0 はスライドが現れたときの姿で、文脈だけ（見出し・小見出し・導入の 1 文）。`data-step="k"`（k = 1, 2, …）の要素は段階 k で現れる。材料（箇条書きの項目・式・表の行・図の部分）は話す順に出す。式とそれを導く 1 文は同じ段階（`<div data-step="k">` で一緒に囲む）。1 枚の段階は 5 前後まで
- 結論の行は自動で**最後の段階** `concl` になる。`data-step` を付けない
- スライドのどこにも `data-step` がなければ、上の階層の箇条書きの項目（`.body > ul > li`・`.body > ol > li`）に 1, 2, … が自動で付く。どれか 1 つにでも `data-step` があれば自動にはならないので、出すものすべてに `data-step` を付ける
- 部品は自分の段階を足す（§3）。`data-from`（既定 1）から始まる
- つまりスライドの段階は `0 … max` と、結論の行があれば `concl`。`static` のスライドは段階 0 だけ

### 2.4 数式（KaTeX。組むときに描く）

- **R-math** 行内は `\( … \)`、別行は `\[ … \]`。式の中の `<` は `\lt`、`>` は `\gt`。KaTeX の標準のほかに使えるマクロ：`\hlE{…}`（emph）`\hlT{…}`（term）`\hlM{…}`（muted）、`\htmlId{ID}{…}`、`\htmlData{mark=ID}{…}`、`\htmlClass{…}{…}`、`\morph{ID}{…}`。`\newcommand` と `\color` は使わない。記号は最初に使う所で定義する（`\(\mu\)`：母平均）

### 2.5 注目の演出とモーフ

- **R-marks** 口述原稿の `{mark:ID}`（§4）は、**同じスライド**の目印に印を付ける。{{contract §7 "目印："}}
- モーフ（なくてよい）：`<section class="slide" data-morph>` は前のスライドの要素を滑らせて今の位置へ動かす。両方のスライドの要素に同じ `data-id="…"`、式の一部は両方に `\morph{ID}{…}`。段階 0 で見えている要素だけが動く

### 2.6 部品

- **R-components** 動く図は一覧（§3）の Web Components `<m-…>` で、`.body` の中に置く。どれにも高さ（`style="height:380px"`）と `aria-label` を付ける。データは子の `<script type="application/json">…</script>` **1 つ**にその場で書く（`{{JSON:…}}` は使わない）。**図の数字は正しく**（計算する。見た目のために値を作らない。架空のビジネスの数字は架空と書く）。関数の式は JavaScript（`Math.exp(x)`・`x**2`）。動きが説明になる所だけに使い、たいていのスライドには要らない

### 2.7 スライドに収める（1280×720。検査器のエラー）

- **R-title** 見出し：日本語は 26 字まで（全角 1・半角 0.5）、英語は 60 文字まで。コロンで終えない
- **R-concl** 結論の行：日本語は 35 字まで、英語は 70 文字まで。1 行
- **R-fit** 本文は 565 px（`noconcl` なら 680 px）より上で終える：1 枚におよそ 8 行・100 字・英語 60 語、または `big` の式 1 つと短い箇条書き 3 つ、または高さ 380 px までの部品と短い 1 行（2 行なら 330 px まで）。入らなければスライドを分ける。字を縮めず、字の大きさを書かない。図の中の字は 24 px 以上
- **R-style** 日本語のスライドは常体（だ・である、体言止め）で、スライドに です・ます を使わない。句読点はデッキ全体で 1 つの組（`、。` か `，．`）。英語のスライドは短い句で

## 4. narration.md

```markdown
# 口述原稿：<教材の題名>

## 減衰の式
[0] 減衰の式です。時刻ごとに残っている原子の数を考えます。
[1] 残る数は、はじめの数に、時間とともに小さくなる指数関数を掛けたものです。
[2] Expert: {mark:n0|circle}{N₀|エヌゼロ} は、はじめの数です。
    Novice: 時刻ゼロのときの数、ということですか。
[concl] 半分になるまでの時間は、崩壊定数だけで決まります。
```

- スライドごとに 1 つの節を、**スライドの順に、すべてのスライド（表紙も）について**：`## <スライドの見出し>`（R-headings）。`{#id}` は付けない（R-noids）
- **R-narr-steps** 段階の印は `[0]` `[1]` … と `[concl]`。**どのスライドのどの段階にも口述原稿を書き**（段階 0 から max まで、結論の行があれば `[concl]`）、**ない段階の印は書かない**（`static` の表紙は `[0]` だけ。結論の行のないスライドに `[concl]` はない。`[01]` とは書かない）。段階の中では、その段階で現れるものだけを話す
- **R-dialogue** 行は `Expert:` か `Novice:` で始める。1 つの段階に何回かの発言を書いてよい（続きの行は字下げ）。話者のない行は Expert。Expert が説明し、Novice が学ぶ人の聞きそうな短い問いを言う掛け合いにする（内容のスライドの多くで。毎段階でなくてよい）。話者が 1 人なら名前を書かない
- `{cue}`：段階の中の同期点。部品の `cues(k)` の 1 つに 1 つ（部品の README が求めるときだけ。ほかは書かない）
- `{mark:ID}`・`{mark:ID|効果}`・`{mark:ID|効果|hold=秒}`・`{mark:clear}`：目印のことを言う言葉の**すぐ前**に置く。1 段階に 1〜2 個まで。言葉でも言う。{{contract §7 "効果："}}
- **R-reading** `{表示|読み}` は **1 つの記号か 1 つの用語**の読み：`{θ|シータ}`、`{N₀|エヌゼロ}`、`{x̄|エックスバー}`、`{論語|ろんご}`。1 つの記号に星・プライム・添え字・ハットやバーが付いていてもよい（`{Q*|キュースター}`、`{x′|エックスプライム}`、`{θ̂|シータハット}`）。表示は普通の文字で書き、LaTeX にせず、式やいくつもの記号にしない（`{1-η|…}`・`{a*b|…}`・`{θとη|…}` は誤り：記号ごとに読みを付け、関係は言葉で言う）
- **R-formula** **式を読み上げない**：口述原稿に LaTeX・`\`・`^`・`_`・`a + b = c` のような文字列を書かない。式の意味を言葉で言う（「残る数は、はじめの数に、時間とともに小さくなる指数関数を掛けたもの」）
- 日本語の口述原稿は話し言葉の です・ます。英語は話し言葉の普通の英語。目安は 1 秒に日本語 5 字・英語 2.5 語。1 回の発言は 1〜3 文

## 5. 直しの依頼

利用者が**直しの依頼**（決まりの名前の付いた問題の一覧と、今のファイル）を貼り付けたら、その問題だけを直し、ほかは変えず、`id="…"` と `{#…}` をすべてそのまま残し（R-noids）、また 2 つの囲みで返す（R-output）。依頼に一部のスライドしかなければ、`deck.html` の囲みにはそのスライドの `<section>` だけを（`<html>` なしで）、`narration.md` の囲みにはその節だけを返す。エディタが id で元の場所に戻す。

## 6. 見本
