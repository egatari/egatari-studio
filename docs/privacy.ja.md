# プライバシー

[English](privacy.md) | 日本語

## このページについて

このページでは、Egatari を作っている私たち（Egatari の開発者）が、Egatari Studio（Egatari ファイルを作るアプリ。https://studio.egatari.org/）と、Egatari ファイルを再生するプレーヤー（Egatari Player）が、インターネットに何を送信し、どの端末に何を保存するかを説明します。

- 対象は、Studio、Studio がエクスポートする `.ega.html`（学習者に配布するファイル）、再生専用のページ Egatari Viewer（https://viewer.egatari.org/）です。
- 書いてあるのは、プログラムの実際の動きです。広告や利用状況の計測は入れていません。
- 学校の IT 担当の方が通信を止めたり確認したりできるように、止め方も書きます。
- 「ライブ」は、授業や発表の最中に、参加者が自分の端末から質問を送信したり投票したりできる機能です。時間を決めて開き、使うかどうかは作成者がファイルごとに選びます。ライブを付けていないファイルは、ライブのサーバーに接続しません。
- コードの中の根拠（ファイルと行）は、英語版の[付録](privacy.md#appendix-evidence-in-the-code-for-maintainers)にあります。

## Egatari ファイルはどこにあるか

- スライド・台本・音声は、作成者の PC の作業フォルダか、Egatari ファイル（`.ega.html`）の中にあります。Studio はそれらをサーバーに送信しません。
- Studio のページは、外部のサーバーへの接続を禁じる設定（CSP の `connect-src 'self'`）で動きます。接続先は Studio のサイト自身だけです。
- 編集中のバックアップは、作成者が選んだフォルダの中の `.cache/edits/` に保存します。上限は 30 個です。
- Google Colab を使うときだけ、作成者が台本の文を自分でエクスポートし、自分で Colab にアップロードします（下の表）。

## インターネットに送信するもの

表の「自動」は、ボタンを押さなくても起きる通信です。「操作」は、作成者や参加者がボタンを押したときだけ起きる通信です。

| 場面 | 送信先 | 送信するもの | 止め方 |
|---|---|---|---|
| Studio のページを開く（自動） | studio.egatari.org（GitHub Pages で配信）。画面を動かすプログラム、フォント、バージョンの一覧（`versions.json`）を同じサイトから読み込む | ふつうのウェブページを開くときと同じもの（IP アドレス、ブラウザの種類など）。サイトを置いている GitHub と Cloudflare の記録は、下の「サイトの記録」のとおり | オフライン版のエディタ（`editor.html` を保存して開く）では、バージョンの一覧を読み込まない |
| AI 音声を「この PC」で作る（操作。初回は確認の画面が出る） | モデルとライブラリの配信元：cdn.jsdelivr.net、huggingface.co、us.aws.cdn.hf.co（Hugging Face の配信用）。この通信は Studio とは別の小さなウィンドウで行う。読み込むプログラムはバージョンを固定し、中身が変わっていないことを確認してから動かす（v0.6.6 から） | ファイルを取得する要求だけ。台本の文やファイルの中身は送信しない。音声は作成者の PC の GPU で生成する | 確認の画面で取り消す。使わなければ何も読み込まない。モデルは「使い方」にある「モデルを削除」で削除できる |
| AI 音声を Google Colab で作る（操作。初回は確認の画面が出る） | 作成者がエクスポートした `tts-job.json` を、作成者が Colab の画面で選ぶ。Colab は Google のサービス | `tts-job.json` の中身：台本の文（読みの辞書を通したもの）、声の名前、ファイルのタイトル（120 字まで）、ファイルの ID、バージョン。スライドとほかのファイルは含まれない。声をまねるために自分の参照音声を選んだ場合は、それも Colab にアップロードする | 「クラウドで作る」を使わず、録音か「この PC」を選ぶ |
| Colab の中（Colab が自動で行う） | GitHub（Studio のプログラム）、PyPI と npm（ライブラリ）、Hugging Face と GitHub のリリース（モデル） | ファイルを取得する要求だけ。Google のサーバーの中で起きる通信 | 同上 |
| 「フィードバックを送信」を押す（操作） | github.com/egatari/egatari-studio/issues/new（新しいウィンドウで開く。フォームは、押した人が送信するまで送信されない） | フォームに最初から入っている欄：バージョン、ブラウザの名前と主なバージョン番号、OS の種類、言語、モード。ファイルの中身は含まれない | ボタンを押さない。`.ega.html` をエクスポートするときに `data-feedback="off"` を付けると、ボタン自体が出ない |
| 「こんなパーツが欲しい…」の窓を開き、「送信」を押す（操作。v0.6.21 から。オフライン版のエディタと、studio.egatari.org 以外のページでは、窓は GitHub へのリンクを出すだけで、どこにも接続しない） | Egatari の開発者が動かす、パーツの依頼の中継（request.egatari.org。Cloudflare Worker）と、Cloudflare Turnstile（challenges.cloudflare.com）。「送信」を押すと、中継が github.com/egatari/components に**公開の Issue** を作る。Issue の作成者の表示は Egatari の開発者の GitHub のアカウントで、送った人の名前は出ない | 窓を開いたとき：確認の枠（中継のページを出した iframe）を request.egatari.org から、その中で Turnstile を challenges.cloudflare.com から読み込む。枠のアドレスには、表示の言語と Studio のサイトのアドレスが入る（枠をその言語で出し、Studio とだけやりとりするため）。確認のため、Turnstile がブラウザの情報と IP アドレスを受け取る（Cloudflare の決まりに従う）。「送信」を押したとき：窓に書いた文字だけ（見せたいもの、書いたときだけ分野と学年・対象）と、確認の答え。Issue の題は、`[request] ` と「見せたいもの」の 1 行目（80 字まで）、本文は 3 つの欄の文字と、Studio から送られたという決まった 1 行。ファイルの中身、名前、メールアドレス、画像、バージョン、端末の情報は含めない。Issue は誰でも読める。中継は IP アドレスを、送り手ごとの回数の上限（1 分に 3 回）と、Cloudflare に Turnstile の答えを確かめてもらうことに使い、何も保存しない | 窓を開かない。学校のネットワークで `request.egatari.org` を止める |
| 手引きやパーツの例などのリンクを押す（操作） | github.com、studio.egatari.org、ライブのホストのページなど | ふつうのリンクを開くときと同じ（行き先のサーバーが受け取るもの） | リンクを押さない |
| ライブ（質問・投票）を使う（参加者が「参加する」を 1 回押す） | ファイルに書いてあるライブのサーバー（既定は https://live.egatari.org。作成者が別のサーバーを指定できる） | 参加者が送信した質問と投票、入力したときだけ名前、端末で作った乱数の ID、接続を保つための ping、参加コード（v0.6.6 から、接続のアドレスには含めず、接続した後の最初のやりとりで送信する）。表示中の位置や時間は送信しない | ライブを付けずにエクスポートする。学校のネットワークで、そのサーバーだけを止める |

補足：
- アクセス解析：Studio とプレーヤーには、アクセス解析のプログラムを含めていません。サイトを置いている GitHub と Cloudflare が残すアクセスの記録は、下の「サイトの記録」のとおりです。
- 外のサーバーからスクリプトを読み込むのは、音声のモデルを取得するウィンドウだけです（バージョンと中身を固定しています）。Studio 本体のページは、外のスクリプトを読み込みません。「こんなパーツが欲しい…」の確認の枠は、中継のページを出した iframe です。Cloudflare Turnstile のスクリプトはその枠の中で動き、Studio のページでは動きません。

## 送信しないもの

Studio とプレーヤーは、次のものを送信しません。

- スライド・台本・音声・画像を Studio のサーバーへ送信することはありません。ファイルを保存したり共有したりする仕組みが、サーバーにありません。
- Studio のプレビューは、外部へ接続しない設定（`connect-src 'none'`）で動きます。
- 読み上げ（ブラウザの音声）には、端末にインストールされている声だけを使います。ネットワーク上の声は選びません。
- 録音は端末の中で処理します。マイクを使うのは、録音のボタンを押したときだけです。
- `.ega.html` は、ライブを付けていなければ、インターネットに何も送信しません（下の節）。
- 学習者がどこを見たかや進み具合を、Egatari のサーバーへ送信することはありません。LMS の中で開いたときと、ほかのページに埋め込んだときだけ、そのページに送信します（下の節）。

## 学習者に配布したファイル（プレーヤー）

- エクスポートした `.ega.html` には、外部への接続を禁じる設定（CSP の `connect-src 'none'`）が入っています。画像・音・フォントには、ファイルの中に含めたものだけを使います。
- 外へ接続できるのは、ライブを付けたファイルだけで、接続先もそのライブのサーバーだけです。条件は次のとおりです。
  - ライブの時間の中であること。
  - ファイルを直接開いていること（LMS や別のページの枠の中では接続しません。枠の中では「ブラウザで参加する」のリンクが表示されるだけです）。
  - 参加者が「参加する」を 1 回押すこと。
- ? のキーの一覧と発表者ビューにある「フィードバックを送信」は、押したときだけ、GitHub を新しいウィンドウで開きます。
- ファイルの中の外へのリンクは、行き先を表示して確認してから開きます。作成者が「埋め込み」（YouTube、Vimeo、Google Maps、OpenStreetMap）を追加したファイルでは、その行き先を表示してよい設定になり、ファイルを開いたときにその行き先から読み込まれることがあります。
- 進み具合の記録：LMS の中（SCORM 1.2）で開いたときは、進み具合（始めた・終えた、読んでいた所、どのステップを見たか、学習した時間。パーツの問いがあれば、どの問いに答えたか・正解したかと、正解した割合の点数）をその LMS に送信します。ほかのページに埋め込んだとき（`?embed=1`）は、同じ出来事を埋め込んだページに知らせます（答えのたびに、問い・正しかったか・選んだもの）。どちらでもないときは、ファイルを開いた人の端末に保存するだけです（上の表）。

## 学校で使うときの確認の方法

CSP（通信を許す相手の設定）で確認する方法：

1. `.ega.html` をテキストエディタで開きます。`<head>` の最初のほうに、`Content-Security-Policy` の `<meta>` が 1 つあります。
2. その中の `connect-src` が `'none'` なら、そのファイルは外部へ接続しません。ライブ付きのファイルなら、接続するのは `connect-src` に書かれた 1 つのサーバー（`https://…` と `wss://…`）だけです。
3. `frame-src` に YouTube などが追加されていれば、そのファイルは埋め込みを使っています。
4. Studio（studio.egatari.org）のページの設定は、`default-src 'self'`、`connect-src 'self'`、`frame-src https://request.egatari.org` です（`frame-src` の中継は、「こんなパーツが欲しい…」の確認の枠のためだけです。v0.6.20 までは `frame-src 'none'`）。AI 音声のウィンドウ（`lab/tts-helper.html`）だけが、`cdn.jsdelivr.net`、`huggingface.co`、`us.aws.cdn.hf.co` に接続します。
5. Egatari Viewer は、通信を許す相手を HTTP ヘッダー（`_headers`）で指定しています。接続するのは Viewer 自身と、ライブのサーバー（既定は live.egatari.org）だけです。

通信を止めたい場合：

- 学校のフィルタで、`cdn.jsdelivr.net`、`huggingface.co`、`us.aws.cdn.hf.co`、`colab.research.google.com`、`live.egatari.org`、`request.egatari.org` を止めてください。止めても、編集・保存・再生はできます。使えなくなるのは「AI 音声をこの PC で作る」、Colab、ライブ、「こんなパーツが欲しい…」だけです。
- 通信なしで使うなら、`editor.html`（オフライン版のエディタ。1 つの HTML ファイル）を配布してください。AI 音声の「この PC」は使えませんが、録音と、前もって作った音声は使えます。
- 作った音声と、エクスポートした `.ega.html` は、通信なしで動きます（ライブを付けていない場合）。

## サイトの記録

サイトを置いている GitHub と Cloudflare は、ふつうのウェブサイトと同じように、アクセスの記録（IP アドレス、ブラウザの種類、開いたページなど）を残します。私たちはその記録を分析や広告に使わず、アクセス解析の仕組みも使っていません。

ライブのサーバー（live.egatari.org）は、ライブの中身（質問・投票・「わからない」の印、入力したときだけ名前、端末で作った乱数の ID）を、そのライブの中だけに置きます。ライブの時間が終わってから猶予の時間（既定 24 時間。ライブを作るホストが 0〜7 日で選べる）が過ぎると、自動で削除されます。結果を保存したいときは、猶予の間にホストのページからダウンロードしてください。

削除された後も、サーバーを置いている Cloudflare の仕組みの中に、最大 30 日分のバックアップが残ります。バックアップに含まれるのは、上に書いたライブの中身だけで、IP アドレスなど、もともと保存していないものは含まれません。このバックアップから戻すには、私たちがそのためのプログラムを作って動かす必要があり、私たちはそれをしません。30 日を過ぎると、バックアップもなくなります。気になる場合は、ライブを付けずにエクスポートするか、自分で用意したライブのサーバーをファイルに指定してください。

IP アドレス、ブラウザの情報、アクセスの記録は保存しません（リクエストの記録も切ってあります）。ライブを作るときだけ、作りすぎを防ぐために IP アドレスを使いますが、保存はしません（Cloudflare の確認の仕組み Turnstile と、回数の上限に使います）。ファイルに別のライブのサーバーが書いてあるときは、そのサーバーの決まりに従います。

パーツの依頼の中継（request.egatari.org）は何も保存しません。文字を検査し、Turnstile の確認を確かめ、GitHub に Issue を作ったら、依頼を忘れます。リクエストの記録も切ってあり、IP アドレスも保存しません。残るのは GitHub の Issue だけです。Issue は公開で、開発者が消すまで残ります。公開するつもりのないことを送ってしまったときは、GitHub の「非公開で報告する」（「問い合わせ」の節）で、Issue のアドレスを添えて削除を頼んでください。
