# 編集アプリ（インストール不要）

[English](editor.md) | 日本語

作業フォルダを直接開き、[開発サーバー](dev-server.ja.md)と同じこと（プレビュー、スライドの上での原稿・台本の編集、コメント）をするウェブページ。[Egatari ファイル（`.ega.html`）](reference.ja.md#1-ファイル--portable)（原稿も中に持つ 1 つの HTML。[Egatari の形式](https://github.com/egatari/egatari-spec)に従う）も、フォルダなしで開き、メモリの上で編集して保存し直せる。インストールもターミナルも要らない。スタート画面は Egatari ファイルを先に置く（「ファイルを開く（.ega.html）…」「新規作成…」。作業フォルダは「フォルダで作業する…」）。

| 形 | 中身 | ここで |
|---|---|---|
| 作業フォルダ | `deck.html`・`narration.md`・`audio/` … の入ったフォルダ。コマンド・AI エージェント（Claude Code・Codex・Gemini CLI など）・ほかのエディタが読み書きする | 「フォルダで作業する…」（Chrome / Edge）で編集する |
| Egatari ファイル（`.ega.html`） | 原稿と音声を中に持つ 1 つの HTML（`--portable`）。ブラウザで開けば再生 | 「開く…」で編集する（どのブラウザでも） |
| 再生専用（`--play-only`） | 原稿を持たない Egatari ファイル | 編集できない（元の Egatari ファイルか作業フォルダを開く） |
| ビルドした HTML（`out/deck.html`） | コマンド（`node kit/build.mjs`）の発表用の出力（編集アプリからはエクスポートしない） | 編集できない（作業フォルダを開く） |

- **ブラウザ：** パソコンの Google Chrome か Microsoft Edge（Windows・macOS・Linux・ChromeOS）。フォルダは File System Access API（`showDirectoryPicker`）を使うので、Safari と Firefox では開けない（スタート画面にそう出て、そこで新しく作る道として「新規作成…」（対話型の生成 AI（ChatGPT・Gemini・Claude など）で作成）を示す）。Egatari ファイルは今のどのブラウザでも開いて編集できる（ファイルを選ぶダイアログがなければ、保存はダウンロードになり、保存のたびにダウンロードに新しいファイルができる。スタート画面と保存の知らせにそう出る：次はいちばん新しいものを開く）
- **通信：** アプリ自身の読み込みのほかは無い。作業フォルダやファイルはブラウザの中で読み書きし、どこにもアップロードしない。「AI 音声をこの PC で作る」（[音声のパネル](#台本の音声音声のパネル)）を使うときだけ、編集アプリのサイトの別の TTS のウィンドウがモデルを取る（編集アプリのページそのものは、そのときもどこにも繋がらない）

## アプリの入手

| 形 | 開き方 | 備考 |
|---|---|---|
| 配信 | <https://studio.egatari.org/> | `main` から `.github/workflows/pages.yml` で公開する。フォントはファイルが使う分だけ読み込む。前の場所 `…/editor/` からはここへ移る |
| オフライン版のエディタ（`editor.html`） | `npm run build:app` のあと `dist/editor.html` をダブルクリック | 約 10 MB（字を全部含めてある）。Chrome・Edge なら `file://` で動く。このファイルを人に渡してもよい |
| 自分のサーバー | `npm run build:app` のあと `dist/` を静的に配信する | どこでもよい（https か `http://localhost`）。サイトのルートと下のパスのどちらでもよい |

`npm run build:app`（`node tools/build-app.mjs [--out dist] [--no-single]`）は先に `npm ci` が要る（バージョンを固定した開発用の依存 esbuild を使う）。

## 使い方

1. **ファイルを開く。** Egatari ファイルはスタート画面の「ファイルを開く（.ega.html）…」か **ファイル ▾ →「開く…」**（[下](#egatari-ファイルフォルダなし)）。作業フォルダ（`deck.html` の入ったフォルダ。`deck.html` がなければフォルダの最上位の最初の `.html`）は編集アプリにドラッグ＆ドロップするか、「フォルダで作業する…」（スタート画面か **ファイル ▾**）を押す。そのフォルダを編集してよいか、ブラウザが 1 回確認する
   - **スタート画面**は上から：**新規作成…**（主のボタン。対話型の生成 AI（ChatGPT・Gemini・Claude など）で作成する。[下](#対話型-ai-で下書きする貼り付けと修正依頼)）、**ファイルを開く（.ega.html）…** とドラッグ＆ドロップの場所、**最近のファイル**、**サンプル**、小さく **パーツの一覧**（[パーツのページ](#すべてのパーツのサンプルparts)の `/parts/` を新しいタブで開く。サイトではサイトのルートからの相対で、凍結したコピー `/vX.Y.Z/` からは `../parts/`。ローカルで開いたオフライン版のエディタでは、ヘルプのパーツのリンクと同じく公開のサイトの <https://studio.egatari.org/parts/>。`app/parts-gallery.js` の `partsIndexHref`）、小さく **Claude Code・Cowork で作る（上級）**（行き先は `app/main.js` の `WITH_CLAUDE_URL` の 1 か所。説明のページは未定）、**フォルダで作業する…**。4 つのファイルの種類の表は使い方（**?**）にある。新しい作業フォルダはコマンドの `npm run new` で作る
   - **続きを開く**：いちばん最近のものが作業フォルダなら、スタート画面の上に **続きを開く：〈フォルダの名前〉**。押すとブラウザが許可を求め、許せばそのフォルダを開く（断ればスタート画面のまま）。ページを再読み込みしたとき（Cmd+R・F5 や、時間を置いて戻ったとき）、そのフォルダの許可がまだあれば（Chrome の「常に許可」など）、押さなくても開き直す。許可がなければ、押すまで許可を求めない。Egatari ファイルは再読み込みすると閉じる（保存していない変更はブラウザに一時保存され、スタート画面の「保存していない変更」から戻せる）
   - **最近のファイル**：作業フォルダと Egatari ファイルがスタート画面に並ぶ（ブラウザがハンドルを IndexedDB に保存する。中身は保存しない）。開き直すとき、ブラウザがもう一度許可を求める（Egatari ファイルは読む許可だけ。書く許可は「保存」のときに求める）。Egatari ファイルが並ぶのは、ブラウザがファイルのハンドルをくれたとき（Chrome / Edge の「ファイルを開く（.ega.html）…」かドラッグ＆ドロップ）だけで、Safari・Firefox では並ばない
   - **サンプル**（配信版だけ）：このリポジトリのサンプル（`examples/`。音声なし）を Egatari ファイルにしたものがスタート画面に並ぶ。いちばん上の列「まず見る」に Egatari の紹介（画面の言語のものが先、もう一方には言語のラベル）とパーツ図鑑（再生だけ。**パーツの一覧** へも）、その下にサンプルの種類のカード **教育**・**ビジネス**・**生活**（添え書きと件数）。カードを押すと、そのサンプルが 1 本ずつのタイルで並ぶ（**戻る** でスタート画面へ）。サンプルが 7 本以上の種類は小見出しで分ける（教育：授業・大学の講義・学会発表・校内研修。授業は教科の順）。タイルは、サムネイル（そのファイルが何をするかがわかるステップ）・題名・場面（教科のある授業は「授業・理科」）・ラベル（本・声・ライブ・縦書き・表示言語と違う言語）・タグ（使っているパーツ。3 つまで、残りは「ほか n と同じ。`tools/examples-sync.mjs --check --lessons` が照らす）。**再生** は同じサイトからファイル（`examples/<名前>.ega.html`）を読み、一覧の sha256（ビルドのときの値）と合うことを確認してから、大きなウィンドウの中でファイルそのもの（自分のプレーヤー）を sandbox 行「構成・テーマ・パーツを引き継ぎます。中身はあなたの題材で新しく作ります」（主のボタンの説明も兼ねる）。**このサンプルを参考に作る**（主のボタン。backlog #130）は新規作成…を、サンプルの使う場面（①）・テーマ（③）・ラベル（④ の伝えたいこと・題材・読み手。サンプルのパーツを順位の一番上に）を入力した形で開く。テーマは、新規作成で選べる同梱のテーマのときだけ引き継ぎ、ほかの名前なら `default` にする（`kit/core/new-deck-pack.mjs` の `sampleTheme`）。紹介のためのサンプルは Egatari のロゴを入れた、そのファイルの中だけのテーマを使うことがあり、それを利用者のファイルに渡してはならないから。① と ③ は答えた 1 行に **サンプルから** のラベル（変えると消える）。④ ではサンプルの伝えたいこと・題材（④ で選べるもの）・学校を選んでおき、サンプルのパーツを順位の一番上にするので、サンプルのパーツから説明が入る（`kit/core/new-deck-pack.mjs` の `sampleChoice`）。② だけが空で開き、タイトルの欄で字を待つ。上に「サンプル「…」から始めます。…② に、作るものの内容を書いてください。」。④ には **サンプル「…」の構成（N 枚の見出しと要点）を指示に添える**（既定で印。外すと指示が小さくなる）：コピーする指示の「頼みたいこと」の後ろに、スライドごとの見出しと要点を、その構成と見せ方に倣うように添える（`kit/core/sample-info.mjs` の `sampleStructureRequest`。サンプルの全文は含めない。構成案ではないので、枚数は ② の長さ（なければ短く）に合わせて縮めさせる。2 回に分けて依頼するかは ② の長さだけで決まる）。作成すると `egatari.json` の `studio.newDeck` に `fromSample`（サンプルの名前）。コマンドの `node kit/llm-pack.mjs --from-sample <名前> [--request <文|ファイル>] [--plan free|paid] [--lang ja|en]` は、② にタイトル（`--request` の 1 行目。残りは内容）を書いて ④ でコピーする指示とバイトまで同じものを出す（サンプルのラベルとパーツの順位で組んだもの。ビルドは `kit/core/new-deck-pack.mjs` を編集アプリと共有し、`tools/test-app-from-sample.mjs` が 4 つのサンプル × 軽量・詳細 × 言語で比べる）。**コピーを開いて編集**（小さく）は、選んだファイルとまったく同じように開く（取り込みの確認も同じ。`tmlr2026-calibration` は独自のパーツがあるので動かす前に確認し、最初の編集の前に編集の確認を出す）。**閉じる**。egatari.org のサンプルのページの「Studio でこのサンプルを参考に作る」は `?from-sample=<名前>`（`examples.json` の名前。例：`kokugo-kanbun`）で同じ新規作成を開く（`?lang=` と一緒に使える。読んだら URL から引数を削除する）。サンプルの一覧はそのバージョンのアプリに組み込んであり、何も読みに行かないので、サイトのルートでも凍結したコピー（`/vX.Y.Z/`）の中でもそのバージョンのサンプルで開き、オフライン版のエディタ（`editor.html`）でも開く。一覧にない名前は、ふつうの新規作成を開き、上に 1 行「サンプル「…」が見つかりません。新規作成を開きました」を出す。サンプルごとの `examples/<名前>/sample.json`（AI への指示・使う場面・テーマ（引き継ぐのは新規作成で選べる同梱のものだけ）・パーツ・構成・本の有無・言語・権利）は、ビルドが確認して一覧に追加する（`tools/examples-portable.mjs`。正しくなければビルドしない）。オフライン版のエディタ（`file://` の `editor.html`）には出ない
2. **編集する。** キーは開発サーバーと同じ（ツールの列にもボタンがある。右のパネルの見出しになるまでは、仮の群 **編集 (e)**・**台本 (n)**・**コメント (c)**・**音声**）

   | キー | すること |
   |---|---|
   | `e` | 編集モード。枠の出た要素を**ダブルクリック**すると原稿（HTML と `\( … \)` の式）が開く。⌘/Ctrl+Enter で保存 |
   | `l` | 先のステップを薄く見せる（オン／オフ。字幕と同じ選択）：全部のステップを見せ、まだ来ていないステップを薄くする（`--preview-opacity`、既定 0.45）。今のステップに印は付けない。`data-preview="none"` を付けた答えは隠したまま。`?mode=talk&preview=1` と同じ |
   | `n` | 表示中のステップの台本の引き出し（話者、発言の追加・削除・並べ替え。語の読み方は下の **読み方…**） |
   | Alt+クリック（Mac は ⌥ option+クリック） | その要素について コメントを保存する（`comments.json`）。押した点もピンとして保存される |
   | `m`（編集モードのバーの「マーカー（m）」のボタン、編集中は「マーカー」（キーは m）になるスライドのツールバーのペンのボタンでも。`d` でも開く） | マーカー（編集モードの間だけ）：スライドに丸や矢印を描く。描き終えるとその印についてコメントの欄がサイドパネルに開く。欄が開いている間は続けて描け（矢印と丸、いくつもの印。20 本まで）、どの線も同じコメントの印になる。「保存」で全部の印をコメントと一緒に保存し（`strokes`）、「キャンセル」で全部破棄する |
   | `c` | 未対応のコメントの一覧（番号付き）。開いている間、表示中のステップのピンがスライドの上に出る。クリックでそのスライドとステップへ（ピンが光る）、「解決」で対応済み |

   編集モードのバー・原稿の欄・台本の引き出し・コメントの欄と一覧は、どれも右の 1 つのパネル（プレビューはその横に縮む）にあり、パネルの上には橙のバー **編集中 — アプリ** が付く。どれもファイルの中身ではなく編集アプリのページの一部。**スライドの場所に見えるものはファイルが描けるもの。信じてよいのはエディタ自身のパネルのツールだけ。** 原稿の欄・コメントの欄を開いている間、プレビューはクリックを受けない。プレビューはダブルクリックや Alt+クリックの場所を知らせるだけで、原稿を読み・見せ・「保存」（か ⌘/Ctrl+Enter）を押したときに書くのは編集アプリ。キーはプレビューの上でも編集アプリの上でも効く

   **読み方…**（backlog #101）は、台本の引き出しの語や記号の読み方を付ける。語を選んで（カーソルを語の中に置くだけでもよい。そのときはカーソルの所の語。Word の「ルビ」と同じ）発言の下の **読み方…** を押す。発言の下に小さな欄が開く：**「θ」の読み方**、読み方（その語の読み、なければ同じ台本のほかの所の読み、なければ辞書の読みが入り、どこから入力したかを 1 行で添える）、**読み上げで聞く**・**AI 音声で聞く**（読みだけを、この端末の読み上げか、この PC の AI 音声で。AI 音声は動く所でだけ出す。何も保存しない）、**この台本のすべてに（ほかに n か所）**、**辞書に登録**、**付ける**・**キャンセル**（Enter・Esc）。読みの付いた語なら **読み方を外す** も。
   - 保存するのはいつも `narration.md` の読みの書き方 `{θ|シータ}`（format spec §8.3）。音声はどこで作っても台本だけで決まる。引き出しは `{}` を見せない：読みの付いた語は、その上に小さく読みを出し（ルビ）、押すと読み方の欄が開いて編集・削除できる。カーソルはその語を 1 字のように飛び越え、Backspace・Delete は語ごと削除する。元に戻す・やり直し（⌘/Ctrl+Z、⌘/Ctrl+Shift+Z、Ctrl+Y）は欄が自分で持つ：打った字はまとめ、読み方を付ける・外すのはそれぞれ 1 つ。コピー・切り取りは原稿の文字（`{θ|シータ}`）をクリップボードにコピーし、貼り付けは文字だけを入力して（発言は 1 行なので改行は詰める）読みをルビで見せる。手で `{x|y}` と打った所は、引き出しを開き直すまで打った形のまま。発言の中の Enter は何もしない（発言は 1 行。新しい発言は「＋ 発言を追加」）。
   - 選べるのは 1 つの語か記号だけ（R-reading）：空白・句読点・式（`1-η`・`θとη`）を含む、読みや `{cue}` などの印にかかる、25 字以上、2 つの発言にまたがる選び方は、何を選べばよいかを 1 行で添えて断る。`Q*`・`x′`・`θ̂`・`N₀`・`L殻`・`t-SNE` は 1 つの語。
   - **この台本のすべてに** は、その語の読みの付いていない所すべてに付ける：このステップの中はその場で（元に戻せる）、ほかのステップはこのステップを保存したときに（足もとに「保存すると、ほかのステップの 4 か所にも読み方を付けます」と出る。`narration.md` のバックアップは `.cache/edits/`）。語は丸ごと当てる：`MySQL` の中の `SQL` は変えず、漢字で終わる語は長い漢字の語の中では変えない（`tts/yomi.py` と同じ）。変えるのは発言の文だけで、見出し・`@x-` の行・注は触らない。
   - **辞書に登録** は、語と読みの組をこのブラウザ（`localStorage`。台本の言語ごと、1000 語まで）に保存する。日本語入力のユーザー辞書と同じ。あとで同じ語を選ぶと（どのファイルでも）その読みが入る。付けるのは人なので、台本にはいつも読みが書かれる。辞書にある語はチェックが入った状態で開き、外して「付ける」と辞書から消える。データを保存できないブラウザ（プライベートウィンドウ・サイトのデータを止めた設定・保存に失敗する場合）では、このチェックを押せなくし、わけを 1 行で出す（「このブラウザでは辞書を使えません…読み方はこのまま付けられます」）。ほかはそのまま使える。AI 音声の読み辞書（`tts/yomi.yaml`）とは別のもの：読み辞書は合成の直前に日本語だけに当て、誤読を測った語だけを載せる。ブラウザごとの語を合成のときに当てると、台本が同じでも PC ごとに音声が変わってしまう。
   - 開発サーバーの引き出しにも同じ欄がある（聞く 2 つのボタンはない）。

   **編集モードと発表のツールは同時に使わない。** 編集モードに入ると、レーザーポインター・ペン・消えるペンを切り（書いた線は見えたまま残り、その上には描けない）、自動再生と音声を止め、スライド一覧・黒い画面・キーの一覧（?）・全画面・打ちかけのページ番号を閉じる。授業と字幕はそのまま。編集している間は、ツールバーのボタン（自動再生・レーザーポインター・消えるペン・色・消す・一覧・全画面）を隠し、そのキー（`x` `v` Shift+`d` Backspace `o` `a` `b` `f`）は効かない。ペンのボタンだけは同じ絵のまま **マーカー** という名前で残り、そのボタンとペンのキー `d` は、ペンの代わりにマーカーを入り切りする（上の表）。発表者ビューでツールを選んでも切れる。編集モードを出ても、どれも元には戻さない。入力欄（原稿の欄やスライドの中の入力欄）で打ったキーは、いつも字として入り、ツールやスライドの操作にはならない。今のモードはステータスバーの右端に出し（**編集中**・**発表のツール：ペン**・**表示**）、読み上げソフトにも知らせる。スライドには重ねない

   開発サーバーと同じく、プレビューをビルドした後にファイルが変わっていれば（原稿の hash・台本のバージョンが合わなければ）保存しない。再読み込みしてからもう一度

   **Esc** で、開いているウィンドウを上のものから 1 つずつ閉じる：書いている途中の原稿の欄・コメントの欄、次に音声のパネル・[録音モード](#録音モードキーボードだけで録音する)・台本の引き出し・コメントの一覧・サイドパネル（品質チェック・ファイルの情報・使い方）のうち後に開いたもの。**Shift+Esc** で全部を閉じる。台本の引き出しに保存していない入力があれば先に確認する。確認のウィンドウと一覧は、これまでどおり Esc で閉じる

   **保存の場所。** ステータスバーの左端に、今どこに保存されているかをいつも出す（ツールチップに詳しく）。作業フォルダは「作業フォルダ「…」に保存済み」：各欄の「保存」と録音・取り込み・TTS がその場でフォルダに書くので、**ファイル ▾ →「保存」** は押してもわけを言うだけ。Egatari ファイルにするには **ファイル ▾ →「名前を付けて保存…」**（編集可・`.ega.html`）。Egatari ファイルは「「…」に保存済み」（「保存」で上書き）、ブラウザが上書きできないときは「「…」を開いています（保存はダウンロードに）」（「保存」のたびに新しいファイルがダウンロードされる）、メモリの上にだけ変更があるときは **保存していない変更があります**（タブを閉じると録音も含めて消える）、メモリの上にだけあるファイル（対話型 AI の出力を貼り付けた・スライドのファイルだけを開いた）は **まだファイルに保存していません**
3. **AI エージェントと一緒に。** AI エージェント（やほかのエディタ）がフォルダを変更する間も開いたままでよい。約 1.5 秒ごとにファイルを見て、変わったら再ビルドし、同じスライド・ステップのままプレビューを再読み込みする。原稿の欄や台本の引き出しで入力中のものは、プレビューを再読み込みしても消えない（編集アプリのページにある）。その間に同じ要素やステップが変わっていれば、保存は断る。ビルドに失敗したら、修正されるまでプレビューの上にエラーを表示する
4. **ツールの列。** **ファイル ▾**・**スライド ▾**・**品質チェック**・**プレビュー ▾** の 4 つ（と仮のパネルの群、使い方の **?**）。幅 1280 px 以上なら 1 行に収まり、それより狭いと折り返す。一覧は ARIA のメニューボタンの形：ボタンの Enter・Space・↓ で開いて最初の項目へ、↑ で最後の項目へ。一覧の中は ↑↓ で移り（端で回る）、Home・End で端へ、字でその字で始まる項目へ、→ か Enter で **エクスポート ▸** を開き、← か Esc で閉じる。Esc で一覧を閉じてボタンに戻り、Tab や外を押しても閉じる。一覧や確認のウィンドウが開いている間は、キーをプレビューに送信しない（`e`・`n`・`c` の切り替えにもならない）

### 発表者ビューでの参加者の入力

発表者ビューの「今の画面」で、`m-predict` の数を入力したり、タイマーの **＋1 分／−1 分** ボタンで時間を変えたりできます。本体と「今の画面」には同じ数と延長時間が表示され、本体での変更も発表者ビューに映ります。「次」の画面は作者の値を表示します。入力欄や操作の中のキーはそのパーツが使うので、数を入力してもスライドは進みません。タイマーのボタンをマウスで押した後は、Space でいつもどおり進められます。

数と延長時間は、同じスライド内のステップを進めても戻しても残ります。別のスライドから入ったときや、スライドへ跳んだとき（今いるスライドへのジャンプも含む）に作者の値へ戻ります。動画モードでは参加者の入力を受け付けず、台本・作者の指定した時間・タイムライン・動画・印刷の出力は変わりません。

## スライド一覧（挿入・複製・削除・並べ替え）

プレビューの左の端の **スライド一覧** のつまみで、そこに一覧を開きます（✕ で閉じます）。スライドを順に、そのスライドの最後のステップのサムネイルと見出しで並べます。サムネイルはファイル自身が、一覧の後ろの sandbox の枠に描きます（プレビューと同じ決まり。クリックを受けず、読み上げソフトにも出しません）。一覧・ボタン・確認のウィンドウは編集アプリのページのものです。開いていたかどうかはこのブラウザが記憶します。

- **選ぶ**：スライドを押すか、一覧で ↑ ↓ Home End。プレビューもそのスライドへ動きます。プレビューを動かすと、選択も付いてきます
- **スライドの挿入 ▾**：選んだスライドの後ろに、テンプレートからか、対話型 AI で作成して（**対話型 AI で作成…**。下の「スライドの挿入…」）新しいスライドを挿入します。テンプレートは**見出しと本文**・**2 列**・**図**（点線の枠と図の説明）・**章の扉**（`sec`）・**引用**（`box` と `cite` の行）。id（`s-xxxxxx`。文書の中で使っていないもの）はエディタが付け、台本に `## 見出し {#id}` の節を、前のスライドの節の後ろに、ステップごとの仮の 1 行と一緒に追加します。仮の行は印 `✎` で始まり、テンプレートの字も決まっている（どちらも `kit/core/template-text.mjs` に 1 か所で書く）ので、修正し忘れが見つかります。品質チェック（ここと `npm run check`）は警告にし（`narrPlaceholder`・`templateText`）、TTS の前（音声のパネル・Colab の `tts-job.json`・`tts/synth.py`）と Egatari ファイルをエクスポートする前（編集可・再生専用・ライブ。`--portable`・`--play-only`）に、エディタかコマンドが先に一覧を出します。続けることもできます（**このまま作る**・**このままエクスポート**）。修正しないと、TTS が仮の文を読み上げ、字幕と読める層にも入ります
- **画像を挿入…**：スライドの本文に画像を 1 つ挿入します（handoff #85）。画像は選ぶ（PNG・JPEG・WebP・SVG）か、ウィンドウに貼り付けるかドロップします。編集パネルの HTML の欄にドロップしても同じウィンドウが開きます。**置き方**は本文の中（全幅・半分・3 分の 1）・2 列の左・2 列の右のどれかで、縦横比を保って幅に合わせます（自由な配置と切り抜きはしません。はみ出しは品質チェックが知らせます）。**代替テキスト**は必須で、**飾りの画像（読み上げない）**に印を付けると `alt=""` になります。**出すステップ**でステップ（`data-step`）を選べます。画像は `<img src="data:…">` として `<div class="fig">` に入れ、`.body` の終わり（結論の行の前）か `.cols` の列に置きます（2 列でなければ 2 列にします）。作業フォルダでも同じです。1 MB を超える画像には、小さくしてから入れることをすすめる知らせが出ます。ほかのスライドの操作と同じく元に戻せます
- **しおりを付ける…**：スライドにしおりを付けます（`deck.html` のその `section` の `data-bookmark`。名前は 20 字まで、既定は **質疑用**）。発表のときは、ツールバーと発表者ビューのしおりのボタンでそのスライドにすぐ飛べます（質疑で結果を見せ直すときなど）。`q` で次のしおりへ、**元の位置に戻る** か Backspace で戻ります。しおりのあるスライドでは、同じメニューに **しおりの名前を変更…** と **しおりを外す** が出ます。ほかのスライドの操作と同じく元に戻せます
- **複製**：選んだスライドのコピーを、新しい id ですぐ後ろに挿入します。台本はコピーし、音声はコピーしません。コピーのステップは、録音するか作るまで一覧に **音声が要るステップ N** と出ます
- **削除**（一覧で Delete キーでも）：先に確認します。ウィンドウにはスライドの名前と、一緒に消えるもの（台本の節、`audio/manifest.json` の音声の記録とそのファイル（ほかのステップが使っているファイルは残す）、録音してまだ使っていない音声）を出します。音声の更新が必要なときの決まり（形式 §5.4）と同じく、黙って作り直したり削除したりはしません
- **並べ替え**：一覧の中でドラッグするか、**↑** / **↓** を押すか、一覧で Alt+↑ / Alt+↓。id は変わらず、台本の節も同じ順に並べ替え、音声は id で付いたままです
- **元に戻す**（一覧の上）：直前のスライドの操作を取り消します。原稿・台本・音声の記録と削除した音声のファイルを、エディタが記憶している前の中身で書き戻し、使っていない録音も音声のパネルに戻します。次のスライドの操作まで、Egatari ファイルを保存するまで、別のファイルを開くまで使えます。その間に 3 つのファイルのどれかが変わっていれば（編集・外のツール）戻しません。どの操作でも、書き換える前のファイルは `.cache/edits/` にバックアップします

操作のたびに、`deck.html`・`narration.md`・`audio/manifest.json`（変わったものだけ）を書き、再ビルドし、そのスライドを見せて品質チェックを出します。読み上げソフトには何をしたかを知らせます（live region）。Egatari ファイルでは変更はメモリの上にあり、次の **保存** でファイルを再ビルドします（段 B）。再ビルドしない保存ではスライドの並びを変えられないためです（形式 §7.2。エディタの段 A の保存は `source-changed` で断り、再ビルドしてよいかを確認します）。台本だけを編集できる Egatari ファイル（プレーヤーかパーツライブラリのバージョンが違う）と読み取り専用の Egatari ファイルでは使えません。スライドの id が重なっているファイルは、先に修正する必要があります（理由を出します）。id のないスライドは見出しから決めた名前のままで、挿入したスライドとコピーしたスライドには必ず id を付けます

## 台本の音声（音声のパネル）

ツールの列の **音声** は、同じ信頼するサイドパネルに欄を開く。フォルダでも、開いた Egatari ファイルでも同じに使える。上から 3 つの部分（設計はプロジェクトの覚え書きの `handoff/audio-flow-2026-10-25.md`。backlog #82・#83・#85・#89）：

- **A. このファイルの音声**（いつも上）：状態の 1 行と、ボタンは多くて 1 つ。1 行は、音声のあるステップの数（「まだ音声がありません（8 ステップ）」「8 ステップのうち 5 ステップに音声があります」「8 ステップすべてに音声があります」）、台本が変わって更新が必要なステップの数、声を変えた後も前の声のままの AI 音声のステップの数（`inputHash` は声を含まないので、AI 音声の記録の `recipe.voice` と今の声（Egatari ファイルの選択、なければ `voice.json`、なければ既定）を比べる。`recipe.voice` のない記録と dry-run の音声は数えない）。Egatari ファイルでは「保存するまでファイルには入っていません」を追加する。ボタンは、音声のないステップがあれば **残りの音声を作る（n ステップ）**、古いステップか前の声のステップだけなら **音声を更新（n ステップ）**、Egatari ファイルで作るものがなければ **保存**、音声が 1 つもなければ出さない（B を開いておく）。ボタンは、いちばん新しい音声のやり方で続ける：録音（その最初のステップで録音モードを開く）・クラウド（そのステップの台本をエクスポート。手順 1）・この PC（そのステップを作る）。いちばん新しい音声は、ここで最後に書いたステップの記録、なければ（manifest に時刻はないので）台本の順で最後の、やり方の分かる記録。やり方は記録から決める：`kind: "recorded"` は録音、`kind: "tts"` で `recipe.processing` に `+colab` があればクラウド、ほかの AI 音声はこの PC。取り込んだ音声はやり方に数えない。やり方はどこにも保存しない（前の `egatari.json` の `studio.audioMethod` は読まず、書かない）。やり方が分からない・この端末で使えなければ、ボタンは B を開く。
- **B. 音声をどう付けますか**（初めは開き、全部のステップに音声がそろうとたたむ）：答えはこの順：**自分の声で録音する**（**録音モードを開く (r)**。音声のない最初のステップから）、**AI 音声をクラウドで作る（Google Colab）**、**AI 音声をこの PC で作る**（このブラウザで作れるとき、つまり配信版か配布した編集アプリで WebGPU があるときだけ出す。初めてのときにモデルを取得すると添え、**この PC で作る（n ステップ）** を出す。スマートフォン・タブレット・メモリの少ない端末では、出すが選べず、「この端末では AI 音声を作れません。クラウド（Google Colab）で作ってください」と 1 行添える）。開いたときの答えは、いちばん新しい音声のやり方（録音 → 録音、Colab の AI 音声 → クラウド、この PC の AI 音声 → この PC。この端末で作れなければクラウド）。音声がなければ録音。ここで選んだ答えは、作業フォルダかファイルを切り替えるまで記憶する。AI 音声のやり方を選ぶと、その中の 1 行目に **声** と **▶ 試聴**（1 つ、掛け合いなら **説明する人の声**・**質問する人の声**。新規作成の ② と同じ言葉）を出す：クラウドは手順 1 の上、この PC はボタンの上。録音を選んでいる間は出さない。
- **C. このステップ**（表示中のステップ。スライドに付いていき、音声を作って書いている間はそのステップのままで、スライドが動いたらそう知らせる）：見出し「スライド 3「…」・ステップ 2」、今の音声（「AI 音声 · 5.2 秒」「録音 · 4.8 秒 · 更新が必要」「まだ音声がありません」）、ボタン **▶ 聞く**・**読み上げで聞く**・**● 録音 (r)**・**ファイルから取り込む…**・**↶ 前に戻す**・（この PC で作れるときだけ）**この PC で作り直す**、そのステップの台本（表示のみ。編集は「台本」のパネルで）。`{cue}`・`{mark}` があれば「動きに合わせる所が n 個あります（録音では C で設定できます）」。

細かいこと：

- **今の音声。** `audio/manifest.json` にあるステップの音声を再生する（フォルダやファイルから編集アプリのページで読む。プレビューからは受け取らない）。**▶ 聞く** で鳴らし、種類（**録音**・**AI 音声**・**取り込み**）、長さ、出どころ（TTS ならエンジン・モデル・声・シード）も出す。**更新が必要** の印は、音声を作った後に台本が変わったか、どの台本から作ったか分からないこと（format spec §5.4：`inputHash` が `null` か今の台本と違う。`inputHash` のない前の `tts/synth.py` の manifest では、TTS のバックアップ `audio/seg_<digest>.json` で比べる）。古いステップは、品質チェック（ビルドの警告）と `npm run check` にも出る。読み上げるためのステップの台本も出す：欄は台本の長さに合わせて伸び（パネルの半分ほどまで）、右下の角で大きさを変えられる。掛け合いの台本では各ターンに Expert か Novice の印を付ける（台本の書き方。声の欄は説明する人・質問する人）。**↶ 前に戻す** で、最後に作った音声の前にそのステップが持っていた音声に戻す（下を参照）。
- **録音。** **● 録音 (r)**（と B の **録音モードを開く (r)**。音声のない最初のステップで）は、パネルのステップで[録音モード](#録音モードキーボードだけで録音する)を開く（録音の方法は 1 つ）。1 段だけなら **Space** で録音を始め、話して、もう一度 **Space**、そして **Esc**：パネルに戻り、そのステップの新しい音声を見せる（パネルは録音モードの裏で開いたまま）。録音モードは台本を大きく出してその横にメーターを置き、録音した音声はすぐにそのステップの音声にする。ここの **↶ 前に戻す** でそのステップの前の音声へ順に戻れる（音声のファイルは削除しない）。
- **ファイルから取り込む…** は WAV・MP3・M4A・Ogg・WebM・FLAC を読む（64 MiB まで。大きさは読む前に確認する）。録音と同じく、すぐに使う。
- **声。** 話す役ごとに 1 つ（1 人の語りなら 1 つ、掛け合いなら Expert と Novice）の欄で選ぶ：日本語の台本は `bob` と `alice`、英語の台本は Kokoro の声（米・英の 8 つ。残りは **ほかの声** に畳む）。**▶ 試聴** で事前に作った短い音声を鳴らす（`lab/voices/samples/`。モデルは読み込まない）。作業フォルダでは選んだ声を `voice.json` に書く。Egatari ファイルではこの表示を開いている間だけ記憶し（`voice.json` を変えると保存が再ビルドになるため）、作った音声の記録には使った声の名前が残る。`voice.json` の声が、この PC で作る AI 音声にないときは、日本語も英語も同じに扱う：パネルがそう知らせ、TTS はその役の既定の声（`bob`・`alice`、または `am_michael`・`af_heart`）で作る。TTS のウィンドウは知らない名前を断る（黙って別の声にしない）。
- **AI 音声をこの PC で作る**（B。音声の要るステップをまとめて）と **この PC で作り直す**（C。そのステップ）は、ブラウザの中で AI 音声を作る：日本語の台本は Irodori-TTS 500M-v3（読み辞書 `tts/yomi.yaml` を `tts/yomi.py` と同じ規則で通す。声は `voice.json` のもの、既定は `bob` と `alice`。シード 0、ステップ 40。ローカルの mlx のサーバーもシード 0 だが、ブラウザは別の乱数の作り方で雑音を作るので、ローカルで作った音と波形は同じにならない）、ほかの言語は Kokoro-82M v1.0（`bob` → `am_michael`、`alice` → `af_heart`。`voice.json` に Kokoro の声の名前を書いてもよい）。`{cue}`・`{mark}` で分けた部分ごとに合成して後処理し、`tts/synth.py` と同じくつなぐ（ターンの間は 350 ms）ので、タイミングの時刻を持つ（`sync: "auto"`）。初めてのときは何を取得するかを表示して確認し（Irodori の fp16 で約 1.26 GB、fp16 のシェーダーのない GPU では 2.44 GB、Kokoro で約 330 MB。2 回目からはブラウザのキャッシュから読む）、編集アプリのサイトの小さなウィンドウ（`lab/tts-helper.html`）を開く。そのウィンドウがモデルを読み込み、この PC の GPU で合成する。ウィンドウに渡すのは読む文（読み辞書の後）と声の名前だけで、返ってくるのは音だけ。WebGPU が要り（パソコンの新しい Chrome か Edge）、オフライン版のエディタ（`file://`）では使えない。使えないときは「この PC」の答えもボタンも出さない（WebGPU の有無を前に出した言い方はしない）。作れる端末は、3 つがそろうとき：WebGPU がある、メモリが 8 GB 以上（`navigator.deviceMemory`。分かるブラウザだけ）、粗いポインタだけの小さな画面（画面の短い辺が 1024 px 以下。スマートフォン・タブレット）でない（`app/tts-client.js` の `deviceLimit`）。WebGPU があってもそろわない端末では、「この PC」の答えと **この PC で作り直す** を出すが押せず、わけを 1 行（ボタンは title）に書く。ほかの参照音声は `tts/synth.py` で。エンジンはスライドではなく台本の言語で決める：`voice.json` の `"lang"`、次に台本の文（日本語のファイルでも発言がほとんど英語なら英語）、最後に `<html lang>`。出す声と読み辞書も同じ言語に従う。
- **後処理** は `tts/core.py` と同じことをブラウザでする（`kit/core/audio-core.mjs`）：モノラル、44.1 kHz、前後の無音を削る（20 ms のウィンドウで −45 dB、50 ms 残す）、音量を −20 LUFS に（EBU R128 の積分ラウドネス、一律のゲイン。トゥルーピークが −1.5 dBTP を超えるので ffmpeg の loudnorm なら動的な処理に切り替えるところでは、ゲインを −1.5 dBTP で止める）。この違いがあるので、後処理の名前は別の `trim-45-loud-20-cap-v1` にする。`tools/test-audio-core.mjs` が同じ入力で `tts/core.py` と長さと音量を比べる。
- **文の前処理**（`kit/core/tts-normalize.mjs`、規則 `join-num-counter@1`）は、各部分をエンジンに渡す直前に、ブラウザでも Colab のノートブック（`colab/egatari_tts.py`。同じ規則で、共有の例で突き合わせる）でもかける：算用数字（0-9・全角の０-９。1.5 のような小数も）と、その直後の日本語の文字（ひらがな・カタカナ・漢字）の間の空白（ASCII・全角）を取る。「1 歩」は「1歩」になり、「いちぽ」と読まれない。「3 分」「10 本」「2 つ」も詰める一方、「x 2 y」「Chapter 3 is」や数字の前の空白（「第 3 章」）はそのまま。助数詞の読みの表は持たない。これは「何を言うか」ではなく「どう合成するか」なので、`ttsParts` と `inputHash` は変えず、新しい音声の recipe に `"textNormalize": "join-num-counter@1"` を書く（format spec §5.4）。この項目のない音声（これまでに作ったすべて）は**古くならず**、そのまま鳴り、音声のパネルも一覧にしない：読みがおかしいと聞こえたステップは **この PC で作り直す** かクラウドで作り直す。
- **音声を書く**（録音・取り込み・TTS の直後）ときは、新しい音声を MP3（LAME、64 kbps の CBR、モノラル、44.1 kHz）にして、`audio/<rec|tts|imp>_<hash>.mp3` と `audio/manifest.json` のステップの記録を書く。MP3 のエンコーダは編集アプリのコードに含めない：編集アプリのサイトの `vendor/lame-wasm/` にある手を加えない `lame-wasm` のファイルで（LAME は LGPL。NOTICE を参照）、新しい音声を MP3 にするときだけ読み込む。オフライン版のエディタは MP3 のエンコーダを持たず、WAV（16 bit。ファイルは大きい）で保存する。配信版でもエンコーダを読み込めなければ WAV。MP3 は 1105 標本（符号化の遅れ 576 と復号の遅れ 529、0.025057 秒）遅れて始まるので、それを `startOffset` に書き、ランタイムはその時刻から鳴らす（`dur` とタイミングの時刻がずれない）（前の manifest は `.cache/edits/` にバックアップし、前の音声のファイルは残す。`tts/synth.py` が古い wav を残すのと同じ）。記録には出どころを書く：`kind`（`recorded`・`tts`・`imported`）、`inputHash`（その音声を作ったときの台本）、TTS なら `recipe`（`engine`・`model`・`voice`・`seed`・`dictionary` = 読み辞書の SHA-256）、どの種類にも `processing`（`trim-45-loud-20-cap-v1`）、MP3 なら `startOffset`。機器の名前・元のファイル名など録音した状況の記録は書かない。録音と取り込みにはタイミングの時刻がない（`sync: "none"`、cues は空）ので、タイミングに合わせた動きと強調は時間で進む。ステップの長さは新しい音声に合わせて決まる（manifest の `dur`。ランタイムがそこからタイムラインを計算する）。`timeline.json` の `dur` の上書きがあればそちらが勝ち、パネルがそれを知らせる。書けなかった新しい音声（読み取り専用のファイル・編集の確認を断った）は **まだ使っていない音声** に「この音声を使う」と一緒に残り、使うか別のファイルを開くまでメモリの上にある。「前に戻す」のための前の記録もメモリの上だけに置く（ステップごとに 20 まで。別のファイルを開くまで）。`tts/synth.py` は録音と取り込みを残す（`--replace-recorded` で置き換える）。
- **読み上げで聞く**（音声ファイルにはなりません）。 今のステップの台本を、この端末の読み上げの声で読む（format spec §5.6 のプレビュー）。読みの `{x|y}` は y を読み、`{cue}`・`{mark:…}` と `@x-` の行は読まない。日本語には AI 音声と同じ読み辞書（`tts/yomi.yaml`）と文の前処理（`join-num-counter@1`）を当てる（`kit/core/read-aloud.mjs`、プレーヤーと同じ）。**選んだ語を読み上げで聞く** は、台本の欄で選んだ語や文だけを読む（このステップの `{x|y}` の読みも当てる。**読み方…** の「読み上げで聞く」も同じ口 `readAloud(text, lang)`（`app/read-aloud.js`）を使う）。読んでいる間は「読み上げ中」と出て、「■ 止める」・別のステップへの移動・パネルを閉じると止まる。端末の中で動く声（`localService`）だけを使い、ネットワークの声は使わない。その言語の声が端末にないときは、そう知らせ、音声が要るなら AI 音声（クラウドの Google Colab か、この PC）で作るよう案内する。何も書かない：作業フォルダにも Egatari ファイルにも音声の記録にも残らず、音声ファイルにはならない。
- **Egatari ファイル：** 新しい音声でメモリの上のフォルダが変わり、**保存** で再ビルドせずに書く（段 A：そのステップの音声の記録・ランタイムの音声の項目・中の音声だけが変わる）。
- **AI 合成音声。** どこかのステップの音声を TTS で作った（`kind: "tts"`）ときは、プレーヤーのツールバーに小さなラベル「AI 音声」（説明は「音声は AI で合成したものです」）、キーの一覧（<kbd>?</kbd>）に同じ文、そのステップの発表者ビューに 1 行が出る。スライドの上や字幕には出さない。取り込んだ音声（`kind: "imported"`）は、キーの一覧と発表者ビューに「音声の作り方は記録されていません」と出し、録音には印を付けない。Egatari ファイル・再生専用の派生を含むどの出力も、種類を `deck-audio` の `kind` に含める（format spec §5.2・§7.3）。

## 録音モード（キーボードだけで録音する）

音を宣言する、または `events(k)` を持つパーツを含むファイルでは、スライドのツールバーに **効果音をミュート** が出ます。Tab で選び、Enter または Space で切り替えます。押された状態ではパーツの音がすべて消えます。端末に保存できる場合は、ブラウザがこの選択を保存します。スライドショーでステップを前へ進めると（手で進めても再生でも）、参加者の操作の後から音が鳴ります。画面の内容はそのまま見られます。録音モードでは開いている間だけパーツの音を止め、閉じると保存した選択に戻します。

<kbd>r</kbd>（編集アプリのページでもスライドの上でも）か、音声のパネルの「● 録音 (r)」で、台本を全部キーボードだけで録音するための広い表示を開きます。ステップの台本を**大きく**出し（掛け合いは Expert / Novice のラベル。長い台本は中でスクロール）、プレビューは横の細いスライドのサムネイルになって録音の位置に付いてくるので、図を見ながら読めます。音声のパネルと同じく信頼する編集アプリの表示の中にあり、マイク・録音・後処理・書き込みはプレビューでは一切行いません（スライドからの知らせで開けるのは録音モードだけで、録音は始まりません）。開いている間、プレビューは inert です。表示中のステップ（音声のパネルからならパネルのステップ）から始まり、台本のあるステップを順に録音します。録音の方法はこれだけです：音声のパネルの「● 録音 (r)」は録音モードを開き、パネルは裏で開いたままなので、**Esc** で新しい音声の出たパネルに戻ります。

**連続録音**は初めはオンで、この端末に保存します。ステップを移動してもテイクや効果音は鳴りません。

| キー | 動作 |
|---|---|
| **Space** | 録音の開始／停止。止めると後処理（音声のパネルと同じ：前後の無音を削る・−20 LUFS・モノラル 44.1 kHz）をして、**すぐそのステップの音声**にします（kind `recorded`。これまでどおり「前に戻す」で戻せます）。ステップは変わりません。開いた直後（とステップを移動した直後）は、そのステップを読み終えるまで Space のボタンが **準備中…** になります。その間に押した Space は記憶しておき、準備ができしだい録音を始めます（2 回押しても 1 回） |
| **Enter** | 録音中なら停止して確定し、次のステップへ。録音した後（または音声のあるステップ）なら次のステップへ。**連続録音**がオンなら、前のテイクを整えて保存した後、次のステップに音声がない・音声の更新が必要なときだけ録音を始めます。今の台本に合う音声があれば待機します。オフなら次のステップは毎回待機します。最後のステップでは、Enter でテイクを採用して止まります。音声のないステップでは、進まずにそう知らせます |
| **Backspace** | 再録音。録音中は今のテイクを破棄します（何も書きません）。録音した後は、そのテイクを「前に戻す」で外して前の音声に戻し、次の Space を待ちます。戻せるのは、このモードで録音した音声だけです |
| **←** / **→** | 前・次のステップ（録音中なら先に止めて採用） |
| **C** | 録音中に、台本の `{cue}`・`{mark}` のタイミングごとに押します（タイミングは ①②… のチップで出て、次のタイミングは太い枠、押したものは ✓）。押した時刻が cue になります（`sync: "manual"`。時刻は押した生の時刻から、前の無音を削った分を引いたもの）。押した数がタイミングの数と違えば cue は書かず（`sync: "none"`。警告を出し、図は時間で進みます）、間違った同期は作りません |
| **Esc** | 閉じる（録音中は今のテイクを破棄します。**Shift+Esc** は開いているウィンドウを全部）。フォーカスは元の場所に戻ります |

1 段は **Space → 話す → Enter** です。再録音したテイクは前のテイクの cue を使いません（仕様 §5.3）：`sync: "none"`・cue なしから始まり、C で埋めます。台本を編集して音声が古くなったステップには「古い」の知らせ、タイミングがあって cue が未設定のステップには「図は時間で進みます」の知らせが出ます。掛け合いはステップごとに 1 本のテイクです（1 人が両方の役を読むか、2 人が交互に）。入力レベルのメーターと経過時間（1 つのテイクは 600 秒で止まり、そこまでを使う）、テイクの長さと音量の調整、音が割れていそうなときの警告が出ます。機器から遅れて届く標本を受け取るため、停止後も 0.15 秒間受け取ります。無音を削る前に、停止キーの押下の 30 ms 前から後を除き、開始はキーの解放（押下から最低 120 ms 後）のさらに 30 ms 後までを除きます。Enter も、前のテイクの末尾と次のテイクの先頭に同じ処理をします。マイクは録音モードを閉じるまで開いたままで（許可は 1 回、録音の開始の遅れなし）、閉じると手放します。書き込みが断られたとき（読み取り専用のファイル・編集の確認を断った）は、そのテイクは音声のパネルの「まだ使っていない音声」に残ります。

読み上げソフトには、録音モードは modal の dialog です。live region がステップ（n / N・題・音声の有無・タイミングの数）・「録音中」・連続録音のときの「連続録音中：ステップ 3/7」・押したタイミング・テイクの結果を知らせ、alert の領域が問題を知らせます。どのキーにもボタン（キーの aria-keyshortcuts つき）があり、`prefers-reduced-motion` ではメーターを 1 秒に数回だけ更新します。録音モードの間、<kbd>e</kbd>・<kbd>n</kbd>・<kbd>r</kbd> は何もせず、ツールバーは inert です。

## 添付（下書き・試行）

下書き・試行（形式の §3.8 の案）：役割ごとに追加してよい形式と中身の確認は[参照](reference.ja.md#1-ファイル--portable)のとおり。

**ファイル ▾ →「ファイルの情報…」** は、`egatari.json` の `metadata` の題名・ライセンス・作成者・著作権・クレジットの表示を出し（ここでは読み取り専用。作業フォルダなら `egatari.json` を編集する）、形式（「形式：Egatari 1.0（WD …）」。ファイルの `version` と、`vendor/egatari-spec/SOURCE.json` に仕様のコピーのバージョンがあればそのバージョン）と作った Studio（「作った Studio：0.4.6」。`generator.version` から。作業フォルダは「この Studio：…」）、「再生は、ファイルに入ったプレーヤーで動きます。編集はいつも最新の Studio で行ってください」の添え書きを出し、その下に添付（見出しは「添付（下書き・試行）」）を出す。添付は、作業フォルダか開いた Egatari ファイルの `attachments/` の下のファイルを並べる（形式の §3.8：読み手のための元の原稿・PDF・コード・データ・補足。[参照](reference.ja.md#1-ファイル--portable)）。**ファイルを追加…** でコピーして追加する（役割は形式から推す：`.pdf` → pdf、`.tex`・`.bib`・`.docx`・`.md` → source、`.py`・`.ipynb`・環境の定義 → code、`.csv`・`.tsv`・`.json`・`.xlsx` → data、画像と `.txt` → supplement）、ファイルごとに題を尋ねる（要る。1 行で 120 字まで。ファイル名から埋めてあり、編集できる）。形式が許さないファイルは、理由と規則（§3.8）を言って断る：名前から分かるもの（実行できるファイル・`.js`・`.bat`・`.ps1` など OS がスクリプトとして開く拡張子・HTML・SVG・ZIP・マクロを入れられる Office のファイルと、.doc・.xls・.ppt の古い Office のファイル・音声と動画・どの役割も受けない形式）は題を尋ねる前に、中身から分かるもの（JavaScript のある PDF・文書の中へ移るほかの開いたときの動作や `GoTo`・`URI` のほかの動作のある PDF・パスワードの要る暗号化した PDF・マクロや外への参照のある Office・名前を変えた実行ファイル・2 つの形式を重ねたファイル・音声と動画）は読んだ後・書く前に。表計算のソフトが数式として読みうる値は通知して追加する。行ごとに役割（なし：追加するが読み手の一覧に表示されない。ファイルの形式を受けない役割は断る）・題（要る：ないものは追加するが一覧に表示されない。削除できない）・説明（任意。1〜2 文で 300 字まで。ダウンロードの一覧の題の下に出る）・**名前を変更…**（新しい名前も追加するときと同じく確認する）・**削除**。役割・題・説明は `egatari.json`（`attachments`。ほかの項目は残し、`.cache/edits/` にバックアップ）に書く。`attachments/` の外・`..`・予約名・重なる名前は断り、上限（1 つ 10 MiB・合わせて 20 MiB・100 個）を超えるファイルは読む前に断る。フォルダから削除するときは `.cache/edits/` にバックアップを保存する。エディタは添付を開かず、プレビューにも渡さない。Egatari ファイルでは **保存** まではメモリの上で、保存は段 A：変わるのは索引の添付の項目・その塊・原稿の hash だけ。Egatari ファイルの最初の変更の前には、ほかの編集と同じく編集の確認が出る。**ライブの結果を取り込む…** は、ライブからダウンロードした結果を役割 `data` の添付にし、要約を出す（[ライブ](distributing.ja.md#ライブ授業中の質問と投票下書き)の「授業の後」）。

## 本（下書き）

下書き（形式の §9C、`article-v1`）。本のあるファイル（`article.md` か `article/<名前>.md`。[本を書く](article.ja.md)）も、ほかのファイルと同じように開けます。本を書くのは Claude Code やコマンドで、編集アプリでは本を読む・編集する・印刷します。本のツール（Egatari Text の読み手。圧縮して約 350 KB）と citeproc-js（文献を引く本だけ）は、本のあるファイルを初めて開いたときに読み込みます。本のないファイルでは読み込みません。

- **プレビュー ▾ →「表示」：スライド・スライドと本・本** で、プレビューのプレーヤーの並べ方を、参加者・学習者が見るのと同じ形にします（プレーヤーの本のパネル：同期・**スライドで見る**・**本で読む**。[Viewer](viewer.ja.md) と同じ）。プレーヤーの中で並べ方を変えると、この選択も変わります。
- ツールの列の **本** で「本」のパネルを開きます。**スライドと本が合っていないかもしれません** は、リンクした後に字が変わったスライドと節（と、まだ確認していない組）を挙げます。読み比べて、合っていれば **確認済みにする**（**すべて確認済みにする**）を押します。今の状態を `egatari.json` の `articleLinks` に記録します（形式の §9C.7）。どちらの字も自動では修正しません。
- 「本」のパネルには、本のエラーと警告（`npm run check` と同じ）と、本のファイルごとのふつうの文字の欄（上でファイルを選ぶ）もあります。**保存**（<kbd>⌘</kbd>/<kbd>Ctrl</kbd>+<kbd>Enter</kbd>）は、UTF-8・改行 LF・Unicode の NFC で書きます（形式の §9C.2）。作業フォルダではそのファイルに書き（前の中身は `.cache/edits/` にバックアップします）、Egatari ファイルではメモリの上のファイルを変更し、**ファイル ▾ → 保存** のときに本だけを再ビルドします（スライドはバイトのまま。形式の §9C.1）。エラーのある本は保存しません。知らせに修正が必要な所を挙げます。
- **ファイル ▾ → エクスポート ▸ → 本を印刷** は、本を A4 縦で印刷します。スライドへのリンクは、ファイルの言語で「→ スライド 5・ステップ 3」（ステップ 0 へのリンクは「→ スライド 5」）と刷ります。本のないファイルでは、この項目は **台本を印刷** で、スライドを 1 枚ずつ小さく（最後の状態で）、その台本と並べて刷ります。**スライドを印刷** は、これまでどおりスライドを 1 枚ずつ刷ります。
- citeproc で引用の書式を整えたときは、本の下と「本」のパネルに「Citations formatted by citeproc-js — (c) Frank Bennett — citeproc-js implements the Citation Style Language — https://citationstyles.org/」の 1 行を出します（CPAL-1.0 の Exhibit B。[NOTICE](../NOTICE)）。
- まだできないこと：本の貼り付けと取り込み（Markdown・TeX・Word）、スライドと節のリンクを手で修正すること、引用の書式を選ぶこと、B5 と 2 枚を 1 枚に印刷すること。本の表示は、使っている端末のフォントで出ます。

## Egatari ファイル（フォルダなし）

Egatari ファイルは、`npm run build -- <deck.html> --portable`（または編集アプリの **ファイル ▾ →「名前を付けて保存…」**）が書くもの（作業フォルダの最上位に、題名から作った名前で書き、パスを表示する）。ビルドしたスライドと同じように再生でき、スライド・台本・音声を中に持つので、元のフォルダがなくても編集アプリで編集できる。人への配布の方法（Google ドライブ・メール・LMS）は [distributing.ja.md](distributing.ja.md)。

- **開く。** スタート画面の「ファイルを開く（.ega.html）…」か **ファイル ▾ →「開く…」** を押すか、ファイルをスタート画面にドラッグ＆ドロップする。編集アプリはファイルをバイト列として読み、スクリプトを動かさない HTML の解析器で、Web Worker の中で取り出す。ファイルそのものをページとして読み込むことはないので、取り出しの間に中のものは何も動かない。形式のハッシュ・大きさの上限・パスの規則を先にすべて確認する（`npm run portable -- unpack` と同じ）。HTML は上限（要素・属性・入れ子の深さ）を解析の途中で数えながら解析し、中の原稿のファイルに書かれたタグも 500000 までにするので、小さな要素を何百万も並べたファイルは、全部の木を作る前に断る。読むのに 30 秒より長くかかれば Worker を止めて断る。開いたファイル（フォルダ・Egatari ファイル）のビルドとコードの確認も Worker の中で、ビルドの上限（[reference](reference.ja.md#ビルドの上限)）の内で行い、60 秒より長くかかればその Worker を止めて失敗にする（`build-timeout`）。その間もページは固まらない。フォルダから読むのはビルドが参照したファイルだけ（同時に 8 つまで、1 つは一覧の大きさまで。一覧の後で大きくなったファイルは断る）で、止めた Worker からの答えは破棄する。どのファイルも、読む前に `File.size` で、読んだ後に読んだバイトで大きさを確認し（`app/bounded-read.js`）、`deck.html`・`narration.md`・`comments.json` には決まった上限（32 MiB・16 MiB・4 MiB）があり、超えるものは読まずに断る。原稿はメモリの上（メモリの上のフォルダ）に置き、プレビュー・編集のツール・品質チェックはフォルダのときと同じように動く。フォルダがないので、外での変更は見張らない
- **保存。** 「保存」は、ブラウザが書き込めるハンドルをくれたとき（Chrome / Edge の「ファイルを開く（.ega.html）…」かドラッグ＆ドロップ。初めは許可を求めることがある）は同じファイルに書き直す。そうでなければ保存先を確認し、保存のダイアログがなければ（Safari・Firefox）ダウンロードする。文書の識別子（`docId`）は変えず、`derivedFrom` を付けることも変えることもない。**ファイル ▾ →「名前を付けて保存…」** は、**新しいファイルとして保存する（元のファイルとは別のものになります）** かを確認する
  - 印を付けたとき：保存先を確認し、新しい `docId` のファイルとして書く。元のファイルを `derivedFrom`（元の `docId` と原稿の hash）に記録し、著作権・クレジット・作成者・編集の記録はそのまま残す。開いている文書は新しいファイルになる（この後の保存も新しい識別子のまま）
  - 付けないとき：保存先を確認し、同じファイル（同じ `docId`）を別のファイルに書く

  ファイル名の前の ● は保存していない変更の印。ページを離れるときや別のファイルを開くときは先に確認する。どの保存でも、ライセンス・著作権・クレジット・作成者、編集アプリの知らない索引の項目（どの深さでも：metadata・音声の記録・塊・パーツとテーマ・拡張の中）と拡張のデータは残し、触れていない音声はバイトのままコピーする。設定のファイル（原稿のルートにあるファイルの識別子と metadata）がないファイルには、編集アプリが追加することがある。それで原稿の hash は変わるが、保存はもともとそれを書き直す
- **再ビルドせずに保存する。** 台本（発言の文・強調・タイミング）、音声、`timeline.json` の秒数の上書きだけが変わったときは、「保存」はスライドを再ビルドしない。[形式](https://github.com/egatari/egatari-spec)がそういう編集に挙げる所（§7.2 の段 A）だけを書き換える：ランタイムの台本・強調・秒数・音声のデータのうち変わったステップの項目、スクリプトなしで読める文字の層のうち変わったステップ、原稿の hash と索引とその hash、中に入れたファイル（新しい中身を追加し、どこからも参照されなくなった中身を除く）、そして新しい文に、埋め込んだ字にない字があるときだけ、字の補い（その字を含む字の分割ファイルだけを、編集アプリが持つ字から入れた新しい style 要素。前からある字のデータには触れない）。ファイルのほかのバイトは、ほかのツールや別のバージョンが書いたランタイムも含めて、1 バイトも変えない。状態の欄に「再ビルドせずに」と出る。ステップの台本をすべて削除すると、そのステップの音声も消える。保存の知らせに警告があることが出て、品質チェックのパネルにそのステップが出る。秒数の上書きは項目ごとにコピーし、各ステップの長さはランタイムがそれまでと同じ式で計算する
- **再ビルドして保存する。** スライドを編集したとき（または上の所の外が変わった、ファイルのビルドしたスライドと原稿が食い違うとき）は、編集した原稿から編集アプリに同梱の kit・パーツ・テーマでファイル全体を再ビルドするので、プレビューとまったく同じに再生する。保存の前に **「スライドはこのエディタの今のバージョンで再ビルドされます。編集していないスライドも、見え方が変わることがあります。」** と知らせ、再ビルドせずに保存できない理由も見せ、「再ビルドして保存」を押してから保存する（キャンセルなら変更は保存しないまま）。まだ一度も保存していないファイル（AI の出力から作った・`deck.html` だけを開いた）は、確認せずに再ビルドする（このエディタがビルドしたものなので、ほかは変わらない）。テーマを変えただけ（**テーマを変更…**）のときは、そのことだけを言う：**「テーマを変更したので、スライドを新しいテーマで再ビルドして保存します。…」**。ファイルがほかのプレーヤーを持っていたとき（索引のプレーヤーが Egatari Player でない）は、続けて **「プレーヤーが変わります」** のウィンドウで、ファイルのプレーヤーと保存したファイルに入るプレーヤーを名前とバージョンで見せる（「このファイルは Other Player 2.0.0 で再生します。保存すると、Egatari Player 1.0.0 で再生するファイルになります。…」）。「保存」で保存し、「キャンセル」なら変更は保存せず、ファイルもそのまま（形式の仕様 §4.1）。同じプレーヤーの新しいバージョンになるだけなら確認しない。まだできないこと：再ビルドの前と後のスライドを比べること。保存した後にプレビューで確認する
- **更新が必要な音声。** ステップの台本を編集しても、その音声には触れない（バイトも種類もそのまま）。そのステップは警告に「音声の更新が必要」と出て、保存したファイルでも音声の記録は作ったときの台本の hash のままなので、どの読み手にも古いと分かる。[音声のパネル](#台本の音声音声のパネル)で録音し直すか、作り直す
- **ファイル ▾ → エクスポート ▸ →「作業フォルダにエクスポート…」** は、選んだ空のフォルダに原稿・音声・`audio/manifest.json` を書く（`npm run portable -- unpack` と同じファイル）。空でないフォルダは断る。エクスポートしたフォルダは、ふつうの作業フォルダとして開け、ビルドでき、まとめられる
- **ファイル ▾ →「名前を付けて保存…」**（フォルダを開いているとき）は、フォルダを Egatari ファイル（編集可・`.ega.html`）にする。最初に表示するファイルの名前はタイトル（設定のファイルの `metadata.title`、なければスライドの `<title>`）で、どの OS でも使える形にする（`\ / : * ? " < > |` と制御文字を除き、頭の点と終わりの点・空白を除き、`CON` などの予約の名前を避け、80 字・255 バイトまで）。題名がなければスライドのファイルの名前。初回はファイルの識別子をフォルダの設定のファイルに書き、次からのエクスポートでも同じものを使う
- **作業フォルダからエクスポートしたファイル**（`exportedFrom`、形式の §3.1）。作業フォルダの「名前を付けて保存…」（コマンドの `--portable` も）は、そのファイルに作業フォルダからエクスポートしたという印を、エクスポートしたときのフォルダの原稿の hash と一緒に付ける（時刻・パス・名前は含めない）。そういうファイルを開くと「このファイルは、作業フォルダ（スライドと台本のファイルを入れたフォルダ）からエクスポートしたものです。ここで編集しても、作業フォルダのファイルは変わりません。作業フォルダを持っていなければ、気にせずこのまま編集して保存できます。」と知らせ（警告ではなく、ふつうの案内の行）、**作業フォルダにエクスポート…** のボタン（ファイル ▾ → エクスポート ▸ →「作業フォルダにエクスポート…」と同じ）を出す。編集は断らない。「保存」と「名前を付けて保存…」は印を変えないので、ファイルの原稿の hash が印と違ってくると「エクスポートしたあと、このファイルで編集した所があります。」を追加する。「新しいファイルとして保存する」に印を付けた保存は印を外す（新しい `docId` のファイルはエクスポートしたファイルではないので、開き直しても知らせは出ない）。フォルダなしで編集アプリから始めたファイル（貼り付けたもの・`deck.html` だけから開いたもの）には印が付かない。展開したフォルダは印を持たず、原本になる。次のエクスポートが新しい印を書く。エクスポートしたファイルと作業フォルダの両方がローカルにあれば、`npm run portable -- compare <ファイル> <フォルダ>` がエクスポートの後にどちらを編集したかを言う（[参照](reference.ja.md#1-ファイル--portable)）。
- **ファイルに入らないもの：** コメントと `.cache/edits/` のバックアップはメモリの上にだけ残る（コメントは見直しの覚え書きなので、形式が外す）

### このブラウザに一時保存する、保存していない変更

Egatari ファイルを編集している間、保存していない変更をこのブラウザの中（IndexedDB）に一時保存する。タブを閉じても落ちても消えない。変更から約 2 秒後（直し続けても 10 秒に 1 回、タブが隠れたときはすぐ）に、開いたときのファイルと、それから変わったファイルだけ（スライド・台本・`egatari.json`・`timeline.json`・添付・本・音声のファイルと `audio/manifest.json`。「保存」が書くものと同じ）を一時保存する。録音はファイルに書いた時点で一時保存される。コメント・開いた欄に打ちかけの文字・録音中のテイクは一時保存しない。

- **復元。** 同じファイル（名前と中身が同じ）をもう一度開くと **「保存していない変更があります」**（「「…」に、保存していない変更があります（…、このブラウザに一時保存したもの）。復元しますか？」）と確認し、**変更を破棄** と **復元** を出す。Esc ならあとで決める。スタート画面の **保存していない変更** にも並ぶ（行ごとに **復元** と **変更を破棄**）。そこでの復元は、一時保存したファイルのコピーを開くので、ファイルを選び直さなくてよい。復元は変更をファイルの上に書き戻して再ビルドする。ファイルにするには「保存」を押す。元のファイルが変更を一時保存した後に変更されていれば、上書きせずに保存先を確認する。
- **2 つのタブ。** タブごとに自分の変更を一時保存し、開いている間はそれを持つ（Web Locks）。ほかのタブで開いている変更は、確認も一覧への表示もしない。同じファイルを 2 つのタブで編集しても、一時保存した変更を互いに上書きしない。
- **消えるとき。** ファイルに保存すると削除する。**変更を破棄**（ここ、または別のファイルを開くときの問い）でも削除する。最後に変更してから 30 日たったもの、10 件を超えた古いものは削除する。**? →「このブラウザに一時保存した、保存していない変更」** に件数と大きさ、**すべて破棄** がある。ブラウザが削除することもある（ディスクの空きが足りないとき、Safari は約 7 日開かないとき）。初めて一時保存するときに、削除しないようブラウザに求める（永続の保存）。
- **限り。** 一時保存するものが 256 MiB を超えるファイルは一時保存しない（1 回だけ通知する）。ブラウザの保存領域が足りないときは「このブラウザに変更を一時保存できませんでした（保存領域が足りません）。」と 1 回だけ知らせ、次の変更でまた試す（編集は続けられる）。ステータスバーのツールチップが「復元できます」と言うのは、実際に一時保存できているときだけ。
- **プライバシー。** 変更はこの端末のこのブラウザの中にだけあり、アップロードしない。
- **作業フォルダ** はその場でフォルダに書くので、何も一時保存しない。

### 編集の確認（このファイルを編集しますか）

ファイルを編集のために開くたびに、最初の変更の前に（編集モードや台本の引き出しで最初に保存するとき、または「編集」「台本」を押したとき）、ファイルに書かれた題名・作成者・著作権・ライセンス・クレジットの表示を見せる（どれも申告で、確認したものではない）。改変を認めないライセンス（Creative Commons の `-ND`、All rights reserved）か、ライセンスがなく著作権の表示だけのときは、改変や改変したものの配布が権利者の著作権を侵すおそれがあると知らせ、確認のチェックを入れるまで編集を始めない。キャンセルならファイルは変わらない。保存で著作権・クレジット・作成者を削除することはない。

### ほかの人のファイルの保存（このファイルの作成者ですか）

編集アプリには、だれが編集しているかが分からない。そこで、作成者・著作権・ライセンス・クレジットの表示が書かれたファイルの変更を初めて保存するとき、「**このファイルの作成者ですか**」と確認する（形式の §7.3）。どちらかを選ぶまで「保存」は押せない。

- 「**はい、このファイルの作成者です**」：ふつうに保存する。
- 「**いいえ、ほかの人のファイルを編集しています**」：名前（学校名など）と、省略できる「編集した内容」を入力する。保存で `metadata.edits` に 1 件追加し、プレーヤーの「ファイルの情報」の作成者の後に「編集：名前（内容）」と出る。同じ名前の項目が既にあれば、その内容だけを新しくする。ライセンスが変更を示すよう求めていて（CC BY 4.0 などの Creative Commons の 4.0 のライセンス）、名前を空にしたときは、名前のない項目を追加し、「元のファイルから編集されています」と出る。

答えはこの端末でファイル（`docId`）ごとに保存する（ブラウザの保存領域。ファイルには書かない）ので、確認するのは 1 回だけ。ファイルに入るのは入力した名前と内容だけ。このエディタで作ったファイル（AI の出力から作ったもの、`deck.html` だけを開いたもの）では確認しない。保存で `edits` の既にある項目を削除したり変更したりすることはなく、「新しいファイルとして保存する」でも残る。キャンセルなら変更は保存しないまま。

再ビルドしない保存（台本・音声・秒数の所だけの書き換え）は、ファイルのプレーヤーを変更しない。編集の記録を表示するのは Egatari Player の 1.9.0 から（`kit/core/player.mjs` の `EDITS_SHOWN_SINCE`）なので、それより前のプレーヤー（または別のプレーヤー）のファイルに再ビルドしない保存で編集の記録を追加するときは、「**この Egatari ファイルのプレーヤーは古いため、編集の記録はファイルに入りますが、再生するときに表示されません。**」と知らせ、ファイルのプレーヤーの名前とバージョンを見せる。

- 「**プレーヤーを更新して保存**」：スライドを再ビルドして保存する（スライドを編集したときと同じ道で、「スライドを再ビルドして保存します」の確認も同じに出る。別のプレーヤーのファイルなら、続けて「プレーヤーが変わります」も出る）。保存したファイルは今のプレーヤーで再生し、編集の記録が表示される。
- 「**保存**」：今までどおり再ビルドせずに保存する。編集の記録はファイルに入るが、プレーヤーはそのまま。その文書を開いている間は、もう知らせない。
- 「キャンセル」：保存しない。次の保存でまた知らせる。

### スライドのファイル（deck.html）・ビルドした発表の HTML を開いたとき

- **スライドのファイル**（作業フォルダの `deck.html`。GitHub から落としたものなど。`<section class="slide">` があり、ビルドのランタイムや形式のブロックがない）は断らない。台本・音声・その作業フォルダだけのパーツは同じフォルダに別のファイルとしてあることを説明し、「作業フォルダを開く…」（フォルダを選ぶダイアログ。選んだフォルダをふつうに開く）・「このファイルだけを開く」・「キャンセル」を出す。「このファイルだけ」は `deck.html` だけのメモリの上のファイルを新しく作る：台本と音声はない。パーツライブラリのパーツとテーマは使え、参照しているのにないファイル（その作業フォルダだけのパーツ・`{{JSON:…}}` のデータ・取り込み・図）はビルドの知らせ（1 つにつき 1 回）になり、中身なしでビルドする（メモリの上のファイルはすべてこうする。フォルダは今までどおり、ないファイルがあればビルドが失敗する）。ほかの開いたファイルと同じに扱う：ファイルにコードがあれば先に確認し、新しい `docId` で、編集の確認は出さず（権利が書かれていない）、`deck.html` だけを開いていてまだ保存していないことを知らせる。「保存」は保存先を確認する：「Egatari ファイル（`.ega.html`）に保存…」か「作業フォルダにエクスポート…」（空のフォルダ）
- **ビルドした発表の HTML**（`out/deck.html` など。ビルドのランタイムと `deck-meta` はあるが原稿がない）は専用の言葉で断る：発表用にビルドしたもので、作業フォルダ（「作業フォルダを開く…」を出す）か Egatari ファイルを開くように言う
- **Egatari ファイルの再生専用版**（`.play.ega.html`）はそう名指しして断る：そのままブラウザで再生でき、編集するには元の Egatari ファイルか作業フォルダを開く。ほかの HTML は「Egatari ファイルではない」と言う

### 断るファイル・読み取り専用で開くファイル

- **理由を見せて断る：** Egatari ファイルでないもの・再生専用のもの（上を参照）、ハッシュが合わないもの・一部が欠けたもの、許されないパス（`../` など）、索引の同じ名前の項目、設定のファイルと食い違う文書の識別子、新しい原稿の書き方のバージョン
- **新しい major のバージョン、編集アプリが実装していない必須の機能：** 編集のためには開かず、エクスポート（作り直し）もしない。索引と中のデータが、編集アプリの知っているバージョンの規則で確認できれば、原稿を取り出す「作業フォルダにエクスポート…」を申し出る。確認できなければ取り出しも断る（そういうファイルもブラウザで再生はできる）
- **台本・音声・秒数だけ：** パーツライブラリ・テーマ庫のパーツの hash が編集アプリのものと違う（または編集アプリにない）もの、パーツが必要とする特定のバージョンのパーツがない既存のファイル。編集アプリではそのとおりに再ビルドできないので、台本・音声・秒数だけを編集できると上に知らせる。「編集」（スライドの文字）は断り、台本の引き出しは使え、「保存」は再ビルドせずにその所だけを書き換える。スライドの編集・テーマの変更・置き換えはできない。必要なパーツがないときは、どのパーツが何を必要とするかを知らせ、再ビルドするにはパーツを更新するよう案内する。プレビューはそのファイル自身のプレーヤーで、残るパーツを再生する
- **読み取り専用：** それ以外の理由で編集アプリでビルドできないもの、ひとつ前の種類で、しかもビルドしたスライドと原稿が食い違うもの。ファイルは表示し、保存は断り、「作業フォルダにエクスポート…」はできる
- **独自のコード：** ファイルが自前のコードを持つかは、ビルドした文書から決める（取り込み・前処理の後の原稿全体。ビルドがテキストとして読むファイルは拡張子によらずすべて含み（`/*INCLUDE:…*/` で取り込んだ画像のファイルも）、そのあとプレビューに出すのと同じバイト）。`src` がなく中身が空か空白だけの `<script>` はコードに数えない（コメントだけのものは数える）。調べるためにフォルダをもう一度読むことはしない。そういうファイル（と「extended」のファイル）は、その中のものが動く前に通知して確認し、「プレビューを始める」を押してからプレビューを始める（キャンセルならファイルは開かない）。確認する前にプレビューを空にするので、前のファイルも新しいファイルも、確認のウィンドウの後ろに表示されることも動くこともない。開いている間は上に知らせを出す：コードはプレビューの中だけで、外へ繋がらずに動き、ファイルを書き換えられない。パーツ（`components/…`、どれかの `.js`）や `deck.html` のスクリプトを持つフォルダも、開くたびに 1 回同じことを確認する（あとからそういうコードが現れたときも）

## 対話型 AI で下書きする（貼り付けと修正依頼）

初めの下書きは、AI エージェントを使わずに、対話型の生成 AI（ChatGPT・Gemini・Claude など）でも作成できる。AI への指示の全体（詳細の指示）は [authoring-with-llms.ja.md](authoring-with-llms.ja.md)（[English](authoring-with-llms.md)。規格・出力の形と標準パーツ）と、材料の種類ごとの**セットの指示** [llm-parts/](llm-parts/)：`stats`・`data`・`math`・`maps`・`kokugo`・`english`・`music`・`business`・`tools`・`science`。パーツの段（標準・専門・特殊）とセットはパーツライブラリ 2.0 の manifest から決まり、標準パーツはいつも、専門のパーツはそのセットがあるときだけ指示に入り、特殊のパーツは入らない（backlog #125）。④ で軽量の指示を選ぶと、編集アプリは軽い指示をコピーする（下の ④）：中核の 4 つのほかの標準パーツは、パーツの一覧の 1 行だけにする。`node tools/make-llm-guide.mjs` が規約・パーツの README・`tools/llm-guide/` から作り、古くなるか大きさの上限（`kit/core/llm-pack-assemble.mjs` の `PACK_CAP_KB`：軽量の指示は標準パーツすべてで 45 KB、詳細の指示は標準パーツとどの 2 つのセットの組み合わせでも 150 KB）を超えると `npm test` が失敗する。`npm run gen` は軽量の指示のセットごとの大きさ（新規作成と同じに収めたもの。`kit/core/llm-pack-assemble.mjs` の `fitPack`：45 KB を越えたら中核の 4 つも短くし、それでも越えれば専門のパーツを外す）と、詳細の指示のいちばん大きい組み合わせの大きさを出す。詳細の指示ですべてのセットを一度に選んだ指示も 150 KB の上限に収まる（収まらないときだけ知らせるだけ）。上限を超えたときは、どの指示か（軽量・詳細、言語、セット）、何バイト超えたか、大きい節 3 つを出す。`node kit/llm-pack.mjs --sets stats,math --lang ja` はエディタが軽量の指示でそのセットを選んだときと同じに収めた文章を出す（中核の 4 つを短くした・専門のパーツを外したときは stderr に出す。`--no-fit` でビルドしたままの指示）。`--plan paid` でどのパーツも詳しく、`--sets all --plan paid` で全体。`--list` でセットと、軽量の指示の収めた大きさと収める前の大きさ（KB は UTF-8 のバイト数 / 1024）。`--help` で使い方。

**新規作成…** の **指示をコピー** の横に **AI のスキルをダウンロード** を出す。添え書きは「Claude などの対話型 AI に追加すると、指示を貼り付けずに作成できます。Studio を更新したら追加し直してください（スキルの指示と品質チェックはバージョンごとに変わります）」。表示言語（ja または en）の make の ZIP を対話型 AI に追加し、その出力を Studio に貼り付ける。

- **対話型 AI は、ふつうの 3 つのコマンドの中の 1 つのやり方。** 出力の取り込み方（新しいファイル・スライドの挿入・今のファイルの置き換え）はコマンドが決め、そこに選ぶ欄はない。言葉は「出力」「コードブロック」（はじめに「灰色の枠」と言い添える）「指示」で、ボタンは押すと起きることの名前（**作成**・**挿入**・**置き換える**）

  - **新規作成…**（スタート画面か、**ファイル ▾ → 新規作成…**）：対話型 AI の道だけで、下のページがすぐに開く。スライドのテンプレートは **スライドの挿入…** に、新しい作業フォルダはコマンドの `npm run new` に
  - **スライドの挿入…**（**スライド ▾ →「スライドの挿入…」** か、スライド一覧の **スライドの挿入 ▾**）：**テンプレートから**（スライド一覧のテンプレート）と **対話型 AI で作成**。新しいスライドは、選んだスライドの後ろに入る（スライド一覧を閉じてツールの列から選んだときは、プレビューに出ているスライドの後ろ）

- **サンプルを参考に作る（このサンプルを参考に作る）。** 新規作成のページのはじめの説明の下、**AI の出力を貼り付ける** の隣に **このサンプルを参考に作る** があり、その下に「構成・テーマ・パーツを引き継ぎます。中身はあなたの題材で新しく作ります」。押すと ① 〜 ⑤ と **作成** を隠し、**参考にするサンプルを選んでください** と、スタート画面のサンプルと同じ一覧（`sample.json` のあるもの。題名・枚数・本の印）を、それぞれの **選ぶ**（読み上げの名前は「選ぶ: 題名」）と一緒に出す。選ぶと、サンプルのウィンドウの **このサンプルを参考に作る** を押したとき（と `?from-sample=`）と同じ、サンプルから始めた新規作成を開き直す（上の「サンプル」）。**問いに答えて作る** で戻る。一覧はアプリに組み込んであるので、オフライン版のエディタでも出る。サンプルから始めた新規作成と、サンプルのないビルド（`--no-examples`）には出ない
- **ファイルから読む。** ⑤（と貼り付けだけの表示、挿入と修正の ③）の 2 つの欄の下の **ファイルから読む**（「出力のファイル（.txt・.md）を選ぶか、欄にドラッグ＆ドロップします」）で、ChatGPT や Claude がファイルで渡した出力を読める。選んだファイルはスライドの欄に、落としたファイルは落とした欄に入れ、貼り付けた字と同じに分ける・移動する（信頼しないのも同じ）。読むのは上限つきの読み取り（`app/bounded-read.js`）だけで、上限は貼り付けた原稿と同じ（32 MB。`READ_LIMITS.source`）。超えるファイルは読まずに「このファイルは大きすぎます（32 MB まで）。AI の出力のファイルを選び直してください」、.txt・.md でないファイルは「テキストのファイル（.txt・.md）を選んでください」と断り、欄はそのまま
- **作っている間。** **作成** を押してからファイルが表示されるまで（出力からファイルを作り、開き、最初にビルドするまで。ふつう 1〜2 秒）、ファイルを開くときと同じロゴを「ファイルを作っています…」と一緒に出し、その間にスタート画面には戻らない（サンプルから作るときも同じ。Egatari ファイルの **置き換える** は「置き換えています…」）。ビルドされなければウィンドウに戻ってわけを出し、貼った字は残る。
- **長いものは 2 回に分けて。** 長さが 9 枚から（分は 1 分 ≒ 1 枚）は、コピーする文の最後に「まず構成案だけを返してください」（R-outline）が付き、AI は ```` ```outline ```` のコードブロック 1 つ（全スライドの見出しと 1 行の要点の表）で返す。⑤ は **⑤ AI の構成案を貼り付けます** になり（構成案の欄と **次へ**。その間 **作成** は押せない）、受け取ると「構成案：24 枚 **変更**」にたたみ、「6 枚ずつ作ります」と一覧と **1〜6 枚目の指示をコピー**（その範囲の `deck.html` の全体を、構成案と一緒に依頼する）と 2 つの欄を出す。作成すると、構成案を `egatari.json` の `studio.outline`（`{v: 1, next, rows}`）に保存する（`updateConfig` を通すので、ほかの項目はバイトのまま）。知らせに **構成案：残り N 枚（全 M 枚）** と **次の 6 枚を作成…** が出て、スライドの挿入のページで次の範囲（「構成案の 7〜12 枚目」。構成案と前のスライド付き）を依頼し、挿入した後に `next` を進める。壊れた構成案（コードブロックがない・閉じていない・表の行がない・見出しのない行・2 枚より少ない・60 枚より多い）は、わけを言って断る

  エディタは 2 つのコードブロック `deck.html` と `narration.md` を取り出す（```` ```html ````・```` ```markdown ````・```` ```html title="deck.html" ```` のような名前や、コードブロックの前の行のファイル名も分かる。Windows の改行、前・間・後の文章、余分なコードブロックはかまわない。同じファイルが 2 つなら最後のものを使う）。コードブロックの右上のボタンでコピーしたものには ``` の行がないので、中身から決める（`<section class="slide"` があればスライド、`## 見出し` と `[0]` などの行があれば台本）。``` の行がなく両方が入ったものは分けられないので、コピーの仕方を添えて断る。どちらでもないものも断る。閉じていないコードブロックは出力が途中で切れたということなので、その欄にそう書き、**続きを依頼する指示をコピー** を出す（足りない台本だけ、または全体を短くして、もう一度出力するよう依頼する）。切れたのが台本だけなら、スライドは受け取り、もう一度出力された台本を台本の欄に貼る。コードブロックの印なしで画面からコピーした出力の全体は、`<!DOCTYPE html>` から `</html>` までをスライド、その後ろを台本として取り出し、そのことを知らせる
- **id。** AI にはスライドの id を書かないように依頼している。エディタは、id のないスライドに新しい id を付け、台本の見出しを `## 見出し {#id}` に書き換える（`npm run ids` と同じ本体の `kit/core/slide-ids.mjs`）。見出しが同じスライドが 2 枚以上あれば、台本のその見出しの節を順に対応させる
- **開いたファイルと同じに扱う。** 原稿はビルドの Worker で Egatari ファイルにし、開いたファイルとまったく同じに開く：コードの確認は中身から決めるので、`<script>`（ほか動くもの）の入った出力は先に **プレビューを始める** かを確認し、キャンセルなら何も開かない。新しいファイルは新しい `docId` で、まだ保存していない（●）。**保存** で保存先を確認する。開くときに、最後に指示をコピーしたときの選び方を `egatari.json` の `studio.newDeck`（`{v: 1, plan, category, subcategory, purposes, subjects, audience}`。④ で選んだラベルと、① か学校から決めた読み手。v0.6.18 より前の記録の `parts` は読まない。前の記録の `tools`・`purposesOff` は読むだけで書かない。`plan` は `free` か `paid`、plan のない前の記録は `free`。`updateConfig` を通す）に保存する。シード値は書かない（format spec §8.4：パーツの見せ方は `variant="<名前>"` だけで選び、書かなければそのパーツの既定の見せ方。原稿にある `variant` はそのまま残す。前の原稿の `data-egatari-seed` は誰も読まない属性で、削除せずにそのまま残る）。自分の下書きなので編集の確認は出さない。開いたら品質チェックをかける
- **スライドの挿入… → 対話型 AI で作成**（backlog #93）。3 つの問い：**① どんなスライドを挿入しますか**（挿入する場所を表示し、挿入する枚数（1〜10）と挿入したいスライドの内容）→ **② 対話型 AI に指示を送信します**（専用の短い指示。`kit/core/llm-insert.mjs`：「スライド X の後ろに、続きのスライドを n 枚」、スライドの見出しの一覧、挿入する場所の前のスライドとその台本だけ。このファイルを作ったのとは別のチャットに送信するときは **このファイルを作ったのとは別のチャットに送信する（指示の全体も付けます）** に印を付けると、前に指示が入る——印を付けると、合わせた文章が詳細の指示と同じくらい長くなりうるので、新規作成の ④ と同じ **指示をファイルに保存**／**指示をコピー** の主従の入れ替えと添付の案内の行が出る）→ **③ AI の出力を貼り付けます**（新規作成の ⑤ と同じ 2 つの欄。台本の欄が空なら「台本なしで挿入します」）→ **挿入**。出力のスライドを順にその場所へ挿入し、スライド一覧と同じやり方（`newIdFor`）で新しい id を付け、台本の節（`## 見出し {#id}`）を同じ順で追加し（台本のないスライドには仮の行）、スライド一覧と同じ道で書き（`.cache/edits/` のバックアップ・**元に戻す**・再ビルド）、品質チェックをかける
- **修正…** **① どこを修正しますか**（修正したいこと。なくてもよい）→ **② 対話型 AI に修正依頼を送信します**（品質チェックの指摘（かけ直す）、① に書いたこと、開いているコメント（`comments.json`。解決したものは含めない。ピンやマーカーの画像は backlog #90）、今のスライドと台本。修正することがなければそう言う）→ **③ AI の出力を貼り付けます**（同じ 2 つの欄。「修正したスライドだけが出力されたときは、そのスライドだけを置き換えます」）→ **置き換える**。片方の欄だけでも押せる（横に「台本は今のままにします」か「スライドは今のままにします」）
- **AI への修正依頼をコピー。** 品質チェックのパネルにある。修正依頼の文章をクリップボードにコピーして見せる：指摘（エラーと警告）、それが破った規格（規格には `R-title` のような名前があり、文章は同じ指示から取る）、ファイルが使っているパーツの説明（指示と同じ文章）、はみ出しと小さい字の量（「本文を 97 px（46 px の行でおよそ 3 行）減らす」「字を 23.2px から 24px 以上に上げる」）、台本についてのビルドの知らせ、今の `deck.html` と `narration.md`。スライドと台本が長い（合わせて 40000 字を超える）ときは、指摘のあるスライドとその台本だけを載せ、そのスライドだけを返すよう依頼する。文章の横の **修正依頼をコピー** で、何度でもコピーし直せる（ほかのものをコピーした後など）。同じチャットに貼り付け、**AI の出力を貼り付ける…** を押すと、**修正…** の ③ が開く
- **スライドの画像と確認の依頼をコピー。** 品質チェックのパネルの **修正…** の下にある。1 回押すと、2 つをいっしょにクリップボードにコピーする：プレビューに表示中のスライドを最後のステップまで進めた PNG の画像（1280 × 720）と、図と結論の行が同じことを言っているか・図がつぶれたり切れたりしていないかを確認し、修正が必要な所があればスライドの HTML（`deck.html`）のどこをどう修正すればよいかを示すよう依頼する、短い文。依頼の文はスライド（番号・タイトル・id）とステップを書く。対話型 AI に貼り付ける。画像はプレビューの中で描くので、どこにもアップロードしない。プレビューの位置も変わらない。画像をクリップボードにコピーできないブラウザ（コピーが断られたときも）では、ウィンドウに **画像を保存**（PNG をダウンロードして添付する）と **依頼の文をコピー**（文だけをコピーする）が出る
- **置き換え（修正… の ③）。** 出力を今のファイルに入れる（Egatari ファイル（再生専用）では使えない）。文書はそのまま：Egatari ファイルなら `docId`・設定・音声・パーツを残して原稿だけを入れ替える（保存するまでは未保存）。フォルダなら `deck.html` と `narration.md` を、`.cache/edits/` にバックアップを残して書き、コードが現れたらコードの確認をもう一度表示する。id 付きの `<section>` の一部だけの出力は、そのスライドと台本の節だけを置き換える。台本の欄だけなら台本だけを（節がどれも id 付きなら、その節だけを）置き換える
- **品質チェックに追加したもの：** スライドにないステップの台本（エラー）、表紙など static のスライドの台本、式やいくつもの記号を入れた読みの指定 `{x|y}`（警告。読みは 1 つの記号か用語に 1 つ）。コマンド版の品質チェックも同じ 3 つを見る

## 書き換えるファイル

開発サーバーとまったく同じ（[dev-server.ja.md](dev-server.ja.md) の「書き換えるファイル」）。どれも選んだフォルダの中

- `deck.html`：編集した要素の中身だけ
- `narration.md`：編集したステップの行だけ（注釈やほかの行はそのまま）
- `comments.json`：コメント `[{id, created, key, range, pin, quote, comment, status}]`（`pin` は押した点 `{x, y}` のスライドの座標、1280×720。マーカーは描いた印 `strokes` を追加する（前のコメントは 1 本の `stroke` のこともある）：[規約 §13](contract.ja.md#13-レビューのメモ手書きの印)。[開発サーバー](dev-server.ja.md#書き換えるファイル)を参照。コメントが何を指しているかを見るには、フォルダに `npm run comment-shots -- <作業フォルダ>` を動かす：未対応のコメントごとに、そのステップをピン付きで `.cache/comment-shots/` に描く）
  パーツの上のマーカーのコメントには `part: {name, id?}` も保存する（そのステップの重心の下にある最も内側の `m-*` タグと、あれば `data-id`）。AI への修正依頼には「パーツ：<tag>（data-id: <id>）」の 1 行を追加する（id がなければ括弧は省く）。パーツの外の文章や図は、これまでの近くの字のまま。`part` のない前のコメントも使え、読み手は知らない項目を無視する。
- `audio/<rec|tts|imp>_<hash>.mp3` と `audio/manifest.json`：音声のパネルの **この音声を使う** で（変わるのはそのステップの記録だけ。前の manifest はバックアップする）
- [スライド一覧](#スライド一覧挿入複製削除並べ替え)で：`deck.html`（スライドをまるごと挿入する・コピーする・削除する・移動する）、`narration.md`（節をまるごと）、`audio/manifest.json` と、スライドを削除したときはその音声の `audio/` のファイル（先にバックアップする。元に戻すで書き戻す）
- [「本」のパネル](#本下書き)で：保存した本のファイル（`article.md` か `article/<名前>.md`。ファイルをまるごと）と、**確認済みにする** では `egatari.json` の `articleLinks`（ほかの項目はバイトのまま）
- `.cache/edits/`：書き換える前の `deck.html`・`narration.md`・`audio/manifest.json`（と本のファイル・`egatari.json`）（新しい 30 個。掃除で削除するのはバックアップの名前の形（`<時刻>-<名前>`）のファイルだけで、フォルダのほかのものは残す）
- 作業フォルダの「名前を付けて保存…」・「参加者用（再生専用）…」・「LMS 用（SCORM）…」では選んだファイル（と、初回はフォルダの設定のファイルに書くファイルの識別子。SCORM の zip はダウンロードするだけ）
- Egatari ファイルを開いたとき：保存するまで何も書かない（編集したものはメモリの上）。保存では選んだファイルだけ（再ビルドしない保存では、上に挙げた所だけを書き換える）、「作業フォルダにエクスポート…」では選んだ空のフォルダのファイルだけ

## できないこと

- **Chrome・Edge だけ。** スマートフォンのブラウザもフォルダを開けない
- **この PC で AI 音声を作るモデル。** モデルは編集アプリのサイトのブラウザのキャッシュに置かれる（Irodori-TTS は約 1.26 GB、Kokoro は約 330 MB）。「使い方」に、このサイトが使っている保存領域（`navigator.storage.estimate`）と入っているモデルが出て、「モデルを削除」で削除できる（作った音声は消えない。次に使うときに取得し直す）。TTS のウィンドウはモデルを読み込むとき、古いバージョンのモデルのキャッシュを削除し、ブラウザに保存領域を残すよう求める（`navigator.storage.persist`）。求めが通らなければ、ディスクの空きが足りないときにブラウザがモデルを削除することがあり、Safari は 1 週間ほど開かないと削除する
- **コマンドで行うもの：** 自分の参照音声やサーバーのエンジンでの TTS（`tts/synth.py`）・動画（`tts/` `render/`）、品質チェックのコマンド版（`npm run check`）、`tools/pdf.mjs`。プレビューは `audio/manifest.json` の音声（フォルダでも Egatari ファイルでも）を自動再生（`a`）で鳴らす：編集アプリが音声のファイルを読んでそのバイトをプレビューに渡し、プレビューは自分の文書の `blob:` の URL で鳴らす（砂場のプレビューはフォルダも編集アプリの `blob:` の URL も読めない）
- **音声のパネルは編集アプリだけ。** 開発サーバーには音声のパネルがない（フォルダを編集アプリで開くか、`tts/synth.py` を使う）。AI 音声をこの PC で作るには、WebGPU と、配信版か配布した編集アプリが要る
- **フォントはコマンドと同じくサブセット化する。** Egatari ファイルに保存・エクスポートするとき、埋め込むフォントをファイルが使う字だけにサブセット化する。コマンドと同じ harfbuzz（WebAssembly）なので、字はコマンドでビルドしたものとバイトまで同じ（`tools/test-app.mjs` と `tools/test-font-subset.mjs` が確認する）。サブセット化のツール（`font-subset.js`、約 2 MB）は初めてエクスポートするときに読み込み、読み込めなければ分割ファイルをそのまま含める（大きくなるだけで、見た目は同じ）。プレビューはサブセット化しない。後で字を追加する編集（台本や本の段 A の保存）は、埋め込んだどのフォントにも、その字だけの小さな補いを追加する。フォントのファイルを持たない編集アプリ（オフライン版のエディタ `editor.html` は明朝を持たない）でも保存はでき、開く端末のフォントで出る字を名指して知らせる
- **オフライン版のエディタに明朝はない。** 配信版の編集アプリは BIZ UDP明朝を持つ（明朝を使うファイル、たとえばテーマ `kokugo` のときだけ読む）が、オフライン版のエディタ `dist/editor.html` は小さく保つために持たない。そこでは明朝のファイルは知らせを表示してビルドされ、開く端末の明朝で表示されます
- **同梱のもの。** パーツライブラリのパーツ（`vendor/components/` のすべてのバージョンと `components.lock.json`）・テーマ（`themes/`）・ランタイム（`kit/`）は、アプリをビルドしたときのもの。ファイルは、記録したハッシュに合うバージョンのパーツがアプリにあれば、そのバージョンで再ビルドする。テーマも同じく記録したバージョンで再ビルドする（前のバージョンは `vendor/themes/` と `themes.lock.json`）。そのバージョンが今のバージョンでなければ、プレビューは記録した色のままで、上の知らせがそう言い、今のバージョンで変わる色（前 → 今、色見本つき）を挙げて「テーマを更新」を出す。今のバージョンで再ビルドするのはそのボタンを押したときだけ（`egatari.json` の `themes` とファイルの記録を変更する。保存すると新しい色で書く）。黙って色を変えない（[リファレンス](reference.ja.md)「テーマのバージョン」）。作業フォルダの中のパーツとテーマ（`components/<名前>/index.js`、`themes/<名前>/`）は、いつもどおりフォルダから読む。どちらにもないテーマ（自分のテーマのフォルダにある機関のテーマなど。コマンドは `EGATARI_THEMES`・`~/.egatari/themes` で見つける）は `theme not found: "<名前>"` と警告して `default` でビルドし、プレビューの上の知らせに「テーマを読み込む…」を出す（警告の一覧にも）
- **テーマを読み込む。** 「テーマを読み込む…」（テーマの知らせ、新規作成の ③ のテーマの一覧の最後、スタート画面の「自分のテーマ…」）で、小さなウィンドウ「テーマを読み込む」を開く：「テーマを ZIP ファイルか、テーマのフォルダから読み込みます。」と、「ZIP ファイルを選ぶ…」「フォルダを選ぶ…」（フォルダを選べるブラウザ（Chrome・Edge）だけ）「キャンセル」。ファイルやフォルダを選ぶダイアログはそのボタンから開くので、iPad でも開ける。
- **自分のテーマのフォルダ。** 「フォルダを選ぶ…」で、自分のテーマのフォルダ（たとえば `~/.egatari/themes`。macOS の選ぶダイアログでは ⌘⇧. で隠しフォルダが見える）を 1 回だけ選ぶ。その後はコマンドと同じ順と同じルートの決まりでテーマを探す：作業フォルダ → その `themes/` → このフォルダ → 同梱のテーマ。テーマのファイル・ロゴ・`extends` の親は、そのテーマのルート（か同梱のテーマ）の外に出ない。フォルダは読み取り専用で開き、書き込まない。中身は Egatari ファイルと同じく信頼しない（テーマの CSS は同じ消毒を通り、ロゴは data URI になる）。読むのは、ビルドが使うテーマのファイルだけ。ブラウザはフォルダのハンドルを IndexedDB に保存し（中身は保存しない）、次に要るときに読む許可をもう一度求める：知らせに「テーマのフォルダ「<名前>」を使う」を出す。「自分のテーマ…」で今のフォルダとそのテーマを見て、「このフォルダの登録を解除」で登録を解除する。Egatari ファイルにエクスポート・保存すると、使った自分のテーマは原稿の `themes/<名前>/` として入るので、ほかの所でも同じテーマで再ビルドできる（`npm run build -- --portable` で作った Egatari ファイルは、もうそこに入れている）
- **ZIP ファイルのテーマ（自分のテーマ）。** フォルダを選べない Safari・Firefox・iPad も含め、どのブラウザでも「ZIP ファイルを選ぶ…」で `.zip` からテーマを読み込める。ZIP ファイルの中の深さ 5 までの、`tokens.css` のあるフォルダがそれぞれ 1 つのテーマで、名前はそのフォルダの名前（ZIP ファイルの最上位に `tokens.css` があればファイルの名前）。すべて読み込むので、同じ ZIP ファイルの中のテーマどうしの `extends` も解決する。読むのは `tokens.css`・`theme.json`・その `logos` に書いたテーマのフォルダの中のロゴ・最上位の `LICENSE*` だけ。ZIP ファイルは信頼しない：32 MB・3000 項目・テーマのファイルは合わせて 16 MB まで（tokens.css 4 MB、theme.json 64 KB、ロゴは 1 つ 4 MB）。`..`・絶対パス・シンボリックリンクの項目や、1 つの小文字の識別子（`^[a-z][a-z0-9-]{0,63}$`）でないテーマの名前があれば、ファイルごと読み込まず、その項目の名前と次にすることを知らせる。読み込んだテーマは中身ごとこのブラウザに保存し（IndexedDB。テーマの名前ごと）、テーマの一覧の「自分のテーマ」の見出しの下に出す。同じ名前のテーマがもうあれば置き換え、「同じ名前のテーマ「<名前>」があったので、今読み込んだものに置き換えました。」と知らせる。スタート画面の「自分のテーマ…」は、保存したテーマを見せる名前ごとに並べ、それぞれに「削除」を付ける（確認してから削除する：「「<名前>」をこのブラウザから削除します。読み込んだ ZIP ファイルは残ります。」）。削除したテーマを使うファイルは `default` でビルドし、知らせに「このブラウザに保存したテーマにありません（削除したか、まだ読み込んでいません）。「テーマを読み込む…」で ZIP ファイルかテーマのフォルダから読み込んでください」と出す。ビルドは保存したテーマをテーマのフォルダと同じ場所・同じ順・同じ決まりで読み、テーマのフォルダにも同じ名前のテーマがあれば、あとから選んだ・読み込んだほうを使う（そのようなフォルダを選ぶと「同じ名前のテーマ「<名前>」が、このブラウザにも保存してあります。フォルダのものを使います。」と知らせる）。テーマの ZIP ファイルの作り方：テーマのフォルダを圧縮する（Mac は Finder で右クリック →「圧縮」、Windows は右クリック →「ZIP ファイルに圧縮する」）か、GitHub のテーマのリポジトリで「Code」→「Download ZIP」
- **読まないもの：** `.` で始まる名前と、`out/` `audio/` `video/` `bundle/` `node_modules/` のフォルダ（3000 ファイル・10 階層まで）。`audio/` は Egatari ファイルに保存するときだけ読む
- **再ビルドはまだ比べない。** スライドを編集した後の保存は、同梱の kit でファイル全体を再ビルドする（なので、古い・新しい build で作ったファイルは編集した所の外も変わり、字は分割ファイルごと埋め込む）。編集したスライドのほかにどのスライドが変わったかは、まだ見せない
- **字の補いは多めになることがある。** 絞り込んだ字に `unicode-range` のないファイル（以前のバージョンがコマンドで作ったもの）では、元の台本の字があることしか分からないので、絞り込んだ字がもう持っている字の分割ファイルも追加することがある（ファイルが少し大きくなる。字が欠けることはない）
- **ファイルの中からの通信は止まる。** 外部の画像やスクリプト（`https://…`）はプレビューに出ない（build はもともと警告する）

## 仕組みと安全

- **ビルドは 1 つ。** `kit/core/build-core.mjs` がビルドの本体（注記・取り込み・KaTeX・パーツ・台本・強調・秒数・テーマ・ファイルの埋め込み・字）で、Node に依存せず、渡された口を通してだけファイルを読む。`kit/build.mjs` は Node のファイル（とフォントのサブセット化・ffmpeg）を、編集アプリは選んだフォルダと同梱の kit・パーツ・テーマ・KaTeX・フォントと、同じフォントのサブセット化を渡す。サブセット化を切れば、両方が 1 バイトも違わない HTML を出し、エクスポートでサブセット化したフォントもバイトまで同じ（`tools/test-app.mjs` が `examples/minimal` と `examples/tmlr2026-calibration` で確認する）。台本の解析と書き換え（`kit/core/narration-core.mjs`）と新規作成のテンプレート（`kit/templates/new-deck.mjs`）も同じく共有する
- **編集の表示も 1 つで、ファイルの外にある。** `server/editor-ui.js`（原稿の欄・台本の引き出し・コメントの欄と一覧）は、ここでは編集アプリのページで、開発サーバーでは外枠のページで動く。どちらも同じ問い合わせ（`/__dev/source` `/__dev/edit` `/__dev/narration` `/__dev/comment` …）を送信し、開発サーバーは HTTP で、編集アプリはページの中で開いたフォルダについて答える（`app/devapi.js`）。ファイルの中にあるのは知らせを送信する `server/hints.js` だけ（下）
- **ファイルは砂場の中で動き、書き込めない。** プレビューは `allow-same-origin` を付けない `<iframe sandbox="allow-scripts allow-modals">` なので、ファイルは origin を持たない。編集アプリのページ・保存領域・フォルダのハンドルに届かない。`allow-modals` は印刷のため。ページの Content-Security-Policy（アプリ自身の読み込みだけを許し、iframe の移動は許さない：`frame-src 'none'`）に重ねて、プレビューの文書には別の決まりを、ファイルのどのバイトを解析するよりも前に効かせる。編集アプリはプレビューの文書を「信頼する先頭部分（doctype・`<html><head>`・`<meta charset>`・CSP の `<meta>`・小さな信頼する仲立ち）＋ビルドしたファイルそのまま」として作り、ファイルの文書の中を探して決まりを入れることはしない。決まりは `connect-src 'none'`、画像・字・スタイル・音声は `data:` / `blob:` だけ（ビルドが埋め込む）、Worker・iframe・フォーム・`<base>` は使えない（`'unsafe-eval'` は、取り下げたパーツのバージョンのためだけにプレビューの決まりに残す。次の項目）。発表者ビューは編集アプリが開くウィンドウで、その中のファイルもまた同じ決まりの砂場の iframe。やり取りは編集アプリが中継する
- **編集アプリのページは eval を許さない。許していたのは取り下げたパーツのバージョンのため。** ページ自身の Content-Security-Policy に `'unsafe-eval'` はない（あるのは `'wasm-unsafe-eval'` だけで、MP3 エンコーダの WebAssembly のため。`eval` も `new Function` も許さない。配信版も オフライン版のエディタ `editor.html` も。テストがページの CSP 違反を見張る）。パーツライブラリ v1.0.0・1.0.1 の `m-sweep`・`m-curves` は式を `new Function` で動かすので、パーツライブラリはそのバージョンを取り下げ（yank）、置き換えを v1.0.2 とした（[SECURITY.md](../SECURITY.md#components-yanked-by-the-registry)）。取り下げたバージョンを記録したファイルを開くと、編集アプリは知らせと **「1.0.2 で再ビルドする」** ボタンを出し、バージョンを勝手に変更することはしない（仕様 §6。再ビルドするとパーツの同一性の hash や見え方が変わることがあり、再ビルドした後の知らせに、どの hash が変わったかを書く）。そのときまではファイルは今のまま再生できるが、プレビューの枠（`allow-same-origin` のない sandbox。編集アプリのページ・保存領域・フォルダのハンドルに届かない origin）の中だけ。枠はこのページの決まりを受け継ぐので、編集アプリの中では取り下げたバージョンの `m-sweep`・`m-curves` は式を計算できず、図の代わりの表示（`DECK.componentErrors`）になり、ファイルのほかの部分は動く。プレビューの決まり（`PREVIEW_CSP`）と開発サーバーのファイルの文書（編集アプリのページを周りに持たない、最上位の sandbox の文書）は `'unsafe-eval'` を残すので、そちらでは取り下げたバージョンも動く
- **依頼ではなく知らせ。** プレビューには書き込みを依頼する口がない。送信できるのは知らせだけ：「この `data-src` の範囲と hash の要素を修正したい」（編集モードでダブルクリック）、「この要素にコメントしたい」（Alt+クリック。スライドの id とステップ、要素の短い引用、点の近くの字、点のスライドの座標）、キーの `e`・`n`・`c`・`r`・Esc（`r` は録音モードを開くだけ）、今の位置（`deck-pos`）。知らせは書き込む本文を持たない。編集アプリは送信元のウィンドウと知らせの形を確認し、編集モードでないときの edit の知らせは無視し、今の原稿を自分で読み、範囲が今のビルドの編集できる要素で hash が合うことを確認して、自分の欄を見せる。書くのは、その欄や引き出しで「保存」か ⌘/Ctrl+Enter を押したときだけ。編集の確認と読み取り専用のファイルは、これまでどおりこの書き込みにかかる。編集アプリからプレビューに送信するのは、表示に要るものだけ（編集モードの入り切り・印を付ける要素・「そのステップへ」・印刷・品質チェック）。コメントの点は開発サーバーと同じく確認する（数だけ、1280×720 のスライドの外は端に寄せ、ほかの項目は破棄する。`app/devapi.js` も `kit/core/comment-core.mjs` でもう一度確認する）。偽の点で変わるのは印の位置だけで、プレビューの上の印は、編集アプリのページがプレビューの大きさから描く
- **触るのは選んだフォルダかファイルだけ**で、ブラウザの許可を得てから
- **保存は始めたときのファイルに結び付く。** 待つたび（再ビルド・確認のウィンドウ・編集の確認・保存先を選ぶダイアログ・ファイルを作る・書く）の後に、同じファイルが開いたままかを確認し、その確認を書き込みの中まで運ぶ：その間に別のファイルを開いたら、ファイルを入れ替えず（書き込みを取り消す）、ほかにも何も書かない。新しいファイルの識別子をファイルの設定に書くのと「保存した」にするのは、ファイルを書いた後だけ。保存している間にした編集は、保存したファイルに入っていないので、未保存の印のまま
- **信頼する欄で編集している間**（原稿の欄・コメントの欄を開いている、台本の引き出しで入力している・未保存の変更がある）は、プレビューを `inert` にする。その間はスライドからの知らせでパネルの欄を開け閉め・切り替えせず、編集している台本のステップも変更しない
- **フォルダとリンク。** メモリの上・OPFS のフォルダはシンボリックリンクを持てない。選んだフォルダの中のリンクは、Chromium では編集アプリにまったく見えない（一覧に出ず、名前でも開けず、書けない。`tools/test-security.mjs` が確認する）ので、ビルドがリンク越しにフォルダの外のファイルを読むことはない。File System Access API には編集アプリ自身がリンクを見分ける手段がないので、これはブラウザに頼っている
- **マイクと TTS は編集アプリのページだけで。** 録音（`getUserMedia`・`MediaRecorder`）・取り込み・後処理・MP3 にするのは編集アプリのページで、プレビューからは始められず、プレビューから音声を受け取ることもない。録音は録音モードだけで行い、開いている間プレビューは `inert`。音声のパネルが音声を作って書いている間は、スライドからの知らせでパネルのステップを変更しない。ページの決まりはそのままで通信を許さない：この PC で作る AI 音声は、同じサイトの別のウィンドウ（`lab/tts-helper.html`。テストページと同じく、バージョンを固定したライブラリを jsDelivr から、モデルを Hugging Face から取る）で動かし、ウィンドウに送信するのは読む文と声の名前だけ。編集アプリはそのウィンドウからの音だけを受け、標本化周波数と長さを確認し、録音と同じく後処理する。フォルダから読む音声には上限がある（manifest は 16 MiB、音声のファイルは 1 つ 64 MiB）
- **Egatari ファイルを開いても、その中のものは何も動かない。** ファイルはバイト列として読み、スクリプトを動かすブラウザと同じ解析の規則で（何も実行しない）Web Worker（編集アプリに同梱。ページの決まりは `blob:` の Worker だけを許す）の中で解析する。そのファイルへ移動したり、ページに入れたりはしない。動くのは原稿から再ビルドしたファイルだけで、フォルダのときと同じ砂場のプレビューの中

## GitHub Pages で配布する

`.github/workflows/pages.yml` が `node tools/build-app.mjs --out _site --parts` でビルドし、GitHub Pages に置く（編集アプリはルート `/`、オフライン版のエディタは `/editor.html`、テストページは `/lab/irodori.html`。前に編集アプリがあった `/editor/` は、問い合わせと `#` を残して `/` へ移動するページ）。パスはどれも相対なので、同じファイルが独自ドメイン <https://studio.egatari.org/>（Settings → Pages → Custom domain で設定し、サイト全体に効く）でも <https://egatari.github.io/egatari-studio/>（独自ドメインへ移る）でも動く。置く（deploy）のはリリースのタグだけ：タグ `vX.Y.Z`（数 3 つ。`v0.5.0-rc.1` などの rc のタグは置かない）を push したときと、そのタグで workflow を走らせたとき（そのバージョンを置き直す）。`main` への push と pull request はビルドするだけで（リリースの前にビルドの壊れに気づくため）、ブランチで走らせるとビルドするだけの試し。リリースの手順は [RELEASING.ja.md](../RELEASING.ja.md)。Pages を設定するまでは何も置かない

1. Settings → Pages → Build and deployment → Source を **GitHub Actions** にする
2. Settings → Secrets and variables → Actions → Variables に `EDITOR_PAGES` = `true` を追加する（なければビルドするだけで、何も置かない）
3. Settings → Environments → `github-pages` → Deployment branches and tags にタグの決まり `v*.*.*` を追加する（この environment はふだん `main` だけを許すので、追加しないとタグからの deploy は断られる）
4. リリースのタグを push するか、タグを選んで workflow を走らせる（Actions → pages → Run workflow）

ビルドはサンプルも Egatari ファイルにして `examples/<名前>.ega.html` に置き（`tools/examples-portable.mjs`。合わせて約 37 MB。`--no-examples` で含めない）、横にサムネイル（`<名前>.cover.webp`）を置いて、編集アプリのスタート画面に並べる。`examples/index.json` で `path` のあるサンプル（本のある `heikin-chuouchi`・`rashomon` と、egatari.org のギャラリーの 17 本）は [egatari/examples](https://github.com/egatari/examples) をそのままコピーしたもの。`node tools/examples-sync.mjs <clone> --commit <sha> <名前>…` がコピーし、`SOURCE.json` にコミットと各ファイルの sha256 を書く。`--check`（`npm run gen:check`）はコピーが編集されていないかを確認するので、修正するときは元のリポジトリで直してコピーし直す。サムネイルは `examples/_covers/`：egatari.org のギャラリーにあるものはサイトの絵をそのまま（`node tools/example-covers.mjs --site <site>/src/gallery`）、Studio だけのものは選んだ絵（`--picked <フォルダ>`）か 1 枚目のスライドから作った絵（`npm run covers`）。ビルドするのはサンプルのフォルダの一時的なコピーから（`examples/` には何も書かない）。`egatari.json` のないサンプル（テンプレートとしてコピーしてよい `minimal` など）には名前から決めた `docId` を与えるので、ビルドするたびに同じ文書になる

ビルドは make の生成元から `egatari-make-<version>-ja.zip` と `egatari-make-<version>-en.zip` を `dist/` に書く。ダウンロードはこのサイト内のファイルを使い、単体の `editor.html` はオフラインでも使えるよう両言語の ZIP を埋め込む。凍結した `/vX.Y.Z/` と編集アプリのサイトのアーカイブも、`dist/` のほかのファイルと一緒に ZIP を持つ。

### すべてのパーツのサンプル（`/parts/`）

`--parts` を付けると、ビルドはすべてのパーツのサンプルのページも作る（`tools/parts-gallery.mjs`。約 40 秒・10 MB）：`components2.lock.json` の既定（`default`）のパーツライブラリのバージョンのすべてのパーツを、説明の 1 枚と動くサンプルのスライドで、「新規作成…」の ④ と同じく伝えたいことごとに並べ、前のバージョンと比べて新しい・変わった・サンプルが変わったの印を付ける。置く場所は `/parts/v<パーツライブラリのバージョン>/`（たとえば <https://studio.egatari.org/parts/v2.1.1/>）で、`/parts/index.html` がバージョンを並べ（いまのバージョンが先）、`/parts/versions.json` も書く。編集アプリの使い方と「新規作成…」の ④ は絶対の URL で張るので、オフライン版のエディタ・`file://`・Colab からも開ける。ページは取り込んだリリースのコピーだけから、git もネットワークも使わずにビルドする：そのバージョンのファイルを `vendor/components/sha256/`（そのリリースが配布したときのコピー。`components2.lock.json` の `catalogues.<バージョン>.content` にパーツごとに記録）から tarball と同じ形に並べ（`vendor/components-2/manifest-<バージョン>.json` とファイルごとに照らす）、パーツライブラリ自身の `gallery.mjs --pack` でまとめ、`kit/build.mjs` でビルドする。そのツールは egatari/components の決まったコミットのコピーを `vendor/components-gallery/` に持つ（`SOURCE.json` がリポジトリ・コミット・各ファイルの sha256 を記録。`node tools/parts-gallery.mjs --verify` が確認し、`--sync <checkout>` が取得し直す）ので、タグからビルドするリリースのアーカイブも同じページを作る。編集アプリと同じく、公開したバージョンは凍結する：ビルドは前の各リリースのアーカイブの `parts/` を `/parts/` に移動し（`/vX.Y.Z/` の下には置かない）、同じパーツライブラリのバージョンは最初に公開したリリースのページを残す。いまビルドしたものは、前に公開していないバージョンにだけ使う

### リリースに添えるファイル

`npm run release:assets`（`tools/release-assets.mjs`）が同じサンプルのファイルを `out/release/` にビルドし、`examples.json`（名前・題名・言語・枚数・大きさ・sha256、本があるかの `book`）を添える。make の生成元から `egatari-make-<version>-ja.zip` と `egatari-make-<version>-en.zip` も書く。どこにも上げない。GitHub のリリースには人の手で添える（たとえば `gh release create v<バージョン> out/release/*`）

### バージョンごとの URL（凍結したコピー）

サイトは置くバージョンの下限（v0.6.0。下の **置くバージョンの下限**）からのすべてのリリースを残す。ルートは最新のリリース、`/vX.Y.Z/`（たとえば <https://studio.egatari.org/v0.4.2/>）はそのリリースを凍結したコピーで、中の形は同じ（`/vX.Y.Z/editor.html`・`/vX.Y.Z/lab/…`・`/vX.Y.Z/examples/…`）。Pages は 1 回に 1 つの artifact を置くので、リリースの deploy がビルドする（`node tools/site-versions.mjs assemble`）：いまビルドしたものをルートと `/v<そのバージョン>/` に、公開済みの前の各リリースのうち下限からのものは添えたファイル `editor-site-vX.Y.Z.tar.gz` を取り、リリースの説明の行 `editor-site-vX.Y.Z.tar.gz sha256: <16 進>`（と GitHub が記録するそのファイルの digest）と合うか確認して `/vX.Y.Z/` に広げる。そのファイルのないリリース（v0.4.0 まで）は飛ばし、sha256 の行がない・合わないときはビルドを失敗にする。このファイルはビルドした `dist/` を、何度作っても同じバイトになるようにまとめたもの（`node tools/site-versions.mjs asset vX.Y.Z` が、タグの git worktree で `npm ci` してからビルドする）で、リリースのときに添える（[RELEASING.ja.md](../RELEASING.ja.md)）。ルートの `versions.json` がバージョンを並べる。`main` への push と pull request でも、同じビルドを試しとして走らせる。1 つのバージョンが約 50 MB なので、GitHub Pages の上限 1 GB には約 18 バージョンが入る。800 MB を超えると知らせ、1 GB を超えると失敗にする。どちらの知らせも、置いている最も古いバージョンを、次に下限を上げるときの候補として挙げる

- **前のリリースは 1 つだけ。** サイトに置くのは今のバージョン（ルートと `/vX.Y.Z/`）と、その 1 つ前のリリースだけ（`tools/site-versions.mjs` の `KEEP_PREVIOUS = 1`。2026-11-11 の作者の決定）。リリースのたびに入れ替わる：v0.6.9 を置くと v0.6.8 を置き、v0.6.7 から前は下の「もう置いていない」のページになる。候補（rc）では、その前の最新のリリースを置く。前のリリースだけが公開したパーツライブラリのバージョンのサンプルのページも、一緒に置かなくなる。各リリースの一式は GitHub のリリースから取れる
- **置くバージョンの下限。** `tools/site-versions.mjs` の `HOSTED_FROM`（いまは `0.6.0`。v0.6.5 のサイトが 1030 MB になり GitHub Pages に断られたあとの、2026-11-06 の作者の決定）が、サイトに置く最も古いバージョン。それより前のリリースで、添えたファイルが `editor-site-vX.Y.Z.tar.gz` か `editor-site-vX.Y.Z.archived.tar.gz` のどちらかの名前であるものは、ビルドが取りも広げもせず、`/vX.Y.Z/index.html` だけを書く。日本語と英語の短いページで、そのバージョンはもう置いていないこと、GitHub のリリース（一式はそこから取れる）と最新版へのリンクを出す。ビルドの記録にはバージョンごとに 1 行が出る。これらのバージョンは `versions.json` に含めないので、バージョンの一覧に出ない。その下のほかのパス（`/vX.Y.Z/editor.html`）は 404 になる。下限を上げるには、`HOSTED_FROM` を残す最も古いバージョンにして（知らせが候補を挙げる）もう一度置く。リリースに添えたファイルはそのままでよい。ファイルの名前を `editor-site-vX.Y.Z.tar.gz` に戻しても、下限より前のバージョンはまた置かれない。また置くのは `HOSTED_FROM` を下げたときだけ（サイトは 1 GB に収まる必要がある）。v0.4.1〜v0.4.8 のファイルは、下限を入れる前に `editor-site-vX.Y.Z.archived.tar.gz` に名前を変えて残してある。`node tools/site-versions.mjs verify` が確認するのは `editor-site-vX.Y.Z.tar.gz` の名前のファイルだけ

- **知らせと一覧。** コピーは上に 1 行を出す：「Egatari Studio v0.4.2（そのリリースのまま凍結したコピー）を使っています」・最新版（ルート。`?lang` は残す）へのリンク・ほかのバージョンの一覧。✕ で隠せる。ルートはスタート画面の下にバージョンの一覧を出す。この知らせより前にビルドしたコピー（v0.4.1・v0.4.2）には、ビルドが `index.html` と `editor.html` にルートの `version-notice.js` を読み込ませる（決まりの `<meta>` の後に `<script>` を 1 つ。コピーのほかの所は変えない）
- **ブラウザのデータは共有。** どのバージョンも同じサイト（同じ origin）なので、ブラウザのデータを共有する：最近開いたもの（IndexedDB の `motion-slides-editor`。ファイルのハンドルと名前だけを持ち、どのバージョンも同じ形で読むので、あるバージョンで開いたファイルはどのバージョンにも並ぶ）・表示言語（`localStorage`）・利用者のテーマのフォルダ・この PC で AI 音声を作るモデル（Cache Storage。モデルのバージョンごとの名前なので、同じモデルのバージョンどうしは 1.26 GB の取得を共有する）。ほかのモデルのバージョンのキャッシュを削除するのはルートだけで、コピーは削除しない（`lab/model-cache.mjs` の `inFrozenCopy`）。ただしコピーの v0.4.1・v0.4.2 はこの決まりより前のものなので、後のリリースがモデルを変更すると、その新しいモデルを削除する。最近開いたものの保存の形を将来変えるときは、DB の名前を変更すること（古いコピーも開き続けるため）。service worker はない。ウェブアプリの manifest の scope は各コピーのフォルダ

ふだんはブラウザの言語（日本語か英語）に合わせる。右上の **English / 日本語** のボタンで切り替えるか、`…/?lang=en`・`?lang=ja` で開く。選んだ言語は記憶しておき、ファイルを開いたまま切り替えても同じフォルダを開き直す（開いた Egatari ファイルは閉じる。保存していない変更があれば先に確認する）。編集のツール（編集モード・原稿の欄・台本の引き出し・コメント）は編集アプリの言葉に合わせる（開発サーバーではスライドの言語 `<html lang>` に合わせる）。
