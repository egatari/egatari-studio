### Changed

- New lessons are built with parts library 2 (the default 2.x catalogue, which the chat AI's instructions describe since #125): New… (pasting an AI's output into a new lesson), `npm run new` / `npx egatari new` and the working folders the make skill writes get `egatari.json` with `"componentsCatalogue": "2"`. Lessons and folders without that setting keep parts library 1; nothing switches silently. When a 1.x working folder fails to build only because it uses parts that library 2 has (#165), the editor's error offers "Use parts library 2", which writes that one setting (other members byte for byte) and rebuilds. A pasted reply that cannot build in an open single file now gets the same message with the fix, in the editor's language.
- A parts library 2 lesson whose own `<script>` uses the player's 1.x helpers (`DECK.define`, `DECK.MotionElement`, `DECK.el`, …) keeps them in the built player, so such code still runs instead of failing silently; lessons that do not use them stay without them.
