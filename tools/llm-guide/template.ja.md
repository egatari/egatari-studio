# チャットの AI で Egatari の教材を書く

[English](authoring-with-llms.md) | 日本語

無料のプランのチャットの AI に送るときは、編集アプリの「新規作成」でコピーしてください。軽くした指示になります。

**使う人へ。**チャットの AI（claude.ai・Gemini・ChatGPT など）に、[Egatari](https://github.com/egatari/egatari-spec) の教材（Egatari はオープンなファイル形式、Egatari Studio はその編集アプリ）の初めの下書きを書かせるための指示のまとめです。段階ごとに出る HTML のスライドと、その口述原稿ができます。インストールもコーディング道具も要りません。

1. 新しいチャットを開き、**「AI への指示」から最後までをすべて**貼り付け、続けて系列の指示（下）をすべて貼り付け、最後に **頼みたいこと** の記入欄（タイトル・対象・長さ・言語・話者・そのほかの希望。話者は既定で 1 人）を埋めて送ります。編集アプリは問いに答えるだけで指示を組み合わせ、最後に「頼みたいこと」を付けてコピーします（**新規作成… → 4 つの問いに答える → 指示をコピー**。書いたものが最後に入るので、長い貼り付けがチャットで添付の形になっても、そのまま送れます）
2. AI の出力には、灰色の枠（コードブロック）が 2 つあります。それぞれ枠の右上のコピーのボタンで写し、Egatari Studio のその窓の ⑤ の 2 つの欄（スライド・台本）に貼り付けて **作成** を押します（出力をまとめて写したときは、どちらかの欄に貼れば 2 つに分けて入れます）。エディタがどのスライドにも変わらない id を付け、品質チェックをかけて開きます
3. 品質チェックの指摘を直すか、品質チェックの板の **AI への修正依頼をコピー** を押して同じチャットに貼り付け、AI の出力を **修正…** の ③ に貼り付けて **置き換える** を押します。あとからスライドを足すには **スライドの挿入… → チャットの AI に書いてもらう**

**毎回貼るか、一度登録するか。**指示はチャットのはじめに毎回貼るのが既定です。どのチャットの AI でも使え、いつも今の指示になります。よく教材を書くなら、チャットの AI に指示を登録しておくこともできます（編集アプリでコピーするか、このファイルと要る系列の指示をテキストのファイルに保存して使う）：

- **claude.ai**：プロジェクトを作り、指示をプロジェクトの指示に貼るか、プロジェクトのファイルとして加えます。そのプロジェクトのチャットはどれも指示を使います。スキルが使えるなら、スキルに指示を入れることもできます
- **ChatGPT**：プロジェクト（指示かファイル）か、カスタム GPT。指示はカスタム GPT の指示の欄に収まらない長さなので、ナレッジのファイルとして加え、指示の欄には「添付の Egatari の指示にそのまま従う」と書きます
- **Gemini**：Gem。指示を Gem の指示に貼るか、長すぎればファイルとして加えます

登録した指示は自動では新しくなりません。指示のはじめに **指示の版：…** の行があるので、編集アプリが新しくなったらコピーし直した指示の版と比べ、違えば登録したものを差し替えます。登録した指示は Claude Code のスキル（`skills/`）とは別物です。スキルは手元のコンピュータで教材の品質チェック・組み立て・読み上げ（TTS）までしますが、指示はチャットの AI に、貼り戻す 2 つのファイルを書かせるだけです。

# AI への指示

指示の版：`{{PACK_VERSION}}`

短い **Egatari の教材**を 1 つ書いてください。段階ごとに出る HTML のスライド（`deck.html`）と口述原稿（`narration.md`）で、どちらも自動で組まれ、品質チェックを受けます。ここにないものは使えません。教材は頼まれた言語で書きます（スライドと口述原稿は同じ言語）。規格には **R-fit** のような名前があり、修正依頼は破った規格を名前で示します。依頼は最後の **頼みたいこと**（かその前の会話）にあります。空の項目やない項目はほどよく決め、A と B が両方残っていれば書き込みのある方に従います。

**よくある失敗：**

- **2 つの囲みはどちらも最後まで書いて閉じる。**囲みの途中で終わらない（R-output）。構成案がなければ、教材は短くする（5〜8 枚）。頼む文に構成案とその範囲があれば、その範囲のスライドをちょうどその枚数だけ書く（エディタは 1 回に 6 枚までしか頼まないので、収まる）
- **1280×720 のスライドの大きさ**（品質チェックが測る。R-fit）：本文の場所は 1184 × 443 px（565 px まで。`noconcl` なら 1184 × 558）。字は 32 px・1 行 46 px で、入るのは**およそ 8 行**。はみ出す 46 px ごとに 1 行を削る。**図や部品の中も含め、字はすべて 24 px 以上**
- **グラフと図：**部品は大きさによらず字を 24〜28 px で描くので、決めるのは部品の大きさ（R-fit）
- **その場で書く `<svg>`：**字は「表示の幅 ÷ viewBox の幅」で縮むので、viewBox を表示の画素で書く（`<svg viewBox="0 0 560 320" width="560" height="320">`）。`font-size` は 24 以上。`width:100%` と別の幅の viewBox を組み合わせない。合う部品があれば部品を使う

## 1. 出力の形

- **R-output** 返事は**ちょうど 2 つのコードの囲み**にし、この順で、名前を `deck.html` と `narration.md` にする（始まりの行は ```` ```deck.html ```` と ```` ```narration.md ````）。間には何も書かない（前後に 1 行の添え書きはよい）。1 つのファイルを囲みに分けない。ファイル・キャンバス・添付にせず、返事の本文に書く。ほかのファイルを参照しない（画像・`{{FIG:…}}`・`{{JSON:…}}`・外の URL・`<link>` は使わない）。囲みの途中で終わらない（長すぎるなら枚数を減らす。ただし構成案の範囲を頼まれたら、ちょうどその枚数）
- **R-outline** **構成案だけ**を頼まれたら（長い教材を 2 回に分けて作るとき）、`outline` という名前の囲み 1 つ（始まりの行は ```` ```outline ````）だけで返し、`deck.html` と `narration.md` は書かない：列が「番号」「見出し」「要点（1 行）」の Markdown の表で、スライドごとに 1 行、全スライドを順に。その後の頼む文は範囲を示す（「構成案の 7〜12 枚目」）ので、その見出しと要点のとおりに、ちょうどそのスライドを書く
- **R-noids** スライドの id を**書かない**。`<section class="slide">` に `id` を付けず、口述原稿の見出しにも `{#…}` を付けない。id は取り込みでエディタが付ける。id のあるデッキを渡されたとき（修正依頼）は、今ある `id="…"` と `{#…}` をそのまま残す

## 2. deck.html

### 2.1 骨組み

```html
<!DOCTYPE html>
<html lang="ja" data-theme="default">
<head>
<meta charset="utf-8">
<meta name="viewport" content="width=device-width, initial-scale=1">
<title>教材の題名</title>
</head>
<body>
<div id="stage">
  <section class="slide cover noconcl static"> … </section>
  <section class="slide"> … </section>
</div>
</body>
</html>
```

- `lang`：`ja`・`en` など（教材の言語）。`data-theme`：{{THEMES}} のどれか（ビジネス・ピッチは `business`、国語は `kokugo`、ほかは `default`）
- `<script>` は部品のデータ（§2.6）だけ。`<style>` は配置（大きさ・間隔）だけに使い、色は書かない

### 2.2 スライド

- 普通のスライド：`<h2>` の見出し、`<div class="body">…</div>`、`<div class="concl"><span>…</span></div>`（結論の行。短い 1 文）
- 表紙：`<section class="slide cover noconcl static">` に、あれば `<div class="venue">…</div>`、`<h1>題名</h1>`、あれば `<div class="au">…</div>`
- 章の扉：`<section class="slide sec noconcl static"><h1>章の題</h1></section>`
- `<section>` の class：`noconcl`（結論の行なし）、`static`（段階なし）、`nostep`（箇条書きも初めから全部）、`layout-tate`（縦書き。kokugo の系列の指示があるときだけ）、属性 `data-morph`（§2.5）
- `.body` の中：`<p class="sub">` 小見出し、`<div class="big">` 主要な式、`<p class="note">` 補足、`<div class="thm">` 定理の枠、`<div class="cols">` 横並び、普通の `<p>` `<ul>` `<ol>` `<table>`
- 字の強調（色を付ける唯一の方法）：`term`（用語・問い）、`emph`（結論・問題・目標）、`muted`（既知の結果・控えめ）、`b`（太字）
- **R-headings** スライドの見出し（表紙と扉は `h1`、ほかは `h2`）は**すべて違う**ものにする（同じなら語を足す）。そのスライドの口述原稿の節は `## ` に続けて**見出しとまったく同じ文字列**で始める（`<br>` などのタグは除く）
- **R-colors** 色はテーマだけで：上の class と式のマクロ `\hlE` `\hlT` `\hlM`。16 進・`rgb()`・色の名前・`\color`・`\textcolor` は使わない。部品や SVG の中では：{{contract §3 "**色はテーマの CSS 変数だけ"}}

### 2.3 段階（出す順 = 話す順）

- **R-steps** 段階 0 は現れたときの姿で、文脈だけ（見出し・小見出し・導入の 1 文）。`data-step="k"`（k = 1, 2, …）の要素は段階 k で現れる。材料（箇条書きの項目・式・表の行・図の部分）は話す順に出す。式とそれを導く 1 文は同じ段階（`<div data-step="k">` で一緒に囲む）。1 枚の段階は 5 前後まで
- 結論の行は自動で**最後の段階** `concl` になる（`data-step` を付けない）
- `data-step` が 1 つもないスライドでは、上の階層の箇条書きの項目（`.body > ul > li`・`.body > ol > li`）に 1, 2, … が自動で付く。1 つでもあれば自動にならないので、出すものすべてに付ける
- 部品は自分の段階を足す（§3）。`data-from`（既定 1）から始まる
- つまり段階は `0 … max` と、結論の行があれば `concl`。`static` のスライドは段階 0 だけ

### 2.4 数式（KaTeX）

- **R-math** 行内は `\( … \)`、別行は `\[ … \]`。式の中の `<` は `\lt`、`>` は `\gt`。標準のほかに使えるマクロ：`\hlE{…}`（emph）`\hlT{…}`（term）`\hlM{…}`（muted）、`\htmlId{ID}{…}`、`\htmlData{mark=ID}{…}`、`\htmlClass{…}{…}`、`\morph{ID}{…}`。`\newcommand` と `\color` は使わない。記号は最初に使う所で定義する（`\(\mu\)`：母平均）

### 2.5 注目の演出とモーフ

- **R-marks** 口述原稿の `{mark:ID}`（§4）は、**同じスライド**の目印に印を付ける。{{contract §7 "目印："}}
- モーフ（なくてよい）：`<section class="slide" data-morph>` は前のスライドの要素を今の位置へ滑らせる。両方のスライドの要素に同じ `data-id="…"`、式の一部は両方に `\morph{ID}{…}`。段階 0 で見えている要素だけが動く

### 2.6 部品

- **R-components** 動く図は一覧（§3）の Web Components `<m-…>` で、`.body` の中に置く。どれにも高さ（`style="height:380px"`）と `aria-label` を付ける。データは子の `<script type="application/json">…</script>` **1 つ**にその場で書く。**図の数字は正しく**（計算する。見た目のために値を作らない。架空の数字は架空と書く）。関数の式は算術の式だけで、コードとしては実行されない（`Math.exp(x)`・`x**2`）。動きが説明になる所だけに使う（たいていのスライドには要らない）

### 2.7 表し方を選ぶ

- **R-purpose** 表し方は習慣でなく、そのスライドで言いたいことから選ぶ。作者がグラフの種類を言っていればそれに従う。表は全パーツの一覧を兼ねる。使うのは渡された文章に説明のあるパーツだけ（§3 と、入っている系列）。ほかの系列のパーツの方が合うときは、1 行のメモでそう伝える

{{PURPOSES}}

- **R-whole** 箇条書き・数字の札・円グラフは全体を一度に見せる。台本が 1 つずつ取り上げるときだけ 1 行ずつ出す（箇条書きなら全体に 1 つの `data-step` を付けるか、スライドに `nostep`）

### 2.8 スライドに収める（品質チェックのエラー）

- **R-title** 見出し：日本語は 26 字まで（全角 1・半角 0.5）、英語は 60 文字まで。コロンで終えない
- **R-concl** 結論の行：日本語は 35 字まで、英語は 70 文字まで。1 行
- **R-fit** 本文は 565 px（`noconcl` なら 680 px）より上で終える：1 枚におよそ 8 行・100 字・英語 60 語、または `big` の式 1 つと短い箇条書き 3 つ、または高さ 380 px までの部品と短い 1 行（2 行なら 330 px まで）。入らなければスライドを分ける。字を縮めず、字の大きさを書かない。図の中の字は 24 px 以上
- **R-style** 日本語のスライドは常体（だ・である、体言止め）で、です・ます を使わない。句読点はデッキ全体で 1 つの組（`、。` か `，．`）。英語のスライドは短い句で

## 4. narration.md

```markdown
# 口述原稿：<教材の題名>

## 減衰の式
[0] 減衰の式です。時刻ごとに残っている原子の数を考えます。
[1] 残る数は、はじめの数に、時間とともに小さくなる指数関数を掛けたものです。
[2] {mark:n0|circle}{N₀|エヌゼロ} は、時刻ゼロのときの、はじめの数です。
[concl] 半分になるまでの時間は、崩壊定数だけで決まります。
```

- スライドごとに 1 つの節を、**スライドの順に、すべてのスライド（表紙も）について**：`## <スライドの見出し>`（R-headings）。`{#id}` は付けない（R-noids）
- **R-narr-steps** 段階の印は `[0]` `[1]` … と `[concl]`。**どのスライドのどの段階にも口述原稿を書き**（段階 0 から max まで、結論の行があれば `[concl]`）、**ない段階の印は書かない**（`static` の表紙は `[0]` だけ。結論の行がなければ `[concl]` もない。`[01]` とは書かない）。段階の中では、その段階で現れるものだけを話す
- **R-dialogue** **既定は話者 1 人**で、話者名を書かない。掛け合いは頼まれたときだけ（3 人以上を頼まれても 2 役にし、最初にそう書く）：行を `Expert:` か `Novice:` で始め（続きの行は字下げ。話者なしは Expert）、認知的徒弟制の形にする：
  - Novice は相づち役にせず、学ぶ人の疑問を代弁するか、「つまり〜ということですか」と言い換える
  - Expert は答えて具体例か比喩を 1 つ足すか、言い換えを確かめて（違えば直して）1 歩進める
  - 理解の分かれ目（誤解しやすい所、「なぜ」が残る所）にだけ、1 枚に 1 回・2〜3 発言まで。ほかは Expert 1 人
  - 「なるほど」だけの発言、前の発言のくり返しは書かない。例：`Novice: つまり、大きいほど早く着くのですか。` `Expert: いつもではありません。大きすぎると谷を飛び越えます。大股で坂を下りすぎて、向こうの斜面に足が着くように。`
- `{cue}`：段階の中の同期点。部品の `cues(k)` の 1 つに 1 つ（部品の説明が求めるときだけ）
- `{mark:ID}`・`{mark:ID|効果}`・`{mark:ID|効果|hold=秒}`・`{mark:clear}`：目印のことを言う言葉の**すぐ前**に置く。1 段階に 1〜2 個まで。言葉でも言う。{{contract §7 "効果："}}
- **R-reading** `{表示|読み}` は **1 つの記号か 1 つの用語**の読み：`{θ|シータ}`、`{N₀|エヌゼロ}`、`{論語|ろんご}`。1 つの記号に星・プライム・添え字・ハットやバーが付いていてもよい（`{Q*|キュースター}`、`{θ̂|シータハット}`）。表示は普通の文字で書き、LaTeX にせず、式やいくつもの記号にしない（`{1-η|…}`・`{θとη|…}` は誤り：記号ごとに読みを付け、関係は言葉で言う）
- **R-formula** **式を読み上げない**：口述原稿に LaTeX・`\`・`^`・`_`・`a + b = c` のような文字列を書かない。式の意味を言葉で言う（§4 の見本の [1]）
- 日本語の口述原稿は話し言葉の です・ます。英語は話し言葉の英語。目安は 1 秒に日本語 5 字・英語 2.5 語。1 回の発言は 1〜3 文

## 5. 修正依頼

利用者が**修正依頼**（規格の名前の付いた指摘の一覧と、今のファイル）を貼り付けたら、その指摘だけを直し、ほかは変えず、`id="…"` と `{#…}` をすべてそのまま残し（R-noids）、また 2 つの囲みで返す（R-output）。依頼に一部のスライドしかなければ、そのスライドの `<section>` だけ（`<html>` なし）とその節だけを 2 つの囲みで返す（エディタが id で元の場所に戻す）。
