# Egatari Viewer

[English](viewer.md) | 日本語

Egatari Viewer は、[Egatari](https://github.com/egatari/egatari-spec) のファイル（.ega.html）を、開く端末の中で開いて再生する Web アプリです。置き場所は `https://viewer.egatari.org/` の予定で、ホーム画面に追加したときの名前は **Ega Viewer**、アイコンは「え」（Egatari の印。Egatari Studio のアイコンは「す」）です。**まだ公開していません**（[公開の手順](#公開の手順管理者向け)）。

配布する人向け：[iPhone・iPad で Egatari ファイルを開く（Egatari Viewer）](viewer-sharing.ja.md)。

Egatari ファイルを Web ページとして開けない場面があるために作りました。

- iPhone・iPad は、ファイルのアプリからこの端末の HTML のファイルを開けない
- Android のファイルのアプリには、ブラウザにうまく働かない `content://` のアドレスを渡すものがある
- チャット（Slack など）は大きなファイルのプレビューに失敗する

参加者はページの中でファイルを選びます（Android では、インストールしたアプリに共有もできます）。ファイルはページの中で読み、どこにもアップロードしません。

## 使い方

- **ファイルを開く**：「ファイルを開く」を押すか、ページにファイルをドロップします。再生するのは Egatari のファイルだけで、`deck-meta` が Egatari のものでないページは断ります。上のバーにファイルのタイトルと、「Egatari ファイル（編集可）」（原稿の層のある Egatari ファイル）か「Egatari ファイル（再生専用）」かを出します。どちらも同じように再生します。編集は Egatari Studio で行います。
- **作成と編集**：ファイルにほかの人が編集した記録（`metadata.edits`、仕様 §3.6.1）があれば、題の下に 1 行「作成：<作成者> ／ 編集：<いちばん新しい項目> ほか n 件」を出します。名前のない項目は「元のファイルから編集されています」。押すと、作成者・編集（古い順にすべて）・著作権・ライセンスの一覧を開きます。Viewer が `deck-meta`（なければ索引の `metadata`）から読むので、ファイルに入っているプレーヤーのバージョンに関係なく出ます（段 A の保存で edits を追加してもプレーヤーは変わらないため）。記録のないファイルでは表示しません。
- **最近のファイル**：開いたファイルは「この端末にだけ保存されます」の知らせのもとで、ブラウザの中の OPFS（origin ごとの非公開のファイル領域）に保存されます。ページから OPFS に書けないブラウザ（古い Safari）では IndexedDB に保存します。10 個まで。1 つずつ、またはすべてを削除できます。「開いたファイルを「最近のファイル」に保存する」をオフにすると保存しません。**「共有の端末」**は、学校の iPad のように複数の人で使う端末のためのもので、オンにすると最近のファイルを保存せず、いま保存されているものも削除します（選んだことはこの端末に保存します）。既定はオフです（`play/main.js` の `SHARED_DEVICE_DEFAULT`。定数 1 つで変更できます）。そのため「ファイルを開く」のすぐ下の 1 行で、開くファイルがどうなるかを知らせます：「開いたファイルのコピーを、この端末の「最近のファイル」に 10 件まで保存します。」（保存しない設定や共有の端末では、保存しないこと）。「共有の端末」のスイッチへのリンクと、コピーがあるときは「すべて削除」（一覧のボタンと同じく確認してから削除する）を添えます。どこにもアップロードしません。最初の 1 件が「最近のファイル」に入ったとき（保存する設定がオンで共有の端末がオフのとき）、起動につき 1 回だけブラウザに永続化を依頼します（`navigator.storage.persist()`。失敗しても気にせず、再生を待たせも遅らせもしません）。これで WebKit（Safari 17 以降・iOS 17 以降）が、この origin を自分の判断で削除しなくなります。知らせの下には、ブラウザの実際の答え（`navigator.storage.persisted()`）を示す行が出ます（共有の端末のときと、何も保存されていないときは表示しません）。
- **インストール**：ページは Web アプリ（manifest と service worker。`name` は「Egatari Viewer」、`short_name` は「Ega Viewer」、iOS には `apple-mobile-web-app-title`）です。Android とパソコンの Chrome ではブラウザのメニューからインストールし、iPhone・iPad では 共有 → ホーム画面に追加。一度開いた後は、オフラインでも開けます。iOS と iPadOS にはインストールの案内がないので、iPhone・iPad のブラウザのタブで開いたとき（ホーム画面からでないとき）は、スタート画面に iOS の言葉どおりの 1 行（Safari：「共有」（□に↑の形）→「表示を増やす」→「ホーム画面に追加」→「追加」。iOS の Chrome（CriOS）：「共有」→「表示を増やす」→「ホーム画面に追加」（「Web アプリとして開く」はオンのまま。これで全画面で開き、オフラインでも使える。2026-10-27 に iPad で確認）→「追加」）を、× で閉じるまで表示します（この端末に保存します）。Android では、ブラウザが `beforeinstallprompt` を出したときに、`prompt()` を呼ぶ「インストール」のボタンを表示し、インストールした後とホーム画面から開いたときは隠します。パソコンではどちらも出しません（.ega.html をブラウザでそのまま再生できるため）。
- **共有で開く（Android）**：インストールしたアプリは共有の受け先になります。ファイルのアプリやチャットから .ega.html を共有し、Egatari Viewer を選びます。
- **言葉**：日本語が先で、「English」のボタンで英語に切り替えます（この端末に保存します）。

## マークアップ（ハイライトと暗記）

学習者は本の字にハイライトを引き、それで暗記の練習ができる（マークアップの段 1。メモ・スライドへのペン・エクスポートは後の段）。言葉は `docs/terms.md` のとおり：マークアップ・ハイライト・暗記・一覧。

- **ハイライト**：本の字を選ぶと、小さなポップアップ（黄・桃・青の 3 色）が出る。マウスでは選んだ所のすぐ上。タッチの画面では、本の画面の下端に固定して出し（ボタンは 44 px）、選んだ所が下端の近くなら上端に出す。そこにファイル自身のもの（プレーヤーのツールバーや字幕。ウィンドウの四隅の下に何があるかを調べて見つける）があればその上に、ホーム画面のアプリでは下の安全域の上に出す。名前は「選んだ字に色を付ける」で、× で閉じられる（選んだ字はそのまま。同じ選択では出し直さない）。iOS は自分のメニュー（コピー・調べる …）を、余白があれば選んだ所のすぐ上、なければすぐ下に出すので、選んだ所の近くはどちらかで必ず重なった（iPad、2026-11-09）。選んだ所から離れた端なら、どちらでも重ならない。引いたハイライトを押すと同じポップアップで色の変更・削除ができる。色は「文字と背景」の白・セピア・黒ごとに決まった組で、1 型・2 型・3 型の色覚のシミュレーションでもどの 2 色も離れ、字のコントラストは 4.5:1 以上（下の表）。**塗り**はマークアップの層で描く。本のスクロールする箱（`.dx-body`、`position: relative`）の中、本文の後に要素を 1 つ追加し（shadow tree なのでファイルのスタイルは届かない）、ハイライトを字の塊ごとの箱として描く。字と重ねて混ぜる（白とセピアは `mix-blend-mode: multiply`、黒は `screen`）ので、字と一緒に遅れなくスクロールし、タップと選択はそのまま下の字に届く。描くのは画面の近くのハイライトだけ（見えている所と、その前後半画面ずつ。読む順に並べた一覧を半分ずつ調べて最初の 1 つを探す）で、その外までスクロールすると描き直す。字がスクロールせずに動いたとき（字の大きさ・行間・背景・画面の大きさや向き（本文とスクロールする箱の ResizeObserver）、フォント・画像・数式の遅い読み込み、`<details>` の開閉）も描き直す。**重さ**：上限の 2,000 件をテスト用の小さな本に詰めた場合（電話の画面で約 900 件が画面の近く）、字の大きさを変えた後の描き直しは WebKit で約 42 ms、Chromium で約 9 ms（`tools/test-viewer-markup.mjs`）。印刷では層を出さない（段 1 は本をそのまま印刷する）。層には字がないので、本をコピーしても本の字だけがコピーされる。混ぜた後の字のコントラストも 9 組すべて 4.5:1 以上（一番低いのは黒の上の黄で 4.9:1）。本の字と HTML は変えない。CSS Custom Highlight API は使わない：iPad（2026-11-09）の Safari は、ルビの付いた字を塗らず、色を変更・削除した後も、ほかの所が描き直されるまで前の色を残したため。
- **マークアップ**（上のバーの右、「ファイルを閉じる」の隣。760 px 未満では蛍光ペンのアイコンだけ）を押すと、上のバーがマークアップのバー（暗記・暗記する色（暗記の間）・一覧）に入れ替わる。もう一度押すか Esc（ファイルの中でも）で戻る。マークアップのバーは上のバーの場所に出て、高さも変えないので、ファイルの枠の上には何も出ず、枠も動かない（ライブの項：枠の上に出る操作はタップを取りこぼす）。ボタンは本のあるファイルでだけ出す（中身に依る道具は、プレーヤーのしおりのボタンと同じく使えるときだけ出す。作者の iPad の確かめ 11/22）。そのときはスライドだけの表示でも出る。本が画面にないときは、バーに暗記と一覧の代わりに案内だけを出す：「ハイライトは本に引けます（「表示」で「本」か「スライドと本」を選びます）。台本にはまだ引けません。」（ファイルの枠が `hello {supported, article, shown}` で知らせる）。案内は上のバーの中で 3 行までに折り返すので、枠はやはり動かない。
- **暗記**：暗記する色（既定は全部。切り替えの名前は「暗記する色：黄」など）のハイライトの字を、その色で不透明に塗りつぶして隠す。押すとそのハイライトだけ現れ、色はそのまま残る。**キーボード**：隠したハイライトごとに、読む順のボタン（Tab）がある。名前は「隠したハイライトを表示（黄）」で、Enter か Space で現れ、フォーカスは次に移る。キーはファイルのプレーヤーより先に受ける（プレーヤーは Space で次のステップへ進むため）。ボタンは本文の後のマークアップの層にあるので、Tab では本のリンクの後に来る（段 1 ではこれでよいとした）。ボタンどうしは読む順で、フォーカスしたものはブラウザが見える所までスクロールする。塗りつぶしそのものは aria-hidden（読み上げソフトは字をそのまま読む）。塗りつぶしも同じ層に描き、傍点と、ハイライトしたルビの字の読み（ふりがな）も覆う（ふりがなが見えると答えが分かってしまうため）。行立ての数式は塗りつぶし（と色の箱）1 つにまとめ、同じ行のかけらも 1 つの箱にするので、数式が記号ごとのがたがたの塗りつぶしにならない。マークアップのバーを閉じると暗記は終わり、全部の色が表示に戻る。
- **一覧**：ハイライトを節ごとに並べ、押すとそこへ移動する。色ごとに、色の意味（この端末の全部のファイルで使う。なくてもよい）、この色だけ表示・この色を非表示（今だけ）・この色をすべて削除（ページの中で確認する：「黄のハイライトを 12 件削除します。元に戻せません。」）。ファイルが編集されて元の文がなくなったものは「場所が見つからないハイライト」に並べ、勝手には削除しない。
- **場所の覚え方**は egatari-spec annotations.md（Highlight record）のとおり：節の `data-section-id`（節の外は `""`）と、表示された字（ルビの読みと KaTeX の隠れた MathML は除く）の引用（exact は 1,000 字まで、前後は 32 字まで）。付け直しは、節の中で前後の一番合う所、なければ本全体、それでもなければ「見つからない」として保存しておく。字の大きさ・行間・背景・ページ割りでは動かず、ファイルが再ビルドされても付け直す。**ルビ**：ルビのひとまとまり（親字の並びと、その後の `rt`。1 つの読みを語の上に書いたときは語全体、1 字ずつ読みを書いたときは 1 字ずつ）を 1 つの単位とする。まとまりの親字の途中から始まる・途中で終わる選択は、保存する前にまとまりの端まで広げ（画面の選択そのものは動かさない）、親字とその読みを 1 つの箱として塗り、暗記でも一緒に隠す。この決まりの前に作った、まとまりの途中で終わる記録は、付け直した後に同じように広げ、id・色・作った日を変えずに保存し直す（枠から `widen` を送り、ページは前の引用を含むものだけを受け取る）。
- **保存**：この端末の中だけ（IndexedDB `egatari-viewer-notes`、docId ごとに 1 件）。ファイルには書かず、どこにも送信しない。`madeOn` にバージョン（`fileSha256`、編集できる Egatari ファイルなら `sourceSha256` も）を保存する。編集できる Egatari ファイルとその再生専用版は同じ記録を使う。最初のハイライトを保存したとき、「最近のファイル」と同じく削除されにくい保存を依頼する。**共有の端末**では保存しない（バーに「共有の端末なので、ハイライトは保存されません。」）。「共有の端末」をオンにすると、保存したハイライトも削除する。ハイライトは学習者が自分で作ったものなので、先にページの中で数を示して確認する（「この端末に保存したハイライト（3 つのファイル、25 件）も削除します。元に戻せません。」、手書きもあれば一緒に示す。削除して切り替える／キャンセル）。保存したものがなければ、そのまま切り替える。
- **色**（「文字と背景」の背景ごとに決まった組。上のバーの色見本は白の組。ページからは本の背景が見えないため）。Machado（2009）の最も強いシミュレーションで、どの 2 色の間でも一番小さい CIE76 ΔE と、各色の字のコントラスト：

  | 背景 | 黄 | 桃 | 青 | 通常 | 1 型 | 2 型 | 3 型 | 字のコントラスト |
  |---|---|---|---|---|---|---|---|---|
  | 白 `#ffffff` | `#fff066` | `#ff9eb0` | `#79b8ff` | 61 | 37 | 54 | 38 | 14.8 / 8.9 / 8.4 |
  | セピア `#f6eedb` | `#f5e04a` | `#f797a8` | `#70aae6` | 59 | 33 | 50 | 33 | 11.7 / 7.4 / 6.4 |
  | 黒 `#000000` | `#7d6800` | `#a5304a` | `#1f4f94` | 64 | 42 | 32 | 44 | 4.6 / 5.7 / 6.8 |

  一番近いのは桃と青（1 型）、黄と桃（3 型）。白の上の黄は 3 型でページとの差が ΔE 16 しかなく薄いが、塗りとしては読める。
- **切り離し**：枠の側（`play/markup-frame.js`）は信頼する先頭部分のシムの後にあり、塗る・場所を探す・依頼する、だけをする。ページの側（`play/markup.mjs`）が記録を持ち、`{egaViewer: "markup-…"}` の依頼を、その枠から、決まった形と大きさで、1 つのファイルにつき 2,000 件まで、ページ自身がファイルから読んだ `docId` に対してだけ受ける。**分かっている限界**：枠の側のスクリプトはファイルのスクリプトと並んで動くので、ファイルのスクリプトはページが送り込んだハイライトを読め、色を変更・削除できる。記録はファイルが名乗る `docId` で選ばれ、docId は秘密ではない（ファイルのどのコピーにも入っている）ので、悪意のあるファイルがほかのファイルの docId を名乗れば、そのファイルのハイライトを受け取り、変えられる。外へは送信できず（枠の `connect-src 'none'`）、名乗っていない docId の記録には届かない。学習者が付けた色の意味はページの中に留め、枠には色の名前（黄・桃・青）だけを渡す。マークアップのバーを開いている間は、ファイルの中で押した Esc はバーを閉じ、ファイルのプレーヤーには届かない。
- `tools/test-viewer-markup.mjs`（Chromium。`--webkit` で WebKit）がこれらを確認する。スライドだけ・電話の幅でのマークアップのボタンと案内、本のないファイルでボタンが出ないこと、強調・ルビ・数式・用語のリンクをまたぐハイライト、ルビのまとまり（1 つの読みの語は広げる、1 字ずつの読みは 2 つの書き方とも 1 字ずつ、前の記録を 1 度だけ書き直す、暗記の塗りつぶしは語と読みに 1 つ）、編集したファイル、偽の依頼、暗記のキーボード、スライドと本を並べた表示（スライドの上に何も出ず、矢印のキーで進む）、電話の幅も。
- **後で**：発表バーの中のマークアップボタン（プレーヤー `kit/` の受け口）、台本で読む、メモ、`.ega-notes` のエクスポートと読み込み。
- **前に見ていた所から開く**（プレーヤーの仕様 P5・P8）：ファイルごと（docId、なければファイルの SHA-256）に、最後に見ていたステップをこの端末の中だけに覚えます（`localStorage` の `egatari-viewer-resume`、新しい 50 ファイルまで。`play/resume.mjs`）。開き直すと、プレーヤーの `ready` にあるタイムラインに対して、そのステップへ `seek` を送り、ファイルの上の端に「前に見ていた所（スライドの題）から開きました」と「最初から再生」・× を出します（12 秒で消えます）。「最初から再生」で最初のステップへ戻り、最初のステップでは何も覚えません。**共有の端末**では覚えません（「共有の端末」をオンにしたとき、最近のファイルをすべて削除したときに、覚えた位置も削除します）。ライブのあるファイル（主催者が進める）と、`ready` を送らない古いプレーヤーでも使いません。ファイルにもうないステップは無視します。**設定**も同じように扱います（Player P5・P8 の `prefs`）：プレーヤーで並べ方・本の字の大きさと背景・字幕とその大きさを変えると、プレーヤーが知らせ、Viewer は並べ方をファイルごとに、ほかを端末で 1 つ覚えて（`localStorage` の `egatari-viewer-prefs`、`play/prefs.mjs`）、`ready` の直後に送り返します（`ready` の命令の一覧に `prefs` があるプレーヤーにだけ）。共有の端末では覚えず、「共有の端末」をオンにすると削除します。`tools/test-viewer-resume.mjs`（Chromium・WebKit）が確認します。
- **印刷と添付の保存は、Viewer ではできません。** ファイルは、印刷の画面を開くこともファイルを保存することもできない枠（sandbox）の中で再生するため（[ファイルを切り離すしくみ](#ファイルを切り離すしくみ)）、Viewer には印刷がなく、ファイルの添付も保存できません。印刷や PDF への保存は、ファイルを Egatari Studio で開き、「スライドを印刷・PDF に保存」「本を印刷」「台本を印刷」で行います。添付は、ファイルをパソコンのブラウザで直接開くと、ファイル自身のプレーヤーが一覧を出して保存できます。Viewer で添付を保存できるのは、プレーヤーからページに渡す口（`saveAttachment`、Egatari Player 1.1 で予定）ができてからです。

## 手書き（スライドとメモ欄）

- **手書き**（上のバーの「マークアップ」の隣）を押すと、ファイルの枠をスライドの高さに縮め、スライド（1280 × 720 の座標）とその下のメモ欄を 1 枚の面にします。メモ欄からスライドへ矢印を引くように、またいで書けます。手書きの間、このボタンは「手書きを終了」と読め、押された見た目になります。押すと元に戻ります。上のバーの閉じるボタンは「ファイルを閉じる」と読め、二つを取り違えません（手書きのない電話では「閉じる」）。ライブのあるファイルと、幅 600 px 未満の画面（電話。メモ欄が小さすぎ、上のバーの場所も要る）では出しません。決めたこと：教科書リーダーのメモ §3.2B（付箋をやめ、スライドごとのメモ欄。手書きは本の本文の上には書かない。本文は流れ直すと線がずれるため）。
- **書く**：Apple Pencil とマウスで書きます。指は書きません（手のひらを置いたまま書けるように）。面の上で指を横にはらうと、ステップを移ります。Pencil のないときは「指で書く」をオンにすると指でも書けます。書いている間の線は `getCoalescedEvents` の点をすべて使い、`getPredictedEvents` の先読みを薄く重ねます（作者の iPad の試作の測定、2026-11-18：どちらもあり、move から描画まで中央 6 ms・90% 7 ms）。
- **道具**（面の下のバー、どれもアイコンで、名前は読み上げとツールチップに）：ペン、消しゴム（触れた線を 1 本ごと削除する。Pencil の消しゴムの側でも消える）、ペンの色、取り消し、前へ・次へ、指で書く。**ペンの色**は黒・赤・青の決まった 3 色で、自由な色は出しません（§3.2A）。線には色の名前を残し、スライドの地が明るいか暗いかで、その地で読める濃さで描きます（明るい地：#1f1f1f・#d22a3a・#1f5fbf、暗い地：#f2f2f2・#ff7b88・#7db8ff）。
- **メモ欄の地**はスライドの地と同じ色にし、スライドとの間に少しの間と枠の線を置きます。Viewer が暗い背景でも、明るいファイルのメモ欄は白になります。ページからはファイルの中が見えないので、ファイルの枠の中の shim が、スライドを移動するたびにページの依頼（`{egaViewer: "ink-bg"}`）に答えて地の色を返します（`{egaViewer: "ink-bg", rgb: [r, g, b]}`、`play/lesson-shim.js` 5）。ページは、この形で 0〜255 の整数 3 つのときだけ使います。
- **保存**：この端末の中だけ（IndexedDB `egatari-viewer-ink`、ファイルの docId（なければファイルの SHA-256）とスライドの key ごとに 1 件）。ファイルには含めず、どこにも送信しません（ファイルに含めるかどうかは v0.7.0 の後に決める）。1 枚は線 7 本で 15 KB ほど（作者の iPad の試作）。**共有の端末**では保存しません。「共有の端末」をオンにすると、保存した手書きも、数を示して確認してから削除します（「この端末に保存した手書き（2 枚のスライド）も削除します。元に戻せません。」。ハイライトもあれば一緒に示す）。
- `tools/test-viewer-ink.mjs`（Chromium・WebKit）が、枠の高さ、道具の名前（日本語・英語）、メモ欄の地（明るい・暗いファイル）、3 色、消しゴムと取り消し、スライドを移って戻る、開き直し、指（書かない・はらう・指で書く）、形の違う `ink-bg` を無視すること、共有の端末を確認します。

## ファイルを切り離すしくみ

Egatari ファイルは、スクリプトを含む信頼しない HTML です（仕様 §11）。ページはホストとして再生します（仕様 §10.1）。

- ファイルは `<iframe sandbox="allow-scripts">` の中で、文書は `srcdoc` です。`allow-same-origin`・`allow-popups`・`allow-forms`・`allow-modals`・`allow-downloads`・`allow-top-navigation` はありません。origin を持たないので、このページの OPFS・IndexedDB・localStorage・cookie を読めず、DOM にも届きません。ウィンドウを開くことも、ページを移動することもできません。
- 文書は、ページの**信頼する先頭部分**のあとに、ファイルのバイトをそのまま続けたものです（`app/preview-doc.js`。Studio のプレビューと同じ）。先頭部分がプレビューの決まり（`connect-src 'none'`・`frame-src 'none'`・読めるのは `data:` と `blob:` だけ）を持つので、ファイルのバイトを 1 つでも解析する前に決まりが効いています。ファイルの中を探して何かを挿入することはしません。先頭部分には、ページの小さな仲立ち（`play/lesson-shim.js`）も入ります。`?embed=1`（仕様 §9.4）にし、授業の外へ出るリンクをページに渡します。
- `srcdoc` の文書は、ページ自身の決まりも受け継ぎ、両方が効きます。そのため、ページの決まりはインラインのスクリプトとスタイルを許します（ファイルが使うため）。ページ自身はインラインを使わず、スクリプトはすべてファイルで、ファイルやサービスから来た字（題・ファイル名・ライブの字・リンクのアドレス）はどれも字として挿入し、マークアップにはしません。ほかはできるだけ狭くし、`tools/test-play.mjs` がそのまま確認します：`default-src 'none'; script-src 'self' 'unsafe-inline'; style-src 'self' 'unsafe-inline'; img-src 'self' data: blob:; font-src 'self' data:; media-src data: blob:; connect-src 'self' https://live.egatari.org wss://live.egatari.org; worker-src 'self'; manifest-src 'self'; frame-src 'none'; object-src 'none'; base-uri 'none'; form-action 'none'; frame-ancestors 'none'`（`connect-src 'self'` は service worker が入るときのため。Android の共有はシステムからの POST で、ページのフォームではないので `form-action 'none'`）。**次の案：**ファイルの枠を専用のパス（例 `/frame`）から見出しの CSP つきで配布し、`srcdoc` でなく知らせで中身を渡せば、ページの決まりがファイルに受け継がれなくなり、`'unsafe-inline'` を外せます。ページの `connect-src` にはライブの部屋の endpoint がありますが、ファイルの先頭部分がそれを `'none'` に絞るので、部屋に接続できるのはページだけです。
- **ファイル自身の CSP の `<meta>`**（ライブを付けた再生専用のファイルに入るもの。live §2.4。形式の 1.0 からはすべてのファイルに入る：format spec §4.2）は、先頭部分の後のファイルの `<head>` の中に入り、これも効きます。ブラウザはすべての決まりを満たすことを求めるので、ファイルには 3 つのうちいちばん狭いものが効きます。その `connect-src`（ライブの endpoint）は枠の中では意味を持ちません。**`deck-extensions` のブロック**はデータで、ページが何も実行しない解析（`play/scan.mjs`。上限つきの parse5）で自分で読みます。ファイルの中のライブの部分（`kit/live.js`）は、枠の中にいるので接続しません（live §2.1）。ライブはページの側に出すので、ファイルの中のライブの印とパネルは、先頭部分の規則で隠します（「ここからは参加できません」としか言えないため）。`tools/test-play.mjs` は、§4.2 の基本の決まり（`connect-src 'none'` と `liveCsp` の形）を持たせたテスト用のファイルのコピーを再生し、ファイルからの fetch がファイルの決まりと先頭部分の決まりの両方に引っかかることを確認します。
- 枠からの知らせは信頼しない依頼です。その枠（`event.source`）から、origin が `"null"` のものだけを、次の形だけ受けます：位置の知らせ（仕様 §9.4 の `position`、またはプレーヤーの前からの `deck-pos`）、マークアップの依頼 `{egaViewer: "markup-…"}`（[マークアップ](#マークアップハイライトと暗記)）と、リンクの依頼 `{egatari: "openLink", href, text, download?}`（仕様 §9.4。この項目だけ、`text` は 200 字まで、`download` は `true` だけで、`download` 属性のあるリンクのときに付く）。ほかは無視します。仲立ちが `openLink` を送信するのは、参加者自身の操作（枠に一時的な操作の印がある本物のクリック）のときだけで、ファイルのスクリプトが作ったクリックでは何も送信しません。ファイルのコードが自分でこの知らせを送信することはできるので、ページは信頼せず、§11 を自分で当て、自分の箱で押されるまで何も開きません。（Studio の編集のプレビューにはこの知らせはなく、プレーヤーが行き先を表示するだけで開く手段は出しません。§11 (g)）
- **全画面。** 枠には全画面の許可がありません（`allow` に `fullscreen` がなく、ページの `Permissions-Policy` は `fullscreen=(self)`）。ファイルが自分で画面を取ることはできません。それでも、プレーヤーの「全画面」のボタンと `f` は使えます。仲立ちがファイルの文書の全画面の API（`requestFullscreen`・`exitFullscreen`・`fullscreenElement`・`fullscreenEnabled`、`webkit` の付いた名前と `fullscreenchange` の出来事）を、ページに `{egaViewer: "fullscreen", on}` と依頼するものに置き換えます。ページは枠の要素そのものを全画面にし（`requestFullscreen`、古い iPadOS では `webkitRequestFullscreen`）、`{egaViewer: "fullscreen-state", on, enabled, refused?}` を返します。参加者が Esc や端末の操作で抜けたときも返します。そのため、ファイルの中のどのプレーヤー（古いバージョンも）でも、入る・抜ける・ボタンの表示が正しく動きます。ブラウザが全画面にするのは参加者自身の操作のとき（枠の中のタップがページに届く）だけなので、ファイルのスクリプトだけでは全画面にできません。ページは、その枠からの、この形のままの依頼だけを受けます。`allow="fullscreen"` にしないわけ：Safari（iPad のエンジン）は opaque origin の `srcdoc` の枠ではこれを無視し（`allow="fullscreen *"` が要る）、しかもファイルにページとは別の自分の全画面を与えてしまうからです。要素の全画面がないブラウザ（iPhone の Safari）では、プレーヤーは全画面のボタンを出さず、キーの一覧にも `f` を載せません。画面を広く使う方法は、スタート画面の「ホーム画面に追加」の 1 行がすでに案内しています。`tools/test-fullscreen.mjs` がこれらを Chromium と WebKit で確認します。

## リンク

ファイルが開くように依頼したリンクは、プレーヤーと同じ決まり `kit/core/link-policy.mjs`（仕様 §11）を通します。確認する箱はページの側（枠の外）にあるので、ファイルがその上に描くことはできません。行き先の host とアドレスを見せ、`https:`・`http:`・`mailto:`・`tel:` のほかは開きません。字が別の host を名指す・ふつうの `https:` でない・ダウンロードする・アドレスにユーザー名やパスワードがある・host が punycode のときは、毎回確認します。ファイルと同じ場所にあるほかのファイル（相対のリンク）はこのページからは届かないので、わけを書いて断ります。ファイルを保存するリンク（`download: true`）も断り、host と「このファイルからは、ほかのファイルを保存できません」を表示して、何も開きません。開くのは、参加者が押す `noopener noreferrer` のふつうのリンクです。一度同意したふつうの `https:` の host は、この閲覧のあいだメモリに記憶し（§11 (f)）、次からは host の名前と「開く」だけの、注意書きのない箱を出します。1 回押すことは要ります。ページは知らせだけでリンクを開かず、Safari はページの中で押さないとタブを開かせないためです。箱は一度に 1 つで、閉じてから 1.5 秒は新しい依頼を無視するので、ファイルが箱を出し続けることはできません。

## ライブ

ファイルに参加コードつきの正しい `extensions.live` がある（ライブを付けてエクスポートした再生専用のファイル）とき、ページがファイルの代わりに働きます（live §2A）。「ライブ」のボタンとパネルをページの側に出し、WebSocket もページが持ちます。

- **先に参加。** ライブのあるファイルは、スタート画面から始まります：ライブの時間と行き先の host のついた「参加する」と、「参加しないで見る」。ファイルの枠はそのどちらかを押してから置くので、「参加する」の押しが枠に取られることはありません。参加しないで見るときは何も要求せず、「参加する」はライブの操作の中にあります。ページが接続しない endpoint のファイルでは、スタート画面に「参加する」の代わりに部屋の参加のページへのリンクを出します。
- 「参加する」を押すまで、またライブの時間の外では、何も要求しません。送信するのは活動に要るものだけです：質問・投票・入力したときだけ名前・この端末で作った番号・ping。部屋からの字は字として見せます。再接続は `LivePolicy.plan`（`kit/core/live-policy.mjs`）のとおりです。
- 今のステップは、ファイルの位置の知らせで知り、そのステップの投票を見せます。投票のあるステップになると知らせます。
- **置き方**（`play/layout.mjs`）は、ファイルが始まるときに活動と画面から 1 回だけ決め、再生中は変えません（向きを変えたとき・パソコンのウィンドウのサイズを変えたときだけ置き直す）。画面の大きさは見えている大きさ（`visualViewport`）で、再生中はページの高さもそれに合わせます（`--view-h`。`100dvh` ではない）。iPad の Chrome では、横向きに回した後も `100dvh` が縦向きの高さのまま残り、枠が画面の下にはみ出して、スライドの上に暗い余白が空き、スクロールしても上に戻されました（2026-11-19）：

  | ファイル | 電話（縦） | 電話（横） | 広い画面 |
  |---|---|---|---|
  | ライブなし | ファイルがページいっぱい | 同じ | 同じ |
  | ライブ（投票なし） | ファイルの下に 44 px のバー：状態・「退出する」か「参加する」 | 横の余り（下） | 44 px のバー |
  | ライブ（投票あり） | 16:9 のスライド（表示領域）の下のパネル（投票が先頭） | 横の余り（下） | 340 px のサイドパネル |

  電話を横にしたとき（高さ 500 px まで）は、ページのバーを隠してスライド（表示領域）を高さいっぱいにします。横の余りが 120 px 以上（19.5:9 の電話で約 150 px）あれば、そこに列を置きます：閉じる・状態・「退出する」か「参加する」・「投票」（押すと列の中に投票を出す）。余りがない（16:9 の電話）ときは、`play/main.js` の定数 `NO_SLACK_VARIANT` で選びます。**'overlay'**（既定。持ち主が選んだもの）はスライドを画面いっぱいのままにし、28 px の状態の表示を枠の上端に、枠を置いたときから重ねておきます。投票は枠の上に重ねたパネルで開きます。**'strip'**（もう一方）はスライドを 28 px 縮めて上にバーを置き、投票はバーの中身を 1 行の投票に切り替えます。測るときは `?noslack=strip` か `?noslack=overlay` で切り替えられます。
- **置き方を変えないわけ。** ひとことで言えば、押しが取られるのは、隠れていたページの操作が、別のプロセスで動く枠の上に現れるときです。ファイルの枠は別のプロセスで動き、Chrome はそこへの押しを、最後に画面に出した時点の当たり判定で振り分けます。ファイルのあった場所にいま現れた操作（枠の上に出したパネルや、縮んだ枠の跡）は、負荷の下の素早い押しで 45 回中 12 回、最初の押しをファイルに取られました。「参加する」を枠より先にし、操作を枠より先に置いて動かさないようにした後は、`tools/play-tap-measure.mjs`（3 つ同時に、各 15 回、操作が見えたらすぐ押す）で取られた押しは 0 回でした：参加 0/45、縦の投票 0/90、横（余りあり）0/135、余りなしはバーも重ねる形も 0/225、向きを変えた直後の最初の押し 0/45、「退出する」0/45。重ねる形が安全なのは、状態の表示がいつも枠の上に出ていて、枠の上で隠したり出したりしないからです（`NO_SLACK_VARIANT` のところの注記）。そこを変えるときは、測り直してください。スライドの大きさは、縦（375 × 667）で 375 × 211 px、横（844 × 390）で 693 × 390、667 × 375 の電話ではバーの形で 617 × 347・重ねる形で 667 × 375、1280 × 800（サイドパネル）で 940 × 529 です。
- **押す場所の大きさ。** 投票の選択肢は行全体が押す場所で、パネル・横の余りの列・重ねる形のパネルでは高さ 44 px、28 px のバーでは 24 × 24 px 以上（WCAG 2.2）です。戻る・投票する・退出する・投票・× も同じです。この大きさで、投票は横の余りの列（選択肢は折り返す）にもバー（1 行）にも収まるので、ほかの層は要りません。行を押す場所にし、重ねる形を既定にして測り直した結果：重ねる形 0/225、バー 0/225、横の余りの列 0/135。
- 「ライブ」のボタン（縦と広い画面）はライブの操作へ焦点を移し、Esc で戻ります。
- **キー**：ステップを進めるキー（← → ↑ ↓、Space、PageUp/PageDown、Home/End）は、焦点がどこにあってもファイルを動かします。ページはファイルが読み込み終わったときに枠へ焦点を移します（Chrome は枠の最初の空の文書に渡した焦点を失い、Safari は断ることがある）。焦点がページ（バー・ボタン・ライブの欄）にある間に押した、ステップを進めるキーは、`{egaViewer: "key", key, shift}` でファイルに渡します。ページのファイルの shim は、プレーヤー自身のボタンと同じように（ファイルの文書への keydown で）押すので、ファイルの中のプレーヤーのバージョンによらず効きます。渡さないもの：入力の欄や矢印を使うパーツの中のキー、リンクの箱が開いている間のキー、ボタン・リンクの上の Space（それを押す）。`tools/viewer-keys-check.mjs` が Chromium（`test-play`）と WebKit（`test-viewer-webkit`、Desktop Safari）で確認します。
- **オフライン**：ネットワークのない端末（`navigator.onLine` が false）で「参加する」を押すと、再接続を繰り返さず、すぐに「この端末はネットワークに接続していません。Wi-Fi などに接続してから、「もう一度試す」を押してください。参加しなくてもファイルは見られます」と表示し、接続してから「もう一度試す」で参加します。失敗を知らせる文は、どれも次にすることで終えます。
- ページが接続するのは、ページ自身の決まりが許す endpoint だけです（ビルドの `--live-endpoint`。既定は `https://live.egatari.org`）。ほかの endpoint のファイルには、部屋の参加のページへのリンク（`/join#room=…&key=…`。参加コード（`key`）は `#` の後ろ）を出し、新しいタブで開きます。
- **ライブからはファイルの中へ何も渡しません。** v1 でファイルから受けるのは、画面のステップの 1 つだけです。まだないもの：質問に付けてスライドに丸を描くこと（枠からページへ線を渡す口がまだない）。
- 先生自身の編集可のファイルの `extensions.live` には参加コードがないので、ライブなしで再生します。

## service worker・オフライン・バージョン

service worker（`play/sw.js`）が保存するのは、ビルドが一覧にしたページ自身のファイルだけで、バージョン（パッケージのバージョンとファイルのハッシュ）の名前のキャッシュに入れます。アプリの外枠、つまりページ・スクリプト・ファイルを読む Worker・スタイルシート・`guard.js`・manifest・アイコンです（ページはシステムの字を使い、字のファイルは読み込みません）。ほかのもの（開いたファイル・共有されたファイル）は保存しません。一度開いた後は、ホーム画面からでもネットワークなしで開けます。ファイルは、オンラインでもオフラインでも、端末の中で読むだけで、どこにもアップロードしません。

**新しいバージョンは次に開いたときから。** 新しいバージョンは動いているバージョンの横に入って待ちます。更新のボタンはありません。入れ替わるのは Viewer を開いたときだけです：Viewer のウィンドウが 1 つも開いていなければブラウザが自分で入れ替え、開いたばかりでスタート画面にいる（ファイルを開いていない）ページは、待っているバージョンに入れ替わるよう依頼して 1 回だけ読み込み直します。service worker が応じるのは、そのページが Viewer のただ 1 つのウィンドウのときだけです（`activate-if-idle`）。ほかのウィンドウで再生しているファイルは入れ替えません。開いている途中で `busy` と返されたページは、1 秒ごとに依頼し直します（入れ替わる前のウィンドウが閉じきるまで一瞬残っていたり、ほかのウィンドウが閉じたりすることがあるため）。開いてから 10 秒より後や、ファイルを再生している間に見つかったバージョンは、次に開くときまで待ちます。スタート画面で Viewer に戻ったときは、開いたときと同じに数えます。ファイルを再生している間は何も要求しません（バージョンを確認するのは開いたときだけ）。

`tools/test-play.mjs` が確認すること：キャッシュがアプリの外枠ちょうどであること。オフラインで、開き直しも読み込み直しもロゴ・manifest・アイコンつきで開け、ファイルを再生でき、サーバーに要求が届かないこと。ファイルの再生中に見つかったバージョンは待つこと（同じバージョン・同じスライド・読み込み直さない。2 つめのウィンドウを開いても）。ウィンドウをすべて閉じて次に開くと新しいバージョンになり、そのキャッシュだけが残ること。スタート画面で開くと入れ替わること（開いている途中で、ファイルを再生しているほかのウィンドウが閉じたときも）。ライブの有無にかかわらず、ファイルのバイトがどの要求・WebSocket の送信にも含まれないこと。

## タッチ

ファイルのプレーヤー（`kit/tools.js`）がタッチを自分で扱うので、ページは何も追加しません。スライドのタップでツールバー（前へ・次へ・字幕・読み上げで聞く …）が起き、ツールバーを起こしたタップはその下のボタンを押しません（`REVEAL_GUARD`、350 ms）。ファイルを開いたときツールバーを 5 秒見せ、隠れている間は小さな取っ手から戻せます。スライドを横に払うか、左右の端をタップすると、前・次のステップへ進みます（[リファレンス](reference.ja.md)、handoff #97）。手書きの間はページの面がファイルの上にあり、その面の指の払いが同じことをします。ファイルの shim（`play/lesson-shim.js`）は、埋め込みの形にすることと、ファイルの外へ出るリンクをページに渡すことだけをします。`tools/test-viewer-webkit.mjs` が Playwright の WebKit と iPad の大きさで、ツールバー・字幕・読み上げを確認します。

## アクセシビリティ

Viewer のページ（上のバー・スタート画面・マークアップのバーと一覧・手書きの道具・確認のダイアログ・ライブの参加の画面とパネル）は WCAG 2.2 AA を目標にします。`tools/test-viewer-a11y.mjs`（Chromium。`--webkit` で WebKit、`--report` で見つかったものを一覧に、`--json <ファイル>` で JSON のファイルに保存）が、axe-core の WCAG 2.0・2.1・2.2 の A と AA の規則を、次の状態のページに当てます：スタート画面（日本語・英語・暗い背景）、ファイルをスライドと本で開いた状態（明るい・暗い）、マークアップのバー、ハイライトのあるマークアップの一覧、色をすべて削除する前の確認、リンクの確認、ライブのあるファイルの参加の前と見ているとき、編集の記録のあるファイルのタイトルの下の「作成と編集」の行とその一覧（明るい・暗い）、手書きの面と道具のバー（明るい・暗い）。ページに違反が 1 つでもあれば落ちます。ファイルの枠の中（ファイルに入っているプレーヤー、`kit/`）も同じ状態で調べて一覧にしますが、落としません。axe が見つけられるのは WCAG の一部だけです。キーボードだけの操作・読み上げ（VoiceOver・NVDA）・400% の拡大は手で確認します。

## 置き場所：Cloudflare Workers の静的なファイル

ページは見出しつきの静的なファイルです。Pages ではなく **Cloudflare Workers の静的なファイル（static assets）**に置きます（`play/wrangler.toml`・`play/wrangler.production.toml`・`play/worker.js`）。

- Cloudflare は新しい静的なサイトを Workers に寄せていて、ライブの部屋（egatari/live）もすでに Worker です。ツール（wrangler）も、設定と公開のしかたも、開発用と本番用の設定の分け方も 1 つで済みます。
- 静的なファイルは `_headers` を読みます。決まりと「枠の中を断る」見出しは、そこからすべてのファイルに付き、コードを動かさずに配布します。ページそのもの（`/`）には `Cache-Control: public, max-age=0, must-revalidate, no-transform` も付けます。こうすると Cloudflare はページを書き換えないので、Web Analytics が解析のスクリプトを差し込めません（Cloudflare の文書にある動き。差し込まれても決まりが止めますが、ページにそもそも載せない）。HTML だけに付けます。`no-transform` は途中での圧縮も止めるので、スクリプトには付けません。
- 小さな Worker は、どのファイルにも当たらない要求だけに答えます。service worker が入る前に届いた Android の共有（`POST /share`）です。ファイルは受け取れない（何もアップロードしない）ので、`/?share=nosw` への 303 を返し、ページが「一度アプリを開いてから、もう一度共有してください」と知らせます。
- 独自ドメイン（`routes = [{ pattern = "viewer.egatari.org", custom_domain = true }]`）なら、`wrangler deploy` が DNS の記録と証明書を自分で作ります。

ページは枠の中では動きません。すべてのファイルに `Content-Security-Policy: frame-ancestors 'none'` と `X-Frame-Options: DENY` を付け、`guard.js` がほかの何よりも先に `window.top` を確認します（重ねての守り）。

## 自分で置く

同じファイルを自分の origin から配布してもかまいません。条件：

- **応答の見出しを送れる置き場所。** `_headers` の見出しをすべてのファイルに付けてください：`Content-Security-Policy`（`frame-ancestors 'none'` を含む）・`X-Frame-Options: DENY`・`X-Content-Type-Options: nosniff`・`Referrer-Policy: no-referrer` と、そこにあるほかのもの。Cloudflare（Workers・Pages）と Netlify は `_headers` をそのまま読みます。nginx・Caddy・Apache では、その行をサーバーの設定にコピーしてください。GitHub Pages など見出しを送れない置き場所は使わないでください。枠の中を断れず、ページの決まりもブラウザの既定だけになります。
- **HTTPS**（service worker と OPFS は安全な文脈でしか動かない）。
- **専用の origin**。どの編集アプリとも別の origin にしてください（live §2A.4）。一緒に Egatari Studio を置くなら、その origin とは分け、ここで再生したファイルが編集アプリの保存先に届かないようにします。
- **`POST /share`** には `/?share=nosw` への `303 See Other` を返す（`play/worker.js` と同じ）。そうしないと、共有はアプリを一度開いた後でしか働きません。
- **ライブの部屋**：ページが接続してよい部屋のサービスごとに `--live-endpoint <部屋のサービス>` を付けてビルドしてください。ほかの endpoint のファイルには参加のリンクだけを出します。

## サイトのプレーヤー

見出しを送れない静的なサイト（GitHub Pages の egatari.org）は、サンプルを Viewer ではなくサイトのプレーヤーで再生する。`node tools/build-site-player.mjs [--out フォルダ]` が `site-play.js`（`play/site-player.mjs` からビルドする 1 つの ES モジュール。Viewer の枠・信頼する先頭部分・ファイルの仲立ち・リンクの箱）、`site-play.css`、`BUILD.json`（Studio のバージョンとコミット、各ファイルの SHA-256、ページの決まり）を書く。サイトはこれを Studio のコミットに固定してコピーする。

- ページは `<div id="egatari-player" data-lock="<lock の URL>" data-files="<フォルダの URL>">` と `<script type="module" src="site-play.js">` で、`?id=<id>` で開く。`data-player-title` のある要素にはファイルのタイトルが入る。最初の `<meta http-equiv="Content-Security-Policy">` は `BUILD.json` の `pageCsp`：Viewer の決まりからライブを除き（`connect-src 'self'` は lock とファイルのため）、meta では書けない `frame-ancestors` を除いたもの。代わりに、ほかのページの枠の中では何も再生しない。
- lock は JSON の `{lessons: [{id, sha256, size, title, lang}]}`（ほかのキーはサイトのもの。egatari.org はサンプルのリリースとその SHA256SUMS から書く）。ファイルは `<data-files><id>.ega.bin` で、同じ origin から `application/octet-stream` として配布するので、直接開くとダウンロードになり、サイトの origin では描かれない（仕様 §10.1）。読む前に大きさと SHA-256 が lock と合うことを確認し、合わなければ何も再生せず、理由を出す。この照合が見つけるのは古いファイルや壊れたファイルで、置き場所そのものが乗っ取られた場合ではない（lock とファイルは同じ origin から来る）。
- ファイルは Viewer と同じく再生する：`srcdoc` ＝信頼する先頭部分（プレビューの決まり、その後にファイルの仲立ち）＋ファイルのバイトそのまま、`sandbox="allow-scripts"`（opaque な origin）。`srcdoc` の文書はページの meta の決まりも受け継ぐ。枠から受けるのは openLink（リンクの箱で。§11）と全画面の依頼だけ。ライブ・マークアップ・最近のファイル・保存・service worker はない。
- `tools/test-site-player.mjs`（Chromium。`--webkit` で WebKit）は、そのような置き場所と同じく見出しなしでページを配り、次を確認する：ファイルは opaque な origin で動き、保存場所・ページ・ネットワークに届かない。1 バイト違う・lock より長い・知らない id・id なしでは何も再生しない。リンクの依頼はリンクの箱を通り、`javascript:` は開かない。枠以外からの依頼は無視する。ほかのサイトの枠の中では何も再生しない。

## v1 にないもの

- iOS のラッパーのアプリ（後で）。
- 質問に付けてスライドに丸を描くことを、ページを通して行うこと。
- ファイルからの印刷と添付の保存（枠に `allow-modals` も `allow-downloads` もない）。ページ自身のバーの全画面のボタン（プレーヤーのボタンと `f` は、上のとおりページを通して使える）。
- OS からファイルを直接開くこと（パソコンの `file_handlers`）。
