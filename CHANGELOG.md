## [Unreleased]

### Added

- **Attachments** (format spec §9C.3): files for readers rather than for rendering (original source, typeset PDF, code, data, supplements). In a working folder they live in `attachments/`, with roles (`source`, `pdf`, `code`, `data`, `supplement`) and optional titles in `egatari.json` under `attachments` (the same shape as the file's `index.attachments`; unknown members are kept). `--portable` packs every regular file under `attachments/` (links not followed, hidden files and backups left out) within the build's read budget and the attachment limits, 20 MiB each, 50 MiB together and 100 files (over a limit: left out with a warning); only files with a valid role are listed in `index.attachments`. Attachments are not code (an `.html` attachment does not make the file Extended) and add nothing to `requires`. **Player:** a single file lists its attachments under **?** and with a paperclip button in the control bar, download only: the index hash, each attachment's size and SHA-256 are checked, and the bytes are saved as `application/octet-stream` through a `download` link, so HTML, SVG or PDF attachments are never opened or run (a corrupt one is not saved). Play-only copies and the normal build carry none. **Editor:** **Attach** in the toolbar opens a side panel for working folders and single files: add files (role guessed from the extension), role, title, rename and remove (a folder keeps a backup in `.cache/edits/`); names outside `attachments/`, with `..` or colliding, and files over the limits are refused before they are read. In a single file, saving is tier A: only the index's attachment entries, their chunks and the source hash change (a change to an attachment that the slide source mentions needs a rebuild). **Checker:** warns about missing or unknown roles, listed files that do not exist, names that are not allowed and files over the limits. Code: `kit/core/attachments.mjs`, identifiers in `kit/core/format.mjs` (`ATTACH_DIR`, `ATTACH_KEY`, `ATTACH_ROLES`), `app/attachments-panel.js`, workspace `remove()`. Tests: `tools/test-attachments.mjs` (in `npm test`: CLI build, unpack roundtrip, play-only, limits and names, checker, tier A with the region-aware diff, player download without navigation or execution, editor panel for a single file and a folder). Docs: reference, editor (ja/en), SECURITY
- **Egatari logo.** The mark (the hiragana え in Japanese corner brackets, its first stroke drawn as a sun) is in `assets/logo/` and at the top of the READMEs (light / dark through `<picture>`). The editor app has it as its favicon (`favicon.ico` / `favicon-dark.ico`: the bracketless glyph at 16 px, bracketed at 32 and 48 px, the dark one through `media="(prefers-color-scheme: dark)"`), apple-touch icon (180 px) and, on the hosted editor, a web app manifest with 192 and 512 px icons (the single-file `editor.html` embeds the icons as `data:` URIs and has no manifest), and in its header (the 32 px version). Waits longer than about 1 s (opening a file or an example, a slow build, browser TTS) draw the mark once (`egatari-draw-*.svg`; the final state only with reduced motion). The logo is not covered by the MIT license: it may be used unmodified to refer to Egatari or Egatari-compatible software (NOTICE, `assets/logo/README.md`). The `.ega.html` player does not contain it
- **Your own theme folders.** The build, checker, dev server and portable export also look for themes in the folders of `EGATARI_THEMES` (a list separated by the OS path delimiter, `:` or `;` on Windows) and then in `~/.egatari/themes` when it exists. Search order: the deck folder, its `themes/`, your theme folders, the bundled `themes/`. Each folder is a caller-chosen root: its real path is taken once (so `~/.egatari/themes` may be a symbolic link), and the containment rules hold inside it (no link or `extends` leaves that folder except to the bundled themes; `"extends": "default"` is the bundled `default`). A folder of `EGATARI_THEMES` that does not exist is skipped with a warning. The dev server rebuilds when a theme folder changes. A portable file stores a theme from these folders as the deck's `themes/<name>/`, so it rebuilds with the same theme on another machine and in the editor app (`kit/theme-dirs.mjs`; docs: reference ja/en, Themes and Environment variables)
- A theme the deck names (`<html data-theme>` or a parent in `extends`) that is found nowhere no longer stops the build with `theme not found`: it warns `theme not found: "<name>" — …` with where it looked and where to put the theme, and builds with `default` (or without the parent). In the editor app the same warning points to **Choose theme folder…** (below). `--theme` with a name that is not found is still an error. Tests: `tools/test-theme-dirs.mjs` (in `npm test`: search order, `EGATARI_THEMES`, a symbolic-link `~/.egatari/themes`, the missing-theme warning, containment, the portable export)

- `m-codetree` (`components/codetree/`, in the catalog, with a demo): decoding a bit string with a code tree, for a data-compression lecture (Modified Huffman, ITU-T T.4). The tree is built from the code table (`[{run, white, black}]` or `{white: {code: run}, black: {…}}`; prefix conflicts are reported): the root's left is the white tree, its right the black tree, branch 0 left. Decoding starts white; a terminating code (run < 64) switches the colour, a make-up code (run ≥ 64) keeps it, `EOL` returns to white; a code not in the table, a string that ends inside a code and a make-up code without its terminating code are reported. One step per codeword, with one cue per bit read (a narration with as many `{cue}` as bits keeps the read pointer on the words; one step per bit would split the narration into one line per bit), and a last summary step with both trees and every decoded path (the print and still state). In each step the tree is laid out again around the codeword (only the current colour's tree is expanded to `depth`, deeper and other subtrees are folded into small triangles, nodes slide between layouts), a read pointer moves along the bit string in step with a dot travelling down the tree, the leaf gives the run, and the run is filled into a scan line of white and black pixel cells, where a make-up and its terminating code combine into one run (`白 64 ＋ 2 ＝ 66`). Deep trees (black codes run to 13 bits) are shown through a window of a few levels that follows the travelling dot: the camera position is an eased function of the path progress, so the tree flows up as the dot goes down; in the window the tree is laid out again along the path (each sibling branch folded into a triangle on the other side) and the camera also pans so the path in the window stays centred; nodes fade at the window edges, only the incoming path is drawn across the top edge, and a breadcrumb above the window (`黒の木：ここまで 0000 0110`) keeps the colour and the bits read so far; `window="auto"` (default) follows only when the whole tree would leave less than 44 px between levels (shallow codes look as before), a number sets the window size, and the summary shows the window of the deepest path. Nodes, leaves, bits, codewords and runs carry `data-mark` names (`ct-w-1101`, `ct-w64`, `ct-bit-3`, `ct-cw-2`, `ct-run-1`) for `{mark:…}`. The demo decodes `11011011111` (white 64 + white 2, black 2) with the T.4 tables, follows the 12-bit black code of run 30 in `1000 000001101000 0111`, and shows an invalid code with a small table. New `tools/test-codetree.mjs` in `npm test` (tree building, colour alternation, make-up + terminating, EOL, invalid and incomplete codes); `tools/test-shape.mjs` covers its data shape

- Editor app: **Choose theme folder…** for decks (folders, single `deck.html` files and portable rebuilds) whose theme is neither in the deck nor bundled. The missing-theme warning shows it in a notice above the preview and in the warnings panel; **Theme folder…** in **Open ▾** and on the first screen shows the current folder and its themes and changes or forgets it. The folder (for example `~/.egatari/themes`) is picked once with the directory picker in read-only mode, its handle is kept in IndexedDB (not its contents) and read permission is asked again the next time it is needed (**Use theme folder “<name>”**). The in-browser build mounts it as a user theme folder (`/user-themes`, `env.themeDirs`), so the search order and containment rules are those of the command line (deck folder, its `themes/`, this folder, bundled themes) and only the files of the themes a build uses are read, in the build worker through the page; theme CSS and logos go through the usual theme sanitising. A portable file exported or saved from the editor carries the user theme it used as `themes/<name>/`. The editor never writes to the folder (`app/theme-folder.js`; docs: editor ja/en). Tests in `tools/test-app.mjs` with an origin-private folder as the theme folder: the prompt, picking (read mode), the theme's tokens and logo in the main-thread and worker builds, the deck's `themes/` winning, a logo outside its theme refused, the portable export, remembering across reloads, asking for permission again, Forget, and a folder without themes

### Changed

- **Two words for where a deck lives**, everywhere in the editor app and the docs: **working folder** (作業フォルダ: `deck.html`, `narration.md`, `audio/` …) and **single file (`.ega.html`)** (1 ファイル（.ega.html）), replacing “deck folder”, “source folder”, “portable file” and their Japanese variants (デッキのフォルダ・原稿のフォルダ・持ち運べる 1 ファイル・持ち運べる教材のファイル). Menu items follow: **Open single file…**, **Open working folder…**, **Export working folder…**, **Export single file (.ega.html)**, **Export built HTML**. File formats, options and APIs keep their names. The reference anchors are now `#single-file---portable` / `#1-ファイル--portable`
- Editor app: the first screen puts single files first. The main actions are **Open single file…**, **New deck** and **Paste AI output**; a working folder opens from the secondary “Open working folder…”. A small table explains working folder, single file, play-only file and built HTML (also in Help)
- Editor app: **Open file…** (or drop) with a deck source `deck.html` (slides, no built runtime or format blocks) no longer says the file is play-only. A dialog explains that narration, audio and the deck's own components live next to it in a folder and offers **Open the folder…**, **Open this file only** and **Cancel**. *This file only* opens a new in-memory deck with just `deck.html` (no narration or audio; registry components and themes work), treated like any opened file (the code question applies, new `docId`, unsaved), and **Save** asks whether to save a portable file or export to an empty folder
- Editor app: a built presentation (`out/deck.html`) is refused with its own message (open the source folder, offered in the dialog, or a portable file), a play-only portable file with a message that names it, and other HTML as “not a portable file” (ja/en). The reader reports which of these a file without an index is (`sourceKind` in `kit/core/portable.mjs`, the error's `details.kind`)
- Build: the new option `missingFiles: 'warn'` turns a referenced file that does not exist (`{{JSON:…}}`, includes, figures) into a warning, once per file, and leaves it empty. The editor uses it for every in-memory deck (opened files, `deck.html` alone, pasted AI output); folders and the command line still fail on a missing file
- **The AI instruction pack is split into a common body and series packs.** `docs/authoring-with-llms(.ja).md` is now the common body (contract rules with the same rule ids `R-…`, sizes, output format, and the components any lesson may use: `m-menu`, `m-flow`, `m-bars`, with a new small worked example using `m-flow`); `docs/llm-parts/<series>(.ja).md` add the components of one kind of lesson: `academic` (`m-sweep`, `m-curves`, `m-seq`, `m-collect`; axis-chart sizes), `business` (`m-kpi`, `m-quad`, `m-market`, and the money and service flows of `m-flow` as an extension), `kokugo` (`m-kanbun`, `m-kobun`, `m-gendai`, vertical `layout-tate` slides) and `info` (`m-codetree`), each with its worked example. Every kit component declares its place with `series:` in its README frontmatter (`common` or a series), and the generator fails for a component without one; README text between `<!-- llm: <series> -->` and `<!-- llm: end -->` goes to that series as an extension, and `<!-- llm: omit -->` blocks (implementation notes) and timing attributes (in seconds) are left out of the pack. One function assembles the text, `buildPack({series, lang})` in `kit/core/llm-pack.mjs` (`series`: names, `'all'` or `[]`), used by the editor, by `node kit/llm-pack.mjs --series academic,info --lang ja` (`--list` for the series and sizes, in English and Japanese columns or one language with `--lang`; `--help` / `-h` prints the usage, and an unknown option is refused with it) and by `tools/make-llm-guide.mjs`, which now also writes the assembled data `kit/core/llm-pack-data.mjs`. `--check` in `npm test` also checks the sizes: the common body with one series warns above 35 KB and fails above 40 KB, all series fail above 64 KB (now about 22–35 KB and 57–59 KB). Sizes are shown the same way everywhere (`packKb`: UTF-8 bytes / 1024 with one decimal): the `--list` columns and the paste dialog, which shows the sizes of the instructions in the UI language
- Editor app: **Paste AI output…** lets you tick the series packs to copy with the common body (each with the size it adds, and the total). With a deck open, the series of its components and theme are ticked (`seriesForDeck`), otherwise `academic` (ja/en; docs: editor ja/en). Tests in `tools/test-app-llm.mjs`
- `buildFixRequest` (`kit/core/llm-fix.mjs`) no longer takes the instruction text: it quotes the rules from the common body itself and adds the notes of the components the included slides use (the same text as in the pack; `components` in the result). A caller that still passes `guide` gets a console warning and the argument is ignored

## [0.4.0] - 2026-10-19

### Added

It starts with the most common failures: both blocks complete and closed (fewer slides if the reply may be long), the slide's measured sizes (body 1184 × 443 px, 46 px per line, all text ≥ 24 px), how to size charts (components draw labels at 24–28 px; axis charts 300–380 px high and ≥ 560 px wide) and inline SVG (viewBox in displayed pixels). - **Business and pitch components** (`components/`, in the catalog, each with a demo; the screen depends only on `DECK.seek(i, k, t)`):
  - `m-bars`: bars that grow from 0 step by step, vertical or horizontal (rankings), one or more series (series named on the first group, no legend), values with thousands separators and a unit written at the bar end once a bar has grown (`count="true"` counts up instead), a group `tone` to highlight one. `scale` widens the value axis at a step (log-interpolated, the previous range kept as a faint band, tick sets swapped), so a bar can push through the top of the axis. It generalizes the deck-local bars of `examples/tmlr2026-calibration`, which keeps its own choreographed component (a deck's `components/` is looked up first)
  - `m-quad`: a 2×2 positioning map (or SWOT-style grid) with labelled poles and quadrant names; items are placed one per step, the `self` item is emphasized with a ring, and `to` slides an item to a target with a dashed trail
  - `m-market`: TAM / SAM / SOM as nested circles, each shrinking out of the previous one, with key, value and basis written to the right; fixed ratios (default) or area proportional to the value, bottom-aligned or concentric
  - `m-kpi`: KPI cards with a big number and unit, an optional prefix, a ▲ / ▼ delta (coloured by whether the direction is good) and a note; the number counts up from 0 (or `from`) with an ease-out that is a function of (k, t) only
- `m-flow`: money and value flows, backward compatible (edges without the new fields draw as before). `kind` (`money` / `service` / `data`) sets colour, width and dash; `amount` adds a bold amount on the other side of the label; `shift` offsets an edge so that the two directions between the same boxes run side by side; `pulse` sends a train of dots along an edge in its own step or in the listed steps (`pulse-dur`, `pulse-n`), and `cues(k)` returns the pulse start times so a narration `{cue}` can time them (still `null` for figures without `pulse`)
- `m-quad` moves an item's label to the other side of its dot, then above or below, when it would cross an axis line (checked at the start and the `to` position); `m-flow` moves an edge label or amount away from the line, then to the other side, when it would come within `label-gap` (12 px) of a box or leave the figure. Positions use width estimates from the character count, so they do not depend on font loading. `tools/test-components.mjs` now also reports text that crosses an axis line (`line.axis`) or comes within 4 px of another box (`rect.box`)

## [0.3.0] - 2026-10-18

A deck as one portable file you can reopen and fix, following **Egatari** (絵語り), an open [format for portable decks](https://github.com/egatari/egatari-spec) (draft 1.0): stable slide ids, `--portable` / `--play-only` export and `npm run portable -- unpack|pack`, the editor app opens and saves these files without the folder (narration and timing edits are saved without rebuilding the slides), and the editing UI now runs outside the deck so a deck cannot change your files. The security section below collects the results of seven review rounds.

### Security

- `tools/get-fonts.mjs` downloads the fonts from a fixed commit of google/fonts, stops if a file is larger than expected and checks its SHA-256 before using it (it used the moving `main` branch without limits)
- SECURITY.md lists the residual risks accepted after the review of this version line

- **One bounded reader for untrusted files.** Every read of deck, workspace or portable-file data goes through `kit/bounded-read.mjs` (Node: `readRegular(path, {max})` — regular files only, `lstat` and `fstat` of the opened descriptor, non-blocking open, refused before reading when larger than `max`, at most `max` bytes read, growth refused) or `app/bounded-read.js` (browser: `readFileBounded(file, {max})` — `File.size` checked before `arrayBuffer()`, the bytes read checked after; `File.text()` is no longer used), sharing limits and errors in `kit/core/bounded-read-core.mjs`; the default limit is 32 MiB. New `tools/test-raw-reads.mjs` (in `npm test`) fails on any raw read (`readFileSync`, `fs.readFile`, `createReadStream`, `text()`, `arrayBuffer()`, …) outside these modules unless it is allowlisted, with a reason, as a read of trusted repository files. Routed through it: the dev server's and the editor's reads of `deck.html` (32 MiB), `narration.md` (16 MiB) and `comments.json` (4 MiB) — over the limit they answer 413 without reading, and refuse with 413 a save that would exceed it (previously `comments.json` was read whole and, if unreadable, overwritten); `npm run portable -- unpack`, which now refuses an input over the format's 100 MiB from the opened file's size before reading or copying it, and a FIFO without blocking; `npm run ids`, `kit/check.mjs`, `readNarration`, `render/` and the font-subset cache; the lab page's voice file.
- **Sizes are bytes.** The build's charged reader counts text in UTF-8 bytes: adapters may return `{text, bytes}` (`env.readTextBytes`, used by Node and the editor), and text from adapters that do not is charged its UTF-8 length, never its UTF-16 length (previously multi-byte text from a size-less adapter was undercounted up to three times).
- **Audio compression reads only what was charged.** The `.wav` source is read once through the bounded reader, up to the size charged for it (growth is refused), hashed from those bytes, and given to ffmpeg as a copy in a private temporary folder instead of reopening the original path.
- **Concurrent editor reads stay within the reservation.** Each of the up to 8 concurrent workspace reads of a build is capped at its listed size, which was reserved before dispatch; a file that grew since the listing is refused even within the limit. Previously each read was allowed the whole remaining budget (8 files listed as 1 B under a 64 B budget allocated 8 × 57 B before refusing).
- **Portable export projects every layer before building it.** The archive chunks are encoded only after the whole file has been checked; the index is checked from a lower bound before it is serialized (also against the reader's 4 MiB `indexBytes`), and the readable layer is counted in escaped characters (`&` → `&amp;`) while it is built and refused as soon as it would not fit. Previously the readable layer was built, escaped, before the whole-file check, and the index size was not checked.
- **Portable export shares the build's budget.** `exportPortable` (`--portable`, `--play-only`, the editor's export) creates one budget, passes it to the build and reads everything it reads itself — narration, the copied source, component and theme files, `voice.json`, `egatari.json`, audio and its segment metadata — through the same charged reader; audio is charged before compression too (also audio referenced from the archive). The projected size of the archive chunks is checked before they are encoded, and the whole file, including the readable layer, index and chunks inserted after the build, before it is joined. Previously these reads went around the budget: a 1 GiB `voice.json` or audio entry was read (and a 1 GiB MP3 produced), and the inserted layer was not size-checked.
- **Reads are reconciled with the bytes actually read, and only regular files are read** (format spec §11, `vendor/egatari-spec` synced to c576bb8). `env.size` is now an estimate: each read is charged max(estimate, actual), and a file that turns out larger than its reported size is refused (`build-too-large`, “changed while reading”). Reads get the number of bytes they may return. On Node the build checks the file with `lstat` and the opened descriptor with `fstat` (regular file, same file), opens it non-blocking and reads from that descriptor at most the allowed bytes, never `readFileSync` on an unchecked path; FIFOs, devices and sockets are refused with `build-not-a-file` before reading. The editor app re-checks `File.size` right before `arrayBuffer()` and charges the bytes read. Previously a finite `size()` suppressed the actual count (`size() => 0` let 32 bytes through a budget of 4), and a FIFO placed as an include or `tokens.css` passed the checks with size 0 and blocked the build in `readFileSync`.
- **Dev server: watchers stay inside the deck folder.** The deck folder, `audio/`, `data/`, `figs/` and `components/` are watched only if they are real folders inside the deck folder's real path (`lstat` / `realpath`); a symbolic link (also one pointing inside) is not watched, with one warning. Previously a symlinked `audio/` pointing elsewhere was watched, and changes there triggered rebuilds (nothing was read from it).
- **One read budget for the whole build.** Every file the build reads — source, includes, embeds, `theme.json`, `tokens.css`, logos and parent themes, components, narration, audio (also before compression), fonts and the runtime — now counts toward the include count and one aggregate read budget (`readChars`, 256 Mi), charged from the file size before reading (`env.size`), so an oversized file is refused with `build-too-large` without being read; logos and the whole output are size-checked before they are joined. Previously theme logos (10 001 were accepted), theme CSS and component scripts were not counted. The editor app no longer prefetches every small file of the folder: it reads only the files a build references (export too), at most 8 at a time, within the same budget checked from the listing, and stops starting reads when the build is stopped.
- **Build-worker messages are bound to their worker.** The editor app's build worker and portable-reader worker clients tie every request and reply to the worker object and generation that made it: replies and requests from a stopped or older worker are dropped, a worker's file requests are answered only to that worker and only for the workspace of one of its pending builds, request ids are unique across generations, and a deadline stops only the worker it belongs to. Previously a stopped worker's pending read reply could reach its replacement, whose ids had restarted.
- **Registry names are identifiers.** Registry `components[].name` and `themes[].name` in a portable file must match `^[a-z][a-z0-9-]{0,63}$` (format spec, `vendor/egatari-spec` synced to f031391); the reader refuses others, the writer does not record them, and `npm run portable -- unpack` compares registry components through a contained regular-file read under `components/`. Previously `name: "../../private"` passed validation and the CLI hashed a file outside the registry.
- **Editor backup cleanup deletes only backups.** The editor app's folder and in-memory workspaces now share the backup name rule (`kit/core/backup-name.mjs`) with the dev server's cleanup, and delete only `<time>-<name>` files directly in `.cache/edits/`; previously any file there beyond the newest 30 could be deleted.
- **No symbolic links followed out of a deck folder** ([format spec](https://github.com/egatari/egatari-spec) §11). All writes of the dev server (source edits, narration, comments, backups in `.cache/edits/`), `npm run ids`, `npm run portable -- unpack` / `pack`, the build's `out/` and `egatari.json` go through one helper (`kit/safe-fs.mjs`): it refuses when the file or any folder between the deck folder and it is a link (also an inside or dangling one), checks the real parent, and writes an exclusive temporary file that is synced and renamed over the target. Backup cleanup deletes only regular, backup-named files in a checked backup folder; previously a linked `comments.json` or `narration.md` let a save overwrite an outside file, and a linked `.cache/edits` received backups and lost its oldest entries. The build now checks components, `theme.json`, `tokens.css`, logos and every `extends` parent by real path against their authorized root (deck folder, `components/`, `themes/`) before reading, carrying the root through inheritance; previously a linked `tokens.css` or `index.js`, or an `extends` with `../` or an absolute path, put an outside file into the built deck. In the editor app, Chromium does not expose links in a picked folder (tested).
- **Classification parses with scripting enabled**, like the browser that shows the deck: `<noscript><p title="</noscript><script>…</script>"></p></noscript>` was read as an attribute by the classifier but ran in the preview. The build's boundary search, the portable reader and tier-A edits use the same mode.
- **Build limits and a build worker.** The build counts includes, embeds and formulas while expanding and stops with `build-too-large` (defaults: 10 000 includes and embeds, 64 Mi characters after preprocessing, 256 Mi after embedding, 500 000 tags per parse, 20 000 formulas; configurable). The editor app builds and classifies opened decks in a worker that is stopped after 60 s (`build-timeout`), so a deck that includes a small file 100 000 times no longer freezes the page.
- **A narration save no longer clears newer input.** The drawer keeps an edit revision; a save response marks it saved, and lets it follow the deck, only if nothing was typed after the save was sent. Otherwise the newer text stays, the drawer stays unsaved and the preview stays inert.
- **Code is classified on the built document.** Whether a deck can run code is decided from the document the build produces — after every include and preprocessing step, covering every file read as text whatever its extension, and on the same bytes that are rendered ([format spec](https://github.com/egatari/egatari-spec) §6). The build inserts its trusted parts (fonts and runtime CSS, the runtime scripts) at element boundaries found by parsing, not by regular expressions, reports where it put them, and classifies everything else; a trusted part that the deck's bytes swallow or break out of is not trusted. The editor app classifies the preview document itself instead of reading the folder a second time, and keeps the previous preview until the question about code is answered. A portable file is classified on its extracted source and on a build of it; exports take their profile from the same result. `<meta http-equiv="refresh">` counts as code.
- **Component formulas: one selection rule.** `m-curves` uses its data only when exactly one direct child `<script>` has the type `application/json` (trimmed, case-insensitive; any id). The classifier applies the same rule, treats several or nested data blocks as code, and checks every candidate formula, so a decoy block (for example `id="deck-…"`) cannot hide the formula that runs.
- **Dev server: no top-level preview.** `/preview` serves the deck only with a capability issued with the frame page (or presenter window) and `Sec-Fetch-Dest: iframe`; opened directly it returns a 403 text page that runs nothing. Tests check that a framed preview cannot reach an outside URL with `top.location`, `window.open`, a `target=_blank` link or `location.replace`.
- **Saves recheck their deck after every wait.** Portable saves and the folder writes recheck the workspace after the permission prompt, the save picker and while writing, abort the file write when another deck was opened, write the settings (new lesson id) and mark the deck saved only after the final write, and keep the unsaved mark when an edit happened during the save.
- **Bounded reading of portable files.** The reader parses with budgets for elements, attributes and nesting counted while parsing (`kit/core/bounded-html.mjs`) and limits the tags in the extracted source; the editor app stops a read after 30 s. A 90 MiB file of tiny elements is refused in under 0.1 s.
- **The preview is inert while you edit narration**, too, and hints from the deck do not open, close or switch panels while you edit in a trusted field.
- **The preview policy is in force before any deck byte.** The editor app builds the preview document (and the presenter view and its inner views, also in the single-file build) as a trusted prefix — doctype, `<html><head>`, `<meta charset>`, the policy `<meta>` and the trusted shim — followed by the built deck unchanged, instead of searching the deck's markup for `<head>` (which a comment, a `<template>`, an attribute value or an early `<script>` could defeat). The editor page's own policy now has `frame-src 'none'`, so a deck cannot navigate its frame to the app's origin or to a `data:` URL. `tools/test-security.mjs` (in `npm test`) tries eleven such documents against a page with the editor's policy.
- **Dev server: one framable preview endpoint.** The deck document moved to `/preview`, with a CSP `sandbox` directive (opaque origin even when opened directly); the deck's and the frame page's `frame-src` allow only that endpoint. Files of the deck folder under `/deck/…` all carry `Content-Security-Policy: sandbox; default-src 'none'` and `nosniff`; anything but audio, video, images and fonts is served as `text/plain` or `application/octet-stream` with `Content-Disposition: attachment`, so an HTML or SVG file placed in the folder never runs as a document.
- **Whether a deck can run code is decided from its content**, not from the profile a portable file declares ([format spec](https://github.com/egatari/egatari-spec) §6; `kit/core/code-scan.mjs`): scripts without a data type, event-handler attributes, `javascript:` URLs, `srcdoc`, embedded documents, included SVG or HTML with any of these, JavaScript files, and component formulas that are not plain arithmetic. A file declared “core” with code in it is asked about like any other, with a warning about the inconsistent label. Every preview and presenter-view load — including reloads, polling rebuilds and opening the presenter — goes through that question; Cancel also closes the current preview and presenter view. Exports use the same rule for their profile.
- **Sizes are checked before allocation** (format spec §11): the editor app refuses a file from `File.size` before reading it, the reader counts the extracted size per path (several paths may share one blob) before decoding, and the reader worker transfers each blob once with a path table instead of one copy per path.
- **Saves are bound to their workspace.** Each write is tied to the workspace and a generation counter captured when it starts; if another deck is opened meanwhile, it is cancelled with a message and nothing is written to either. Writes run one at a time, and the source (or narration) is read again right before writing: an outside change after the check gives a conflict instead of being overwritten. Portable saves are serialized and bound the same way.
- **Editing controls are outside the slide area.** The edit-mode bar, source box, note box and list and the narration drawer form one side panel next to the preview, under an orange marker bar (“Editing — app” / “Editing — dev server”) that the deck cannot draw outside its frame; while a source or note box is open, the preview is `inert`. Anything inside the slide area can be drawn by the deck; trust only controls in the editor's own panels.
- **The preview can no longer write.** In the dev server and in the editor app, the editing UI (source card, narration drawer, comment box and list; `server/editor-ui.js`) moved out of the deck into a trusted page: the dev server's new frame page at `/` (the deck is now an iframe at `/deck/`) and the editor app's own page. The deck runs in a sandboxed iframe with an opaque origin and only sends hints (`server/hints.js`: the element or step to open, a note position, the keys `e` / `n` / `c` / Esc, its position), which carry no text to write. The trusted UI reads the source itself, checks the range against the current build and the hash, and writes only when Save (or ⌘/Ctrl+Enter) is pressed in it. The editor app no longer answers write requests from the preview at all (`app-api` is gone), and `server/client.js` is replaced by `server/hints.js` and `server/editor-ui.js`
- Dev server: the per-run token is embedded only in the frame page, never in the deck document; `/__dev/` refuses `Origin: null` and cross-site `Sec-Fetch-Site` even with the token; text edits must name an element marked editable by the current build, narration edits a slide of the deck; the frame page cannot be framed (`frame-ancestors 'none'`)
- No network from the preview: the deck document gets a Content-Security-Policy with `connect-src 'none'`, every other resource from `data:` / `blob:` only (the dev server also allows its own `/deck/audio/`, and frames only `/preview`), no workers, forms or `<base>` — in the dev server as a response header, in the editor app as the first element of the preview document
- Editor app: before running a deck's own code — a portable file with the “extended” profile, or a folder with components (`.js` files) or scripts in `deck.html` — the editor says so and starts the preview only after “Start the preview” (Cancel opens nothing)
- `tools/hostile-deck.mjs`: a deck whose component and inline script try to write (old write messages and hints with forged text, reading the token, reaching the parent document, `fetch` / XHR / beacon to the write endpoints with and without a guessed token); `tools/test-dev-server.mjs` and `tools/test-app.mjs` check that nothing in the folder changes and that only Save in the trusted UI writes

A security release. It matters only if you build, check or serve a deck folder that you did not create yourself (for example, one downloaded or received from someone else). The editor app in Chromium is not affected by the first two items.

### Security

- The dev server (`npm run dev`) no longer follows symbolic links placed in the deck folder when it saves. - Low: the cleanup of old backups in `.cache/edits/`, in both the dev server and the editor app, deleted any file there beyond the newest 30, not just backups. It now deletes only files with the backup name form (`<timestamp>-<name>`), shared by both through `kit/core/backup-name.mjs`
- SECURITY.md now says exactly what is and is not contained (see "What is not covered")

- **Attention marks** (`{mark:ID|effect}` in the narration): hand-drawn underline, circle, box, spotlight and laser dot, timed to the narration
- **Morph transitions** (`data-morph`, `\morph{ID}{…}`, `data-id`) that slide equations and elements from the previous slide
- **Presenter tools**: presenter view with speaker notes and timer, slide overview, laser pointer, pen and fading pen, a control bar, a key list (`?`), and a feedback link that sends no slide content
- **Themes** derived from one base color (`themes/<name>/tokens.css`, optional `theme.json` with `extends` and logos): `default`, plus the institutional themes `tml`, `tcue`, `wsd` and `ohte`
- **Checker** (`kit/check.mjs`): overflow, text size, steps, narration coverage, contrast, component determinism, marks and morphs, with Japanese and English rules
- **Dev server** (`server/dev.mjs`, default port 8730): live reload, in-browser editing of the source and the narration, comments for Claude Code in `comments.json`, local-only with a per-start token
- **PDF** export (`tools/pdf.mjs`), one page per slide
- **Narrated video (optional tier 2)**: TTS through an OpenAI-compatible speech server (`tts/synth.py`, Irodori-TTS for Japanese, VoxCPM2 for other languages) with a reading dictionary and caching, frame-exact rendering to per-step MP4 clips and a full video (`render/render.mjs`), a lesson bundle for canon (`render/export-canon.mjs`), and self-playing HTML with embedded AAC audio (`--embed-audio`)
- **Claude Code skills**: `motion-slides`, `motion-slides-video` and `motion-components`
- **Examples**: `examples/minimal` (Japanese, gradient descent) and `examples/tmlr2026-calibration` (English, a TMLR 2026 paper)
- Docs: README (English and Japanese), the contract (`docs/contract.md`), a reference of every option, syntax and key (`docs/reference.md`, `docs/reference.ja.md`), guides for the dev server and video, CONTRIBUTING, SECURITY, issue forms
- Tests (`npm test`) and GitHub Actions running them on Node 22 and 24, plus a TTS dry-run through video export
