# 編集アプリ（インストール不要）

[English](editor.md) | 日本語

デッキのフォルダを直接開き、[開発サーバー](dev-server.ja.md)と同じこと（プレビュー、スライドの上での原稿・口述原稿の編集、Claude への指示）をするウェブページ。[持ち運べる 1 ファイル](reference.ja.md#持ち運べる-1-ファイル--portable)（原稿も中に持つ 1 つの HTML。[持ち運べるデッキの形式](https://github.com/egatari/egatari-spec)に従う）も、フォルダなしで開き、メモリの上で直して保存し直せる。インストールもターミナルも要らない。

- **ブラウザ：** パソコンの Google Chrome か Microsoft Edge（Windows・macOS・Linux・ChromeOS）。フォルダは File System Access API（`showDirectoryPicker`）を使うので、Safari と Firefox では開けない（最初の画面にそう出る）。持ち運べる 1 ファイルは今のどのブラウザでも開いて直せる（ファイルを選ぶ画面がなければ、保存はダウンロードになる）
- **通信：** アプリ自身の読み込みのほかは無い。デッキのフォルダやファイルはブラウザの中で読み書きし、どこにも送らない

## アプリの入手

| 形 | 開き方 | 備考 |
|---|---|---|
| 配信 | <https://editor.egatari.org/>（このドメインが使えるようになるまでは <https://egatari.github.io/egatari-studio/>） | `main` から `.github/workflows/pages.yml` で公開する。字はデッキが使う分だけ読む。前の場所 `…/editor/` からはここへ移る |
| 1 ファイル | `npm run build:app` のあと `dist/editor.html` をダブルクリック | 約 10 MB（字を全部入れてある）。Chrome・Edge なら `file://` で動く。このファイルを人に渡してもよい |
| 自分のサーバー | `npm run build:app` のあと `dist/` を静的に配る | どこでもよい（https か `http://localhost`）。サイトの根でも、下のパスでもよい |

`npm run build:app`（`node tools/build-app.mjs [--out dist] [--no-single]`）は先に `npm ci` が要る（版を固定した開発用の依存 esbuild を使う）。

## 使い方

1. **デッキを開く。** デッキのフォルダ（`deck.html` の入ったフォルダ。`deck.html` がなければフォルダの最上位の最初の `.html`）を画面に落とすか、「フォルダを開く」を押す。そのフォルダを編集してよいか、ブラウザが 1 回たずねる
   - **新しいデッキ**：`npm run new` と同じ雛形から `deck.html` と `narration.md` を作る（タイトル・言語・テーマ）。空のフォルダを選べばそこに、空でなければ中にタイトルの名前のフォルダを作る
   - **最近開いたフォルダ**：最初の画面に並ぶ（ブラウザがフォルダのハンドルを IndexedDB に残す。中身は残さない）。開き直すとき、ブラウザがもう一度許可を求める
2. **直す。** キーは開発サーバーと同じ（道具の列にもボタンがある）

   | キー | すること |
   |---|---|
   | `e` | 編集モード。枠の出た要素を**ダブルクリック**すると原稿（HTML と `\( … \)` の式）が開く。⌘/Ctrl+Enter で保存 |
   | `n` | 表示中の段階の口述原稿の引き出し（話者、発言の追加・削除・並べ替え） |
   | Alt+クリック（Mac は ⌥ option+クリック） | その要素について Claude への指示を残す（`comments.json`） |
   | `c` | 未対応の指示の一覧。クリックでそのスライドへ、「解決」で対応済み |

   編集モードの帯・原稿の欄・口述原稿の引き出し・コメントの欄と一覧は、どれも右の 1 つの板（プレビューはその横に縮む）にあり、板の上には橙の帯 **編集中 — アプリ** が付く。どれもデッキではなく編集アプリのページの一部。**スライドの場所に見えるものはデッキが描けるもの。信じてよいのはエディタ自身の板の道具だけ。** 原稿の欄・コメントの欄を開いている間、プレビューはクリックを受けない。プレビューはダブルクリックや Alt+クリックの場所を知らせるだけで、原稿を読み・見せ・「保存」（か ⌘/Ctrl+Enter）を押したときに書くのは編集アプリ。キーはプレビューの上でも編集アプリの上でも効く

   開発サーバーと同じく、プレビューを組んだ後にファイルが変わっていれば（原稿の hash・口述原稿の版が合わなければ）保存しない。読み込み直してからもう一度
3. **Claude Code と一緒に。** Claude Code（やほかのエディタ）がフォルダを変える間も開いたままでよい。約 1.5 秒ごとにファイルを見て、変わったら組み直し、同じスライド・段階のままプレビューを読み込み直す。原稿の欄や口述原稿の引き出しで入力中のものは、プレビューを読み込み直しても残る（編集アプリのページにある）。その間に同じ要素や段階が変わっていれば、保存は断る。組み立てに失敗したら、直るまでプレビューの上にエラーを出す
4. **発表する・渡す。** 道具の列から（幅 1280 px 以上なら 1 行に収まり、それより狭いと折り返す）。「開く ▾」に「フォルダを開く…」と「ファイルを開く…」、「書き出す ▾」に書き出しと印刷がまとまっている
   - **簡易チェック**：`npm run check` の一部をプレビューの中で行う（はみ出し・文字の大きさ・タイトルと結論の字数・口述原稿の抜け・パレットのコントラスト）。結果をクリックでそのスライドへ。目安であって全部の検査ではない：部品の再現性・タイムライン・モーフ・読み上げは見ない。画面の大きさが違うので、数値がコマンドの検査とわずかに違うことがある
   - **書き出す ▾ →「HTML を書き出す」**：編集の仕掛けを除いて組み、1 つの HTML に保存する（保存先をたずねる）。ダブルクリックでどこでも発表できる
   - **書き出す ▾ →「印刷 / PDF」**：デッキをブラウザの印刷にかける（`tools/pdf.mjs` と同じく、各スライドの最終状態を 1 ページずつ。「PDF に保存」を選び、「背景のグラフィック」を入れる）
   - **発表者ビュー**（デッキの `p` でも）：今の画面・次の段階・口述原稿（カンペ）・経過時間・描く道具の窓。編集アプリの窓のプレビューを操作する
   - **全画面**：プレビューを画面いっぱいにする（投影用）

## 持ち運べる 1 ファイル（フォルダなし）

持ち運べる 1 ファイルは、`npm run build -- <deck.html> --portable`（または編集アプリの「1 ファイル（持ち運べる形）を書き出す」）が書くもの。組んだデッキと同じように再生でき、デッキの原稿と音声を中に持つので、元のフォルダがなくても編集アプリで直せる。

- **開く。** 「ファイルを開く…」（最初の画面か、道具の列の「開く ▾」）を押すか、ファイルを最初の画面に落とす。編集アプリはファイルをバイト列として読み、スクリプトを動かさない HTML の解析器で、Web Worker の中で取り出す。ファイルそのものをページとして読み込むことはないので、取り出しの間に中のものは何も動かない。形式のハッシュ・大きさの上限・パスの規則を先にすべて確かめる（`npm run portable -- unpack` と同じ）。HTML は上限（要素・属性・入れ子の深さ）を解析の途中で数えながら解析し、中の原稿のファイルに書かれたタグも 500000 までにするので、小さな要素を何百万も並べたファイルは、全部の木を作る前に断る。読むのに 30 秒より長くかかれば Worker を止めて断る。開いたデッキ（フォルダ・持ち運べる 1 ファイル）の組み立てとコードの確かめも Worker の中で、組み立ての上限（[reference](reference.ja.md#組み立ての上限)）の内で行い、60 秒より長くかかればその Worker を止めて失敗にする（`build-timeout`）。その間もページは固まらない。フォルダから読むのは組み立てが参照したファイルだけ（同時に 8 つまで、1 つは一覧の大きさまで。一覧の後で大きくなったファイルは断る）で、止めた Worker からの答えは捨てる。どのファイルも、読む前に `File.size` で、読んだ後に読んだバイトで大きさを確かめ（`app/bounded-read.js`）、`deck.html`・`narration.md`・`comments.json` には決まった上限（32 MiB・16 MiB・4 MiB）があり、超えるものは読まずに断る。原稿はメモリの上（メモリの上のフォルダ）に置き、プレビュー・編集の道具・簡易チェックはフォルダのときと同じように動く。フォルダがないので、外での変更は見張らない
- **保存。** 「保存」は、ブラウザが書き込めるハンドルをくれたとき（Chrome / Edge の「ファイルを開く…」かドラッグ＆ドロップ。初めは許可をたずねることがある）は同じファイルに書き直す。そうでなければ保存先をたずね、保存の画面がなければ（Safari・Firefox）ダウンロードする。文書の識別子（`docId`）は変えず、`derivedFrom` を付けることも変えることもない。「保存」の横の一覧（保存 ▾）には次の 2 つがある
  - **「新しい教材として保存…」**：保存先をたずね、新しい `docId` の教材として書く。元の教材を `derivedFrom`（元の `docId` と原稿の hash）に記録し、著作権・クレジット・作り手はそのまま残す。開いている文書は新しい教材になる（この後の保存も新しい識別子のまま）
  - **「別のファイルに保存…」**：保存先をたずね、同じ教材（同じ `docId`）を別のファイルに書く

  ファイル名の前の ● は保存していない変更の印。ページを離れるときや別のファイルを開くときは先にたずねる。どの保存でも、ライセンス・著作権・クレジット・作り手、編集アプリの知らない索引の項目（どの深さでも：metadata・音声の記録・塊・部品とテーマ・拡張の中）と拡張のデータは残し、触れていない音声はバイトのまま写す。設定のファイル（原稿の根にある教材の識別子と metadata）がないファイルには、編集アプリが足すことがある。それで原稿の hash は変わるが、保存はもともとそれを書き直す
- **組み直さずに保存する。** 口述原稿（発言の文・注目の演出・区切り）、音声、`timeline.json` の秒数の上書きだけが変わったときは、「保存」はスライドを組み直さない。[形式](https://github.com/egatari/egatari-spec)がそういう編集に挙げる所（§7.2 の段 A）だけを書き換える：実行系の口述原稿・注目の演出・秒数・音声のデータのうち変わった段階の項目、スクリプトなしで読める文字の層のうち変わった段階、原稿の hash と索引とその hash、中に入れたファイル（新しい中身を足し、どこからも参照されなくなった中身を除く）、そして新しい文に、埋め込んだ字にない字があるときだけ、字の補い（その字を含む字の分割ファイルだけを、編集アプリが持つ字から入れた新しい style 要素。前からある字のデータには触れない）。ファイルのほかのバイトは、ほかの道具や別の版が書いた実行系も含めて、1 バイトも変えない。状態の欄に「組み直さずに」と出る。段階の口述原稿をすべて消すと、その段階の音声も消える。保存の知らせに警告があることが出て、「警告」の一覧にその段階が出る。秒数の上書きは項目ごとに写し、各段階の長さは実行系がそれまでと同じ式で計算する
- **組み直して保存する。** スライドを直したとき（または上の所の外が変わった、ファイルの組んだ教材と原稿が食い違うとき）は、直した原稿から編集アプリに同梱の kit・部品・テーマでファイル全体を組み直すので、プレビューとまったく同じに再生する。保存の前に **「スライドはこのエディタの今のバージョンで組み直されます。編集していないスライドも、見え方が変わることがあります。」** と知らせ、組み直さずに保存できない理由も見せ、「組み直して保存」を押してから保存する（取消なら変更は保存しないまま）。まだできないこと：組み直しの前と後のスライドを比べること。保存した後にプレビューで確かめる
- **古い音声。** 段階の口述原稿を直しても、その音声には触れない（バイトも種類もそのまま）。その段階は警告に「音声が古い」と出て、保存したファイルでも音声の記録は作ったときの口述原稿の hash のままなので、どの読み手にも古いと分かる。編集アプリで音声を作り直す・録り直すことはまだできない。フォルダに書き出してコマンドで TTS を
- **書き出す ▾ →「フォルダに書き出す…」** は、選んだ空のフォルダに原稿・音声・`audio/manifest.json` を書く（`npm run portable -- unpack` と同じファイル）。空でないフォルダは断る。書き出したフォルダは、ふつうのデッキのフォルダとして開け、組め、まとめられる
- **書き出す ▾ →「1 ファイル（持ち運べる形）を書き出す」**（フォルダを開いているとき）は、フォルダを持ち運べる 1 ファイルにする。初回は教材の識別子をフォルダの設定のファイルに書き、次からの書き出しでも同じものを使う
- **ファイルに入らないもの：** Claude への指示（コメント）と `.cache/edits/` の控えはメモリの上にだけ残る（コメントは見直しの覚え書きなので、形式が外す）

### 権利の確認

ファイルを編集のために開くたびに、最初の変更の前に（編集モードや口述原稿の引き出しで最初に保存するとき、または「編集」「口述原稿」を押したとき）、ファイルに書かれた題名・作り手・著作権・ライセンス・クレジットの表示を見せる（どれも申告で、確かめたものではない）。改変を認めないライセンス（Creative Commons の `-ND`、All rights reserved）か、ライセンスがなく著作権の表示だけのときは、改変や改変したものの配布が権利者の著作権を侵すおそれがあると知らせ、確認のチェックを入れるまで編集を始めない。取消ならファイルは変わらない。保存で著作権・クレジット・作り手を消すことはない。

### 断るファイル・読むだけで開くファイル

- **理由を見せて断る：** 持ち運べる 1 ファイルでないもの・再生専用のもの、ハッシュが合わないもの・一部が欠けたもの、許されないパス（`../` など）、索引の同じ名前の項目、設定のファイルと食い違う文書の識別子、新しい原稿の書き方の版
- **新しい major の版、編集アプリが実装していない必須の機能：** 編集のためには開かず、書き出し（作り直し）もしない。索引と中のデータが、編集アプリの知っている版の規則で確かめられれば、原稿を取り出す「フォルダに書き出す…」を申し出る。確かめられなければ取り出しも断る（そういうファイルもブラウザで再生はできる）
- **口述原稿・音声・秒数だけ：** 実行系の約束の版が違うもの、部品庫・テーマ庫の部品の hash が編集アプリのものと違う（または編集アプリにない）もの。編集アプリではそのとおりに組み直せないので、口述原稿・音声・秒数だけを編集できると上に知らせる。「編集」（スライドの文字）は断り、口述原稿の引き出しは使え、「保存」は組み直さずにその所だけを書き換える。組み直しの要る変更は保存できない
- **読むだけ：** 編集アプリで組み立てられないもの、ひとつ前の種類で、しかも組んだ教材と原稿が食い違うもの。デッキは表示し、保存は断り、「フォルダに書き出す…」はできる
- **独自のコード：** デッキが自前のコードを持つかは、組んだ文書から決める（取り込み・前処理の後の原稿全体。組み立てがテキストとして読むファイルは拡張子によらずすべて含み（`/*INCLUDE:…*/` で取り込んだ画像のファイルも）、そのあとプレビューに出すのと同じバイト）。調べるためにフォルダをもう一度読むことはしない。そういうデッキ（と「extended」のファイル）は、その中のものが動く前に知らせてたずね、「プレビューを始める」を押してからプレビューを始める（取消ならファイルは開かない）。たずねる前にプレビューを空にするので、前のデッキも新しいデッキも、たずねる窓の後ろに出ることも動くこともない。開いている間は上に知らせを出す：コードはプレビューの中だけで、外へ繋がらずに動き、ファイルを書き換えられない。部品（`components/…`、どれかの `.js`）や `deck.html` のスクリプトを持つフォルダも、開くたびに 1 回同じことをたずねる（あとからそういうコードが現れたときも）

## 書き換えるファイル

開発サーバーとまったく同じ（[dev-server.ja.md](dev-server.ja.md) の「書き換えるファイル」）。どれも選んだフォルダの中

- `deck.html`：編集した要素の中身だけ
- `narration.md`：編集した段階の行だけ（注釈やほかの行はそのまま）
- `comments.json`：Claude への指示 `[{id, created, key, range, quote, comment, status}]`
- `.cache/edits/`：書き換える前の `deck.html`・`narration.md`（新しい 30 個。掃除で消すのは控えの名前の形（`<時刻>-<名前>`）のファイルだけで、フォルダのほかのものは残す）
- 「新しいデッキ」では `deck.html` と `narration.md`、「HTML を書き出す」「1 ファイル（持ち運べる形）を書き出す」では選んだファイル（と、初回はフォルダの設定のファイルの教材の識別子）
- 持ち運べる 1 ファイルを開いたとき：保存するまで何も書かない（直したものはメモリの上）。保存では選んだファイルだけ（組み直さない保存では、上に挙げた所だけを書き換える）、「フォルダに書き出す…」では選んだ空のフォルダのファイルだけ

## できないこと

- **Chrome・Edge だけ。** スマートフォンのブラウザもフォルダを開けない
- **コマンドで行うもの：** 読み上げ音声（TTS）・動画・教材バンドル（`tts/` `render/`）、全部の検査（`npm run check`）、`tools/pdf.mjs`。フォルダの音声（`audio/`）は読まない：自動再生は音声がないときと同じ既定の秒数
- **書き出しが大きい。** コマンドの build は fonttools で和文の字を絞り込める（`node tools/get-fonts.mjs`）が、ブラウザではできないので、使う字を含む分割ファイルをそのまま埋め込む（TTF がないときのコマンドと同じ）。`examples/minimal` は編集アプリで約 2.0 MB、絞り込んだ `npm run build` で 0.7 MB。見た目は同じ
- **同梱のもの。** リポジトリの部品（`components/`）・テーマ（`themes/`）・実行系（`kit/`）は、アプリを組んだときのもの。デッキのフォルダの中の部品とテーマ（`components/<名前>/index.js`、`themes/<名前>/`）は、いつもどおりフォルダから読む
- **読まないもの：** `.` で始まる名前と、`out/` `audio/` `video/` `bundle/` `node_modules/` のフォルダ（3000 ファイル・10 階層まで）。`audio/` は持ち運べる 1 ファイルに書き出すときだけ読む
- **組み直しはまだ比べない。** スライドを直した後の保存は、同梱の kit でファイル全体を組み直す（なので、古い・新しい build で作ったファイルは直した所の外も変わり、字は分割ファイルごと埋め込む）。直したスライドのほかにどのスライドが変わったかは、まだ見せない
- **音声はまだ編集アプリで作れない。** 組み直さない保存は音声を残し、直した段階を古いと示す。音声を作る・録ることはまだ編集アプリにない
- **字の補いは多めになることがある。** 絞り込んだ字に `unicode-range` のないファイル（前の版がコマンドで作ったもの）では、元の口述原稿の字があることしか分からないので、絞り込んだ字がもう持っている字の分割ファイルも足すことがある（ファイルが少し大きくなる。字が欠けることはない）
- **デッキの中からの通信は止まる。** 外部の画像やスクリプト（`https://…`）はプレビューに出ない（build はもともと警告する）

## 仕組みと安全

- **組み立ては 1 つ。** `kit/core/build-core.mjs` が組み立ての本体（注記・取り込み・KaTeX・部品・口述原稿・注目の演出・秒数・テーマ・ファイルの埋め込み・字）で、Node に依存せず、渡された口を通してだけファイルを読む。`kit/build.mjs` は Node のファイル（と fonttools の絞り込み・ffmpeg）を、編集アプリは選んだフォルダと同梱の kit・部品・テーマ・KaTeX・字を渡す。字の絞り込みを切れば、両方が 1 バイトも違わない HTML を出す（`tools/test-app.mjs` が `examples/minimal` と `examples/tmlr2026-calibration` で確かめる）。口述原稿の解析と書き換え（`kit/core/narration-core.mjs`）と新しいデッキの雛形（`kit/templates/new-deck.mjs`）も同じく共有する
- **編集の画面も 1 つで、デッキの外にある。** `server/editor-ui.js`（原稿の欄・口述原稿の引き出し・コメントの欄と一覧）は、ここでは編集アプリのページで、開発サーバーでは外枠のページで動く。どちらも同じ問い合わせ（`/__dev/source` `/__dev/edit` `/__dev/narration` `/__dev/comment` …）を送り、開発サーバーは HTTP で、編集アプリはページの中で開いたフォルダについて答える（`app/devapi.js`）。デッキの中にあるのは知らせを送る `server/hints.js` だけ（下）
- **デッキは砂場の中で動き、書き込めない。** プレビューは `allow-same-origin` を付けない `<iframe sandbox="allow-scripts allow-modals">` なので、デッキは origin を持たない。編集アプリの画面・保存領域・フォルダのハンドルに届かない。`allow-modals` は印刷のため。ページの Content-Security-Policy（アプリ自身の読み込みだけを許し、iframe の移動は許さない：`frame-src 'none'`）に重ねて、プレビューの文書には別の決まりを、デッキのどのバイトを解析するよりも前に効かせる。編集アプリはプレビューの文書を「信頼する先頭部分（doctype・`<html><head>`・`<meta charset>`・決まりの `<meta>`・小さな信頼する仲立ち）＋組んだデッキそのまま」として組み、デッキの文書の中を探して決まりを入れることはしない。決まりは `connect-src 'none'`、画像・字・スタイル・音声は `data:` / `blob:` だけ（組み立てが埋め込む）、Worker・iframe・フォーム・`<base>` は使えない（部品が `new Function` で式を作る（`m-sweep f="…"` など）ので `'unsafe-eval'` は残す）。発表者ビューは編集アプリが開く窓で、その中のデッキもまた同じ決まりの砂場の iframe。やり取りは編集アプリが中継する
- **頼みではなく知らせ。** プレビューには書き込みを頼む口がない。送れるのは知らせだけ：「この `data-src` の範囲と hash の要素を直したい」（編集モードでダブルクリック）、「この要素にコメントしたい」（Alt+クリック。スライドと段階の鍵と、要素の短い引用）、鍵の `e`・`n`・`c`・Esc、今の位置（`deck-pos`）。知らせは書き込む本文を持たない。編集アプリは送り元の窓と知らせの形を確かめ、編集モードでないときの edit の知らせは無視し、今の原稿を自分で読み、範囲が今の組み立ての直せる要素で hash が合うことを確かめて、自分の欄を見せる。書くのは、その欄や引き出しで「保存」か ⌘/Ctrl+Enter を押したときだけ。権利の確認と読むだけのファイルは、これまでどおりこの書き込みにかかる。編集アプリからプレビューに送るのは、見せるのに要るものだけ（編集モードの入り切り・印を付ける要素・「その段階へ」・印刷・簡易チェック）
- **触るのは選んだフォルダかファイルだけ**で、ブラウザの許可を得てから
- **保存は始めたときのデッキに結び付く。** 待つたび（組み直し・確かめの窓・権利の確認・保存先を選ぶ画面・ファイルを作る・書く）の後に、同じデッキが開いたままかを確かめ、その確かめを書き込みの中まで運ぶ：その間に別のデッキを開いたら、ファイルを入れ替えず（書き込みを取り消す）、ほかにも何も書かない。新しい教材の識別子をデッキの設定に書くのと「保存した」にするのは、ファイルを書いた後だけ。保存している間にした編集は、保存したファイルに入っていないので、未保存の印のまま
- **信頼する欄で編集している間**（原稿の欄・指示の欄を開いている、口述原稿の引き出しで入力している・未保存の変更がある）は、プレビューを `inert` にする。その間はデッキからの知らせで板の欄を開け閉め・切り替えせず、編集している口述原稿の段階も替えない
- **フォルダとリンク。** メモリの上・OPFS のフォルダはシンボリックリンクを持てない。選んだフォルダの中のリンクは、Chromium では編集アプリにまったく見えない（一覧に出ず、名前でも開けず、書けない。`tools/test-security.mjs` が確かめる）ので、組み立てがリンク越しにフォルダの外のファイルを読むことはない。File System Access API には編集アプリ自身がリンクを見分ける手段がないので、これはブラウザに頼っている
- **持ち運べる 1 ファイルを開いても、その中のものは何も動かない。** ファイルはバイト列として読み、スクリプトを動かすブラウザと同じ解析の規則で（何も実行しない）Web Worker（編集アプリに同梱。ページの決まりは `blob:` の Worker だけを許す）の中で解析する。そのファイルへ移動したり、ページに入れたりはしない。動くのは原稿から組み直したデッキだけで、フォルダのときと同じ砂場のプレビューの中

## GitHub Pages で配る

`.github/workflows/pages.yml` が `node tools/build-app.mjs --out _site` で組み、GitHub Pages に置く（編集アプリは根 `/`、1 ファイル版は `/editor.html`、試験ページは `/lab/irodori.html`。前に編集アプリがあった `/editor/` は、問い合わせと `#` を残して `/` へ移すページ）。パスはどれも相対なので、同じファイルが独自ドメイン <https://editor.egatari.org/>（Settings → Pages → Custom domain で設定し、サイト全体に効く）でも <https://egatari.github.io/egatari-studio/> でも動く。置く（deploy）のは `main` だけで、ほかのブランチで走らせると組んで artifact を上げるところまでする。Pages を設定するまでは何もしない

1. Settings → Pages → Build and deployment → Source を **GitHub Actions** にする
2. Settings → Secrets and variables → Actions → Variables に `EDITOR_PAGES` = `true` を足す（なければ push で置く手順を飛ばすので、Pages を有効にする前に失敗しない）
3. 1 回走らせる（Actions → pages → Run workflow）か、`main` に push する

## 確かめ方

`node tools/test-app.mjs [作業用のフォルダ] [--shots 画像のフォルダ]`（`npm test` に入っている）は、作業用のフォルダに編集アプリを組んで 127.0.0.1 で配り（サイトの形も、根と下のパスの両方で確かめる：編集アプリがコンソールのエラーなしに開く、`/editor/?lang=en#x` が `/?lang=en#x` へ移る、`/editor.html` と `/lab/irodori.html` が開く）、ブラウザの OPFS（origin-private file system）にデッキのフォルダを作って `window.__APP_TEST_OPEN(handle)` で開く。同じ HTML になること・原稿の編集（その間にファイルが変わったときの 409 も）・口述原稿の引き出し（発言を足す・CRLF のまま・409）・指示・外での変更・組み立ての失敗・簡易チェック・書き出し・発表者ビュー・英語の画面・`file://` の 1 ファイル版と、コンソールのエラーが無いことを確かめる。書き込みを試みるデッキのフォルダ（`tools/hostile-deck.mjs`：古い書き込みの知らせと偽の本文の知らせを送り、合言葉を探し、編集アプリのページに触り、書き込みの口に `fetch`・XHR・beacon する部品とインラインのスクリプト）は、動く前にたずね、フォルダの中を何も変えず、編集アプリで「保存」を押したときだけ書かれることを確かめる。持ち運べる 1 ファイルは、`examples/minimal`（dry-run の音声つき）と `tools/portable-fixtures.mjs` の試験用の文書から作り、開く・権利の確認（改変を認めないライセンスの確認も）・文字と口述原稿の編集・OPFS のファイルのハンドルへの保存・開き直し（同じ `docId`、変えていない音声の hash が同じ、展開したフォルダがメモリの上のものと同じ）・「フォルダに書き出す…」と「1 ファイルを書き出す」（同じバイト）・独自のコードの知らせ・印のスクリプトが編集アプリのページでも読み取りの Worker でも動かないこと・断るファイル（パスの抜け出し・新しい major の版・索引の重複・知らない必須の機能）・読むだけのファイル・ダウンロードでの保存、組み直さない保存（形式の所だけが変わることを、場所を見分ける差分で。新しい漢字の字の補い）、組み直しの知らせと取消、新しい教材として保存（`docId`・`derivedFrom`）、知らない索引の項目がどちらの保存でも残ること、テーマ庫の hash が違うファイル（口述原稿だけ）、知らない必須の機能のファイルの取り出し、独自のコードをたずねる後ろのプレビューが空であること、道具の列が両方の言葉で 1280 px と 1440 px で 1 行に収まることを確かめる。`node tools/test-tier-a.mjs`（これも `npm test` に入っている）は組み直さない保存だけを、`examples/minimal` と `examples/tmlr2026-calibration` で確かめる：場所を見分ける差分、ヘッドレス Chrome での再生、展開とまとめ直し、ほかの書き手のファイル、知らない項目、音声の差し替え、新しい教材、断る場合。`node tools/test-workspace.mjs` は、メモリの上のフォルダと権利の規則をブラウザなしで確かめる。

## 画面の言葉

ふだんはブラウザの言語（日本語か英語）に合わせる。右上の **English / 日本語** のボタンで切り替えるか、`…/?lang=en`・`?lang=ja` で開く。選んだ言葉は覚えておき、デッキを開いたまま切り替えても同じフォルダを開き直す（開いた持ち運べる 1 ファイルは閉じる。保存していない変更があれば先にたずねる）。編集の道具（編集モード・原稿の欄・口述原稿の引き出し・コメント）は編集アプリの言葉に合わせる（開発サーバーではデッキの言語 `<html lang>` に合わせる）。
